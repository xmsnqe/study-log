# 文件内部存储

## 📍知识定位

### 在408体系中的位置

文件内部存储是文件管理章节的核心内容之一，涵盖文件的**目录结构**、**文件目录管理**（FCB的组织方式）、以及文件系统内部的数据结构（如文件分配表FAT、索引节点inode等）。它在408考试中**选择题**和**大题**均有涉及，其中索引文件的计算（直接/间接索引）是典型的大题考点。

### 学习前置条件

- **文件管理概述**：理解文件的基本概念、文件控制块（FCB）的作用
- **文件物理结构**：了解连续分配、链接分配、索引分配三种方式
- **存储器**：理解磁盘空间分配与外存管理的基本原理（[[存储器]]）
- **IO系统**：了解文件I/O的底层硬件机制（[[IO系统]]）

### 学完之后支撑的知识点

- **文件共享与保护**：文件共享机制（符号链接/硬链接）与FAT/inode的关系
- **目录管理**：多级目录结构、文件路径的查找
- **文件分配表(FAT)**：FAT12/16/32等文件系统的具体实现
- **索引节点(inode)**：Unix/Linux文件系统的核心机制
- **磁盘分配与回收**：空闲空间管理与文件存储的关联

## 📝核心概念与原理

### 一、文件的目录结构 🔥

#### 1. 目录的概念

> **目录（Directory）**：是文件管理系统中用于**组织文件**的一种数据结构。目录本身也是一种文件（目录文件），其中包含了子目录或文件的信息（FCB）。

```
目录的本质：
目录文件 = 目录文件头 + 目录项（FCB）的集合
每个目录项包含：文件名 → 文件号（inode号）
```

#### 2. 目录的结构分类

**（1）单级目录结构（Single-Level Directory）**

```
┌─────────────────────────────────┐
│          目录文件                │
├─────────────────────────────────┤
│  data.txt  → inode 1001         │
│  main.c    → inode 1002         │
│  photo.jpg → inode 1003         │
└─────────────────────────────────┘
```

- **优点**：结构简单，易于实现；同一用户创建的文件易于管理。
- **缺点**：
  - 所有文件并列在同一个目录中，**文件命名冲突**（不能有同名文件）
  - 随着文件数量增多，目录查找时间增加
  - 不支持多用户共享
- **适用场景**：单用户、文件数量少的系统（如早期MS-DOS）。

> ⭐ **选择题考点**：单级目录结构只适用于单用户系统，不支持多用户。

**（2）两级目录结构（Two-Level Directory）**

```
用户A的目录               用户B的目录
┌──────────────────┐      ┌──────────────────┐
│ data.txt  → 1001 │      │ program.c → 2001 │
│ main.c    → 1002 │      │ game.exe→ 2002   │
└──────────────────┘      └──────────────────┘
```

- **优点**：每个用户有自己的目录，**不同用户可以有同名文件**，避免了文件命名冲突。
- **缺点**：用户之间无法直接共享文件；目录管理仍然简单。
- **适用场景**：早期的多用户系统。

**（3）多级目录结构（多级目录 / 树形目录结构）⭐ 🔥**

```
根目录 (/)
├── userA/
│   ├── data.txt  → inode 1001
│   └── subdir/
│       └── note.c → inode 1005
├── userB/
│   └── program.c → inode 2001
└── shared/
    └── common.h  → inode 3001
```

- **结构特点**：目录可以嵌套，形成**一棵目录树**（目录项中包含子目录的FCB）。
- **优点**：
  - 文件层次化管理，便于查找和分类
  - 不同目录中可以有同名文件
  - 支持复杂的共享机制
- **缺点**：文件路径变长，文件操作时需要遍历多级目录。
- **适用场景**：现代操作系统（Unix/Linux/Windows）均采用多级目录结构。

> ⭐ **选择题高频考点**：多级目录结构是树形结构，根目录是唯一入口，路径表示方式为 `根目录/子目录/.../文件名`。

**（4）无环图目录结构（Graph Directory）**

```
userA/data.txt  ─────┐
                     ├─────► 共享文件 common.h ───► inode 3001
userB/data.txt  ─────┘
```

- 允许**一个文件有多个父目录**（即多个用户共享同一文件）。
- 必须保证目录图中**无环**（防止无限循环遍历目录）。
- 通过**符号链接（软链接）**实现。

> 从CSAPP视角看，Unix/Linux的硬链接（hard link）允许多个目录项指向同一个inode；软链接（symbolic link）则创建一个包含目标路径的新inode。

#### 3. 目录查找过程 🔥

> 当用户访问一个文件时，操作系统需要逐级查找目录：

```
访问路径：/home/userA/data.txt

查找步骤：
1. 从根目录查找 "home" → 找到目录项，获得子目录的inode
2. 从 home 目录查找 "userA" → 找到目录项，获得子目录的inode
3. 从 userA 目录查找 "data.txt" → 找到目录项，获得文件的inode
4. 通过inode找到文件的FCB和外存物理地址
```

**时间复杂度分析**：
- 路径长度为 $n$ 级，需要 $n$ 次目录查找
- 每次查找在当前目录中线性扫描FCB列表（无索引优化时）
- 若目录已建立哈希索引，则查找时间降为 $O(1)$

> ⭐ **选择题高频考点**：文件路径的查找是**逐级进行**的，必须从根目录开始，逐级深入。

### 二、文件目录表（FDT）与索引节点（inode）🔥

#### 1. 文件目录表（FDT）

> **文件目录表（File Directory Table, FDT）**：是操作系统在内存中维护的一个数据结构，用于存放当前打开文件所在目录的目录项（FCB）信息。

```
┌─────────────────────────────┐
│  进程A的文件打开表            │
├─────────────────────────────┤
│  fd=0 → 标准输入              │
│  fd=1 → 标准输出              │
│  fd=2 → 错误输出              │
│  fd=3 → FCB(/home/data.txt)  │
│  fd=4 → FCB(/home/main.c)    │
└─────────────────────────────┘
```

| 表项 | 说明 |
|------|------|
| **文件名** | 文件的符号名称 |
| **文件号（inode号）** | 唯一标识文件的整数 |
| **外存地址** | 文件在外存上的起始磁盘块号 |
| **文件长度** | 文件的字节数或记录数 |
| **访问权限** | 读/写/执行权限 |
| **访问次数** | 当前打开该文件的进程数 |
| **修改时间** | 最后一次修改时间 |

> ⭐ **选择题考点**：FDT是内存中的目录表，每次打开文件时系统会将外存的FCB调入内存的FDT中。

#### 2. 索引节点（inode）⭐ 🔥

> **索引节点（inode, Inode）**：是Unix/Linux文件系统（如ext2/3/4）中用于描述文件元数据的**核心数据结构**。每个文件在文件系统中都有一个唯一的inode。

**inode包含的信息**：

| 类别 | 内容 |
|------|------|
| **文件基本信息** | 文件类型、长度、时间戳（创建、修改、访问） |
| **权限信息** | 所有者、所属组、其他用户的rwx权限 |
| **数据块指针** | 直接指针、间接指针（一级/二级/三级间接） |
| **链接数** | 指向该inode的目录项数量（硬链接数） |

```
Unix文件系统结构：
┌───────────────────────────────────────────┐
│  Super Block（超级块）                      │
│  ┌───────────────────────────────────────┐ │
│  │ 文件系统信息（块大小、总块数、空闲块数）   │ │
│  └───────────────────────────────────────┘ │
│                                           │
│  Inode Table（inode表）                     │
│  ┌───────┬───────┬───────┬───────┐        │
│  │ inode │ inode │ inode │ inode │ ...     │
│  │  #100 │  #101 │  #102 │  #103 │        │
│  └───────┴───────┴───────┴───────┘        │
│                                           │
│  Data Blocks（数据块）                      │
│  ┌───────┬───────┬───────┬───────┐        │
│  │ blk 1 │ blk 2 │ blk 3 │ blk 4 │ ...     │
│  └───────┴───────┴───────┴───────┘        │
│                                           │
│  Directory（目录项）                       │
│  ┌───────────────────────────────────────┐ │
│  │ "data.txt" → inode 100                │ │
│  │ "main.c"   → inode 101                │ │
│  └───────────────────────────────────────┘ │
└───────────────────────────────────────────┘
```

> ⭐ **选择题高频考点**：
> 1. inode中**不存储文件名**，文件名存储在目录项中
> 2. inode存储文件的元数据和数据块指针
> 3. 一个文件对应一个唯一的inode号

**inode的数据块指针结构**（ext2文件系统）：

| 指针类型 | 数量 | 说明 |
|---------|------|------|
| **直接数据块指针** | 12个 | 直接指向数据块 |
| **一级间接指针** | 1个 | 指向一级索引块，索引块中存放数据块号 |
| **二级间接指针** | 1个 | 指向二级索引块，二级索引块中存放一级索引块号 |
| **三级间接指针** | 1个 | 指向三级索引块 |

```
假设磁盘块大小为 4KB，每个块号占 4B：
每个块可容纳 4KB / 4B = 1024 个块号

文件大小上限 = 直接块 + 一级间接 + 二级间接 + 三级间接
             = 12 × 4KB + 1024 × 4KB + 1024 × 1024 × 4KB + 1024^3 × 4KB
             = 48KB + 4MB + 4GB + 4TB ≈ 4TB
```

> ⭐ **选择题高频考点**：inode数据块指针的计算是408大题的经典考点，务必掌握。

### 三、文件分配表（FAT）🔥

#### 1. FAT的基本概念

> **文件分配表（File Allocation Table, FAT）**：是**FAT文件系统**（如FAT12、FAT16、FAT32）中用于管理文件存储的**核心数据结构**。FAT表位于磁盘的特定区域，记录了每个磁盘块的占用情况以及文件各数据块之间的链接关系。

```
磁盘布局（FAT文件系统）：
┌─────────────────────────────────────────────┐
│  boot sector（引导扇区）                      │
│  ┌─────────────────────────────────────────┐│
│  │ 文件系统参数（块大小、FAT数量、...）       ││
│  └─────────────────────────────────────────┘│
│                                             │
│  FAT1（主FAT表）                            │
│  ┌───┬───┬───┬───┬───┬───┬───┬───┐         │
│  │0x1│0x2│0xFF│0xFF│0x3│0x4│0x5│...│         │
│  └───┴───┴───┴───┴───┴───┴───┴───┘         │
│  表项含义：                                 │
│  0x1 → 文件1的第1块                          │
│  0x2 → 文件1的第2块                          │
│  0xFF → 文件1的最后一块（EOF）                │
│  0xFF → 保留/坏块                            │
│                                             │
│  FAT2（备用FAT表，与FAT1相同）               │
│  ┌───┬───┬───┬───┬───┬───┬───┬───┐         │
│  │0x1│0x2│0xFF│0xFF│0x3│0x4│0x5│...│         │
│  └───┴───┴───┴───┴───┴───┴───┴───┘         │
│                                             │
│  数据区（Data Area）                         │
│  ┌───┬───┬───┬───┬───┬───┬───┬───┐         │
│  │ blk│ blk│ blk│ blk│ blk│ blk│ blk│ ... │
│  └───┴───┴───┴───┴───┴───┴───┴───┘         │
└─────────────────────────────────────────────┘
```

#### 2. FAT表项的含义

| FAT表项值 | 含义 |
|----------|------|
| `0x000` | 空闲块（未分配） |
| `0x001` | 保留（不使用） |
| `0x002` ~ `0xFFE` | 指向下一个数据块的块号（文件中的下一块） |
| `0xFFF` | 文件末尾（EOF, End of File） |
| `0xFF7` | 坏块 |
| `0xFF8` ~ `0xFFF` | 保留（如坏块标记） |

#### 3. FAT类型对比 ⭐

| 类型 | 表项位数 | 最大簇大小 | 最大卷大小 | 最大文件数 | 适用场景 |
|------|---------|-----------|-----------|-----------|---------|
| **FAT12** | 12位 | 0.5KB | 32MB | 4078 | 软盘、嵌入式系统 |
| **FAT16** | 16位 | 4KB | 2GB | 65518 | 早期硬盘、U盘 |
| **FAT32** | 32位（实际使用28位） | 32KB | 2TB | 约40亿 | U盘、SD卡 |
| **exFAT** | 64位 | 32KB | 128PB | 约27亿 | 大容量U盘、SD卡 |

> ⭐ **选择题考点**：FAT12/16/32的区别在于表项位数，位宽越大，支持的磁盘容量和文件数量越大。

#### 4. FAT与inode的对比 ⭐

| 对比项 | FAT | inode |
|--------|-----|-------|
| **存储位置** | FAT表位于磁盘/内存中 | inode表位于文件系统分区中 |
| **信息内容** | 记录数据块之间的链接关系 | 记录文件元数据+数据块指针 |
| **文件名存储** | 在目录项中 | 在目录项中（不在inode中） |
| **访问速度** | 需要依次遍历FAT表项（链表式） | 数据块指针直接给出（随机访问） |
| **磁盘碎片** | 容易产生碎片（FAT表需要连续存储） | 支持索引分配，碎片较少 |
| **适用文件系统** | FAT12/FAT16/FAT32 | ext2/ext3/ext4, NTFS |

```
FAT访问文件的步骤（链式）：
文件起始块号 → FAT表中查找 → 下一块号 → FAT表中查找 → 下一块号 → ... → 0xFFF

inode访问文件的步骤（随机）：
文件inode号 → inode表中查找 → 直接/间接指针 → 数据块号 → 直接访问磁盘块
```

> ⭐ **选择题高频考点**：FAT是**链表式**访问（需要遍历FAT表），inode是**索引式**访问（数据块指针直接给出块号）。

### 四、索引文件的块数计算 🔥

#### 1. 直接索引文件

```
文件由 n 个逻辑块组成，每个逻辑块对应一个直接磁盘块：
文件块数 = 直接指针数

假设每个磁盘块可容纳 m 个块号（索引表项）：
一个索引块可以存放 m 个块号
```

#### 2. 一级间接索引文件

```
一个索引块存放 m 个块号：
最大文件块数 = m（即一个索引块中的所有块号都指向数据块）
```

#### 3. 二级间接索引文件

```
一级索引块存放 m 个一级索引块号
每个一级索引块存放 m 个数据块号

最大文件块数 = m × m = m²
```

#### 4. 三级间接索引文件

```
最大文件块数 = m × m × m = m³
```

#### 5. 综合计算示例 🔥

> **例题**：某磁盘的块大小为 512B，每个块号占 2B。一个文件采用索引分配方式，FCB中有 10 个直接索引项、1 个一级间接索引项、1 个二级间接索引项、1 个三级间接索引项。求该文件最大可达多少字节？

```
解题步骤：
1. 每个块可容纳的块号数 m = 512B / 2B = 256

2. 直接索引部分：
   直接索引块数 = 10
   直接索引可容纳 = 10 × 512B = 5120B

3. 一级间接索引部分：
   一级间接块数 = 256（一个索引块存放256个块号）
   一级间接可容纳 = 256 × 512B = 131072B

4. 二级间接索引部分：
   二级间接块数 = 256 × 256 = 65536
   二级间接可容纳 = 65536 × 512B = 33554432B

5. 三级间接索引部分：
   三级间接块数 = 256 × 256 × 256 = 16777216
   三级间接可容纳 = 16777216 × 512B = 8589934592B

6. 文件最大字节数 = 5120 + 131072 + 33554432 + 8589934592
                    ≈ 8623625216B ≈ 8.23GB
```

> ⭐ **选择题/大题高频考点**：索引文件的块数计算是408考试中的必考题型。务必记住公式：
> - 直接索引：$n$（直接指针数）
> - 一级间接：$m$（每块容纳块号数）
> - 二级间接：$m^2$
> - 三级间接：$m^3$

### 五、文件共享机制 ⭐

#### 1. 共享文件的基本概念

> 在多用户系统中，多个用户可以共享同一个文件。文件共享的核心问题是：**如何避免为同一文件在内存中建立多个FCB副本**，以及如何管理共享权限。

#### 2. 共享方式

**（1）复制FCB方式（不推荐）**

```
进程A  → FCB(file.txt)
进程B  → FCB(file.txt)  ← 重复的FCB
进程C  → FCB(file.txt)  ← 重复的FCB
```

- **缺点**：占用大量内存；修改一个FCB时需要同步更新所有副本。

**（2）共享FCB方式（推荐）**

```
进程A  → 文件打开表[fd=3] → ─┐
进程B  → 文件打开表[fd=2] → ─┤→ FCB(file.txt)（共享）
进程C  → 文件打开表[fd=4] → ─┘
```

- **优点**：共享同一个FCB，节省内存；修改时自动同步。
- **需要解决的问题**：
  1. **打开计数**：FCB中记录打开次数，只有当打开次数为0时才释放FCB
  2. **共享打开**：只打开一次，多个进程共享
  3. **独立打开**：每个进程独立打开，但共享同一个FCB

**（3）FAT文件系统共享**

```
硬链接（Hard Link）：
  /home/userA/file.txt ───► inode 1001 ───► 磁盘块
  /home/userB/file.txt ───► inode 1001 ───► 磁盘块
  （硬链接数 = 2）

软链接（Symbolic Link）：
  /home/userA/link.txt ───► inode 2001 ───► 包含路径"/home/userB/file.txt"
  /home/userB/file.txt ───► inode 1001 ───► 磁盘块
```

> ⭐ **选择题考点**：
> 1. 硬链接：多个目录项指向同一个inode，删除一个不影响其他
> 2. 软链接：创建一个新inode，内容为指向目标文件的路径
> 3. 软链接删除目标文件后，软链接失效（变成"悬挂链接"）

### 六、文件的逻辑结构与物理结构的关系 🔥

| 逻辑结构 | 物理结构选择 | 说明 |
|---------|-------------|------|
| 流式文件 | 连续分配 / 链接分配 / 索引分配 | 操作系统不解释内容，物理结构由系统决定 |
| 记录式文件 | 连续分配 / 索引分配 | 连续分配适用于定长记录；变长记录更适合索引/链接 |
| 数据库文件 | 索引分配 | 便于随机访问记录，支持高效查找 |

> 从CSAPP视角看，文件的逻辑结构对内核透明，内核只管理inode/FAT和数据块。应用层通过 `read()` / `write()` 系统调用读写文件，操作系统负责将逻辑字节偏移转换为物理磁盘块号。

### 目录结构对比

| 对比项 | 单级目录 | 两级目录 | 多级目录 | 无环图目录 |

| **同名文件** | ❌ 不允许 | ✅ 允许（不同用户） | ✅ 允许（不同目录） | ✅ 允许 |
| **共享支持** | 不支持 | 不支持 | 支持 | 支持 |

### FAT vs inode 对比

| 对比项 | FAT（文件分配表） | inode（索引节点） |
|--------|------------------|------------------|
| **核心数据** | 记录数据块的链接关系（链表） | 记录文件元数据+数据块指针 |
| **访问方式** | 链式访问（需遍历FAT表） | 索引访问（指针直接定位） |
| **目录项内容** | 文件名 + 起始块号 | 文件名 + inode号 |
| **共享机制** | 通过目录项中的起始块号 | 通过多个目录项指向同一inode |
| **文件系统** | FAT12/16/32, exFAT | ext2/3/4, NTFS |
| **关联文档** | [[文件分配表(FAT)]] | [[索引节点(inode)]] |

### 硬链接 vs 软链接

| 对比项 | 硬链接（Hard Link） | 软链接/符号链接（Symbolic Link） |
|--------|-------------------|-------------------------------|
| **本质** | 多个目录项指向同一inode | 创建新inode，内容为指向目标的路径 |
| **inode号** | 相同 | 不同 |
| **删除源文件** | 不影响链接文件 | 链接文件失效（悬挂链接） |
| **跨文件系统** | 不支持 | 支持 |
| **对目录** | 不支持（系统保护） | 支持 |
| **命令** | `ln 源 目标` | `ln -s 源 目标` |
| **关联文档** | [[文件共享与保护]] | [[文件共享与保护]] |

### 直接索引 vs 间接索引

| 对比项 | 直接索引 | 间接索引 |
|--------|---------|---------|
| **指针位置** | inode中直接存储数据块号 | inode中存储索引块号，索引块中存储数据块号 |
| **访问次数** | 1次磁盘访问（数据块） | 至少2次磁盘访问（索引块+数据块） |
| **支持文件大小** | 有限（受直接指针数限制） | 很大（多级间接可支持TB级） |
| **适用场景** | 小文件（快速访问） | 大文件 |

## ⚠️考试高频坑点

### 坑点1：inode是否存储文件名 ⭐

> 【教材原文】inode中**不存储文件名**，文件名存储在目录项（directory entry）中。目录项中的"文件名 → inode号"是文件系统实现文件名到inode映射的关键。
>
> 【考试考法】以下哪项信息存储在inode中？
> A. 文件名  B. 文件类型  C. 目录项  D. 文件路径
>
> **答案**：B（inode存储文件类型、权限、时间戳、数据块指针等元数据，不存储文件名和路径）

### 坑点2：索引文件块数计算的m值 ⭐

> 【考试考法】磁盘块大小512B，块号占4B，则 m = 512/4 = 128。
>
> 易错点：计算 m 时忘记考虑块号占用的字节数，直接取块大小 512 或 4 作为 m 值。

### 坑点3：FAT表项与磁盘块的关系 ⭐

> 【考试考法】一个FAT表项对应一个磁盘块。FAT表本身需要连续存储。
>
> 易错点：误以为FAT表项和磁盘块没有一一映射关系。

### 坑点4：多级目录查找的逐级性 ⭐

> 【教材原文】路径查找必须从根目录开始，逐级深入，不能跳级。
>
> 【考试考法】在多级目录结构中，访问文件 /a/b/c.txt 需要查找几次目录？
> **答案**：3次（查找 a → 查找 b → 查找 c.txt）

### 坑点5：FAT与inode的访问方式混淆 ⭐

> 【考试考法】以下关于FAT和inode的说法正确的是？
> A. FAT是索引方式访问  B. inode是链表方式访问  C. FAT是链表方式访问  D. 两者都是随机访问
>
> **答案**：C（FAT是链表方式，inode是索引方式）

### 坑点6：软链接与硬链接的区别 ⭐

> 【考试考法】以下说法正确的是？
> A. 硬链接可以跨文件系统  B. 软链接删除源文件后仍可用  C. 硬链接创建的新文件与源文件共享同一inode  D. 软链接的inode号与源文件相同
>
> **答案**：C
