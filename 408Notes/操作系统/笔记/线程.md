# 线程

## 📍知识定位

### 在 408 体系中的位置

线程（Thread）是操作系统调度的基本单位，是进程内部的执行流。线程概念的引入解决了进程作为资源和调度统一单位的低效问题。它是 408 考试中**选择题必考、大题偶尔考查**的内容。

### 学习前置条件

- **进程管理**：理解进程概念、进程与程序的区别
- **进程控制块(PCB)**：理解 PCB 中包含的资源信息
- **进程状态与转换**：理解进程状态模型

### 学完之后支撑的知识点

- **进程调度**：线程级调度比进程级调度更高效
- **同步与互斥**：线程间共享资源的同步问题
- **进程通信**：线程间通信比进程间通信更高效

## 📝核心概念与原理

### 1. 线程的基本概念

线程是**进程内部的一个执行流**，是操作系统调度的基本单位。一个线程是进程中的一条执行序列，共享进程的资源（如代码段、数据段、打开的文件描述符等），但每个线程拥有独立的程序计数器、寄存器集合和栈。

> ⭐ **选择题高频考点**：进程是资源分配的基本单位，线程是调度执行的基本单位。这是 408 考试最经典的定义，必须准确记忆。

**线程与进程的核心区别：**

| 对比项 | 进程 | 线程 |
|--------|------|------|
| 资源拥有 | ✅ 拥有资源的独立单位 | ❌ 不拥有资源（共享进程资源） |
| 调度单位 | ❌ | ✅ 线程是调度的基本单位 |
| 独立性 | 有独立的地址空间 | 共享进程的地址空间 |
| 拥有资源 | 代码段、数据段、打开的文件等 | 栈、寄存器、PC（程序计数器） |
| 通信方式 | 需要 IPC（进程间通信） | 直接读写进程的共享数据 |
| 开销 | 创建/撤销/切换开销大 | 创建/撤销/切换开销小 |
| 并发性 | 进程间可并发 | 同一进程的多线程也可并发 |

### 2. 线程的组成

线程由三部分组成：

| 组成 | 说明 |
|------|------|
| **线程 ID** | 唯一标识线程的整数 |
| **程序计数器（PC）** | 指向线程即将执行的下一条指令 |
| **寄存器集合** | 保存线程执行时的临时数据 |
| **栈（Stack）** | 保存线程的局部变量、函数调用参数、返回地址等 |

> 每个线程拥有独立的栈，这使得线程可以独立地执行函数调用。而进程间通信需要操作系统内核的介入，线程间通信直接读写共享数据即可。

### 3. 线程模型

线程的实现模型分为三类：

#### （1）用户级线程（User-Level Thread，ULT）

所有用户级线程的映射和管理都在用户态完成，内核不知道用户级线程的存在。

```
进程 A:  [线程1][线程2][线程3]  →  内核看到的只是一个进程
```

| 优点 | 缺点 |
|------|------|
| 线程切换无需内核介入，速度快 | 一个线程阻塞，整个进程阻塞 |
| 无需修改内核，可在不支持线程的 OS 上实现 | 多核 CPU 无法真正并行执行多个线程 |
| 调度算法可针对应用定制 | 资源仍按进程分配，线程无法获得更多资源 |

#### （2）内核级线程（Kernel-Level Thread，KLT）

线程的创建、撤销、切换由内核完成，每个内核线程对应一个用户线程。

```
进程 A:  [线程1]  [线程2]  [线程3]
              ↓       ↓       ↓
内核:      [KLT1]  [KLT2]  [KLT3]
```

| 优点 | 缺点 |
|------|------|
| 多个线程可在多核 CPU 上真正并行 | 线程切换需要内核介入，开销较大 |
| 一个线程阻塞不影响其他线程 | 内核需要管理更多数据结构 |
| 内核可以调度更高优先级的线程 | 系统调用次数多，性能降低 |

#### （3）混合线程模型（混合级）

结合 ULT 和 KLT 的优点，允许多个用户级线程映射到一个内核级线程。

```
进程 A:  [线程1][线程2]  [线程3][线程4][线程5]
              ↓       ↓       ↓
内核:      [KLT1]  [KLT2]  [KLT3]
```

| 特点 | 说明 |
|------|------|
| 灵活度 | 可以调整用户线程与内核线程的映射比例 |
| 效率 | 大多数线程操作在用户态完成，仅在必要时涉及内核 |
| 代表系统 | Windows、Solaris 等采用混合模型 |

> ⭐ **选择题高频考点**：内核级线程模型中，一个线程阻塞不会影响同进程的其他线程执行；而用户级线程模型中，一个线程阻塞会导致整个进程阻塞。

### 4. 线程与进程的关系

| 关系维度 | 说明 |
|---------|------|
| 父子关系 | 线程是进程的子集，一个进程可以包含多个线程 |
| 资源共享 | 同一进程的所有线程共享进程的地址空间、文件描述符、信号处理等 |
| 资源隔离 | 不同进程之间的资源是隔离的（独立的地址空间） |
| 创建开销 | 创建线程的开销远小于创建进程（共享资源，无需创建地址空间） |
| 切换开销 | 线程切换只需保存/恢复寄存器，无需切换页表；进程切换需要 TLB 刷新 |

> 🔥 **大题考点**：线程切换和进程切换的开销对比。线程切换只需保存寄存器上下文（PC、SP、通用寄存器），不需要切换页表；而进程切换需要保存/恢复寄存器、切换页表（TLB 刷新），开销更大。

### 5. 线程的优点与局限

#### 优点

| 优点 | 说明 |
|------|------|
| **提高响应性** | 多线程程序的部分阻塞不影响其他线程执行 |
| **共享内存** | 线程共享进程内存，无需 IPC 即可通信 |
| **经济高效** | 线程创建/切换/撤销的开销远小于进程 |
| **充分利用多核** | 多线程可在多核 CPU 上真正并行执行 |

#### 局限

| 局限 | 说明 |
|------|------|
| **编程复杂** | 多线程需要同步互斥，容易产生竞态条件和死锁 |
| **调试困难** | 并发程序的错误往往是随机的、难以复现 |
| **缺乏标准** | 不同操作系统对线程的实现差异较大 |
| **内核级线程开销** | KLT 模型下，线程创建和切换仍有内核开销 |

## ⚖️易混淆概念对比

| 对比项 | 进程 | 线程 |
|--------|------|------|
| 是资源分配单位 | ✅ 是 | ❌ 否 |
| 是调度单位 | ✅ 是 | ✅ 是 |
| 拥有独立地址空间 | ✅ 是 | ❌ 否（共享） |
| 拥有独立栈 | ✅ 是 | ✅ 是 |
| 拥有独立寄存器 | ✅ 是 | ✅ 是（PC、SP等） |
| 通信方式 | IPC（管道、消息队列、共享内存等） | 共享内存（直接读写） |
| 创建开销 | 大（需创建地址空间、页表等） | 小（只需创建栈和寄存器） |
| 切换开销 | 大（需切换页表、TLB 刷新） | 小（只需保存寄存器） |
| 一个进程可包含多个 | ❌ 一个进程就是一个 | ✅ 是（多线程） |
| 一个线程可包含多个 | ❌ | ❌ |

## ⚠️考试高频坑点

| 坑点 | 错误理解 | 正确理解 |
|------|---------|---------|
| 线程是否拥有地址空间 | 误认为线程拥有独立的地址空间 | 线程共享进程地址空间，每个线程只有独立的栈 |
| 线程阻塞的影响 | 误认为所有线程模型下，一个线程阻塞不影响其他 | 用户级线程模型下，一个线程阻塞会导致整个进程阻塞 |
| 多线程并行 | 误认为多线程一定并行执行 | 单核 CPU 上多线程是并发而非并行；多核 CPU 上才可能并行 |
| 线程是进程的子集 | 误认为线程是进程的一部分（子进程） | 线程是进程内的一个执行流，不是子进程 |
| 进程和线程的调度单位 | 混淆谁是调度单位 | 线程是调度的基本单位，进程是资源分配的基本单位 |
