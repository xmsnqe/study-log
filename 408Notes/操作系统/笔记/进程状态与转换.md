# 进程状态与转换

## 📍知识定位

### 在 408 体系中的位置

进程状态与转换是进程管理的核心内容，描述了进程在其生命周期中经历的各种状态及其转换条件。它是理解进程调度、同步互斥、死锁等后续知识的基础。408 考试中常以**选择题**形式考查状态转换模型，偶尔以**大题**形式出现在综合分析中。

### 学习前置条件

- **进程控制块(PCB)**：理解 PCB 中包含进程状态信息
- **进程管理**：理解进程的基本概念

### 学完之后支撑的知识点

- **进程调度**：从就绪到运行的转换需要调度
- **同步与互斥**：阻塞状态的产生（等待信号量、等待 I/O）
- **死锁**：死锁进程处于阻塞状态

## 📝核心概念与原理

### 1. 进程的三种基本状态

进程的三种基本状态是进程状态模型的**最核心概念**，也是 408 考试必考内容。

| 状态 | 含义 | 说明 |
|------|------|------|
| **就绪状态（Ready）** | 进程已获得除 CPU 外的所有必要资源，只要获得 CPU 即可立即执行 | 就绪进程排成就绪队列 |
| **运行状态（Running）** | 进程已获得 CPU，正在处理器上执行 | 只有就绪进程才能进入运行状态；多 CPU 系统中可同时有多个运行态进程 |
| **阻塞状态（Blocked/Waiting）** | 进程正在等待某一事件发生（如 I/O 完成、信号量 V 操作） | 阻塞进程即使 CPU 空闲也无法执行 |

> ⭐ **选择题高频考点（三大铁律）：**
> 1. 就绪 → 运行：由调度程序触发（分配 CPU）
> 2. 运行 → 就绪：时间片用完或被抢占（**不是**由等待事件触发）
> 3. 运行 → 阻塞：进程主动请求某个资源（如 I/O 请求、等待信号量 P 操作）
> 4. **阻塞 → 运行 不能直接转换**，必须先到就绪态

> 🔥 上述第 4 条是 408 选择题最常见的坑点——"阻塞态可以直接转换为运行态"是错误的。

### 2. 三状态模型

三状态模型是最简洁的进程状态模型：

```
           调度
  就绪 ──────────→ 运行
    ↑                 │
    │        等待事件 │
    │                 ↓
    ←──────── 阻塞
       事件完成
```

状态转换及其触发条件：

| 转换 | 触发条件 | 说明 |
|------|---------|------|
| 就绪 → 运行 | 进程调度程序调度 | 分配 CPU |
| 运行 → 就绪 | 时间片用完 / 被更高优先级进程抢占 | 非自愿让出 CPU |
| 运行 → 阻塞 | 进程请求 I/O / 等待信号量 P 操作 | 自愿让出 CPU |
| 阻塞 → 就绪 | I/O 完成 / 等待的事件发生 / 信号量 V 操作 | 事件完成 |

### 3. 五状态模型（增加新建和终止）

五状态模型在三种基本状态基础上增加了两个状态：

| 状态 | 含义 |
|------|------|
| **新建（New）** | 进程正在被创建，尚未完全初始化 |
| **终止（Exit）** | 进程正在被撤销，释放资源 |

```
                  创建
    新建 ──────────→ 就绪
                       │
                       │  调度
                       ↓
                       运行
                    ╱    │    ╲
                  退出  让出  等待
                   │    │     │
                   ↓    ↓     ↓
                       终止   阻塞
                            ↑
                            │ 事件完成
                    事件完成│
                   ════════
```

五状态的转换：

| 转换 | 触发条件 |
|------|---------|
| 新建 → 就绪 | 进程创建完成，加入就绪队列 |
| 运行 → 终止 | 进程正常结束 / 异常终止 / 被操作系统终止 |
| 运行 → 就绪 | 时间片用完 / 被抢占 |
| 运行 → 阻塞 | 请求 I/O / 等待信号量 P 操作 |
| 阻塞 → 就绪 | I/O 完成 / 信号量 V 操作 |

> ⭐ 选择题高频考点：**阻塞态不能直接转换为运行态**，必须经过就绪态。这是考试最常考的点之一。

### 4. 状态转换的关键判断

#### 什么操作会导致进程阻塞？

- `P 操作`（信号量）：当信号量 ≤ 0 时，进程执行 P 操作进入阻塞
- `I/O 请求`：read/write/open 等系统调用，进程等待 I/O 完成
- `等待事件`：如等待另一个进程发送消息
- `等待锁`：获取自旋锁失败（在非自旋锁情况下）

#### 什么操作会导致进程从阻塞转为就绪？

- `I/O 完成中断`：I/O 设备完成数据传输，产生中断
- `V 操作`（信号量）：释放资源，唤醒等待队列上的进程
- `事件发生`：如消息到达、定时器到期
- `唤醒原语`：显式唤醒等待队列上的进程

#### 什么操作会导致进程从运行转为就绪？

- `时间片用完`：分时系统中，进程运行时间超过分配的时间片
- `被抢占`：更高优先级进程进入就绪队列，调度器将其抢占
- `I/O 请求（不阻塞的情况）`：某些系统下非阻塞 I/O 不会导致阻塞

> ⚠️ 注意：运行态进程**不能因为请求 I/O 直接进入终止状态**，它先转为阻塞，待 I/O 完成后转为就绪，再由调度程序转为运行。

## ⚖️易混淆概念对比

| 对比项 | 三状态模型 | 五状态模型 |
|--------|-----------|-----------|
| 状态数 | 3（就绪、运行、阻塞） | 5（新增新建、终止） |
| 适用场景 | 简单进程管理 | 实际操作系统（如 Windows、Linux） |
| 考试频率 | 基础概念 | 实际系统分析 |

| 对比项 | 阻塞 → 就绪 | 运行 → 就绪 |
|--------|-----------|-----------|
| 触发条件 | I/O 完成、信号量 V 操作 | 时间片用完、被抢占 |
| 进程是否自愿 | 非自愿（被动） | 非自愿（被动，但非退出 CPU） |
| 进程优先级 | 通常保持原有优先级 | 通常保持原有优先级 |
| 是否需要重新调度 | 是 | 否（已经在运行） |

## ⚠️考试高频坑点

| 坑点 | 错误理解 | 正确理解 |
|------|---------|---------|
| 阻塞→运行直接转换 | 认为阻塞进程可以直接获得 CPU 执行 | 必须经过就绪态，由调度程序选择 |
| 运行→阻塞的触发 | 认为运行进程可以因为任何原因进入阻塞 | 只能因为请求某资源（I/O、P 操作）而阻塞 |
| 就绪→阻塞 | 认为就绪态可以直接进入阻塞态 | 就绪态进程必须先获得 CPU 进入运行态，才能请求资源进入阻塞 |
| 多个阻塞进程同时就绪 | 认为只有一个进程能进入就绪态 | 多个事件完成可同时唤醒多个进程到就绪队列 |
| 时间片用完→阻塞 | 认为时间片用完进程会阻塞 | 时间片用完→就绪，进程仍然可以运行 |
