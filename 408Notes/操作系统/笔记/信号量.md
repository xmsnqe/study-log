# 信号量

## 📝核心概念与原理

### 1. 信号量的定义与分类

信号量是一个整型变量（或结构体），根据取值不同表示不同的资源状态。它是实现进程同步和互斥的重要工具。

| 类型 | 说明 | 取值含义 |
|------|------|---------|
| **整型信号量** | 最简单的信号量，值为非负整数 | 表示可用资源的数量 |
| **记录型信号量** | 包含 value 和 L（等待队列指针）的结构体 | value > 0：可用资源数；value = 0：无等待进程；value < 0：|-value| 为等待进程数 |
| **AND 信号量** | 一次等待多种资源，同时分配或全不分配 | 解决资源分配中的死锁问题 |
| **信号量集** | 一般化的 AND 信号量 | value ≥ valueS 且 value ≤ valueM |

> ⭐ **选择题高频考点**：记录型信号量的 value 字段含义是最常考的内容。value > 0 表示可用资源数，value = 0 表示无资源且无等待进程，value < 0 表示无资源且 |-value| 个进程在等待。

### 2. P/V 操作原语

P 操作和 V 操作是信号量机制的核心操作，必须是**原子操作**（不可分割）。

#### （1）整型信号量的 P/V 操作

```
wait(S) {        // P 操作
    while (S <= 0)
        ;         // 忙等
    S--;
}

signal(S) {      // V 操作
    S++;
}
```

> ⚠️ 整型信号量的缺点：P 操作时进程忙等（ Busy Waiting ），浪费 CPU 资源。这就是为什么后来引入了记录型信号量。

#### （2）记录型信号量的 P/V 操作（重点掌握）

```c
typedef struct {
    int value;           // 信号量值
    struct process *L;   // 等待队列指针
} Semaphore;

wait(S) {            // P 操作
    S.value--;
    if (S.value < 0) {
        block(S.L);    // 阻塞进程，放入等待队列
    }
}

signal(S) {          // V 操作
    S.value++;
    if (S.value <= 0) {
        wakeup(S.L);   // 从等待队列中唤醒一个进程
    }
}
```

> 🔥 **大题必考**：记录型信号量的 P/V 操作是 408 大题的核心。必须准确理解：P 操作递减信号量并可能阻塞进程；V 操作递增信号量并可能唤醒进程。

### 3. 信号量实现互斥

利用信号量实现互斥的核心思想：将临界区用 P/S 和 V/S 操作包围。

```c
Semaphore mutex = 1;     // 互斥信号量，初值为 1

// 进程 Pi
do {
    P(mutex);            // 进入临界区前申请资源
    // 临界区（Critical Section）
    V(mutex);            // 离开临界区释放资源
    // 剩余区（Remainder Section）
} while (true);
```

> ⭐ 互斥信号量的初值必须为 1，因为互斥表示每次只能有一个进程进入临界区。如果初值不为 1，则不能实现互斥。

#### 互斥信号量的关键要点

| 要点 | 说明 |
|------|------|
| 初值 | 必须为 1 |
| P/V 操作位置 | P 在临界区前，V 在临界区后 |
| P/V 成对 | 每个临界区必须有且仅有一个 P 和一个 V |
| P 操作失败 | 信号量 ≤ 0 时进程阻塞 |
| V 操作效果 | 可能有进程被唤醒（从阻塞态→就绪态） |

### 4. 信号量实现同步

信号量也可以用来实现进程间的同步协调。同步信号量的初值通常为 0。

```c
// 进程 Pi 和 Pj，要求 Pi 在 Pj 之前执行
Semaphore sync = 0;      // 同步信号量，初值为 0

// 进程 Pi（先执行）
do {
    // ... 前驱操作 ...
    V(sync);             // 发送信号，通知后继
} while (true);

// 进程 Pj（后执行）
do {
    P(sync);             // 等待前驱信号
    // ... 后续操作 ...
} while (true);
```

> ⭐ 同步信号量的初值为 0，表示需要等待前驱进程发送信号。V 操作在前驱进程的末尾，P 操作在后继进程的开始。

### 5. 信号量操作的关键规则

| 规则 | 说明 | 违反后果 |
|------|------|---------|
| P、V 操作必须成对 | 每个临界区必须有且仅有一个 P 和一个 V | 缺少 P：无法互斥；缺少 V：死锁 |
| P 操作在前，V 操作在后 | P 在临界区前，V 在临界区后 | P 在 V 后：可能导致多个进程同时进入临界区 |
| V 操作在临界区之后 | 不能在临界区内释放锁 | 在临界区内 V 操作：其他进程可能提前进入临界区 |
| 信号量初值正确 | 互斥信号量初值=1，同步信号量初值=0 | 初值错误导致互斥失效或同步错误 |
| P/V 操作原子性 | P/V 操作必须是不可分割的 | 非原子性：竞态条件 |

> ⚠️ **选择题高频坑点**：P 操作的信号量初值检查与递减是在同一个原子操作中完成的，不能拆分。如果在检查后、递减前被抢占，其他进程可能同时进入临界区。

## ⚖️易混淆概念对比

| 对比项 | 整型信号量 | 记录型信号量 |
|--------|-----------|-------------|
| 数据结构 | 简单整型 | 结构体（含 value 和等待队列） |
| 等待方式 | 忙等（Busy Waiting） | 阻塞（Blocking） |
| CPU 利用率 | 低（浪费 CPU） | 高（阻塞进程让出 CPU） |
| 实现复杂度 | 简单 | 较复杂 |
| 408 考法 | 概念性考查 | 大题计算/分析 |

| 对比项 | 互斥信号量 | 同步信号量 |
|--------|-----------|-----------|
| 初值 | 1 | 0 |
| 用途 | 保护临界资源 | 协调进程执行顺序 |
| P 操作位置 | 进入临界区前 | 等待事件发生后 |
| V 操作位置 | 离开临界区后 | 事件发生时 |
| value 含义 | 可用资源数 | 已收到的信号数 |

## ⚠️考试高频坑点

| 坑点 | 错误理解 | 正确理解 |
|------|---------|---------|
| P/V 操作是否原子 | 误认为可以拆分执行 | P/V 操作必须是原子操作，不可分割 |
| 互斥信号量初值 | 误认为可以是任意值 | 必须是 1，表示一次只有一个进程可进入临界区 |
| V 操作位置 | 误认为 V 操作可以在临界区内 | V 操作必须在临界区之后（临界区外） |
| value 为负的含义 | 误认为 value 可以是任意值 | value < 0 时，|-value| 表示等待队列中的进程数 |
| P 和 V 的顺序 | 误认为可以 P 在 V 之后 | P 必须在 V 之前（每个临界区内必须 P 在 V 前） |
| 信号量值与进程数 | 误认为信号量值就是进程数 | value < 0 时，绝对值才是等待进程数 |
