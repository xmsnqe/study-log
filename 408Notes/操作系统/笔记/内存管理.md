# 内存管理概述

## 📍知识定位

### 在408体系中的位置

内存管理（存储器管理）是操作系统核心模块之一，负责管理计算机的主存储器（内存）。它是408考试中**大题和选择题**均重点考察的章节，涉及地址转换、内存分配、虚拟内存等核心概念。

### 学习前置条件

- **进程管理**：理解进程的地址空间概念
- **计算机组成原理**：理解存储器的层次结构、地址空间
- **数据结构基础**：链表（用于空闲分区管理）

### 学完之后支撑的知识点

- 内存分配与回收：具体的内存分配算法
- 虚拟内存：分页、分段、段页式存储管理
- 页面置换算法：缺页中断的处理

## 📝核心概念与原理

### 一、内存管理的基本目标

#### 1. 内存管理的主要功能

| 功能 | 说明 |
|------|------|
| **内存分配与回收** | 为进程分配内存，进程终止时回收 |
| **地址转换** | 将逻辑地址转换为物理地址 |
| **内存保护** | 防止进程访问不属于它的内存区域 |
| **内存扩充** | 通过虚拟技术（如虚拟内存）扩充内存 |

#### 2. 逻辑地址与物理地址 ⭐

> **逻辑地址（Logical Address）**：也称为虚拟地址，是进程执行时由CPU产生的地址，是进程视角的"虚拟"地址。
>
> **物理地址（Physical Address）**：也称为绝对地址，是内存单元的真实硬件地址。

**地址转换（Address Binding）**：

```
逻辑地址 → 地址转换机构（MMU）→ 物理地址
```

地址转换发生在进程执行期间，由MMU（Memory Management Unit，内存管理单元）完成。

> ⭐ **选择题考点**：
> 1. 程序首次装入时，逻辑地址和物理地址可以相同（从0开始）
> 2. 程序执行过程中，逻辑地址始终不变，物理地址可能变化
> 3. 地址转换发生在**程序执行期间**（动态重定位）

### 二、内存保护

#### 1. 地址越界检查

操作系统通过**基址寄存器（Base Register）**和**限长寄存器（Limit Register）**实现内存保护：

```
逻辑地址 < 限长 → 允许访问
逻辑地址 ≥ 限长 → 触发越界中断（保护故障）
```

同时，物理地址 = 基址 + 逻辑地址，需要确保物理地址不超过物理内存的范围。

#### 2. 内存保护的机制

| 机制 | 说明 |
|------|------|
| **寄存器保护** | 使用基址和限长寄存器 |
| **保护键（保护码）** | 内存区域标记为读/写/执行权限 |
| **特殊硬件指令** | 如x86的CPL/DPL机制 |

### 三、内存分配方式

#### 1. 连续分配方式

**单一连续分配**：
- 系统只允许一个用户程序装入内存
- 系统区 + 用户区
- 简单，但内存利用率极低

**固定分区分配**：
- 将内存分为若干个固定大小的分区
- 分区大小可以相等或不等（不等分配更灵活）

| 分区大小 | 优点 | 缺点 |
|---------|------|------|
| 大小相等 | 管理简单 | 内部碎片多 |
| 大小不等 | 内部碎片少 | 管理复杂 |

> **内部碎片（Internal Fragment）**：进程实际使用的空间小于分配的分区大小，剩余空间在分区内无法被其他进程使用。

**动态分区分配（可变分区分配）**：

根据进程的大小动态地分配内存空间。

**分配策略**：
1. **首次适应（First Fit, FF）**：从空闲链首开始查找，找到第一个满足大小的空闲分区
2. **最佳适应（Best Fit, BF）**：选择满足要求的最小空闲分区
3. **最差适应（Worst Fit, WF）**：选择最大的空闲分区
4. **邻近适应（Next Fit, NF）**：从上次查找的位置开始

| 算法 | 优点 | 缺点 | 内存利用 |
|------|------|------|---------|
| FF | 高地址部分有大分区保留 | 低地址部分产生许多小碎片 | 中等 |
| BF | 尽量保留大分区 | 产生许多极小碎片（很难利用） | 较差 |
| WF | 减少小碎片 | 大分区很快被消耗 | 较差 |
| NF | 分配均匀 | 可能破坏局部聚集性 | 中等 |

> ⭐ **选择题高频考点**：
> - 首次适应（FF）算法回收内存时，可能和前面的空闲分区相邻，需要合并
> - 最佳适应（BF）算法产生的碎片最多且最难利用
> - 最差适应（WF）算法每次选择最大分区，大分区很快被耗尽

#### 2. 非连续分配方式

**基本分页存储管理**：
- 将进程的空间分成大小相等的**页面（Page）**
- 将内存空间分成大小相等的**页框/页帧（Frame/Page Frame）**
- 页面的大小 = 页框的大小（通常为4KB、8KB、16KB等）

**基本分段存储管理**：
- 按照程序的逻辑结构分成若干个**段（Segment）**
- 每个段有段号和段内偏移
- 段的大小可以不等

**段页式存储管理**：
- 先将进程分页，再将页面组段
- 兼具分页和分段的优点

> ⭐ **选择题考点**：分页是面向机器的（物理单位），分段是面向用户的（逻辑单位）。

### 四、页表与分段表

#### 1. 页表（Page Table）

页表记录了页号到物理页框号的映射关系。

```
页表项（PTE, Page Table Entry）结构：
┌─────────┬───────────┐
│ 物理页框号  │  状态位、保护位、访问位等  │
└─────────┴───────────┘

进程A的页表：
页号 → 物理页框号
  0  →   5
  1  →  12
  2  →   3
  3  →  20
```

**页表的地址转换公式**：

```
物理地址 = 页框号 × 页大小 + 页内偏移

其中：
页号 = 逻辑地址 / 页大小  （取整）
页内偏移 = 逻辑地址 % 页大小
```

#### 2. 分段表（Segment Table）

分段表记录了段号到段起始地址和段长度的映射关系。

```
分段表项结构：
┌─────────┬──────────┐
│ 段起始地址  │  段长度   │
└─────────┴──────────┘

进程A的分段表：
段号 → 起始地址 | 段长度
  0  →   1000  |   100  （代码段）
  1  →   2000  |   500  （数据段）
  2  →   3000  |   200  （栈段）
```

**分段方式的地址转换公式**：

```
物理地址 = 段起始地址 + 段内偏移

访问检查：段内偏移 < 段长度 → 允许访问
```

> 如果段内偏移 ≥ 段长度 → 触发越界中断。

#### 3. 段页式地址转换

```
逻辑地址 → [段号, 页号, 页内偏移] → 段表 → 页表 → 物理地址
```

**转换过程**：
1. 从段表中找到段号对应的页表起始地址
2. 从页表中找到页号对应的物理页框号
3. 物理地址 = 物理页框号 × 页大小 + 页内偏移

> ⭐ **选择题考点**：段页式需要访问两次内存（一次查段表，一次查页表）。

### 五、快表（TLB, Translation Lookaside Buffer）

#### 1. TLB的作用

由于分页存储管理中每次地址转换需要访问两次内存（查页表+访问数据），**严重降低访问速度**。TLB用于加速地址转换。

```
逻辑地址 → TLB（快表）→ 命中：直接获得页框号
                    → 未命中：访问页表获得页框号

TLB → 页表 → 主存
  ↓      ↓
页框号  页框号
  ↓
物理地址
```

#### 2. TLB的特点

| 特点 | 说明 |
|------|------|
| **全相联映射** | TLB中的任一项都可以存放任意页表项 |
| **替换算法** | FIFO或LRU |
| **命中率** | 通常可达95%以上 |
| **访问一次TLB的时间** | 约为主存的1/10 |

**有效访问时间（EAT, Effective Access Time）计算**：

$$EAT = h \times (t_{TLB} + t_{mem}) + (1-h) \times (t_{TLB} + t_{页表} + t_{mem})$$

简化（假设TLB和页表访问时间近似）：

$$EAT = h \times (t_{TLB} + t_{mem}) + (1-h) \times 2 \times t_{mem}$$

其中：
- h：TLB命中率
- $t_{TLB}$：访问TLB的时间
- $t_{mem}$：访问主存的时间

> 如果考虑页表在TLB中缓存的情况：
> $$EAT = h \times (t_{TLB} + t_{mem}) + (1-h) \times (t_{TLB} + t_{页表} + t_{mem})$$

> ⭐ **选择题高频考点**：
> 1. 有TLB时，若命中：只需访问一次内存（访问数据）
> 2. 有TLB时，若未命中：需要访问两次内存（查页表+访问数据）

### 六、对换（Swap）技术

> **对换（Swapping）**是指操作系统将暂时不能运行的进程调出到外存（交换区），腾出内存空间；当需要运行时，再调入内存。

**对换与虚拟内存的区别**：

| 对比项 | 对换技术 | 虚拟内存技术 |
|--------|---------|-------------|
| 粒度 | 整个进程 | 页面的部分 |
| 透明度 | 对程序员不透明 | 对程序员完全透明 |
| 实现复杂度 | 简单 | 复杂 |
| 内存利用率 | 较低 | 较高 |

### 七、内存管理的硬件支持 ⭐

| 硬件 | 作用 |
|------|------|
| **基址寄存器** | 存放进程的起始物理地址 |
| **限长寄存器** | 存放进程的长度（用于越界检查） |
| **页表寄存器（PTR）** | 存放页表的起始地址和页表长度 |
| **TLB（快表）** | 加速地址转换 |
| **MMU（内存管理单元）** | 完成地址转换、内存保护 |

> 从CSAPP视角看，MMU是CPU的一部分，负责将虚拟地址转换为物理地址。现代处理器（如x86-64）使用多级页表（四级页表）来支持大地址空间。

## ⚖️易混淆概念对比

### 内部碎片 vs 外部碎片

| 对比项 | 内部碎片 | 外部碎片 |
|--------|---------|---------|
| 定义 | 分区内未被使用的空间 | 分区间未被使用的空间 |
| 产生原因 | 分区大小 > 进程大小 | 内存分配不均 |
| 出现在 | 固定分区分配 | 动态分区分配 |
| 减少方法 | 分区大小与进程大小匹配 | 紧凑技术（拼接） |

### 连续分配 vs 非连续分配

| 对比项 | 连续分配 | 非连续分配 |
|--------|---------|-----------|
| 内存分配 | 要求连续空间 | 允许分散分配 |
| 内存利用率 | 较低（有外部碎片） | 较高 |
| 地址转换 | 基址+限长 | 页表/段表 |
| 实现复杂度 | 简单 | 复杂 |
| 代表方式 | 固定分区、动态分区 | 分页、分段、段页式 |

### 逻辑地址 vs 物理地址

| 对比项 | 逻辑地址 | 物理地址 |
|--------|---------|---------|
| 别名 | 虚拟地址 | 绝对地址 |
| 产生者 | CPU（进程视角） | 内存硬件 |
| 地址空间 | 虚拟地址空间 | 物理地址空间 |
| 地址转换 | 需要MMU转换 | 直接使用 |

## ⚠️考试高频坑点

### 坑点1：地址转换的计算 ⭐

> 【考试考法】给定逻辑地址、页大小、页表，求物理地址。
> 步骤：
> 1. 计算页号 = 逻辑地址 / 页大小
> 2. 计算页内偏移 = 逻辑地址 % 页大小
> 3. 查页表获得页框号
> 4. 物理地址 = 页框号 × 页大小 + 页内偏移

### 坑点2：分页与分段的关键区别

> 【教材原文】分页是**面向机器**的（物理单位），目的是提高内存利用率；分段是**面向用户**的（逻辑单位），目的是满足用户的需要（如代码段、数据段分离）。
>
> 【考试考法】选择题问"分页和分段的关键区别"，答案是"分页面向机器，分段面向用户"。

### 坑点3：TLB命中率的计算

> 【考试考法】假设TLB命中率为h=0.95，页表查找时间=100ns，内存访问时间=100ns，求EAT。
> EAT = 0.95 × (10+100) + 0.05 × (10+100+100) = 0.95 × 110 + 0.05 × 210 = 104.5 + 10.5 = 115ns

### 坑点4：页大小的选择

> 【考试考法】页大小越大：
> - 外部碎片减少（最后一页的剩余空间更大但不影响整体）
> - 页表变大（占用更多内存）
> - TLB命中率降低（相同TLB能缓存的页数减少）
>
> 页大小越小：
> - 内部碎片减少
> - 页表变小
> - TLB命中率提高
> - 缺页中断更频繁
