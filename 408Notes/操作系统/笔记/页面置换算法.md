## 📝核心概念与原理

### 一、页面置换的基本原理

> **页面置换（Page Replacement）**：当进程访问的页面不在内存中（缺页中断），且内存中没有空闲页框时，操作系统必须选择一个当前不被使用（或最少使用）的页面换出到外存，以便为新页面腾出空间。

**置换的基本流程**：

```
缺页中断发生 → 检查内存中是否有空闲页框
    → 有空闲页框：直接将新页面调入
    → 无空闲页框：选择置换页面
        → 如果被选页面被修改过，写回外存
        → 释放该页框
        → 将新页面调入页框
        → 更新页表
```

**置换算法的核心指标**：
1. **缺页次数**：越少越好
2. **缺页率**：缺页次数 / 总访问次数
3. **系统开销**：置换算法本身的实现复杂度

### 二、最佳置换算法（OPT, Optimal）⭐

**核心思想**：选择**将来再也不使用**或者**最长时间内不再被访问**的页面淘汰。

```
算法描述：
扫描进程即将访问的页面序列
  → 对于内存中的每个页面，找出其下一次访问的时间
  → 选择下一次访问时间最远（或永不访问）的页面淘汰
```

> ⚠️ **OPT是理想算法，无法实际实现**（因为无法预知未来的页面访问序列）。但OPT提供了理论上的**最优下界**，用于评估其他算法的性能。

**示例**：

假设页框数 = 3，页面访问序列为：1, 3, 0, 3, 5, 6, 3, 0, 3, 0, 6

| 访问页 | 内存状态（3个页框） | 是否缺页 | 置换页面 |
|--------|---------------------|---------|---------|
| 1 | [1] | 是 | - |
| 3 | [1, 3] | 是 | - |
| 0 | [1, 3, 0] | 是 | - |
| 3 | [1, 3, 0] | 否 | - |
| 5 | [1, 3, 5] | 是 | 置换0（0的下次访问在第8步） |
| 6 | [1, 6, 5] | 是 | 置换3（3的下次访问在第7步）|
| 3 | [3, 6, 5] | 是 | 置换1（1永不访问） |
| 0 | [3, 6, 0] | 是 | 置换5（5永不访问） |
| 3 | [3, 6, 0] | 否 | - |
| 0 | [3, 6, 0] | 否 | - |
| 6 | [3, 6, 0] | 否 | - |

- 缺页次数：7次
- 缺页率：7/11 = 63.6%

> ⭐ **选择题考点**：OPT算法是理论最优的，但无法在实际中实现。它用于评估其他算法的性能。

### 三、先进先出置换算法（FIFO, First-In-First-Out）

**核心思想**：选择**最早进入内存**的页面淘汰（即驻留时间最长的页面）。

```
算法实现：使用队列
- 新页面调入时，加入队列尾部
- 置换时，选择队列头部的页面
```

**示例**（页框数=3，序列：1, 3, 0, 3, 5, 6, 3, 0, 3, 0, 6）：

| 访问页 | 内存状态 | 是否缺页 | 置换页面 |
|--------|---------|---------|---------|
| 1 | [1] | 是 | - |
| 3 | [1, 3] | 是 | - |
| 0 | [1, 3, 0] | 是 | - |
| 3 | [1, 3, 0] | 否 | - |
| 5 | [5, 3, 0] | 是 | 置换1（最早进入） |
| 6 | [5, 6, 0] | 是 | 置换3（第二早进入） |
| 3 | [5, 6, 3] | 是 | 置换0（第三早进入） |
| 0 | [0, 6, 3] | 是 | 置换5（现在最早进入） |
| 3 | [0, 6, 3] | 否 | - |
| 0 | [0, 6, 3] | 否 | - |
| 6 | [0, 6, 3] | 否 | - |

- 缺页次数：8次
- 缺页率：8/11 = 72.7%

> ⭐ **选择题高频考点：Belady异常 ⭐**

> **Belady异常（Belady's Anomaly）**：对于FIFO算法，**增加页框数反而可能导致缺页次数增加**。
>
> 例如：页框数从3增加到4时，缺页次数从8次增加到9次。
>
> 其他算法（如OPT、LRU）**不会出现**Belady异常。

> ⭐ **结论性记忆**：
> - 只有FIFO算法会产生Belady异常
> - OPT和LRU算法**绝对不会**产生Belady异常
> - 这是选择题的经典考点

### 四、最近最久未使用置换算法（LRU, Least Recently Used）

**核心思想**：选择**最近最久没有被使用**的页面淘汰。

```
算法实现：使用栈或计数器
- 每次访问页面时，将该页面移到栈顶（或更新时间戳）
- 置换时，选择栈底的页面（最久未使用的）
```

**示例**（页框数=3，序列：1, 3, 0, 3, 5, 6, 3, 0, 3, 0, 6）：

| 访问页 | 内存状态 | 是否缺页 | 置换页面 |
|--------|---------|---------|---------|
| 1 | [1] | 是 | - |
| 3 | [1, 3] | 是 | - |
| 0 | [1, 3, 0] | 是 | - |
| 3 | [1, 0, 3] | 否 | 3被访问，移到顶部 |
| 5 | [5, 1, 0] | 是 | 置换3？不，置换1（1最久未使用） |

等等，我需要重新分析。LRU的关键是"最近最久未使用"，即查看每个页面上次被访问的时间。

| 访问页 | 内存状态（最近使用顺序） | 是否缺页 | 置换页面 |
|--------|------------------------|---------|---------|
| 1 | [1](最近) | 是 | - |
| 3 | [1, 3](最近) | 是 | - |
| 0 | [1, 3, 0](最近) | 是 | - |
| 3 | [1, 0, 3](最近) | 否 | 3被访问，移到最近 |
| 5 | [5, 1, 0](最近) | 是 | 置换3？不，选最久未使用的：1（上次在T=0使用） |
| 6 | [5, 6, 0](最近) | 是 | 置换3？不，选最久未使用的：3（上次在T=3使用） |

让我重新仔细分析：

| 访问页 | 内存状态（最久→最近） | 是否缺页 | 置换页面 |
|--------|----------------------|---------|---------|
| 1 | [1] | 是 | - |
| 3 | [1, 3] | 是 | - |
| 0 | [1, 3, 0] | 是 | - |
| 3 | [1, 0, 3] | 否 | 3重新访问，3移至最近 |
| 5 | [5, 1, 0] | 是 | 置换1（最久未使用：上次访问在T=0） |
| 6 | [5, 6, 0] | 是 | 置换0（最久未使用：上次访问在T=2） |
| 3 | [5, 6, 3] | 是 | 置换5（最久未使用：上次访问在T=4） |
| 0 | [0, 6, 3] | 是 | 置换6（最久未使用：上次访问在T=5） |
| 3 | [0, 3] | 否 | 3重新访问，3移至最近 |
| 0 | [3, 0] | 否 | 0重新访问，0移至最近 |
| 6 | [6, 3, 0] | 是 | 置换3（最久未使用：上次访问在T=8） |

- 缺页次数：9次
- 缺页率：9/11 = 81.8%

> 注意：这个序列的LRU性能比FIFO差，但这是特殊情况。在典型的工作集模式下，LRU通常比FIFO好。

> ⭐ **选择题高频考点**：
> 1. LRU近似OPT（利用局部性原理），但实现复杂（需要硬件支持）
> 2. LRU不会产生Belady异常
> 3. LRU需要记录每个页面的访问时间 → 需要硬件支持（计数器或栈）

### 五、时钟置换算法（Clock, NRU）⭐

**核心思想**：LRU的近似算法，使用**访问位（A位）**和**修改位（M位）**模拟LRU。

```
算法实现：
1. 将内存中的页框链接成一个环形队列（圆时钟）
2. 每个页表项有一个访问位A（被MMU在访问页面时置1）
3. 置换时，扫描时钟：
   → 如果A=0：选择该页面淘汰（如M=1需写回）
   → 如果A=1：给该页面一次机会，将A置0，继续扫描
4. 如果遍历一圈都没有A=0的页面：淘汰第一个A=0的页面
```

**改进时钟算法（Second-Chance）**：

| 扫描到的页面 | A位 | 操作 |
|-------------|-----|------|
| A=0 | 未访问 | 直接淘汰 |
| A=1 | 刚被访问 | 给一次机会：A清0，继续扫描 |
| A=1 | 已给过一次机会 | 再次给机会：A清0，继续 |
| 遍历一圈 | - | 淘汰第一个A=0的页面 |

**Clock算法的分类**：

| 算法 | 说明 | 淘汰条件 |
|------|------|---------|
| **纯Clock（NRU）** | 只看访问位 | A=0的页面淘汰，不分修改状态 |
| **Clock-2（增强型）** | 同时考虑A和M位 | 优先淘汰(A=0,M=0)，其次(A=0,M=1)，最后(A=1,M=0) |

> 从CSAPP视角看，Linux使用的是增强型Clock算法的变种（近似LRU），通过扫描访问位和回收位来选择置换页面。

**示例**（页框数=3，序列：1, 3, 0, 3, 5, 6, 3, 0, 3, 0, 6）：

假设初始A位全为0，访问页面时硬件自动将A置1。

| 访问页 | 内存（页号:A:M） | 指针位置 | 是否缺页 | 置换页面 |
|--------|-----------------|---------|---------|---------|
| 1 | [1:1:0] | →1 | 是 | - |
| 3 | [1:0:0, 3:1:0] | →3 | 是 | - |
| 0 | [1:0:0, 3:0:0, 0:1:0] | →0 | 是 | - |
| 3 | [1:0:0, 3:1:0, 0:0:0] | →0 | 否 | 3的A被置1 |
| 5 | 扫描：1(A=0) → 置换1 | [5:1:0, 3:1:0, 0:0:0] | 是 | 1 |
| 6 | 扫描：3(A=1→0), 0(A=0) → 置换0 | [5:0:0, 3:0:0, 6:1:0] | 是 | 0 |
| 3 | [5:0:0, 3:1:0, 6:0:0] | →6 | 否 | 3的A被置1 |
| 0 | 扫描：3(A=1→0), 6(A=0) → 置换6 | [5:0:0, 3:0:0, 0:1:0] | 是 | 6 |
| 3 | [5:0:0, 3:1:0, 0:0:0] | →0 | 否 | 3的A被置1 |
| 0 | [5:0:0, 3:0:0, 0:1:0] | →0 | 否 | 0的A被置1 |
| 6 | 扫描：5(A=0) → 置换5 | [6:1:0, 3:0:0, 0:0:0] | 是 | 5 |

- 缺页次数：9次
- 缺页率：9/11 = 81.8%

> Clock算法的时间复杂度为O(n)（n为页框数），最坏情况下需要遍历一圈。

### 六、不先进先出置换算法（LFU, Least Frequently Used）

**核心思想**：选择**访问频率最低**的页面淘汰。

```
算法实现：使用计数器
- 每次访问页面时，该页面的计数器加1
- 置换时，选择计数器最小的页面
```

> 局限性：如果一个页面在早期被频繁访问，之后不再需要，它仍然可能因为计数器大而不会被淘汰。
> 改进：**老化LFU**，将计数器定期右移（衰减），消除早期访问的影响。

### 七、最少使用置换算法（LFR / LRU近似）

**核心思想**：结合FIFO和LRU的优点，选择既不是最近访问也不是最早进入的页面。

### 八、驻留集分配算法

#### 1. 平均分配法

$$每个进程分配的页框数 = \frac{总页框数}{进程数}$$

> 简单但不够灵活，不同进程的工作集大小不同。

#### 2. 加权分配法

$$进程i的页框数 = 总页框数 \times \frac{进程i的优先级}{\sum 所有进程的优先级}$$

> 考虑了进程的优先级，优先级高的进程获得更多页框。

#### 3. 工作集分配法

- 监控每个进程的工作集大小
- 分配的页框数 ≥ 工作集大小
- 页框数 < 工作集大小 → 可能产生抖动

> 从CSAPP视角看，工作集模型是避免抖动的最有效方法。

### 九、页面置换算法综合对比

| 算法 | 缺页率 | 实现复杂度 | 硬件需求 | 是否Belady异常 | 实际使用 |
|------|--------|-----------|---------|---------------|---------|
| **OPT** | 最低（理论最优） | 无法实现 | 无法实现 | 无 | 理论参考 |
| **FIFO** | 较高 | 简单（队列） | 无 | **有** | 很少使用 |
| **LRU** | 较低 | 复杂（栈/计数器） | 需要硬件支持 | 无 | 理想目标 |
| **Clock** | 中等 | 中等（环形链表） | 需要访问位 | 无 | 实际使用（Linux） |
| **LFU** | 中等 | 中等（计数器） | 需要计数器 | 无 | 较少使用 |

> ⭐ **选择题结论性记忆**：
> 1. **OPT是理论最优，但无法实现**
> 2. **FIFO会产生Belady异常**（增加页框反而缺页更多）
> 3. **LRU不会产生Belady异常**，且近似OPT
> 4. **Clock是LRU的工程近似**，实际操作系统广泛使用
> 5. 四种算法中，**OPT缺页率最低，FIFO最高**

## ⚖️易混淆概念对比

### OPT vs LRU

| 对比项 | OPT | LRU |
|--------|-----|-----|
| 淘汰策略 | 淘汰最久不会被使用的页面 | 淘汰最近最久未使用的页面 |
| 实现性 | 无法实现（需预知未来） | 可实现（需硬件支持） |
| 缺页率 | 最低（理论最优） | 次低（接近OPT） |
| 硬件需求 | 无（理论算法） | 需要计数器和栈 |
| 关联文档 | 本页面 | [[虚拟内存]] |

### FIFO vs LRU vs Clock

| 对比项 | FIFO | LRU | Clock |
|--------|------|-----|-------|
| 淘汰依据 | 最早进入的页面 | 最近最久未使用的页面 | 访问位为0的页面 |
| 数据结构 | 队列 | 栈或计数器 | 环形链表 |
| 时间复杂度 | O(1) | O(n) | O(n)（平均O(1)） |
| 是否Belady异常 | **有** | 无 | 无 |
| 实现难度 | 最简单 | 最复杂 | 中等 |
| 实际使用 | 少 | 作为理论参考 | 广泛（Linux） |

### 内部碎片 vs 外部碎片在虚拟内存中的表现

| 对比项 | 内部碎片 | 外部碎片 |
|--------|---------|---------|
| 在分页系统中 | 最后一页的剩余空间 | 不存在（页框完全分配） |
| 在分段系统中 | 不存在 | 存在（段大小可变） |
| 在段页式系统中 | 最后一页的剩余空间 | 不存在 |

## ⚠️考试高频坑点

### 坑点1：Belady异常仅FIFO会产生 ⭐

> 【考试考法】以下哪种置换算法可能产生Belady异常？
> A. OPT  B. LRU  C. FIFO  D. Clock
> 答案：C（只有FIFO会产生Belady异常）

### 坑点2：LRU和FIFO的计算方法 ⭐

> 【考试考法】大题中要求用FIFO或LRU进行页面置换计算。
> FIFO看"最早进入"，LRU看"最久未使用"。
>
> ⚠️ 易错点：FIFO的"最早进入"是指**什么时候调入内存的**，而不是什么时候第一次访问的。
> LRU的"最久未使用"需要追踪每个页面**上次被访问的时刻**。

### 坑点3：缺页率的计算 ⭐

> 【考试考法】缺页率 = 缺页次数 / 总访问次数（不是已调页数）。
> 例如：访问序列长度为n，发生了m次缺页中断，缺页率 = m/n。

### 坑点4：修改位对置换的影响 ⭐

> 【教材原文】被修改的页面（M=1）换出时需要写回外存，增加了I/O开销。
>
> 【考试考法】增强型Clock算法优先选择(M=0, A=0)的页面淘汰。
> 如果所有页面M=1，则优先选择(A=0)的页面。

### 坑点5：Clock算法的指针移动 ⭐

> 【考试考法】Clock算法扫描时，指针只向后移动一位（不回头）。
> 如果一圈扫描完都没有A=0的页面（说明所有页面A都被硬件置1了），则所有A位已清零，继续从头开始扫描。

### 坑点6：OPT在选择题中的"陷阱" ⭐

> 【考试考法】题目问"以下哪种算法是实际可实现的？"
> 答：OPT不能实现，FIFO/LRU/Clock可以实现。
> 题目问"哪种算法缺页率最低？"
> 答：OPT（理论最低，但无法实现）。
