# 经典同步问题

## 📍知识定位

### 在 408 体系中的位置

经典同步问题是操作系统同步互斥机制的经典案例，是 408 考试中**大题出现频率最高**的题型之一。主要包含生产者-消费者问题、读者-写者问题、哲学家进餐问题。掌握这些问题的信号量解法是解决大题的基础。

### 学习前置条件

- **信号量**：理解 P/V 操作、记录型信号量的定义与用法
- **临界区**：理解临界区和临界资源的概念
- **同步与互斥**：理解同步和互斥的区别

### 学完之后支撑的知识点

- **死锁**：哲学家进餐问题直接关联死锁的产生与解除
- **进程调度**：信号量的阻塞/唤醒机制与调度队列相关
- **进程通信**：经典问题中隐含进程间的信息传递

## 📝核心概念与原理

### 1. 生产者-消费者问题（Producer-Consumer）

**问题描述**：一组生产者进程和一组消费者进程共享一个初始为空、大小为 n 的缓冲区。生产者负责生产数据放入缓冲区，消费者从缓冲区中取出数据消费。要求：① 缓冲区满时生产者等待；② 缓冲区空时消费者等待；③ 互斥访问缓冲区。

#### 信号量解法

```c
Semaphore mutex = 1;      // 互斥信号量，保护缓冲区的互斥访问
Semaphore empty = n;      // 同步信号量，表示空缓冲区的数量
Semaphore full = 0;       // 同步信号量，表示满缓冲区的数量
```

**生产者进程：**
```c
do {
    // 生产一个产品
    P(empty);             // 申请一个空缓冲区（可能阻塞）
    P(mutex);             // 进入临界区（互斥访问缓冲区）
    
    // 将产品放入缓冲区
    放入缓冲区;
    
    V(mutex);             // 离开临界区
    V(full);              // 增加一个满缓冲区（唤醒消费者）
    
    // 消费产品
} while (true);
```

**消费者进程：**
```c
do {
    P(full);              // 申请一个满缓冲区（可能阻塞）
    P(mutex);             // 进入临界区（互斥访问缓冲区）
    
    // 从缓冲区取出产品
    从缓冲区取出产品;
    
    V(mutex);             // 离开临界区
    V(empty);             // 增加一个空缓冲区（唤醒生产者）
    
    // 消费产品
} while (true);
```

> ⭐ **选择题高频考点**：两个 P 操作的顺序。生产者的 `P(empty)` 和 `P(mutex)` 顺序不能颠倒，否则会因空缓冲区不够而阻塞，但已持有 mutex 锁，导致死锁。消费者的 `P(full)` 和 `P(mutex)` 同理。

#### 关键规则

| 规则 | 说明 | 违反后果 |
|------|------|---------|
| P(empty) 在 P(mutex) 之前 | 先确认有空位再请求互斥 | 颠倒会导致死锁（有空位但被 mutex 阻塞） |
| V(mutex) 在 V(full) 之前 | 先释放互斥锁再通知消费者 | 颠倒不影响功能，但不规范 |
| 互斥信号量初值 | mutex = 1 | 互斥访问 |
| 同步信号量初值 | empty = n, full = 0 | 空满数量 |

> 🔥 **大题必考**：分析生产者-消费者问题的信号量解法时，必须准确写出信号量的定义、P/V 操作的顺序以及每个操作的意义。这是最经典的大题题型。

### 2. 读者-写者问题（Reader-Writer）

**问题描述**：允许多个读者同时读一个共享文件，但写者必须互斥地访问。要求：① 读-写互斥（写者独占）；② 读-读允许（多读者可同时读）；③ 写-写互斥。

#### 第一种实现（读优先）

```c
Semaphore rw_mutex = 1;       // 保护读写操作的互斥
Semaphore read_mutex = 1;     // 保护 read_count 变量的互斥
int read_count = 0;           // 当前正在读的读者数
```

**读者进程：**
```c
do {
    P(read_mutex);            // 保护 read_count
    read_count++;
    if (read_count == 1) {
        P(rw_mutex);          // 第一个读者获取写锁
    }
    V(read_mutex);
    
    // 读操作
    
    P(read_mutex);
    read_count--;
    if (read_count == 0) {
        V(rw_mutex);          // 最后一个读者释放写锁
    }
    V(read_mutex);
} while (true);
```

**写者进程：**
```c
do {
    P(rw_mutex);              // 写者获取写锁（独占）
    
    // 写操作
    
    V(rw_mutex);              // 写者释放写锁
} while (true);
```

> ⭐ **选择题高频考点**：读优先策略下，写者可能"饿死"（如果读者持续到达，写者一直等不到互斥信号量）。这也是改进方向——引入写优先或公平策略。

### 3. 哲学家进餐问题（Dining Philosophers）

**问题描述**：有五位哲学家围坐在圆桌旁，每人面前有一碗饭，每两人之间有一根筷子。哲学家要么吃饭要么思考。吃饭时需要同时拿起左右两根筷子。要求：① 互斥使用筷子；② 防止死锁。

#### 信号量解法（可能导致死锁的初始方案）

```c
Semaphore chopstick[5] = {1, 1, 1, 1, 1};  // 五根筷子信号量

// 哲学家 i（i = 0, 1, 2, 3, 4）
do {
    P(chopstick[i]);              // 拿起左筷子
    P(chopstick[(i+1) % 5]);      // 拿起右筷子
    
    // 吃饭
    
    V(chopstick[i]);              // 放下左筷子
    V(chopstick[(i+1) % 5]);      // 放下右筷子
    
    // 思考
} while (true);
```

> ⚠️ 上述方案可能导致**死锁**——如果所有哲学家同时拿起左筷子，则都在等待右筷子。

#### 防止死锁的解法

| 解法 | 实现方式 | 说明 |
|------|---------|------|
| **最多允许 4 人同时就餐** | 增设一个信号量 `room = 4`，P(room) 在最前 | 至少留一个空位，不会全部 deadlock |
| **奇数先右后左，偶数先左后右** | 根据哲学家编号决定拿筷子顺序 | 打破"同时拿左筷子"的条件 |
| **同时拿起两根筷子** | 使用 AND 信号量 | 一次获取两根，或都不获取 |
| **仅当左右筷子都可用时才拿** | 原子检查+获取 | 使用测试并设置指令或互斥信号量保护 |

> 🔥 **大题必考**：哲学家进餐问题的死锁分析是常见大题。需要识别死锁产生的四个必要条件（互斥、占有并等待、非抢占、循环等待），并给出至少一种解除死锁的方案。

### 4. 三种经典问题的对比

| 问题 | 核心资源 | 信号量个数 | 关键互斥点 | 可能死锁 |
|------|---------|-----------|-----------|---------|
| 生产者-消费者 | 缓冲区 | 3（mutex, empty, full） | 缓冲区访问 | ❌ 否（正确实现不会死锁） |
| 读者-写者 | 文件 | 2（rw_mutex, read_mutex） | 写者独占 | ❌ 否（可能写者饿死） |
| 哲学家进餐 | 筷子 | 6+（5 根筷子 + 可选 room） | 筷子获取 | ✅ 是（可能循环等待） |

## ⚖️易混淆概念对比

| 对比项 | 生产者-消费者 | 读者-写者 | 哲学家进餐 |
|--------|-------------|----------|-----------|
| 资源类型 | 缓冲区（数量固定） | 文件（可共享读） | 筷子（互斥使用） |
| 信号量数量 | 3 个 | 2 个 | 6+ 个 |
| 是否可能死锁 | 否（正确实现） | 否（可能饿死） | 是（可能循环等待） |
| 核心考点 | P/V 操作顺序 | 读写互斥 | 死锁条件 |
| 同步关系 | 生产者等待空位 | 写者等待读者读完 | 哲学家等待两根筷子 |

## ⚠️考试高频坑点

| 坑点 | 错误理解 | 正确理解 |
|------|---------|---------|
| P 操作顺序 | 误认为 P(empty) 和 P(mutex) 顺序无关 | 必须 P(empty) 在 P(mutex) 之前，否则死锁 |
| 写者饿死 | 认为读优先不会有饥饿 | 读优先会导致写者饿死（持续等待） |
| 死锁条件 | 认为生产者-消费者会死锁 | 正确实现不会死锁；哲学家进餐可能死锁 |
| V 操作顺序 | 误认为 V 操作顺序影响功能 | V 操作顺序不影响正确性，但 P 操作顺序影响 |
| 哲学家筷子编号 | 误认为筷子编号是线性的 | 筷子编号是环形的（5%5 取模） |
