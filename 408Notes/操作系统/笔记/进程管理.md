# 进程管理

## 📍知识定位

### 在408体系中的位置

进程管理是操作系统的**核心模块**，涉及进程的创建、撤销、状态转换、调度以及与线程的关系。它是理解并发编程、同步互斥、死锁机制的基础。

### 学习前置条件

- **操作系统概述**：理解操作系统的核心概念、系统调用
- **数据结构基础**：链表（用于进程队列）、树（用于进程控制块PCB的组织）
- **计算机组成原理**：了解CPU的执行机制、中断、Cache

### 学完之后支撑的知识点

- 进程调度：在理解进程管理的基础上，进一步学习CPU调度算法
- 同步与互斥：进程间的协作关系
- 死锁：多个进程竞争资源时可能出现的僵局

## 📝核心概念与原理

### 一、进程的概念与特征

#### 1. 进程的定义

> **进程（Process）**是操作系统分配资源的基本单位，是程序在一个数据集合上运行的过程，是操作系统进行资源分配和保护的独立单位。

进程与程序的区别 ⭐：

| 对比项 | 程序（Program） | 进程（Process） |
|--------|---------------|---------------|
| 本质 | 静态的指令集合 | 动态的执行过程 |
| 组成 | 代码+数据 | PCB+程序段+数据段 |
| 生命周期 | 永久存在 | 有创建、执行、撤销的完整生命周期 |
| 关联性 | 与其他程序无直接关联 | 可与其他进程并发、同步、通信 |
| 标识 | 文件名 | PID（进程标识符） |

> **关键理解**：一个程序可以对应多个进程（如同时打开多个Chrome浏览器窗口）。

#### 2. 进程的特征 ⭐

1. **动态性**：进程是程序的一次执行过程，有生命周期
2. **并发性**：多个进程可在同一时间内同时存在
3. **独立性**：进程是系统中独立运行、独立获得资源和独立接受调度的基本单位
4. **异步性**：进程的执行顺序和速度不确定
5. **结构特征**：每个进程都有PCB（进程控制块）

> PCB是进程存在的唯一标志。OS是通过PCB来感知进程存在的。

#### 3. 进程控制块（PCB）

PCB是操作系统中用来描述进程基本信息和控制进程运行全部过程的数据结构。

**PCB包含的信息**：

| 类别 | 内容 |
|------|------|
| 进程标识信息 | PID（进程号）、PPID（父进程号） |
| 处理机状态信息 | CPU寄存器（程序计数器PC、栈指针SP、通用寄存器）、程序状态字PSW |
| 进程控制信息 | 进程状态、进程优先级、进程同步信号、进程通信信息、资源清单 |

> ⭐ **选择题考点**：进程被调度执行时，OS必须将CPU的处理机状态信息保存到被撤消进程的PCB中；恢复执行时，从PCB中恢复处理机状态信息。

### 二、进程的状态与转换

#### 1. 进程的五状态模型

```
         创建
         ↓
    ┌────(NEW)────┐
    │              │
    │   调度       │  终止
    │   ↓          │  ↓
    │  (READY) ────┼→ (RUNNING) ────→ (TERMINATED)
    │       ↑              │
    │       │     阻塞/中断  │ 阻塞
    │       │              │
    │       └──(BLOCKED)───┘
    │              ↑
    └──────── 就绪 ──┘
```

#### 2. 三状态基本模型 ⭐

将上述简化为最常用的三状态：

| 状态 | 说明 |
|------|------|
| **就绪（Ready）** | 进程已获得除CPU以外的所有必要资源，只要获得CPU即可立即执行 |
| **执行（Running）** | 进程正在CPU上执行 |
| **阻塞（Blocked/Waiting）** | 进程因等待某一事件（如I/O完成）而无法执行 |

#### 3. 状态转换事件

| 转换 | 原因 | 触发事件 |
|------|------|---------|
| 就绪 → 执行 | 调度 | 进程调度程序选中该进程 |
| 执行 → 就绪 | 时间片用完 | 定时器中断（时间片耗尽） |
| 执行 → 阻塞 | 等待事件 | I/O请求、等待子进程等 |
| 阻塞 → 就绪 | 事件完成 | I/O完成中断 |
| 新建 → 就绪 | 调度 | 高级调度（作业调度）将进程调入内存 |
| 执行 → 终止 | 正常退出/出错 | 进程正常结束、异常终止 |

> ⭐ **选择题高频考点**：以下转换**不可能发生**：阻塞 → 执行（必须先转为就绪）；执行 → 终止（需经过调度）；新建 → 执行（需先经过就绪）。

> 🔥 **大题必考**：画出进程三状态转换图，并标注所有状态转换及其触发事件。

### 三、进程的控制

#### 1. 进程的创建

**进程创建的步骤**（以Unix/Linux为例）：

```
步骤1：分配新的PCB
步骤2：分配新进程的唯一标识符
步骤3：为进程分配资源（内存空间、文件描述符等）
步骤4：初始化PCB（设置状态=就绪、设置优先级等）
步骤5：将新进程插入就绪队列
```

**fork()系统调用**（Unix/Linux进程创建的典型方式）：

```c
pid_t pid = fork();
if (pid < 0) {
    // 创建失败
} else if (pid == 0) {
    // 子进程的执行代码
} else {
    // 父进程的执行代码，pid为子进程的PID
}
```

> ⭐ **选择题考点**：fork()调用一次，返回两次。父进程返回子进程的PID（正数），子进程返回0。fork()采用**写时复制（Copy-on-Write）**技术，只有当子进程或父进程真正修改内存时才复制页面。

#### 2. 进程的终止

进程终止的步骤：

```
步骤1：从父进程等待队列中找到等待退出的子进程，读取退出状态
步骤2：清除子进程在就绪队列和阻塞队列中的表项
步骤3：若子进程仍在运行，则停止执行
步骤4：回收子进程的资源
步骤5：将子进程的PCB从系统中删除
```

#### 3. 进程的中断与恢复

- **进程中断**：当某进程由于某种原因需要暂停执行时，由OS将其暂停执行，并将该进程的处理机状态保存起来
- **进程恢复**：当条件满足时，恢复进程的现场，将该进程的处理机状态从PCB中恢复

### 四、进程通信

#### 1. 进程通信的基本概念

**进程间通信（IPC, Inter-Process Communication）**是指进程之间交换数据和信息的机制。

#### 2. 共享存储系统

多个进程共享一个公共的缓冲区。

**特点**：
- 通信效率高（直接在内存中交换数据）
- 需要进程同步（互斥访问）
- 适合大数据量的通信

**示例**：共享内存区、共享变量

#### 3. 消息传递系统

通过OS提供的通信服务（发送消息、接收消息）实现通信。

**直接通信方式**：
```
send(P, message)    // 直接将消息发送给进程P
receive(Q, message)  // 从进程Q接收消息
```

**间接通信方式**：
```
send(A, message)    // 将消息发送到邮箱A
receive(A, message)  // 从邮箱A接收消息
```

**特点**：
- 实现简单
- 适合小数据量通信
- 需要消息的格式化和解析

#### 4. 管道通信

**匿名管道（pipe）**：

```c
int pipe(int fd[2]);  // fd[0]用于读，fd[1]用于写
```

**特点**：
- 半双工通信（单向数据传输）
- 只能在具有亲缘关系的进程间使用（父子进程）
- 缓冲区大小有限

> ⭐ **选择题考点**：管道是半双工的，如果需要全双工通信，需要创建两个管道。

#### 5. 信号量机制（为后续同步与互斥做铺垫）

信号量（Semaphore）是一种整型变量，可以通过两个原子操作PV原语来访问：

```
wait(S) {       // P操作
    while (S <= 0) ;  // 等待
    S--;
}

signal(S) {     // V操作
    S++;
}
```

> ⭐ **选择题考点**：PV原语是**原子操作**，不可分割。S=1：互斥信号量；S=0：同步信号量；S=-1：只有一个进程等待。

### 五、线程

#### 1. 线程的定义

> **线程（Thread）**是进程内的一一个执行单元，是OS**调度**的基本单位。一个进程可以包含多个线程，这些线程共享进程的资源，但各自有独立的执行栈和寄存器上下文。

#### 2. 进程与线程的比较 ⭐

| 对比项 | 进程 | 线程 |
|--------|------|------|
| 资源拥有 | 是资源拥有的基本单位 | 基本不拥有资源（只拥有少量必需资源） |
| 调度 | 不是调度的基本单位 | 是调度的基本单位 |
| 独立性 | 有独立的地址空间 | 共享进程地址空间 |
| 开销 | 创建、撤销、切换开销大 | 创建、撤销、切换开销小 |
| 通信 | 需要IPC机制 | 可直接读写进程的共享数据段 |
| 并发性 | 多个进程可并发执行 | 同一进程中的多个线程可并发执行 |

#### 3. 线程模型

**用户线程模型**：

```
用户层：多个用户线程 ↕ 用户线程库
内核层：一个内核线程 → 内核
```

**特点**：
- 线程管理完全在用户空间完成
- 创建和切换速度快
- 一个线程阻塞会导致整个进程阻塞

**内核线程模型**：

```
用户层：一个用户线程
内核层：多个内核线程 → 内核
```

**特点**：
- 线程管理由内核完成
- 线程阻塞不影响其他线程
- 创建和切换开销相对较大

**混合线程模型**：

```
用户层：多个用户线程 ↕ 用户线程库
内核层：多个内核线程 → 内核
```

**特点**：兼顾了用户线程的效率和内核线程的并发能力。

#### 4. 线程的实现方式

| 实现方式 | 说明 | 代表系统 |
|---------|------|---------|
| 用户级线程 | 完全在用户空间实现 | Java早期实现 |
| 内核级线程 | 由操作系统内核管理 | Linux NPTL、Windows |
| 混合实现 | 用户线程映射到内核线程 | 现代多核系统 |

> ⭐ **选择题考点**：Linux从2.6版本开始采用NPTL（Native POSIX Thread Library），每个用户线程对应一个内核线程，称为1:1模型。

#### 5. 线程与进程的比较总结表 ⭐

| 维度 | 进程 | 线程 | 优势 |
|------|------|------|------|
| 地址空间 | 独立 | 共享 | 线程通信方便 |
| 资源开销 | 大（需分配独立地址空间） | 小（共享地址空间） | 线程创建快 |
| 上下文切换 | 慢（涉及页表切换） | 快（无需切换页表） | 线程切换快 |
| 并发性 | 多进程可并发 | 多线程可并发 | 线程并发度更高 |
| 可靠性 | 一个进程崩溃不影响其他进程 | 一个线程崩溃可能导致整个进程崩溃 | 进程隔离性好 |

## ⚖️易混淆概念对比

### 进程 vs 线程

| 对比项 | 进程 | 线程 |
|--------|------|------|
| 定义 | 资源分配的基本单位 | 调度的基本单位 |
| 地址空间 | 独立 | 共享 |
| 创建开销 | 大 | 小 |
| 切换开销 | 大（需切换页表） | 小（同一地址空间） |
| 通信方式 | IPC（管道、消息、共享内存） | 直接读写共享数据 |
| 崩溃影响 | 仅影响自身 | 可能影响整个进程 |

### 用户线程 vs 内核线程

| 对比项 | 用户线程 | 内核线程 |
|--------|---------|---------|
| 管理方式 | 用户态线程库 | 内核管理 |
| 创建速度 | 快 | 较慢 |
| 阻塞行为 | 一个阻塞，整个进程阻塞 | 仅阻塞该线程 |
| 多核利用 | 只能利用一个核 | 可利用多个核 |
| 实现复杂度 | 简单 | 复杂 |

### 阻塞 vs 挂起

| 状态 | 原因 | 位置 | 唤醒方式 |
|------|------|------|---------|
| 阻塞（Blocked） | 等待事件（I/O等） | 内存 | 事件完成中断 |
| 挂起（Suspended） | 内存不足、外部请求 | 外存 | 中级调度调入内存 |

## ⚠️考试高频坑点

### 坑点1：阻塞→执行的转换不可能发生 ⭐

> 【教材原文】进程从阻塞状态只能转换为就绪状态，不能直接进入执行状态。
>
> 【考试考法】选择题常给出一个状态转换图，让考生判断哪个转换是错误的。阻塞→执行是**绝对错误**的转换。

### 坑点2：进程创建与线程创建的性能对比

> 【考试考法】比较fork()和pthread_create()的性能。
> 由于fork()需要复制地址空间（虽然使用写时复制技术），所以**创建线程比创建进程快得多**。

### 坑点3：信号量的物理含义 ⭐

> 【教材原文】信号量S的物理含义：
> - S > 0：可用资源数
> - S = 0：无可用资源，无等待进程
> - S < 0：|S|为等待队列中的进程数
>
> 【考试考法】给出S的初始值和PV操作的序列，求最终S的值。如：S初值=3，执行5次P操作、3次V操作，最终S = 3-5+3 = 1。

### 坑点4：管道通信的方向性

> 【教材原文】匿名管道是**半双工**的，数据只能单向流动。
>
> 【考试考法】选择题常问"管道通信的特点"，正确选项应包含"半双工"。
