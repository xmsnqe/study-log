# 操作系统概述

## 📍知识定位

### 在408体系中的位置

操作系统是408计算机学科综合考试四大模块之一（数据结构、计算机组成原理、操作系统、计算机网络）。操作系统模块的**核心目标**是：管理计算机硬件与软件资源，合理组织计算机工作流程，为用户提供良好的接口。

### 学习前置条件

- **数据结构基础**：需要理解树（用于文件系统目录结构）、链表（用于进程队列管理）等数据结构。
- **计算机组成原理基础**：需要了解CPU（处理器）、存储器（内存、Cache、外存）、I/O设备等硬件基础知识。
- **计算机网络基础**（可选）：理解网络协议有助于后续学习网络文件系统。

### 学完之后支撑的知识点

- 进程管理 → 多线程、并发程序设计
- 内存管理 → 虚拟内存机制、地址转换
- 文件系统 → 磁盘调度、文件存储
- I/O管理 → 设备驱动、缓冲管理

## 📝核心概念与原理

### 一、操作系统的定义

> **操作系统（Operating System, OS）**是管理计算机硬件与软件资源的系统软件，同时也是计算机系统的内核与基石。它负责处理诸如内存分配、进程管理、文件管理、设备管理等核心任务，并在用户程序与计算机硬件之间提供接口。

从CSAPP的视角看，操作系统是一个特殊的程序（称为**内核**），它在特权模式下运行，拥有对硬件的直接访问权限。普通应用程序运行在用户模式下，通过**系统调用**请求操作系统提供服务。

### 二、操作系统的四个基本特征 ⭐

#### 1. 并发（Concurrency）

**定义**：指一段时间内宏观上多个事件同时发生，微观上多个事件交替执行。

> 注意区分：**并发 ≠ 并行**
> - **并发（Concurrency）**：宏观同时，微观交替（单核CPU可通过时间片轮转实现多任务）
> - **并行（Parallelism）**：宏观和微观都同时（多核CPU真正同时执行多个任务）

#### 2. 共享（Sharing）

**定义**：指操作系统中的资源可供内存中多个并发执行的进程共同使用。

共享方式分为两类：
- **互斥共享**：一段时间内只允许一个进程访问（如打印机）
- **同时共享**：允许多个进程同时访问（如只读文件）

#### 3. 虚拟（Virtualization）

**定义**：指通过某种技术把一个物理实体转化为多个逻辑上的对应物。

虚拟技术包括：
- **时分技术**：将一台物理CPU虚拟为多个逻辑CPU（多道程序设计）
- **空分技术**：将一台物理内存虚拟为多个逻辑内存（覆盖与交换技术、虚拟内存）

#### 4. 异步（Intermittency）

**定义**：指进程执行的顺序和速度不确定，具有推进性。

在多道程序环境下，进程的执行不是一气呵成，而是走走停停，以不确定的速度向前推进。操作系统必须保证每个进程能在合理的时间内获得执行。

### 三、操作系统的主要功能 ⭐

操作系统管理五大类资源，对应五大功能：

#### 1. 处理器管理（进程管理）

包括：
- **进程控制**：创建、撤销、挂起、恢复进程
- **进程调度**：分配CPU，决定哪个进程何时获得CPU
- **进程同步与通信**：协调多个进程的执行顺序
- **死锁处理**：预防、避免、检测和解除死锁

> ⭐ **选择题考点**：进程调度分为**低级调度**（进程调度，核心功能，分配CPU）、**中级调度**（内存调度，将进程调入/调出内存）和**高级调度**（作业调度，从外存调入内存）。

#### 2. 存储器管理（内存管理）

包括：
- **内存分配与回收**：为进程分配和回收内存空间
- **地址转换**：将逻辑地址转换为物理地址
- **内存保护**：防止一个进程破坏另一个进程或操作系统的数据
- **内存扩充**：通过虚拟技术（如虚拟内存）扩充内存

> 🔥 **大题考点**：虚拟内存的页面置换算法（FIFO、LRU、OPT），缺页中断的处理流程。

#### 3. 文件管理（文件系统）

包括：
- **文件存储空间管理**：管理磁盘空闲空间和使用空间
- **目录管理**：建立、删除、搜索目录
- **文件的读写与保护**：文件创建、读写、删除、保护

#### 4. 设备管理（I/O管理）

包括：
- **缓冲管理**：管理数据在缓冲区中的流动
- **设备分配与回收**：分配独占设备、共享设备、虚拟设备
- **设备处理**：实现设备的驱动程序，完成I/O请求
- **虚拟设备技术**：通过SPOOLing技术将独占设备改造为共享设备

#### 5. 用户接口

包括三层接口：
- **操作接口**：用户程序接口（系统调用）
- **程序接口**：系统调用（System Call）
- **命令接口**：命令行接口（CLI）和图形用户接口（GUI）

> ⭐ **选择题高频考点**：系统调用是操作系统提供给用户程序的功能接口。系统调用通过**陷阱指令（trap/interrupt）**从用户态切换到内核态。常见的系统调用包括：fork、exec、read、write、open、close、malloc等。

### 四、操作系统的发展与分类

| 发展阶段 | 时间 | 核心特征 | 优缺点 |
|---------|------|---------|--------|
| 单机单道批处理 | 1946-1955 | 自动顺序执行 | 提高了CPU利用率，但CPU利用率仍然不高 |
| 联机多道批处理 | 1955-1965 | 多道程序同时进入内存 | CPU利用率和系统吞吐量显著提高 |
| 脱机多道批处理 | 1965-1967 | 输入/输出分离 | 进一步提高了CPU利用率 |
| 分时系统 | 1965-1970 | 时间片轮转，交互性 | 实现了人机交互，响应速度快 |
| 实时系统 | 1965-现在 | 快速响应、高可靠 | 用于工业控制、军事等领域 |
| 通用操作系统 | 1970-现在 | 多种类型融合 | 如Windows、Linux、macOS |

> ⭐ **选择题考点**：分时系统的主要特征是**多路性、独立性、及时性、交互性**。实时系统分为**实时控制系统**和**实时信息处理系统**两类。

### 五、操作系统的核心设计理念

#### 1. 用户态与内核态

- **用户态（User Mode）**：普通进程运行的状态，只能访问用户空间的内存，不能直接访问硬件
- **内核态（Kernel Mode）**：操作系统内核运行的状态，可以访问全部内存和硬件资源

从用户态切换到内核态的方式：
1. **系统调用（System Call）**：进程主动请求操作系统服务
2. **异常（Exception）**：程序执行过程中出现的错误（如除零、缺页）
3. **I/O中断（Interrupt）**：I/O设备完成后通知CPU
4. **管理程序调用（Monitor Call）**：用于程序调试

> ⭐ **选择题高频考点**：系统调用属于**程序性异常**，由进程主动触发；中断属于**外围性中断**，由外部事件触发。

#### 2. 进程模型

- **单地址空间模型**：如早期的MS-DOS，所有程序共享同一地址空间
- **多地址空间模型**：现代操作系统（如Windows、Linux），每个进程有独立的地址空间

#### 3. 微内核与宏内核

- **宏内核（Monolithic Kernel）**：所有服务都在内核态运行（如早期的Unix、Windows）
- **微内核（Microkernel）**：只有最核心的服务（进程通信、基本调度）在内核态运行，其他服务在用户态运行（如QNX、Mach）

> 对比：宏内核效率高但扩展性差；微内核扩展性好但效率略低。现代操作系统（如Linux）采用了混合方案。

### 六、操作系统的系统调用机制

#### 1. 系统调用的工作流程

```
用户程序 → 调用系统调用库函数 → 触发陷阱指令 → 切换到内核态
→ 执行系统调用处理程序 → 返回用户态 → 返回用户程序
```

#### 2. 系统调用与一般函数调用的区别 ⭐

| 对比项 | 系统调用 | 一般函数调用 |
|--------|---------|-------------|
| 调用层级 | 用户态 → 内核态 | 用户态内部 |
| 触发方式 | 陷阱/异常指令 | 直接调用 |
| 执行速度 | 较慢（需切换上下文） | 较快 |
| 作用范围 | 访问操作系统资源 | 仅访问用户数据 |
| 可移植性 | 依赖于操作系统 | 依赖于程序本身 |

#### 3. 常用系统调用

| 系统调用 | 功能描述 |
|---------|---------|
| fork() | 创建子进程 |
| exec() | 执行新程序 |
| wait() | 等待子进程终止 |
| read() | 从文件中读取数据 |
| write() | 向文件中写入数据 |
| open() | 打开文件 |
| close() | 关闭文件 |
| malloc() | 动态分配内存 |

## ⚖️易混淆概念对比

### 并发 vs 并行

| 对比项 | 并发（Concurrency） | 并行（Parallelism） |
|--------|-------------------|-------------------|
| 定义 | 宏观同时，微观交替 | 宏观和微观都同时 |
| 实现条件 | 单核CPU + 时间片轮转 | 多核CPU |
| 本质 | 逻辑上的同时 | 物理上的同时 |
| 关系 | 并发是并行的一种抽象 | 并行是并发的物理实现 |

> ⭐ **选择题考点**：在单核多道程序系统中，只能实现**并发**，不能实现真正的**并行**。

### 分时系统 vs 实时系统

| 对比项 | 分时系统 | 实时系统 |
|--------|---------|---------|
| 核心目标 | 人机交互、响应时间 | 及时响应、高可靠性 |
| 响应时间要求 | 秒级（通常<1秒） | 毫秒级或微秒级 |
| 时间片大小 | 较大 | 很小或无时间片 |
| 可靠性要求 | 一般 | 非常高 |
| 典型应用 | 通用计算 | 工业控制、航空航天 |
| 多路性 | 强 | 弱 |

### 系统调用 vs 库函数

| 对比项 | 系统调用 | 库函数 |
|--------|---------|--------|
| 位置 | 操作系统内核中 | 用户程序库中 |
| 特权级别 | 内核态 | 用户态 |
| 开销 | 高（需上下文切换） | 低（纯用户态调用） |
| 举例 | read、write、open | printf、strcpy、malloc封装 |

## ⚠️考试高频坑点

### 坑点1：操作系统的四个基本特征的顺序记忆

> 考试常以多选题形式考察这四个特征，要求正确排序。记忆口诀：**"并共享虚异步"**（并行共享、虚拟异步）。

### 坑点2：低级调度 vs 中级调度 vs 高级调度 ⭐

| 调度类型 | 别名 | 操作对象 | 频率 |
|---------|------|---------|------|
| 低级调度 | 进程调度 | 进程 | 最高（毫秒级） |
| 中级调度 | 内存调度 | 进程（在内存和外存之间） | 中等 |
| 高级调度 | 作业调度 | 作业 | 最低（分钟级或小时级） |

> 【考试考法】选择题常给出一个场景，要求判断属于哪种调度。例如："某时刻系统需要将处于后备状态的作业调入内存" → 属于高级调度（作业调度）。

### 坑点3：系统调用的实现方式区分

> 【教材原文】系统调用通过"陷阱"（Trap）指令实现，陷阱是**同步、可编程**的中断。
>
> 【考试考法】选择题常问"系统调用属于哪类中断"。陷阱是**程序性异常**（同步中断），而I/O中断是**外围性中断**（异步中断）。

### 坑点4：并发的定义范围 ⭐

> 【教材原文】并发是"同一时间段内多个程序都处于开始到结束之间的状态"。
>
> 【考试考法】常考"并发与并行的区别"。在单核CPU上，多个程序**并发执行**但**不并行执行**。
