# 临界区

## 📝核心概念与原理

### 1. 临界区问题的定义

临界资源（Critical Resource）是指一次仅允许一个进程使用的共享资源。临界区（Critical Section）是指进程中使用临界资源的那段代码。临界区问题的核心要求：

| 要求 | 说明 | 重要性 |
|------|------|--------|
| **互斥访问** | 每次最多只能有一个进程在其临界区内执行 | 必须满足 |
| **前进** | 临界区空闲时，应尽快选择下一个进入的进程 | 必须满足 |
| **有限等待** | 从提出进入请求到获准进入，等待次数应有限 | 必须满足 |

> ⭐ **选择题高频考点**：临界区问题的三个基本条件的名称必须准确记忆——互斥、前进、有限等待。

### 2. 解决临界区问题的方法分类

解决临界区问题的方法分为三类：**软件实现**、**硬件实现**和**信号量机制**。

#### （1）软件实现（算法方法）

软件方法通过进程间的协作来保证互斥，不需要硬件支持。最著名的是 **Peterson 算法**。

##### Peterson 算法（两人进程互斥）

```c
// 全局变量
int turn;          // 轮到谁进入
boolean flag[2];   // flag[i] 表示进程 i 是否想进入临界区

// 进程 i（i = 0 或 1，j = 1 - i）
do {
    flag[i] = true;          // 我想进入临界区
    turn = j;                // 给对方机会
    while (flag[j] && turn == j)  // 如果对方也想进入且轮到他
        ;                    // 忙等
    // 临界区
    flag[i] = false;         // 我不再想进入
    // 剩余区
} while (true);
```

> ⭐ Peterson 算法同时满足了互斥、前进、有限等待三个条件。它是唯一能够用纯软件方法同时满足三个条件的算法（仅适用于两进程）。

| 条件 | Peterson 算法是否满足 | 说明 |
|------|---------------------|------|
| 互斥 | ✅ | 同一时刻只有一个进程进入临界区 |
| 前进 | ✅ | 空闲时按轮流规则分配 |
| 有限等待 | ✅ | 最多等待一次（有限等待） |

#### （2）硬件实现（原子指令方法）

硬件方法通过 CPU 提供的原子指令来实现互斥，是最直接的方法。

##### TestAndSet（TS）指令

```c
boolean TestAndSet(boolean *lock) {
    boolean old = *lock;
    *lock = true;
    return old;
}
```

使用 TS 指令实现互斥：

```c
// 全局变量
boolean lock = false;

// 进程 i
do {
    while (TestAndSet(&lock))  // 如果 lock 原本为 true，则忙等
        ;
    // 临界区
    lock = false;              // 释放锁
    // 剩余区
} while (true);
```

> ⚠️ TS 指令实现存在"有限等待"问题——如果多个进程竞争，可能某个进程长时间等待（虽然不会死锁）。

##### CompareAndSwap（CAS）指令

```c
int CompareAndSwap(int *reg, int oldval, int newval) {
    int temp = *reg;
    if (*reg == oldval) {
        *reg = newval;
    }
    return temp;
}
```

使用 CAS 实现互斥：

```c
// 全局变量
int lock = 0;

// 进程 i
do {
    while (CompareAndSwap(&lock, 0, 1) != 0)  // 如果 lock 原本不是 0
        ;
    // 临界区
    lock = 0;          // 释放锁
    // 剩余区
} while (true);
```

> ⭐ **选择题高频考点**：TestAndSet 和 CompareAndSwap 都是原子指令，由硬件保证不可分割。TS 返回原值，CAS 返回旧值但修改条件不同。这些指令在 x86 架构中对应 `LOCK` 前缀的汇编指令。

#### （3）信号量机制

信号量机制是最通用的解决临界区问题的方法（已在 [[信号量]] 章节详述）。记录型信号量的 P 操作实现进入临界区的判断，V 操作实现离开临界区的释放。

### 3. 临界区问题的实现准则

| 准则 | 说明 | 违反后果 |
|------|------|---------|
| 进入区（Entry Section） | 检查能否进入临界区，不能则等待 | 违反则无法互斥 |
| 临界区（Critical Section） | 访问临界资源的代码段 | 核心区域 |
| 退出区（Exit Section） | 释放资源，唤醒等待进程 | 违反则其他进程无法进入（死锁） |
| 剩余区（Remainder Section） | 不包含临界资源的代码段 | 无特殊要求 |

```c
do {
    // 进入区
    // 检查条件，准备进入
    
    // 临界区
    // 访问共享资源
    
    // 退出区
    // 释放资源
    
    // 剩余区
    // 其他操作
} while (true);
```

### 4. 三种方法的对比

| 方法 | 优点 | 缺点 | 适用场景 |
|------|------|------|---------|
| **Peterson 算法** | 纯软件实现，满足所有条件 | 仅适用于两进程，忙等浪费 CPU | 教学、理解原理 |
| **TestAndSet** | 硬件保证原子性，简单高效 | 忙等浪费 CPU，有限等待不保证 | 实际系统的基础锁实现 |
| **CompareAndSwap** | 灵活性高，支持多条件原子操作 | 实现复杂，忙等浪费 CPU | 高性能并发编程 |
| **信号量机制** | 阻塞式等待，CPU 利用率高 | 实现复杂，需要内核支持 | 通用解决方案 |

## ⚖️易混淆概念对比

| 对比项 | Peterson 算法 | TestAndSet | CompareAndSwap |
|--------|-------------|-----------|---------------|
| 实现方式 | 纯软件 | 硬件原子指令 | 硬件原子指令 |
| 进程数量 | 仅 2 个 | 无限制 | 无限制 |
| 忙等 | ✅ 是 | ✅ 是 | ✅ 是 |
| 互斥 | ✅ 满足 | ✅ 满足 | ✅ 满足 |
| 前进 | ✅ 满足 | ✅ 满足 | ✅ 满足 |
| 有限等待 | ✅ 满足 | ❌ 不保证 | ❌ 不保证 |

## ⚠️考试高频坑点

| 坑点 | 错误理解 | 正确理解 |
|------|---------|---------|
| Peterson 算法适用性 | 认为 Peterson 算法适用于任意进程数 | 仅适用于 2 个进程 |
| TS 的有限等待 | 认为 TestAndSet 满足有限等待 | TestAndSet 只满足互斥和前进，不保证有限等待 |
| 忙等与阻塞 | 认为 TS 和 Peterson 使用阻塞 | 两者都是忙等（Busy Waiting），消耗 CPU |
| 信号量 vs 硬件 | 认为硬件实现比信号量更通用 | 信号量机制更通用（阻塞等待，CPU 利用率高） |
| CAS 与 TS 的区别 | 认为 CAS 和 TS 一样 | TS 设置 lock=true 返回旧值；CAS 只在值等于预期时设置新值 |
