## 📝核心概念与原理

### 一、虚拟内存的基本概念

> **虚拟内存（Virtual Memory）**：是一种允许程序使用的地址空间超过实际物理内存的技术。它通过**按需调入页面**的方式，使得进程能够在看起来拥有连续、大容量的地址空间的同时，实际只占用部分物理内存。

**虚拟内存的核心思想**：

1. **局部性原理（Principle of Locality）**：进程在执行过程中，访问的指令和数据集中在某个较小的地址范围内
2. **仅将当前需要的页面调入内存**：不一次性装入全部页面，而是当访问不在内存的页面时，才从外存调入
3. **页面换出（Swapping Out）**：当内存已满时，选择某些页面换出到外存

```
进程地址空间（虚拟）          物理内存
┌──────────────────┐
│ 代码段（部分调入） │  ┌──────────┐
├──────────────────┤  │ 页框 1    │ ← 已调入页面
│ 数据段（部分调入） │  ├──────────┤
├──────────────────┤  │ 页框 2    │ ← 已调入页面
│ 堆（部分调入）     │  ├──────────┤
├──────────────────┤  │ 页框 3    │ ← 已调入页面
│ 栈（部分调入）     │  ├──────────┤
│  ...             │  │ 页框 4    │ ← 空闲
├──────────────────┤  ├──────────┤
│ 外存中未调入页面  │  │ 页框 5    │ ← 已调入页面
│ （在外存中）       │  └──────────┘
└──────────────────┘
```

> 从CSAPP视角看，虚拟内存让每个进程认为自己独占整个物理内存，每个进程拥有独立的虚拟地址空间。

### 二、请求分页存储管理 🔥

#### 1. 请求分页的基本原理

请求分页（Demand Paging）是对基本分页的扩展，核心区别在于**只在需要时才调入页面**。

**请求分页与基本分页的对比**：

| 对比项 | 基本分页 | 请求分页 |
|--------|---------|---------|
| 装入时机 | 一次性全部装入 | 按需调入 |
| 是否要求全部装入 | 是 | 否 |
| 内存利用率 | 较低 | 较高 |
| 实现复杂度 | 简单 | 复杂（需要缺页中断机制） |
| 支持多道程序设计 | 有限 | 更好 |

#### 2. 页表结构的扩展 ⭐

请求分页需要对页表项进行扩展，增加以下信息：

```
页表项（PTE, Page Table Entry）扩展结构：
┌──────────────────────────────────────┐
│           物理页框号（22 bits）        │
├──────────────────────────────────────┤
│ 访问位(A) │ 修改位(M) │ 状态位(R/S)  │
│  1 bit    │  1 bit    │   1 bit      │
├──────────────────────────────────────┤
│       保护位 │ 外存地址（ displaced）  │
│   2 bits    │     剩余 bits           │
└──────────────────────────────────────┘
```

**各字段的含义**：

| 字段 | 名称 | 作用 |
|------|------|------|
| **状态位（R/S）** | Valid/Invalid bit | 0 = 页面不在内存；1 = 页面在内存 |
| **访问位（A）** | Access bit | 记录页面是否被访问过（用于置换算法） |
| **修改位（M）** | Modify bit | 1 = 页面被修改过，换出时需要写回外存 |
| **保护位** | Protection bits | 读/写/执行权限 |
| **外存地址** | Disk address | 页面在外存（交换区/文件）中的地址 |

> ⭐ **选择题高频考点**：
> 1. 状态位为0时，访问该页面会触发缺页中断
> 2. 修改位为1时，页面换出需要写回外存（增加了I/O开销）
> 3. 访问位为1说明页面近期被使用过（LRU算法会参考）

#### 3. 地址转换过程（请求分页）🔥

```
进程访问逻辑地址：
┌─────────────────────┐
│  段号(可选)  │ 页号  │  页内偏移  │
└─────────────────────┘
         ↓
   查页表（通过页表寄存器PTR）
         ↓
   检查状态位：
     → 状态位=0：触发缺页中断（从外存调入）
     → 状态位=1：继续
         ↓
   检查保护位：
     → 越权：触发保护故障中断
     → 合法：继续
         ↓
   页框号 × 页大小 + 页内偏移 = 物理地址
```

**请求分页的地址转换公式**（与基本分页相同）：

$$
页号 = \lfloor 逻辑地址 / 页面大小 \rfloor
$$

$$
页内偏移 = 逻辑地址 \bmod 页面大小
$$

$$
物理地址 = 页框号 \times 页面大小 + 页内偏移
$$

> ⭐ **选择题考点**：请求分页与基本分页的地址转换公式完全相同，区别仅在于**请求分页需要检查状态位**，可能触发缺页中断。

#### 4. 缺页中断（Page Fault）🔥🔥🔥

> **缺页中断（Page Fault）**：当进程访问的页面不在内存中（状态位=0）时，由MMU触发的中断。操作系统需要完成以下工作：
> 1. 保存当前进程上下文
> 2. 检查引用的合法性（是否越界、是否越权）
> 3. 查找外存中该页面的位置
> 4. 选择一个被淘汰的页面（如果内存已满）
> 5. 将所需页面从外存调入内存
> 6. 更新页表
> 7. 重新执行引发缺页的指令

**缺页中断的处理流程**：

```
1. CPU访问页面 → 状态位=0 → 缺页中断
2. 硬件保存PC和PSW → 操作系统内核处理
3. 检查访问合法性 → 非法：终止进程
4. 检查内存是否有空闲页框
   → 有空闲页框：直接进入步骤6
   → 无空闲页框：选择置换页面 → 如有修改则写回外存 → 释放页框
5. 从外存调入所需页面
6. 更新页表项（设置状态位=1、填充页框号、外存地址）
7. 重新执行触发缺页的指令
```

> 缺页中断与一般中断的区别：
>
> | 区别点 | 一般中断 | 缺页中断 |
> |--------|---------|---------|
> | 来源 | 外设（I/O） | 内存管理单元（MMU） |
> | 对当前指令的影响 | 当前指令已完成 | 当前指令尚未完成，需重新执行 |
> | 是否可屏蔽 | 通常可屏蔽 | 不可屏蔽 |
> | 处理速度 | 较快 | 较慢（涉及磁盘I/O） |

> ⭐ **选择题高频考点**：
> 1. 缺页中断**不是**I/O中断，而是由MMU产生的异常
> 2. 缺页中断处理后，被中断的指令会**重新执行**
> 3. 缺页中断的**响应速度远慢于一般中断**（因为涉及磁盘I/O）

#### 5. 有效访问时间（EAT）的计算 🔥

有TLB时，请求分页的有效访问时间：

$$EAT = h \times (t_{TLB} + t_{mem}) + (1-h) \times (t_{TLB} + t_{页表} + t_{mem} + 缺页开销)$$

如果考虑缺页率 $p$：

$$EAT = (1-p) \times [h \times (t_{TLB} + t_{mem}) + (1-h) \times (t_{TLB} + 2 \times t_{mem})] + p \times 缺页开销$$

其中：
- $h$：TLB命中率
- $p$：缺页率
- $t_{mem}$：访问主存的时间
- $t_{TLB}$：访问TLB的时间

> ⭐ **选择题高频考点**：EAT计算中，缺页开销通常远大于正常访问时间（如10ms vs 100ns），所以即使缺页率很低（如0.1%），也会显著增加EAT。

### 三、请求分段存储管理

#### 1. 基本概念

请求分段（Demand Segmentation）是对基本分段的扩展，同样采用**按需调入**的机制。

**请求分段的地址结构**：

```
┌──────────────────┐
│  段号(s)  │ 段内偏移(d)  │
└──────────────────┘
         ↓
   查段表：
     → 状态位=0：缺段中断
     → 状态位=1 且 偏移<段长：访问
     → 偏移≥段长：越界中断
         ↓
   物理地址 = 段起始地址 + 段内偏移
```

#### 2. 请求分段与请求分页的对比 ⭐

| 对比项 | 请求分页 | 请求分段 |
|--------|---------|---------|
| 页面大小 | 固定（面向机器） | 可变（面向用户） |
| 地址结构 | [页号, 页内偏移] | [段号, 段内偏移] |
| 共享性 | 页面级共享 | 段级共享（更易实现） |
| 动态增长 | 困难 | 容易（段可以动态增长） |
| 外部碎片 | 无 | 有 |
| 程序员可见性 | 不可见 | 可见（可按逻辑模块划分） |

> 从CSAPP视角看，请求分段更符合程序的逻辑结构（代码段、数据段、栈段等各自的按需加载）。

#### 3. 段页式虚拟内存

现代操作系统（如x86-64）通常采用**段页式虚拟内存**，即先分段再分页。

```
逻辑地址 → [段号, 页号, 页内偏移]
              ↓          ↓
          段表 → 页表 → 物理地址
              ↓
         页框号
              ↓
         物理地址 = 页框号 × 页大小 + 页内偏移
```

**段页式地址转换过程**：
1. 段寄存器装入段表起始地址
2. 段号查段表获得页表起始地址
3. 页号查页表获得物理页框号
4. 物理地址 = 页框号 × 页大小 + 页内偏移

> 段页式需要访问：TLB → 段表 → 页表 → 主存。在有TLB命中时，仍需访问两次主存（查段表和页表各一次）。

### 四、虚拟内存的性能考量

#### 1. 工作集模型（Working Set Model）⭐

> **工作集（Working Set）**：进程在一段时间内经常访问的页面集合。

$$WS(t, \Delta) = \{ 页面 \mid t-\Delta \leq 访问时间 \leq t \}$$

其中 $\Delta$ 是窗口大小（时间窗口）。

**工作集模型的核心思想**：
- 如果内存中分配的页框数 < 工作集大小 → 产生大量缺页 → 抖动
- 如果内存中分配的页框数 ≥ 工作集大小 + 开销 → 缺页率低 → 正常运行

> ⭐ **选择题考点**：工作集模型用于避免**抖动**问题，通过监控进程的工作集大小来动态分配页框。

#### 2. 抖动（Thrashing）

> **抖动（Thrashing）**：当进程频繁发生缺页中断，CPU花费在页面置换上的时间多于执行进程的时间时，系统处于抖动状态。

**抖动的成因**：
1. 内存中分配的页框数不足（小于工作集大小）
2. 多道程序度太高，内存紧张
3. 页面置换算法不合理

**抖动的检测与消除**：
1. **检测**：监控缺页率，如果缺页率异常升高则可能存在抖动
2. **消除**：降低多道程序度（挂起部分进程），增加物理内存

> ⭐ **选择题高频考点**：
> 1. 抖动时系统表现为：缺页率急剧升高，CPU利用率急剧下降
> 2. 解决抖动的方法：**降低多道程序度**（减少并发进程数）
> 3. 抖动不是"Cache抖动"，而是虚拟内存中的页面抖动

#### 3. 驻留集（Resident Set）分配

驻留集是分配给一个进程的页框集合。

**静态分配**：
- 固定分配：每个进程分得固定数量的页框
- 可变分配：页框数按比例分配

$$进程i的页框数 = 总页框数 \times \frac{进程i需要的页框数}{\sum 所有进程需要的页框数}$$

**动态分配**：
- 根据进程的工作集大小动态调整页框数
- 使用工作集模型进行页框分配

### 五、虚拟内存的硬件支持

| 硬件 | 作用 |
|------|------|
| **页表寄存器（PTR）** | 存放页表的起始地址和长度 |
| **MMU（内存管理单元）** | 完成虚拟地址到物理地址的转换 |
| **TLB（快表）** | 缓存页表项，加速地址转换 |
| **页尺寸寄存器** | 定义页/帧的大小 |

> 从CSAPP视角看，现代处理器（如Intel x86-64）使用四级页表来支持512GB的虚拟地址空间（48位地址）。TLB有ITLB（指令TLB）和DTLB（数据TLB）两个独立的TLB。

## ⚖️易混淆概念对比

### 请求分页 vs 请求分段

| 对比项 | 请求分页 | 请求分段 |
|--------|---------|---------|
| 单位 | 页面（固定大小） | 段（可变大小） |
| 面向 | 机器（物理单位） | 用户（逻辑单位） |
| 外部碎片 | 无 | 有 |
| 页面共享 | 较难实现（按页共享） | 容易实现（按段共享） |
| 动态增长 | 困难 | 容易 |
| 缺页/缺段触发 | 缺页中断 | 缺段中断 |

### 工作集 vs 抖动

| 对比项 | 工作集 | 抖动 |
|--------|--------|------|
| 定义 | 进程近期频繁访问的页面集合 | 频繁缺页导致性能急剧下降 |
| 性质 | 正常现象（进程特性） | 异常现象（系统问题） |
| 关系 | 页框数 < 工作集 → 导致抖动 | 抖动时缺页率远高于正常水平 |
| 关联文档 | 本页面 | [[页面置换算法]] |

### 缺页中断 vs 一般中断

| 对比项 | 缺页中断 | 一般中断（I/O） |
|--------|---------|----------------|
| 来源 | MMU（内存管理） | 外设（I/O设备） |
| 是否可屏蔽 | 不可屏蔽 | 可屏蔽 |
| 指令恢复 | 重新执行被中断指令 | 继续执行下一条指令 |
| 处理速度 | 慢（涉及磁盘I/O） | 较快（不涉及磁盘） |
| 触发条件 | 访问不在内存的页面 | 外设完成操作或需要服务 |

## ⚠️考试高频坑点

### 坑点1：缺页中断的重新执行 ⭐

> 【考试考法】缺页中断处理后，被中断的指令会重新执行（因为该指令尚未完成）。
> 这是一道经典选择题陷阱：一般中断（如I/O中断）处理后继续执行下一条指令，而缺页中断处理后**重新执行被中断的指令**。

### 坑点2：EAT计算中的多重重访 ⭐

> 【考试考法】有TLB时：
> - 命中TLB：访问1次内存（访问数据）
> - 未命中TLB但页面在内存：访问2次内存（查页表+访问数据）
> - 缺页：访问多次（查页表+调入页面+访问数据）+ 磁盘I/O开销
>
> 典型陷阱：忽略TLB未命中时仍需查页表。

### 坑点3：抖动与多道程序度的关系 ⭐

> 【教材原文】抖动是由于分配给进程的页框数不足导致的。
>
> 【考试考法】解决抖动的方法：**降低多道程序度**（减少并发进程数），让每个进程获得更多页框。
> 错误做法：增加多道程序度、提高页面置换频率。

### 坑点4：修改位的作用 ⭐

> 【考试考法】修改位为1的页面换出时，需要**写回外存**（增加了I/O开销）。修改位为0的页面可以直接丢弃（无需写回）。
> 置换算法应优先选择修改位为0的页面（无修改的页面），以减少写回开销。

### 坑点5：页大小的权衡 ⭐

> 【考试考法】页大小越大：
> - 页表变大（占用更多内存）
> - 内部碎片平均增加
> - TLB命中率降低
> - 缺页中断更频繁
>
> 页大小越小：
> - 内部碎片平均减少
> - 页表变小
> - TLB命中率提高
> - 缺页中断更频繁
