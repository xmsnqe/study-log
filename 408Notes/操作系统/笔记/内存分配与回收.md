# 内存分配与回收

## 📍知识定位

### 在408体系中的位置

内存分配与回收是内存管理的核心子模块，研究操作系统如何为进程分配内存空间，以及进程终止后如何回收内存。它既涉及**连续分配方式**下的具体分配算法，也涉及**非连续分配方式**下的空闲区管理，是408考试中**选择题**的重点考察区域。

### 学习前置条件

- **内存管理**：理解逻辑地址与物理地址、连续分配与非连续分配的基本概念
- **数据结构基础**：链表的基本操作（用于空闲分区链表的插入与删除）
- **计算机组成原理**：理解存储器的层次结构和地址映射

### 学完之后支撑的知识点

- **虚拟内存**：在内存分配的基础上实现请求装入机制
- **页面置换算法**：在虚拟内存框架下处理缺页中断
- **存储碎片整理**：紧凑（拼接）技术

### 跨教材视角

| 教材 | 视角特点 | 侧重点 |
|------|---------|--------|
| CSAPP 第3版 | 从虚拟地址空间的实现看分配 | 堆管理、slab分配、虚拟内存的底层实现 |

> ⭐ **选择题高频考点**：四种动态分区分配算法（FF、BF、WF、NF）的优缺点比较；回收内存时的分区合并情况；固定分区中的内部碎片概念。

## 📝核心概念与原理

### 一、空闲分区的表示与管理

#### 1. 空闲分区链表

操作系统通过**空闲分区表（Free Partition Table）**或**空闲分区链（Free Partition List）**来记录内存中的空闲区域。

**空闲分区表**：每个表项记录一个空闲分区的起始地址和大小。

```
空闲分区表：
┌──────┬──────────┬──────────┐
│ 分区号 │ 起始地址  │ 分区大小  │
├──────┼──────────┼──────────┤
│   0  │  0x0000  │   200KB  │
│   1  │  0x5000  │   100KB  │
│   2  │  0x8000  │   300KB  │
│   3  │  0xD000  │   150KB  │
└──────┴──────────┴──────────┘
```

**空闲分区链**：用链表组织空闲分区，每个结点记录起始地址、大小和指向下一个结点的指针。

> 空闲分区链更适合动态插入和删除操作，是实现分配算法的基础数据结构。

#### 2. 空闲分区的组织方式

| 组织方式 | 说明 | 适用算法 |
|---------|------|---------|
| **按地址递增排列** | 空闲分区按地址从小到大排列 | 首次适应（FF）、邻近适应（NF） |
| **按大小递增排列** | 空闲分区按大小从小到大排列 | 最佳适应（BF） |
| **按大小递减排列** | 空闲分区按大小从大到小排列 | 最差适应（WF） |

### 二、动态分区分配算法 🔥

当进程需要装入内存时，系统从空闲分区中挑选一个足够大的分区分配给它。以下是四种经典算法：

#### 算法一：首次适应算法（First Fit, FF）⭐

**核心思想**：从空闲链首开始查找，找到第一个大小满足要求的空闲分区。

```
分配过程：
从链首 → 扫描空闲分区链
  → 找到第一个大小 ≥ 需要的空闲分区
  → 从中划分出所需大小的空间分配给进程
  → 剩余部分仍留在空闲链中
```

**回收时的合并**（⭐高频）：

```
回收一个分区时，可能与以下四种情况之一合并：

情况1：前有空闲区 → 与前一个空闲区合并
情况2：后有空闲区 → 与后一个空闲区合并
情况3：前后都有空闲区 → 与前后两个合并为一个
情况4：前后都是已分配分区 → 独立成一个空闲分区
```

> ⭐ **选择题高频考点**：
> 1. FF算法回收内存时，如果**前面**有相邻空闲区，需要合并，并将起始地址改为前面空闲区的地址
> 2. FF算法倾向于**保留大分区**在高地址区域（因为总是从低地址开始查找）
> 3. FF算法导致**低地址部分产生许多小碎片**

#### 算法二：最佳适应算法（Best Fit, BF）⭐

**核心思想**：从空闲分区中选择一个大小最接近（刚好满足或略大于）所需大小的分区。

```
分配过程：
扫描全部空闲分区
  → 找到大小 ≥ 需要 且 差值最小 的分区
  → 分配后剩余部分最小（碎片最小）
```

**回收时的合并**：与FF算法相同，需检查前后是否有相邻空闲分区。

> ⭐ **选择题高频考点**：
> 1. BF算法**产生的碎片最多且最难利用**——每次分配都切出极小的碎片
> 2. BF算法**可能保留很大的分区**，但这些大分区很快被后续的小碎片"污染"
> 3. 实际应用中BF算法**效果最差**

#### 算法三：最差适应算法（Worst Fit, WF）⭐

**核心思想**：从空闲分区中选择一个最大的分区分配给进程。

```
分配过程：
扫描全部空闲分区
  → 找到最大的空闲分区
  → 从中划分出所需大小的空间
  → 剩余部分仍然较大，可能仍能满足后续请求
```

**回收时的合并**：与FF算法相同。

> ⭐ **选择题高频考点**：
> 1. WF算法**每次选最大分区**，因此大分区很快被耗尽
> 2. 剩余空间仍然较大，可能满足后续大请求
> 3. WF算法在进程大小相近时效果较好

#### 算法四：邻近适应算法（Next Fit, NF）⭐

**核心思想**：从上次查找的位置（指针位置）开始查找，保证每次分配都从上次中断处开始。

```
分配过程：
从上次分配的分区位置开始 → 向后查找
  → 找到第一个满足条件的空闲分区
  → 如果到了链尾仍未找到，从头继续查找
```

> 从CSAPP视角看，NF算法类似一个循环扫描器，保证内存分配更加均匀。

**回收时的合并**：与FF算法相同。

#### 四种算法综合对比

| 对比项 | FF（首次适应） | BF（最佳适应） | WF（最差适应） | NF（邻近适应） |
|--------|---------------|---------------|---------------|---------------|
| 查找方式 | 从头开始，找第一个满足的 | 扫描全部，找最接近的 | 扫描全部，找最大的 | 从上次位置开始 |
| 空闲分区排列 | 按地址 | 按大小递增 | 按大小递减 | 按地址 |
| 优点 | 保留大分区，查找快 | 碎片小 | 减少小碎片 | 分配均匀 |
| 缺点 | 低地址产生小碎片 | 产生大量小碎片 | 大分区快速耗尽 | 可能破坏局部性 |
| 内存利用率 | 中等 | 较差 | 较差 | 中等 |
| 查找速度 | 快 | 慢（需扫描全部） | 慢（需扫描全部） | 中等 |

> ⭐ **选择题结论性记忆**：
> - 平均情况下，**FF算法效果最好**（查找快，保留大分区）
> - **BF算法效果最差**（产生大量极小碎片，难以利用）
> - **WF算法在大进程密集场景**可能比BF表现好
> - **NF算法适用于进程大小均匀**的场景

### 三、固定分区分配

#### 1. 分配策略

固定分区分配在系统初始化时将内存划分为若干个固定大小的分区，分区大小可以相等或不等。

**分区大小相等的优点和缺点**：

| 优点 | 缺点 |
|------|------|
| 管理简单，实现容易 | 内部碎片多（大分区中的空闲部分浪费） |
| 适合进程大小相近的场景 | 小进程无法利用大分区 |

**分区大小不等的优点和缺点**：

| 优点 | 缺点 |
|------|------|
| 内部碎片较少 | 管理复杂，需要记录每个分区的大小 |
| 可以灵活适应不同大小的进程 | 可能出现某些分区始终无法满足进程 |

#### 2. 内部碎片

> **内部碎片（Internal Fragment）**：进程实际使用的空间小于分配的分区大小，剩余空间在分区内无法被其他进程使用。

**计算方法**：
$$内部碎片 = 分区大小 - 进程实际需要的空间$$

> ⭐ **选择题考点**：内部碎片是固定分区分配的特有问题，与外部碎片（动态分区分配的问题）是不同的概念。

### 四、非连续分配方式的内存管理

#### 1. 分页存储管理的空闲区管理

在分页存储管理中，内存被划分为固定大小的页框（Frame），每个页框可以是"已分配"或"空闲"状态。

**空闲页框的管理**：
- **位图（Bit Map）**：用一个bit表示一个页框是否空闲
  - 0 → 空闲；1 → 已分配
  - 适合小内存（位图大小 = 内存总页框数 / 8 字节）
- **空闲链表（Free List）**：将空闲页框链接成一个链表
  - 适合大内存（避免位图过大占用内存）
- **空闲块表/链**：记录连续空闲页框的起始地址和数量

```
位图示例（8个页框）：
页框号：  0  1  2  3  4  5  6  7
位图值：  0  1  0  0  1  1  0  0

页框0、2、3、6、7为空闲；页框1、4、5为已分配
```

#### 2. 分段存储管理的空闲区管理

分段存储管理中，每个段可以分散存放在不同的内存区域。

```
分段分配：
进程A的段表：
  段0（代码段）→ 页框 [5, 6, 7]  （3个页框连续）
  段1（数据段）→ 页框 [12, 15]    （非连续）
  段2（栈段）  → 页框 [3, 4]      （2个页框连续）
```

#### 3. 伙伴系统（Buddy System）⭐

伙伴系统是**分页**存储管理中的一种高效的空闲内存管理算法，广泛用于 Linux 内核的 slab 分配器。

**核心思想**：
- 内存块的大小只允许取 $2^k$（k = 0, 1, 2, ...）
- 一个大小为 $2^k$ 的内存块，如果分割，则分成两个大小为 $2^{k-1}$ 的"伙伴块"
- 两个相邻的大小相同的空闲块可以合并成一个更大的块

```
伙伴系统的分配过程：

1. 进程申请 7 个页框
2. 系统找到最小的 2^k ≥ 7 的块，即 2^3 = 8 个页框
3. 分配 8 个页框，浪费 1 个页框（内部碎片）

伙伴系统的回收过程：

1. 释放一个 2^k 的块
2. 检查其"伙伴"是否空闲
3. 如果伙伴空闲 → 合并为 2^(k+1) 的块
4. 如果伙伴不空闲 → 保持 2^k 的块
5. 递归检查上级伙伴，直到无法合并
```

> 从CSAPP视角看，伙伴系统通过**按2的幂次分配**简化了内存管理的复杂度和碎片问题。

| 特点 | 说明 |
|------|------|
| 优点 | 回收时合并效率高；查找空闲块速度快 |
| 缺点 | 存在内部碎片（分配2^k，可能浪费）；k 不能太大 |
| 内部碎片率 | 平均不超过 50% |

> ⭐ **选择题考点**：伙伴系统中，一个 64KB 的块分割为 2KB 块，需要分割 4 次（64→32→16→8→2，共 4 次分割，得到 32 个 2KB 块）。

### 五、内存回收与拼接（紧凑）技术

#### 1. 内存回收的四种情况

当一个进程终止或释放内存时，系统回收其占用的分区。回收时需要检查与相邻空闲区的合并关系：

| 情况 | 条件 | 操作 |
|------|------|------|
| **情况1：前有闲** | 回收分区的前一个分区是空闲的 | 与前一个空闲区合并，修改前一个分区的大小 |
| **情况2：后有闲** | 回收分区的后一个分区是空闲的 | 与后一个空闲区合并，修改起始地址为回收分区地址 |
| **情况3：前后都有闲** | 回收分区的前后都是空闲区 | 三个合并为一个，修改前一个分区的大小 |
| **情况4：无空闲邻居** | 回收分区的前后都是已分配分区 | 新建一个空闲分区表项 |

```
情况3示例（合并前）：
[空闲区A] [已分配分区] [空闲区B]
回收已分配分区后：
[空闲区A（扩展后合并三个）]
```

#### 2. 拼接（紧凑）技术

> **拼接（Compaction）**：当内存中存在大量外部碎片时，操作系统将进程在内存中"移动"到一个连续的区域，将所有碎片集中到内存的一端，从而形成一个大的连续空闲区。

**拼接的工作原理**：

```
拼接前：
[进程A][碎片][进程B][碎片][进程C][碎片]

拼接过程：
1. 进程A移至起始地址（不动）
2. 进程B紧跟A
3. 进程C紧跟B

拼接后：
[进程A][进程B][进程C][大碎片]
```

**拼接的代价**：
1. 需要移动大量进程数据（I/O操作）
2. 需要更新所有相关寄存器（基址寄存器、页表等）
3. 拼接期间无法执行进程

> ⭐ **选择题考点**：拼接是解决**外部碎片**的最后手段，代价很高（需要移动数据和更新地址），不应频繁使用。分页/分段等非连续分配方式可以从根本上减少外部碎片。

### 六、堆（Heap）管理

#### 1. 堆的基本概念

从CSAPP的视角看，堆（Heap）是进程地址空间中用于**动态内存分配**的区域。通过 `malloc()` / `free()` 系统库函数进行分配和释放。

```
进程地址空间布局（32位系统）：
┌─────────────┐  ← 高地址
│    栈段      │  向下增长
├─────────────┤
│     堆       │  向上增长
├─────────────┤
│   未映射区域  │
├─────────────┤
│   数据段      │
├─────────────┤
│   BSS段      │
├─────────────┤
│   代码段      │  ← 低地址
└─────────────┘
```

#### 2. 堆分配算法

堆管理与内存分配算法类似，也使用 FF、BF 等算法管理空闲堆块。

| 策略 | 说明 |
|------|------|
| **First Fit** | 找到第一个足够大的空闲堆块 |
| **Best Fit** | 找到最接近需求大小的空闲堆块 |
| **Separate Free Lists** | 按大小建立多个空闲链表 |
| ** segregated Storage** | 将空闲链表按大小范围分组 |

> 现代操作系统的堆管理非常复杂，涉及内存池、缓存对齐等优化。408考试主要关注基本的分配算法。

## ⚖️易混淆概念对比

### 内部碎片 vs 外部碎片

| 对比项 | 内部碎片 | 外部碎片 |
|--------|---------|---------|
| 定义 | 分区内部未被使用的空间 | 分区间未被使用的空间 |
| 产生原因 | 分区大小 > 进程实际使用大小 | 内存分配不均，碎片化严重 |
| 出现在 | 固定分区分配、伙伴系统 | 动态分区分配 |
| 解决方案 | 分区大小与进程大小匹配；伙伴系统的内部碎片可控 | 拼接（Compaction）；分页/分段消除外部碎片 |
| 严重程度 | 较低（可控） | 较高（可能导致"有碎片但无法分配"） |

### 首次适应 vs 最佳适应 vs 最差适应

| 对比项 | 首次适应（FF） | 最佳适应（BF） | 最差适应（WF） |
|--------|---------------|---------------|---------------|
| 查找策略 | 找到第一个满足的即可 | 扫描全部，找最接近的 | 扫描全部，找最大的 |
| 空闲区排列 | 地址递增 | 大小递增 | 大小递减 |
| 查找速度 | 快 | 慢 | 慢 |
| 碎片特征 | 低地址小碎片多 | 极小碎片多且难利用 | 大分区快速耗尽 |
| 综合效果 | 最好（平衡） | 最差 | 中等偏下 |

### 固定分区 vs 动态分区

| 对比项 | 固定分区分配 | 动态分区分配 |
|--------|------------|------------|
| 分区大小 | 系统初始化时确定，固定不变 | 根据进程大小动态创建 |
| 内部碎片 | 有 | 无 |
| 外部碎片 | 无 | 有 |
| 内存利用率 | 较低 | 较高 |
| 管理复杂度 | 简单 | 复杂 |
| 多道程序程度 | 受限 | 较好 |

## ⚠️考试高频坑点

### 坑点1：首次适应算法回收时的合并规则 ⭐

> 【考试考法】回收一个分区时，如果前面有空闲区，必须修改前面空闲区的**大小**（加上回收分区的大小），但起始地址不变。
>
> 如果前后都有空闲区，三个合并为一个，起始地址取前面的，大小为三者之和。

### 坑点2：伙伴系统的分割次数

> 【考试考法】申请 N 个页框，需要找到最小的 $2^k \geq N$，然后从更大的块分割到 $2^k$。
> 分割次数 = $\lceil \log_2 N \rceil$（如果从 $2^k$ 分割），或者 = $k_{start} - k_{final}$。

### 坑点3：最佳适应算法的致命缺陷

> 【考试考法】BF 算法"看似"最优（每次只切最小碎片），但实际上产生的碎片**总量最大且最难利用**，是实际中最不推荐的算法。

### 坑点4：页大小对内外碎片的影响

> 【考试考法】页大小越大 → 内部碎片平均增加（最后一页的剩余空间增大），外部碎片减少；页大小越小 → 内部碎片平均减少，外部碎片增加。
>
> 对于固定分区：分区大小越大 → 内部碎片越多。

### 坑点5：拼接的代价

> 【教材原文】拼接需要移动大量数据和更新地址寄存器，代价极高。
>
> 【考试考法】拼接是解决外部碎片的**最后手段**，不应频繁使用。现代操作系统通过虚拟内存（分页）从根本上减少外部碎片。
