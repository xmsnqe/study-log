# 同步与互斥

## 📍知识定位

### 在408体系中的位置

同步与互斥是操作系统并发管理的核心问题，用于解决多个进程/线程竞争共享资源时产生的竞态条件（Race Condition）。它是408考试中**大题出现频率最高**的章节之一，几乎每年必考。

### 学习前置条件

- **进程管理**：理解进程状态、PCB、进程通信
- **数据结构基础**：队列（用于等待进程的组织）

### 学完之后支撑的知识点

- 死锁：同步互斥是死锁产生的必要条件
- 进程调度：调度算法需要考虑进程状态
- 经典进程同步问题：生产者-消费者、读者-写者、哲学家进餐

## 📝核心概念与原理

### 一、临界资源与临界区

#### 1. 临界资源（Critical Resource）

> **临界资源**是指一次仅允许一个进程使用的共享资源。如打印机、共享变量、共享缓冲区等。

#### 2. 临界区（Critical Section）

> **临界区**是指进程中访问临界资源的那段代码。每个进程进入临界区访问临界资源之前，必须先进行申请，获得许可后方可进入。

#### 3. 进入区与退出区

一个临界区的完整结构：

```
进入区（Entry Section）：
    检查能否进入临界区
    如能进入，则设置"正在进入"标志

临界区（Critical Section）：
    访问临界资源的代码

退出区（Exit Section）：
    清除"正在进入"标志

剩余区（Remainder Section）：
    不访问临界资源的代码
```

#### 4. 互斥与同步的区别 ⭐

| 概念 | 定义 | 关系 | 示例 |
|------|------|------|------|
| **互斥（Mutual Exclusion）** | 多个进程不能同时进入临界区 | 互斥是一种同步的特例 | 多个进程竞争打印机 |
| **同步（Synchronization）** | 多个进程为完成共同任务，执行某种顺序 | 同步协调进程间执行顺序 | 生产者→消费者 |

> **关键理解**：所有互斥关系都是同步关系，但并非所有同步关系都是互斥关系。互斥强调"不能同时做"，同步强调"必须按顺序做"。

### 二、临界区的进入原则（四条件） ⭐

进程在进入临界区时必须遵循以下四个条件：

1. **空闲让进**：临界区空闲时，任何请求进入的进程应立即进入
2. **忙则等待**：已有进程进入临界区，其他进程必须等待
3. **有限等待**：对要求进入临界区的进程，应保证在有限时间内进入（避免饥饿）
4. **让权等待**：进程不能进入临界区时，必须立即释放处理机（不能采用"忙等待"）

> ⭐ **选择题考点**：以上四个条件缺一不可。违反条件3会导致**饥饿**；违反条件4会导致**忙等待**（效率低下）。

### 三、信号量机制

#### 1. 信号量的定义

> **信号量（Semaphore）**是一个整型变量S，除初始化外，仅能通过两个标准原子操作Wait（P）和Signal（V）来访问。

```
P(S):  // 等待/申请资源
    while (S <= 0) {
        // 将进程插入等待队列
        // 阻塞该进程
        // 切换进程
    }
    S--;

V(S):  // 信号/释放资源
    S++;
    if (S <= 0) {
        // 从等待队列中唤醒一个进程
        // 将该进程插入就绪队列
    }
```

#### 2. 整型信号量 vs 记录型信号量

**整型信号量**（Dijkstra原始定义）：

```
P(S):
    while S <= 0 do no-op;
    S := S - 1;

V(S):
    S := S + 1;
```

> 问题：忙等待（busy waiting），浪费CPU。

**记录型信号量**（改进版本，考试常用）：

```
typedef struct {
    int value;              // 信号量值
    struct process *queue;  // 等待队列指针
} semaphore;

P(semaphore *S) {
    S->value--;
    if (S->value < 0) {
        // 将当前进程插入等待队列
        block(S->queue);    // 阻塞进程
    }
}

V(semaphore *S) {
    S->value++;
    if (S->value <= 0) {
        // 从等待队列中唤醒一个进程
        wakeup(S->queue);   // 唤醒进程
    }
}
```

> ⭐ **选择题高频考点**：
> - 信号量S的值≥0：表示可用资源数
> - 信号量S的值<0：|S|表示等待队列中的进程数
> - P操作：申请资源，S-1
> - V操作：释放资源，S+1

#### 3. 信号量的物理含义 ⭐

| S值范围 | 物理含义 |
|---------|---------|
| S > 0 | 可用资源数 = S |
| S = 0 | 无可用资源，无等待进程 |
| S < 0 | 可用资源为0，|S|个进程在等待队列中 |

> 【考试考法】给定初始值和PV操作序列，计算最终S值和等待进程数。
> 例：S初始=5，执行3次P、2次V，S = 5-3+2 = 4（表示4个可用资源）。

#### 4. 信号量的分类

| 类型 | 初始值 | 用途 | 示例 |
|------|--------|------|------|
| **互斥信号量** | 1 | 实现互斥访问 | 保护共享变量 |
| **同步信号量** | 0 | 实现同步顺序 | 生产者-消费者中的缓冲区满/空 |
| **资源信号量** | ≥0 | 表示可用资源数 | 可用打印机数 |

### 四、AND信号量机制（Sentry机制）

> 当进程需要同时申请多个资源时，AND信号量机制确保要么全部分配成功，要么一个也不分配，避免死锁。

```
Swait(S1, S2, ..., Sn)：  // 同时申请多个资源
    检查所有Si，若所有Si > 0，则全部减1
    若有某个Si <= 0，则一个也不分配

Ssignal(S1, S2, ..., Sn)：  // 同时释放多个资源
    将所有Si加1
```

### 五、经典进程同步问题（大题重点） 🔥

#### 问题一：生产者-消费者问题

**问题描述**：
一组生产者进程和一组消费者进程共享一个初始为空、大小为n的缓冲区。
- 生产者：只往缓冲区放产品
- 消费者：只从缓冲区取产品
- 要求：互斥访问缓冲区；缓冲区满时生产者等待；缓冲区空时消费者等待

**解法**：

```
信号量设置：
    mutex = 1        // 互斥信号量，保护缓冲区访问
    empty = n        // 同步信号量，表示空缓冲区的数量
    full = 0         // 同步信号量，表示满缓冲区的数量

生产者进程：
    do {
        生产一个产品;
        P(empty);       // 申请一个空缓冲区
        P(mutex);       // 进入临界区
            将产品放入缓冲区;
        V(mutex);       // 退出临界区
        V(full);        // 增加一个满缓冲区
    } while (true);

消费者进程：
    do {
        P(full);        // 申请一个满缓冲区
        P(mutex);       // 进入临界区
            从缓冲区取走产品;
        V(mutex);       // 退出临界区
        V(empty);       // 增加一个空缓冲区
        消费产品;
    } while (true);
```

> ⭐ **选择题考点**：
> 1. 三个信号量的含义和初值
> 2. P(empty)必须在P(mutex)之前（避免死锁）
> 3. V操作在退出临界区后执行
> 4. P操作必须成对出现（进入和退出临界区）

> **关键思考**：为什么P(empty)和P(mutex)的顺序不能互换？
> 如果P(mutex)在前：生产者先获得互斥锁，再等待空缓冲区，此时消费者无法进入（因为生产者持有了互斥锁），如果缓冲区已满，生产者一直等待，导致**死锁**。

#### 问题二：读者-写者问题

**问题描述**：
一个数据文件可被多个进程共享。
- 读者：只读文件，不写
- 写者：只写文件，不读
- 要求：写者与写者互斥；读者与写者互斥；读者与读者不互斥（允许多个读者同时读）

**解法（读者优先）**：

```
信号量设置：
    mutex = 1        // 保护read_count的互斥
    wrt = 1          // 写者互斥信号量
    read_count = 0   // 读者计数（初始为0）

读者进程：
    do {
        P(mutex);            // 进入临界区，保护read_count
            read_count++;
            if (read_count == 1)
                P(wrt);      // 第一个读者负责阻止写者
        V(mutex);
        
        读文件;
        
        P(mutex);            // 再次进入临界区
            read_count--;
            if (read_count == 0)
                V(wrt);      // 最后一个读者负责释放写者
        V(mutex);
    } while (true);

写者进程：
    do {
        P(wrt);              // 申请写权限
            写文件;
        V(wrt);              // 释放写权限
    } while (true);
```

> ⭐ **选择题考点**：
> 1. read_count = 0时，最后一个离开的读者释放wrt
> 2. read_count = 1时，第一个进入的读者获取wrt
> 3. 多个读者可以同时读（因为read_count > 1时不再需要获取wrt）
> 4. 写者与任何读者互斥

> **注意**：读者优先方案可能导致写者饥饿。另一种解法是"写者优先"，在第一个读者到达时就阻塞后续读者。

#### 问题三：哲学家进餐问题

**问题描述**：
5个哲学家围坐一张圆桌，每人面前有一碗饭，每两人之间有一根筷子。
- 哲学家：吃饭 → 思考 → 吃饭 → ...
- 条件：先拿起左筷子，再拿起右筷子；吃完放下两根筷子

**解法一（简单但可能死锁）**：

```
定义信号量：
    chopstick[5] = {1, 1, 1, 1, 1};  // 每根筷子一个信号量

哲学家i（i=0,1,2,3,4）：
    do {
        P(chopstick[i]);           // 拿起左筷子
        P(chopstick[(i+1)%5]);     // 拿起右筷子
        吃饭;
        V(chopstick[i]);           // 放下左筷子
        V(chopstick[(i+1)%5]);     // 放下右筷子
        思考;
    } while (true);
```

> 问题：如果5个哲学家同时拿起左筷子，就都等待右筷子，形成**循环等待** → 死锁。

**解法二（防止死锁）**：

```
// 方法1：最多允许4个哲学家同时就坐
limit = 4;           // 最多4个哲学家同时尝试获取筷子

// 方法2：奇数号先左后右，偶数号先右后左
if (i % 2 == 0) {    // 偶数号哲学家：先右后左
    P(chopstick[(i+1)%5]);
    P(chopstick[i]);
} else {              // 奇数号哲学家：先左后右
    P(chopstick[i]);
    P(chopstick[(i+1)%5]);
}
吃饭;

// 释放（顺序不影响）
V(chopstick[i]);
V(chopstick[(i+1)%5]);
```

> ⭐ **大题考点**：
> 1. 死锁产生的四个必要条件（见死锁章节）
> 2. 至少需要几个哲学家才能发生死锁？答案：5个同时尝试
> 3. 防止死锁的方法（破坏至少一个必要条件）

### 六、实现互斥的底层机制（CSAPP视角） 🔥

#### 1. TestAndSet指令

```
boolean TestAndSet(boolean *target) {
    boolean rv = *target;
    *target = true;
    return rv;
}
```

> 这是一个**原子操作**，硬件保证在单处理器或多处理器环境下不被打断。

**用TestAndSet实现互斥**：

```
boolean lock = false;

while (TestAndSet(&lock));  // 自旋等待，直到lock变为false（即返回true）
// 临界区...
lock = false;               // 释放锁
```

#### 2. Swap指令

```
void Swap(boolean *a, boolean *b) {
    boolean temp = *a;
    *a = *b;
    *b = temp;
}
```

**用Swap实现互斥**：

```
boolean lock = false;
boolean key = false;

while (true) {
    key = true;
    Swap(&lock, &key);  // 原子交换
    if (!key) break;    // 如果交换后key为false，说明lock原本为false，获得锁
}
// 临界区...
lock = false;  // 释放锁
```

> ⭐ **选择题考点**：TestAndSet和Swap都是硬件提供的原子指令，用于实现用户态的自旋锁。

### 七、管程（Monitor）机制

> **管程（Monitor）**是一种更高级的同步机制，将共享变量、操作这些变量的过程和同步机制封装在一个模块中。

**管程的特点**：
1. 局部变量（共享数据）仅能被管程内的过程访问
2. 进程只能通过调用管程内的过程进入临界区
3. 一次仅允许一个进程在管程内执行

**条件变量**：

```
condition x, y;  // 声明条件变量

x.wait();         // 等待条件，释放管程并阻塞
x.signal();       // 唤醒一个等待的进程
x.broadcast();    // 唤醒所有等待的进程
```

> 管程是Java、C#等语言中synchronized关键字和wait()/notify()方法的理论基础。

## ⚖️易混淆概念对比

### 互斥 vs 同步

| 对比项 | 互斥 | 同步 |
|--------|------|------|
| 目的 | 防止同时访问共享资源 | 协调进程执行顺序 |
| 关系 | 同步的一种特例 | 涵盖互斥 |
| 关注点 | "不能同时做" | "必须按顺序做" |
| 信号量初值 | 通常为1（互斥信号量） | 通常为0（同步信号量） |
| 示例 | 打印机访问 | 生产者→消费者 |

### P操作 vs V操作

| 操作 | 含义 | 对S的影响 | 效果 |
|------|------|----------|------|
| P(S) | 申请资源 | S = S - 1 | 资源-1，S<0时阻塞 |
| V(S) | 释放资源 | S = S + 1 | 资源+1，S≤0时唤醒 |

### 记录型信号量 vs 整型信号量

| 对比项 | 整型信号量 | 记录型信号量 |
|--------|-----------|-------------|
| 等待方式 | 忙等待（while循环） | 阻塞等待（插入等待队列） |
| 效率 | 低（浪费CPU） | 高（不占CPU） |
| 进程管理 | 不涉及进程排队 | 有等待队列 |
| 考试频率 | 了解即可 | 必考 |

## ⚠️考试高频坑点

### 坑点1：PV操作的顺序不能颠倒 ⭐

> 【考试考法】生产者-消费者问题中，P(empty)和P(mutex)的顺序。
> 正确顺序：先P(empty)（申请资源），再P(mutex)（进入临界区）。
> 如果颠倒：先P(mutex)，再P(empty)，当缓冲区满时，生产者持有mutex等待empty，消费者因持有mutex无法消费，**死锁**。

### 坑点2：信号量的初值设置 ⭐

> 【教材原文】互斥信号量初值=1（一次只允许一个进程进入临界区）。
> 同步信号量初值=0（初始无资源，需要等待）。
>
> 【考试考法】给定一个场景，要求判断应该使用几个信号量，每个信号量的初值是多少。

### 坑点3：最后一个读者/第一个读者的特殊处理 ⭐

> 【考试考法】读者-写者问题中，为什么第一个读者需要P(wrt)？最后一个读者需要V(wrt)？
> 答：read_count=1表示第一个读者到达，需要阻止后续写者；read_count=0表示最后一个读者离开，需要释放写者。

### 坑点4：PV操作必须成对出现

> 【考试考法】每执行一次P操作，必须有一个对应的V操作。如果P操作多于V操作，最终所有进程都会阻塞。

### 坑点5：信号量值为负数时的含义 ⭐

> 【教材原文】S<0时，|S|表示等待队列中的进程数。
>
> 【考试考法】给出PV操作序列，求最终S值。如S=3，执行4次P、2次V：S = 3-4+2 = 1。
