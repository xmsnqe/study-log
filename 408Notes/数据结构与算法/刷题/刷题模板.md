## 📝核心概念与解题范式

### 一、408 数据结构大题通用解题步骤

在 408 考研中，数据结构大题（算法设计题）通常要求手写伪代码或 C 代码。以下是严蔚敏教材风格的标准解题范式：

#### Step 1：审题与数据结构选择

- 明确题目要求的**输入**是什么（线性表？二叉树？图？哈希表？）
- 明确题目要求的**输出**是什么（排序结果？查找位置？最短路径？）
- 根据数据特征选择最合适的存储结构：
  - 频繁随机访问 → 顺序存储
  - 频繁插入删除 → 链式存储
  - 需要高效查找 → 哈希表 / 二叉排序树
  - 需要层次遍历 → 树 / 图 + 队列

#### Step 2：算法思路描述（必须先写思路再写代码）

在大题答题中，**必须先写算法思路**，再写代码。思路描述应包含：

```
算法思路：
1. 利用 [某种数据结构/策略]，...
2. 遍历 [数据结构]，对每个元素执行 [操作]，...
3. 最终返回 [结果]。
时间复杂度：O(?)；空间复杂度：O(?)。
```

> 🔥 **大题评分要点**：思路描述占 30%–40% 的分数，仅写代码可能无法获得满分。

#### Step 3：C 语言风格代码实现（严蔚敏 ADT 规范）

**函数签名模板：**

```c
// 函数名：清晰描述功能（中文注释）
// 输入：参数说明
// 输出：返回值说明
// 时间复杂度：O(?)；空间复杂度：O(?)
Status 算法名称(数据结构类型 *L, 其他参数) {
    // 1. 边界条件处理
    if (L == NULL || L->length == 0) return ERROR;

    // 2. 核心逻辑
    // ...

    // 3. 返回结果
    return OK;
}
```

**数据结构定义模板：**

```c
#define OK 1
#define ERROR 0
#define MAXSIZE 100

typedef int Status;
typedef int KeyType;

typedef struct {
    KeyType key;
    // ... 其他数据域
} ElemType;

typedef struct {
    ElemType r[MAXSIZE + 1];  // r[0] 用作哨兵或临时变量
    int length;
} SqList;
```

> ⚠️ **注意事项**：
> - 严蔚敏教材中，顺序表的 `r[0]` 通常用作哨兵或临时变量，数据从 `r[1]` 开始存储
> - 函数参数使用指针时，必须使用 `*`（值传递修改）或 `&`（地址传递）
> - 不得使用 C++ STL 库（如 `vector`、`sort`、`priority_queue` 等），考研中要求手写实现

#### Step 4：复杂度分析（必须写明）

- **时间复杂度**：说明主要操作（比较/交换/移动）的次数推导
- **空间复杂度**：说明额外使用的辅助空间（如临时数组、递归栈）

#### Step 5：边界与特殊情况验证

```
验证：
- 空表（length = 0）
- 单元素表（length = 1）
- 已有序 / 逆序
- 所有元素相同
- 最大规模（测试超时）
```

### 二、选择题解题套路

| 题型 | 解题套路 |
|------|----------|
| 复杂度求取 | 找基本操作 → 计数 → 取最高阶 → 写大O |
| 稳定性判断 | 直接比较元素相同时相对位置是否改变 |
| 原地排序判断 | 是否仅需 O(1) 额外空间 |
| 时间复杂度比较 | 熟记排序算法复杂度表，直接查表比较 |
| 查找 ASL 计算 | 按定义逐层计数，注意成功/不成功的区别 |
| 树/图的性质 | 画树/图辅助分析，利用公式（如 n = n0 + n2 + 1） |
| ADT 操作分析 | 结合存储结构分析操作的时空复杂度 |

---

### 三、易错题型归类

| 题型 | 典型陷阱 | 应对策略 |
|------|----------|----------|
| 排序过程题 | 不记中间过程，只写结果 | 按步骤画出每一趟的结果 |
| 堆排序建堆 | 从根开始建堆（错误） | 从 ⌊n/2⌋ 开始自底向上 |
| 快排划分 | pivot 选择不当导致 O(n²) | 注意三数取中等优化策略 |
| 折半查找判定树 | 叶子层数判断错误 | 从下往上逐层构建判定树 |
| 图的最小生成树 | Kruskal 判环错误 | 用并查集跟踪连通分量 |
| 哈希 ASL | 成功与不成功混淆 | 成功按关键字数平均，不成功按桶数平均 |
| 递归复杂度 | 忽略递归栈空间 | 递归深度 × 每层空间 = 空间复杂度 |

## ⚠️考试高频坑点（刷题层面）

### 坑点1：大题只写代码不写思路

- **阅卷规则**：思路描述占 30%–40% 分数
- **正确做法**：先写 2–3 行思路概述，再写代码
- **模板**：`本算法采用 [策略名]，核心思路是...`

### 坑点2：边界条件处理遗漏

- **常见遗漏**：空表判断、单元素判断、全相等判断
- **正确做法**：在函数开头统一添加边界条件检查
- **得分保障**：即使核心逻辑有误，正确处理边界条件也能获得部分分数

### 坑点3：未写复杂度分析

- **阅卷要求**：算法大题必须标注时间复杂度和空间复杂度
- **正确做法**：在代码末尾或函数注释中明确写出
- **示例**：`// 时间复杂度：O(n log n)；空间复杂度：O(log n)`

### 坑点4：使用 STL 库函数

- **考试禁令**：408 考研要求手写实现，不得使用 `std::sort`、`std::priority_queue` 等
- **正确做法**：手写排序（快速排序等）、手写优先队列（堆实现等）

### 坑点5：递归算法未写终止条件

- **严重错误**：递归函数缺少正确的基准情况（base case）会导致无限递归
- **正确做法**：每个递归函数必须明确写出基准情况和递归步骤
