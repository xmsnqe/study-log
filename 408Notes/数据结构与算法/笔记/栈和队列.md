## ### 📝核心概念与原理

### 一、栈的定义和特点

#### 1. 栈的定义

**栈（Stack）**是限定仅在**表尾**进行插入和删除操作的**线性表**。

- 栈也被称为 **后进先出（LIFO, Last In First Out）** 线性表
- 允许插入和删除的一端称为 **栈顶（Top）**
- 另一端称为 **栈底（Bottom）**
- 不含任何数据元素的栈称为 **空栈**

> 从逻辑结构看，栈是线性表的特例（操作受限），因此线性表的存储结构同样适用于栈。

#### 2. 栈的特点

**LIFO 原则**：最后进入栈的元素最先被取出。

- 类比：一摞盘子——只能在顶部放盘子和取盘子
- 类比：子弹夹——最后压入的子弹最先打出

#### 3. 栈的抽象数据类型（ADT）

```
ADT Stack {
    数据对象：D = {ai | ai ∈ ElemType, i = 1, 2, ..., n, n ≥ 0}
    数据关系：R1 = {<ai-1, ai> | ai-1, ai ∈ D, i = 2, ..., n}
              // 含n个元素的序列，相邻元素间存在次序关系

    基本操作：
        InitStack(&S);           // 构造空栈
        DestroyStack(&S);        // 销毁栈
        ClearStack(&S);          // 将栈清空
        StackEmpty(S);           // 判断栈是否为空
        GetTop(S, &e);           // 取栈顶元素
        Push(&S, e);             // 入栈（插入）
        Pop(&S, &e);             // 出栈（删除）
        StackLength(S);          // 求栈长度
} ADT Stack
```

### 二、栈的表示和实现

#### 1. 顺序栈——用顺序表实现栈

##### （1）结构定义

```c
typedef struct {
    ElemType *elem;    // 存储空间基地址
    int top;           // 栈顶指针（指向栈顶元素所在位置）
    int stacksize;     // 当前分配的存储空间（以元素为单位）
} SqStack;
```

**关键约定说明**（严蔚敏教材采用 top 指向栈顶元素本身）：

- 初始状态（空栈）：`top == -1`，表示无元素
- `top == stacksize - 1`：栈满
- `top == -1`：栈空

> **注意**：另一种常见约定是 `top` 指向**栈顶元素的下一个位置**，此时空栈为 `top == 0`，栈满为 `top == stacksize`。两种方式本质等价，考研以严蔚敏教材约定（`top` 指向栈顶元素）为准。

##### （2）基本操作的算法描述

**① 初始化栈 InitStack**

```c
Status InitStack(SqStack &S) {
    S.elem = new ElemType[MAXSIZE];  // 分配存储空间
    if (!S.elem) exit(OVERFLOW);     // 存储分配失败
    S.top = -1;                       // 栈顶指针置为 -1（空栈）
    S.stacksize = MAXSIZE;            // 初始化栈容量
    return OK;
}
```

**② 入栈 Push_Sq**

```c
Status Push_Sq(SqStack &S, ElemType e) {
    if (S.top == S.stacksize - 1)         // 栈满
        return ERROR;                     // 栈满处理
    S.top++;                              // 栈顶指针+1
    S.elem[S.top] = e;                    // 新元素入栈
    return OK;
}
// 时间复杂度：O(1) ⭐
```

**口诀：先加一再存入。**

**③ 出栈 Pop_Sq**

```c
Status Pop_Sq(SqStack &S, ElemType &e) {
    if (S.top == -1)                      // 栈空
        return ERROR;                     // 栈空处理
    e = S.elem[S.top];                    // 取栈顶元素
    S.top--;                              // 栈顶指针-1
    return OK;
}
// 时间复杂度：O(1) ⭐
```

**口诀：先取再减一。**

##### （3）顺序栈操作的时间复杂度

| 操作 | 时间复杂度 |
|------|-----------|
| 初始化 InitStack | O(1) |
| 入栈 Push | **O(1)** ⭐ |
| 出栈 Pop | **O(1)** ⭐ |
| 取栈顶 GetTop | O(1) |
| 判断栈空 | O(1) |
| 求栈长度 | O(1) |

> 顺序栈所有基本操作的时间复杂度均为 **O(1)**，这是408高频考点。

#### 2. 共享栈

##### （1）设计思想

**两个栈共享同一块连续的存储空间**，两个栈底分别设在存储空间的两端，栈顶指针**相向增长**。

- 栈1：从空间左端向右增长，栈顶指针 `top1` 初始为 -1
- 栈2：从空间右端向左增长，栈顶指针 `top2` 初始为 `stacksize`

##### （2）结构定义

```c
typedef struct {
    ElemType *elem;    // 存储空间基地址
    int top1;          // 栈1的栈顶指针，初始为 -1
    int top2;          // 栈2的栈顶指针，初始为 stacksize
    int stacksize;     // 存储空间大小
} SharedStack;
```

##### （3）栈满条件 ⭐

```
栈满条件：top1 + 1 == top2
```

> 共享栈的优势：只有当两个栈加起来占满整个空间时才真正栈满，比两个独立栈更省空间。

##### （4）共享栈的入栈/出栈

```c
// 栈1入栈
Status Push1(SharedStack &S, ElemType e) {
    if (S.top1 + 1 == S.top2) return ERROR;  // 栈满
    S.elem[++S.top1] = e;                     // top1先加，再存
    return OK;
}

// 栈2入栈
Status Push2(SharedStack &S, ElemType e) {
    if (S.top1 + 1 == S.top2) return ERROR;  // 栈满
    S.elem[--S.top2] = e;                     // top2先减，再存
    return OK;
}
```

所有操作时间复杂度均为 **O(1)**。

#### 3. 链栈——用链表实现栈

##### （1）结构定义

链栈采用单链表实现，**链表的头指针即为栈顶指针**。

```c
typedef struct StackNode {
    ElemType data;
    struct StackNode *next;
} StackNode, *LinkStack;

LinkStack top;  // 栈顶指针，指向链栈的第一个结点（也是栈顶元素）
```

> 链栈不需要定义栈底指针，因为所有操作都在链表头部进行。

##### （2）入栈 Push

```c
Status Push(LinkStack &top, ElemType e) {
    StackNode *s = new StackNode;     // 创建新结点
    s->data = e;                       // 存入数据
    s->next = top;                     // 新结点指向原栈顶
    top = s;                           // 更新栈顶指针
    return OK;
}
// 时间复杂度：O(1) ⭐
```

**口诀：新结点插入链表头部。**

##### （3）出栈 Pop

```c
Status Pop(LinkStack &top, ElemType &e) {
    if (top == NULL) return ERROR;     // 栈空
    StackNode *p = top;                // 暂存栈顶结点
    e = p->data;                        // 取出数据
    top = top->next;                    // 栈顶指针后移
    delete p;                           // 释放原栈顶结点
    return OK;
}
// 时间复杂度：O(1) ⭐
```

**口诀：取走首结点，更新头指针。**

##### （4）链栈的特点

| 对比项 | 顺序栈 | 链栈 |
|--------|--------|------|
| 存储方式 | 连续内存 | 链式指针 |
| 栈顶位置 | 数组尾部 | 链表头部 |
| 栈满判断 | `top == stacksize - 1` | 无需判断（除非内存耗尽） |
| 空间利用 | 预先分配，可能浪费或不足 | 动态分配，按需分配 |
| 时间复杂度 | 所有操作 O(1) | 所有操作 O(1) |

> **链栈不存在栈满情况**（除非内存耗尽），这是链栈的重要特征。

#### 4. 栈与递归

##### （1）递归的机器实现

- 递归函数在**系统栈**中运行，每次递归调用将**返回地址、局部变量、参数**压栈
- 递归终止条件（基线条件）对应**出栈**操作
- 递归深度最大为栈的最大容量

##### （2）递归与栈的转换

任何递归都可以转换为等价的**非递归形式**，方法是使用显式栈模拟系统栈：

```
递归过程 → 系统栈压栈（保存现场）→ 深入递归 → 到达基线条件 → 出栈（恢复现场）→ 返回上一层
```

> 递归算法的时间复杂度和空间复杂度通常与递归深度相关。408考试可能要求分析递归算法的空间复杂度（即栈的最大深度）。

### 三、栈的应用（重点应用）🔥

#### 1. 数制转换

将十进制数 N 转换为 r 进制数。

**算法思想**：**除 r 取余法**

- 将 N 与 r 相除，得到商和余数
- 余数即为转换结果的一位
- 用商继续相除，直到商为 0
- 所有余数**逆序排列**即为结果（后进先出）

```c
// 例：将十进制数 1348 转换为八进制数
// 1348 / 8 = 168 余 4
//  168 / 8 =  21 余 0
//   21 / 8 =   2 余 5
//    2 / 8 =   0 余 2
// 所以 (1348)10 = (2504)8
// 余数依次为 4, 0, 5, 2，逆序后为 2504
```

时间复杂度：O(log_r N)，每次操作 O(1)。

#### 2. 括号匹配检验

**问题描述**：假设表达式中只包含三种括号：圆括号 `()`、方括号 `[]`、花括号 `{}`，检验表达式中的括号是否正确配对。

**算法思想**（栈的应用）

1. 初始化一个空栈
2. 从左到右扫描表达式中的每个字符
3. 遇到**左括号**（`(`、`[`、`{`）→ 入栈
4. 遇到**右括号**（`)`、`]`、`}`）：
   - 栈空 → 匹配失败（右括号多）
   - 栈顶左括号与当前右括号不匹配 → 匹配失败
   - 匹配 → 栈顶左括号出栈
5. 扫描结束后，栈空 → 匹配成功；栈不空 → 匹配失败（左括号多）

```c
Status CheckBrackets(char *expr) {
    SqStack S;
    InitStack(S);
    for (int i = 0; expr[i] != '\0'; i++) {
        if (expr[i] == '(' || expr[i] == '[' || expr[i] == '{') {
            Push_Sq(S, expr[i]);         // 左括号入栈
        } else if (expr[i] == ')' || expr[i] == ']' || expr[i] == '}') {
            if (StackEmpty(S)) return ERROR;  // 右括号多
            char topElem;
            Pop_Sq(S, topElem);
            if (!Match(topElem, expr[i]))   // 括号不匹配
                return ERROR;
        }
    }
    return StackEmpty(S) ? OK : ERROR;     // 栈空则匹配
}
```

时间复杂度：O(n)，空间复杂度：O(n)（最坏情况所有都是左括号）。

#### 3. 表达式求值（⭐🔥 重中之重）

这是栈在408考试中最重要的应用，要求熟练掌握。

##### （1）表达式的基本概念

- **算符**（Operator）：包括运算符（`+`、`-`、`*`、`/`、`^` 等）和界限符（`(`、`)`、`#` 等）
- **优先关系**：算符之间具有预定义的优先级
- **表达式**：由操作数和运算符按一定规则组合而成

##### （2）运算符优先关系（优先矩阵）

严蔚敏教材中定义的算符优先关系为 **三关系**：`<`（小于）、`=`（等于）、`>`（大于）

以 `+`、`-`、`*`、`/`、`(`、`)`、`#` 为例，优先矩阵如下：

| 运算符 | `+` | `-` | `*` | `/` | `(` | `)` | `#` |
|--------|-----|-----|-----|-----|-----|-----|-----|
| `+` | `>` | `>` | `<` | `<` | `<` | `>` | `>` |
| `-` | `>` | `>` | `<` | `<` | `<` | `>` | `>` |
| `*` | `>` | `>` | `>` | `>` | `<` | `>` | `>` |
| `/` | `>` | `>` | `>` | `>` | `<` | `>` | `>` |
| `(` | `<` | `<` | `<` | `<` | `<` | `=` | ? |
| `)` | `>` | `>` | `>` | `>` | ? | `>` | `>` |
| `#` | `<` | `<` | `<` | `<` | `<` | ? | `=` |

- `θ1 < θ2`：`θ1` 优先级低于 `θ2`，应**先处理** `θ2`
- `θ1 = θ2`：优先级相等（仅 `(` 与 `)` 之间），表示括号匹配
- `θ1 > θ2`：`θ1` 优先级高于 `θ2`，应**先处理** `θ1`

##### （3）双栈法核心算法 🔥

设两个栈：
- **OPTR**（运算符栈）：存放运算符
- **OPND**（操作数栈）：存放操作数

**算法步骤**：

```c
Status EvaluateExpression(char *expr) {
    SqStack OPTR, OPND;
    InitStack(OPTR); Push_Sq(OPTR, '#');   // 运算符栈底放'#'作为表达式结束标志
    InitStack(OPND);
    
    char theta, a, b, x;
    char c = GetNextChar(expr, pos);       // 读取第一个字符
    
    while (c != '#' || GetTop(OPTR) != '#') {  // 表达式未处理完或运算符栈非空
        if (!InOp(c)) {                     // c 是操作数
            Push_Sq(OPND, c);               // 操作数进操作数栈
            c = GetNextChar(expr, pos);     // 读下一个字符
        } else {                            // c 是运算符
            switch (Precede(GetTop(OPTR), c)) {
                case '<':                   // 栈顶运算符优先级低
                    Push_Sq(OPTR, c);       // 当前运算符进栈
                    c = GetNextChar(expr, pos);
                    break;
                case '=':                   // 括号匹配
                    Pop_Sq(OPTR, x);        // 弹出 '('
                    c = GetNextChar(expr, pos);
                    break;
                case '>':                   // 栈顶运算符优先级高
                    Pop_Sq(OPTR, theta);    // 弹出运算符
                    Pop_Sq(OPND, b);        // 弹出操作数b
                    Pop_Sq(OPND, a);        // 弹出操作数a
                    Push_Sq(OPND, Operate(a, theta, b));  // 运算并结果入栈
                    break;
            }
        }
    }
    
    ElemType result;
    Pop_Sq(OPND, result);                   // 最终结果
    return OK;
}
```

**算法流程图解**：

```
步骤1：初始化 OPTR 栈底放入 '#'
步骤2：读取字符，分两种情况：
  ├─ 是操作数 → 直接压入 OPND 栈
  └─ 是运算符 → 与 OPTR 栈顶比较优先级：
       ├─ '<'（栈顶优先级低） → 当前运算符压入 OPTR
       ├─ '='（括号匹配）     → 弹出栈顶 '('，继续
       └─ '>'（栈顶优先级高） → 从 OPND 弹出两个操作数，
                               从 OPTR 弹出一个运算符，
                               执行运算，结果压回 OPND
步骤3：重复步骤2，直到两个栈都为空（以'#'为结束标志）
步骤4：OPND 栈顶即为最终结果
```

##### （4）示例演示

以表达式 `2 + 3 * 5 - 1` 为例：

| 步骤 | 当前字符 | OPTR（运算符栈） | OPND（操作数栈） | 操作 |
|------|---------|-----------------|-----------------|------|
| 初始 | - | `#` | （空） | 初始化 |
| 1 | `2` | `#` | `2` | 操作数入OPND |
| 2 | `+` | `#` | `2` | `+` 优先级高于 `#`，入OPTR |
| 3 | `3` | `# +` | `2 3` | 操作数入OPND |
| 4 | `*` | `# + *` | `2 3` | `*` 优先级高于 `+`，入OPTR |
| 5 | `5` | `# + *` | `2 3 5` | 操作数入OPND |
| 6 | `-` | `# +` | `2 15` | `*` 优先级高于 `-`，先算 `3*5=15`；`+` 优先级高于 `-`，入OPTR |
| 7 | `1` | `# +` | `2 15 1` | 操作数入OPND |
| 8 | `#` | `#` | `16` | `+` 优先级高于 `#`，算 `2+15=17`；`# = #`，结束 |

最终结果：16 ✅

##### （5）表达式求值的关键规则

> 1. 操作数和运算符交替入栈
> 2. 比较栈顶运算符与当前字符的优先级
> 3. 栈顶优先级高 → 先运算；低 → 继续入栈
> 4. `#` 作为表达式的开始和结束标志，位于 OPTR 栈底

时间复杂度：**O(n)**，其中 n 为表达式长度。

#### 4. 栈在函数调用中的应用

- 每次函数调用时，系统会将**返回地址、实参、局部变量**压入系统栈
- 函数返回时，系统从栈中恢复这些信息并弹出
- 递归调用的本质就是函数自身的反复压栈和出栈

> 这也是为什么递归可能导致栈溢出的原因——递归深度过大，系统栈被撑满。

---

#### 5. 栈在递归中的应用

- 递归的定义依赖函数自身，而函数调用靠系统栈支持
- 递归的终止条件（基线条件）对应栈的**出栈**操作
- 递归的递推关系对应栈的**压栈**操作

**递归转非递归的方法**：显式使用栈模拟系统栈的行为。

### 四、队列的定义和特点

#### 1. 队列的定义

**队列（Queue）**是只允许在**表尾（队尾 Rear）**进行插入操作、在**表头（队头 Front）**进行删除操作的**线性表**。

- 插入操作称为 **入队（EnQueue）**
- 删除操作称为 **出队（DeQueue）**
- 队列是 **先进先出（FIFO, First In First Out）** 线性表

> 类比：排队打饭——先排的人先打饭

#### 2. 队列的特点

**FIFO 原则**：先进入的元素先被取出。

- 插入端 = 队尾（rear），只能插入
- 删除端 = 队头（front），只能删除

#### 3. 队列的抽象数据类型（ADT）

```
ADT Queue {
    数据对象：D = {ai | ai ∈ ElemType, i = 1, 2, ..., n, n ≥ 0}
    数据关系：R1 = {<ai-1, ai> | ai-1, ai ∈ D, i = 2, ..., n}

    基本操作：
        InitQueue(&Q);             // 初始化队列
        DestroyQueue(&Q);          // 销毁队列
        ClearQueue(&Q);            // 清空队列
        QueueEmpty(Q);             // 判断队列是否为空
        GetHead(Q, &e);            // 取队头元素（不删除）
        EnQueue(&Q, e);            // 入队（插入）
        DeQueue(&Q, &e);           // 出队（删除）
        QueueLength(Q);            // 求队列长度
} ADT Queue
```

### 五、队列的表示和实现

#### 1. 顺序队列及其假溢出问题

##### （1）顺序队列的基本结构

```c
typedef struct {
    ElemType *elem;    // 存储空间基地址
    int front;         // 队头指针，指向队头元素
    int rear;          // 队尾指针，指向队尾元素的下一个位置
    int queuesize;     // 队列最大容量
} SqQueue;
```

> 约定：`rear` 指向**队尾元素的下一个位置**（即下一个入队元素将存放的位置）。

##### （2）基本操作（不循环）

```c
// 入队
Status EnQueue(SqQueue &Q, ElemType e) {
    if (Q.rear == Q.queuesize) return ERROR;  // 队满
    Q.elem[Q.rear++] = e;                      // 在队尾插入，rear后移
    return OK;
}

// 出队
Status DeQueue(SqQueue &Q, ElemType &e) {
    if (Q.front == Q.rear) return ERROR;  // 队空
    e = Q.elem[Q.front++];                 // 取出队头，front后移
    return OK;
}
```

##### （3）假溢出问题 ⭐

```
入队 a, b, c → rear = 3, front = 0
出队 a, b, c → front = 3, rear = 3

此时：front == rear 表示队空，但数组前面还有空闲空间！
这就是"假溢出"——逻辑上空了，但 rear 已经到达数组末尾。
```

- **假溢出**：由于 `front` 和 `rear` 只增不减，导致队空时数组前部空间浪费
- **解决思路**：将顺序队列改造为**循环队列**

---

#### 2. 循环队列（⭐🔥 必考）

##### （1）核心思想

将顺序队列存储空间**看作一个环**，用**取模运算**实现指针的循环移动。

##### （2）结构定义

```c
typedef struct {
    ElemType *elem;      // 存储空间基地址
    int front;           // 队头指针，指向队头元素
    int rear;            // 队尾指针，指向队尾元素的下一个位置
    int queuesize;       // 队列最大容量
} SqQueue;
```

##### （3）初始化

```c
Status InitQueue(SqQueue &Q) {
    Q.elem = new ElemType[MAX_QUEUE_SIZE];
    if (!Q.elem) exit(OVERFLOW);
    Q.front = 0;
    Q.rear = 0;           // 初始状态：队头 == 队尾（空）
    Q.queuesize = MAX_QUEUE_SIZE;
    return OK;
}
```

##### （4）入队 EnQueue_Sq ⭐

```c
Status EnQueue_Sq(SqQueue &Q, ElemType e) {
    if ((Q.rear + 1) % Q.queuesize == Q.front)  // 队满判断
        return ERROR;
    Q.elem[Q.rear] = e;                          // 存入元素
    Q.rear = (Q.rear + 1) % Q.queuesize;         // 队尾指针后移（循环）
    return OK;
}
// 时间复杂度：O(1) ⭐
```

##### （5）出队 DeQueue_Sq ⭐

```c
Status DeQueue_Sq(SqQueue &Q, ElemType &e) {
    if (Q.front == Q.rear)                        // 队空判断
        return ERROR;
    e = Q.elem[Q.front];                           // 取出队头元素
    Q.front = (Q.front + 1) % Q.queuesize;         // 队头指针后移（循环）
    return OK;
}
// 时间复杂度：O(1) ⭐
```

##### （6）队列长度计算公式 ⭐

```
队列长度 = (rear - front + queuesize) % queuesize
```

> 为什么要加 `queuesize` 再取模？因为 `rear` 可能小于 `front`（循环后），直接相减会得到负数。

##### （7）队满与队空的判断 ⭐🔥

| 状态 | 判断条件 | 说明 |
|------|---------|------|
| 队空 | `front == rear` | 初始状态或所有元素已出队 |
| 队满 | `(rear + 1) % queuesize == front` | **牺牲一个存储单元** |

> **关键理解：为什么要牺牲一个存储单元？**
>
> 如果不用此约定，队满和队空的判断条件都是 `front == rear`，无法区分。所以牺牲一个存储单元，使得队满时 `front ≠ rear`，从而区分两种状态。
>
> 实际可容纳的最大元素个数为 `queuesize - 1`。

##### （8）示例演示

设 `queuesize = 5`，初始 `front = rear = 0`：

| 操作 | front | rear | 队列状态 | 说明 |
|------|-------|------|---------|------|
| 初始 | 0 | 0 | （空） | |
| 入 a | 0 | 1 | a _ _ _ _ | rear → 1 |
| 入 b | 0 | 2 | a b _ _ _ | rear → 2 |
| 入 c | 0 | 3 | a b c _ _ | rear → 3 |
| 出 a | 1 | 3 | _ b c _ _ | front → 1 |
| 入 d | 1 | 4 | b c _ _ d | rear → 4 |
| 入 e | 1 | 0 | b c _ _ d | rear → 0，(4+1)%5=0，队满！ |

此时队列中实际有 3 个元素（b、c、d），但 rear 已到达 0，由于 `(0+1)%5 ≠ 1` 不成立，即 `(rear+1)%queuesize == front` 成立，判定为**队满**。

#### 3. 链队——用链表实现队列

##### （1）结构定义（带头结点的链队）

```c
typedef struct QNode {
    ElemType data;
    struct QNode *next;
} QNode, *QueuePtr;

typedef struct {
    QueuePtr front;     // 队头指针，指向头结点
    QueuePtr rear;      // 队尾指针，指向队尾结点
} LinkQueue;
```

> 链队需要**同时维护 front 和 rear 两个指针**：
> - `front`：指向**头结点**（不存数据），`front->next` 指向第一个实际元素
> - `rear`：指向**最后一个结点**，便于在队尾插入

##### （2）入队 EnQueue ⭐

```c
Status EnQueue(LinkQueue &Q, ElemType e) {
    QNode *s = new QNode;     // 创建新结点
    s->data = e;
    s->next = NULL;
    Q.rear->next = s;         // 新结点链接到队尾
    Q.rear = s;               // 更新队尾指针
    return OK;
}
// 时间复杂度：O(1) ⭐
```

##### （3）出队 DeQueue ⭐

```c
Status DeQueue(LinkQueue &Q, ElemType &e) {
    if (Q.front == Q.rear) return ERROR;  // 队空
    QNode *p = Q.front->next;              // 指向第一个实际结点
    e = p->data;                           // 取出数据
    Q.front->next = p->next;               // 跳过结点p
    if (Q.rear == p) {                     // 如果p是最后一个结点
        Q.rear = Q.front;                  // 出队后队空，rear指回头结点
    }
    delete p;                              // 释放结点p
    return OK;
}
// 时间复杂度：O(1) ⭐
```

> **特殊情况处理**：当队列中只有**一个元素**时出队，`rear` 需要指回 `front`（即变为空队列）。

##### （4）链队的特点

| 对比项 | 循环队列 | 链队 |
|--------|---------|------|
| 存储方式 | 顺序存储（数组） | 链式存储（链表） |
| 空间利用 | 固定大小，牺牲一个单元 | 动态分配，无浪费 |
| 队满判断 | `(rear+1)%size == front` | 无需判断（除非内存耗尽） |
| 队空判断 | `front == rear` | `front == rear` |
| 入队时间 | **O(1)** | **O(1)** |
| 出队时间 | **O(1)** | **O(1)** |
| 实现复杂度 | 需处理取模运算 | 需处理指针操作 |

> 链队不需要预先设定队列长度，不存在"队满"（除内存不足外），但增加了结点开销和指针操作复杂度。

### 六、双端队列与优先级队列（了解）

#### 1. 双端队列（Deque, Double-Ended Queue）

**定义**：两端都可以进行**入队和出队**操作的队列。

- 允许在队头和队尾**同时**进行插入和删除操作
- 是队列的推广
- 双端队列可以模拟栈（仅在一端操作）和队列（两端各一个方向操作）

```
ADT Deque {
    基本操作：
        InitDeque(&D);           // 初始化双端队列
        InsertFront(&D, e);      // 在队头插入
        InsertRear(&D, e);       // 在队尾插入
        DeleteFront(&D, &e);     // 从队头删除
        DeleteRear(&D, &e);      // 从队尾删除
        DequeEmpty(D);           // 判断是否为空
        GetFront(D, &e);         // 取队头元素
        GetRear(D, &e);          // 取队尾元素
}
```

> **应用**：某些算法（如回文检测）中需要同时从两端取数据。

---

#### 2. 优先级队列

**定义**：以优先级为序的队列，每次出队的是优先级最高的元素（而非队头元素）。

- 优先级队列可以用**有序链表**或**堆（Priority Queue via Heap）**实现
- 堆实现时，插入和删除的时间复杂度为 O(log n)
- 是操作系统进程调度的重要数据结构

> 优先级队列与栈（LIFO）和队列（FIFO）并列，体现了数据结构的不同排序方式。

## ### ⚖️易混淆概念对比

### 1. 栈 vs 队列

| 对比维度 | 栈（Stack） | 队列（Queue） |
|---------|-----------|-------------|
| 数据访问顺序 | LIFO（后进先出） | FIFO（先进先出） |
| 插入位置 | 栈顶（表尾） | 队尾 |
| 删除位置 | 栈顶（表尾） | 队头 |
| 顺序存储 | 需 top 一个指针 | 需 front 和 rear 两个指针 |
| 栈满/队满判断 | top 与 stacksize 比较 | rear 与 front 关系（牺牲一单元） |
| 典型应用 | 递归、表达式求值、括号匹配 | 广度优先搜索(BFS)、缓冲调度 |

### 2. 顺序栈 vs 链栈

| 维度 | 顺序栈 | 链栈 |
|------|--------|------|
| 存储密度 | 高（无指针域） | 低（每个结点有指针域） |
| 栈满 | 可能 | 几乎不可能（除非内存耗尽） |
| 空间分配 | 静态（预先分配） | 动态（逐个分配） |
| 空间浪费 | 可能浪费或不足 | 无浪费，但有结点开销 |
| 适用场景 | 栈大小已知或可预估 | 栈大小难以预估 |

### 3. 循环队列 vs 链队

| 维度 | 循环队列 | 链队 |
|------|---------|------|
| 空间利用率 | 牺牲一单元，利用率 (n-1)/n | 完全利用，但每结点有额外开销 |
| 入队/出队时间 | O(1)（取模运算） | O(1)（指针操作） |
| 灵活性 | 大小固定，扩容需重新分配 | 动态扩展 |
| 实现难度 | 需要理解取模循环 | 需要处理指针 |

### 4. 队空与队满的本质区别 🔥

这是408最经典的辨析题：

- 对于循环队列，**队空**和**队满**时都满足 `front == rear`
- 因此必须**牺牲一个存储单元**来区分两者：
  - 队空：`front == rear`（队列中实际有 0 个元素）
  - 队满：`(rear + 1) % queuesize == front`（队列中实际有 queuesize - 1 个元素）

> **另一种区分方法**：设置一个计数器 `count`，记录队列中的元素个数。
> - 队空：`count == 0`
> - 队满：`count == queuesize`
> 但这种方法增加了额外的空间开销。

## ### ⚠️考试高频坑点

### 坑点 1：顺序栈的 top 指针约定

- 严蔚敏教材：`top` 指向**栈顶元素**，空栈 `top == -1`
- 另一种常见约定：`top` 指向**栈顶元素的下一个位置**，空栈 `top == 0`
- **考研答题必须明确说明自己采用的约定方式**
- 两种约定的入栈/出栈操作顺序不同，务必对应

### 坑点 2：循环队列的"牺牲一单元"

- 队满条件为 `(rear + 1) % queuesize == front`，而非 `rear == queuesize - 1`
- 实际最大容量为 `queuesize - 1`，不是 `queuesize`
- 队列长度公式：`(rear - front + queuesize) % queuesize`
- **不要漏掉 `+ queuesize`**，否则 `rear < front` 时会得到负数

### 坑点 3：共享栈的栈满条件

- 共享栈的栈满条件为 `top1 + 1 == top2`
- 不是 `top1 == top2`，也不是 `top1 < top2`
- 共享栈的优势是**两个栈互补空间使用**，比两个独立栈更高效

### 坑点 4：链队的特殊情况处理

- 链队出队时，如果队列中**只有唯一一个元素**，出队后需要 `rear = front`（指向头结点）
- 否则 `rear` 会悬挂在已删除的结点上，造成内存泄漏或后续入队错误

### 坑点 5：表达式求值的运算符比较方向

- 比较的是 **OPTR 栈顶运算符**与**当前读取的字符（运算符）**
- `<`：栈顶优先级低 → 当前运算符入栈（`Push(OPTR, c)`）
- `=`：括号匹配 → 弹出栈顶左括号
- `>`：栈顶优先级高 → 从 OPND 弹两个操作数、从 OPTR 弹一个运算符，执行运算
- **方向不可颠倒**，否则算法完全错误

### 坑点 6：递归的深度与栈空间

- 递归的时间复杂度通常由递归深度决定
- 递归的空间复杂度 = 最大递归深度（系统栈的栈深）
- 尾递归可以优化为 O(1) 空间，但 408考试默认不优化

### 坑点 7：顺序栈 vs 链栈的选择

- 考研中如果**栈的大小可以预估**，优先选择顺序栈（存储密度高、操作简单）
- 如果**栈的大小难以确定或变化很大**，选择链栈

### 坑点 8：时间复杂度陷阱

- 所有栈和队列的**基本操作时间复杂度均为 O(1)**
- 表达式求值的时间复杂度为 **O(n)**（n 为表达式长度）
- 数制转换的时间复杂度为 **O(log_r N)**（N 为待转换的十进制数）
