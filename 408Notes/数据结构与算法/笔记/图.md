# 图（Graph）

## ### 📍知识定位

图（Graph）是**数据结构**中最为重要和复杂的非线性数据结构之一，是408计算机考研的**必考核心考点**。

> **承前启后**：在掌握 [[数据结构与算法/笔记/树与二叉树]] 的基础上，将非线性结构的研究从"一棵树"拓展到"任意多节点相互连接"的一般情形。图是树的推广——树是**无环的连通无向图**。

> **实际意义**：图能够描述极其广泛的关系型问题：社交网络、交通路线、任务依赖、电路连接、通信网络等。图中各节点（顶点）之间可以是**任意关系**，而不仅限于层次或父子关系。

---

## ### 📝核心概念与原理

### 一、图的基本概念

#### 1. 图的定义

> 图 G 由一个**顶点集合**和一个**边集合**组成，记作：

$$G = (V, E)$$

其中：

- $V$（Vertex）是图中**顶点**（也称为节点）的**非空有限集合**，记作 $V = \{v_1, v_2, \ldots, v_n\}$，$n$ 为顶点的个数。
- $E$（Edge）是连接 $V$ 中任意两个顶点的**边（或弧）的有限集合**。当 $E$ 为空时，图中只有顶点，无边。

**注意**：与 [[数据结构与算法/笔记/树与二叉树]] 中的树不同，图的顶点集合可以为空的情况**不允许**，即图中至少有一个顶点。

#### 2. 图的分类

| 类型 | 定义 | 特点 |
|------|------|------|
| **无向图** | 若 $E$ 是**无向边**（undirected edge）的集合，每条边都是顶点的**无序偶** $(u, v)$ | 边 $(u,v)$ 与 $(v,u)$ 是同一条边，用**方括号**表示 |
| **有向图** | 若 $E$ 是**有向边（弧，arc）**的集合，每条边都是顶点的**有序偶** $\langle u, v \rangle$ | 边 $\langle u,v \rangle$ 与 $\langle v,u \rangle$ 是两条不同的边，$u$ 为**弧尾**（起点），$v$ 为**弧头**（终点），用**尖括号**或**箭头**表示 |
| **完全图** | 无向图中，任意两个顶点之间都有一条边，共有 $\frac{n(n-1)}{2}$ 条边 | 有向完全图中，任意两个顶点之间都有方向相反的两条弧，共有 $n(n-1)$ 条弧 |
| **稀疏图 / 稠密图** | 相对概念。一般满足 $e < n \log_2 n$ 的为稀疏图，否则为稠密图 | 无严格定量分界，视存储结构选择而定 |
| **加权图（网）** | 图的每条边上带有一个**权值**（weight），表示某种代价、距离或时间等信息 | 通常记为 $(v_i, v_j)$ 或 $\langle v_i, v_j \rangle$ 且带权 $w$，记作 $G=(V, E, W)$ |

#### 3. 子图

> **子图定义**：设有图 $G = (V, E)$ 和图 $G' = (V', E')$，若 $V' \subseteq V$ 且 $E' \subseteq E$，则称 $G'$ 为 $G$ 的**子图**。

- 若 $V' = V$，则称 $G'$ 为 $G$ 的**生成子图**（spanning subgraph）。
- 一个图可以有多个子图。

#### 4. 顶点的度、入度与出度

- **无向图**中，顶点 $v$ 的**度**（Degree）是与 $v$ 相关联的边的数目，记作 $TD(v)$（Total Degree）。
- **有向图**中，顶点 $v$ 的度分为：
  - **入度**（InDegree, ID(v)）：以 $v$ 为**弧头**的弧的数目。
  - **出度**（OutDegree, OD(v)）：以 $v$ 为**弧尾**的弧的数目。
  - 顶点的总度 $TD(v) = ID(v) + OD(v)$。

> **重要性质**：在有 $n$ 个顶点、$e$ 条边的图 $G$ 中：
> $$\sum_{v \in V} TD(v) = 2e$$
> 即**所有顶点的度之和等于边数的2倍**（无向图）。这一结论常用于选择题判断。

#### 5. 路径、回路

- **路径**（Path）：从顶点 $v_p$ 到顶点 $v_q$ 的**顶点序列**，其中相邻顶点之间存在边（或弧）。路径长度：
  - 对于**非加权图**，路径长度 = 路径上边的**数目**。
  - 对于**加权图**，路径长度 = 路径上各边权值之和。
- **简单路径**：序列中**顶点不重复**的路径。
- **回路（环）**：第一个顶点和最后一个顶点**相同**的路径。
- **简单回路**：除第一个和最后一个顶点外，其余顶点**不重复**的回路。

#### 6. 连通性（⭐）

> **无向图**中的连通性：
> - **连通**：顶点 $v_i$ 和 $v_j$ 之间存在**路径**，则称 $v_i$ 和 $v_j$ **连通**。
> - **连通图**：图中**任意两个顶点都连通**的图。
> - **连通分量**：无向图中的**极大连通子图**（"极大"指包含所有可能的顶点）。
>   - 连通图只有一个连通分量，即其自身。
>   - 非连通图有多个连通分量。
>   - **注意区分**：连通分量强调"极大"——包含所有能连通到的顶点；而连通子图只要求子图内任意两顶点连通。

> **有向图**中的连通性：
> - **强连通图**：有向图中，任意两个顶点 $v_i$ 和 $v_j$ 之间都存在**双向路径**（即 $v_i \to v_j$ 且 $v_j \to v_i$）。
> - **强连通分量**：有向图中的**极大强连通子图**。

#### 7. 生成树与生成森林

- **生成树**：对于一个**有 $n$ 个顶点的连通图**，其生成树是包含图中**全部 $n$ 个顶点**和 **$n-1$ 条边**的**极小连通子图**（也是**树**）。
  - 生成树一定包含所有顶点，且边数最少（$n-1$ 条），不存在回路。
  - 一棵有 $n$ 个顶点的生成树**有且仅有 $n-1$ 条边**。
  - 在生成树中添加任意一条边，必形成一个**回路**。
  - 从生成树中删除任意一条边，图将变为**不连通**。
- **生成森林**：非连通图的每个连通分量的生成树组成的**集合**。

> **选择题高频**：
> - 有 $n$ 个顶点的连通图至少有 $n-1$ 条边。
> - 有 $n$ 个顶点的无向完全图有 $\frac{n(n-1)}{2}$ 条边。
> - 有 $n$ 个顶点的有向完全图有 $n(n-1)$ 条弧。

### 二、图的存储结构（⭐🔥）

图的存储需同时存储**顶点信息**和**边（弧）信息**。常见存储结构有五种。

#### 1. 邻接矩阵（数组表示法）

##### （1）存储结构定义

> 用两个数组来表示图：一个**一维数组**存储顶点信息，一个**二维数组**存储边（或弧）的信息。

```c
#define MAXV 100             // 最大顶点数
#define INFINITY 65535       // 表示无穷大

typedef int InfoType;

// 图的邻接矩阵存储结构
typedef struct {
    int no;                   // 顶点编号
    InfoType info;            // 顶点其他信息
} VertexType;                   // 顶点类型

typedef struct {
    int edges[MAXV][MAXV];    // 邻接矩阵（二维数组）
    int n;                     // 图的当前顶点数
    int e;                     // 图的当前边数
    VertexType vexs[MAXV];     // 存放顶点信息
} MGraph;                       // 图的邻接矩阵类型
```

对于**不带权（非加权）图**：
- 若顶点 $i$ 与顶点 $j$ 之间存在边，则 $A[i][j] = 1$（或 TRUE）；
- 否则 $A[i][j] = 0$（或 FALSE）。
- 其中 $A$ 为**邻接矩阵**，是一个 $n \times n$ 的方阵。

对于**带权图（网）**：
- 若顶点 $i$ 与顶点 $j$ 之间存在边，则 $A[i][j]$ 等于该边的**权值**；
- 若不存在边，则 $A[i][j] = \infty$（或用一个足够大的数表示）。

##### （2）无向图的邻接矩阵

- 无向图的邻接矩阵是**对称矩阵**（即 $A[i][j] = A[j][i]$）。
- 可利用对称性**压缩存储**（只存储上三角或下三角部分）。
- 第 $i$ 行（或第 $i$ 列）的非零元素个数即为顶点 $v_i$ 的**度**。

##### （3）有向图的邻接矩阵

- 有向图的邻接矩阵**不一定对称**。
- 第 $i$ 行的非零元素个数 = 顶点 $v_i$ 的**出度**。
- 第 $i$ 列的非零元素个数 = 顶点 $v_i$ 的**入度**。
- 顶点 $v_i$ 的总度 = 第 $i$ 行非零元素个数 + 第 $i$ 列非零元素个数。

##### （4）算法实现

```c
// 求无向图中顶点 v 的度
int GetDegree_MG(MGraph G, int v) {
    int count = 0;
    for (int j = 0; j < G.n; j++) {
        if (G.edges[v][j] != 0 && G.edges[v][j] != INFINITY) {
            count++;
        }
    }
    return count;
}

// 求有向图中顶点 v 的入度和出度
int GetInDegree_MG(MGraph G, int v) {
    int count = 0;
    for (int i = 0; i < G.n; i++) {
        if (G.edges[i][v] != 0 && G.edges[i][v] != INFINITY) {
            count++;
        }
    }
    return count;
}

int GetOutDegree_MG(MGraph G, int v) {
    int count = 0;
    for (int j = 0; j < G.n; j++) {
        if (G.edges[v][j] != 0 && G.edges[v][j] != INFINITY) {
            count++;
        }
    }
    return count;
}
```

##### （5）时间复杂度与空间分析

| 项目 | 复杂度 |
|------|--------|
| 空间复杂度 | $O(n^2)$ |
| 添加顶点 | $O(1)$ |
| 添加边 | $O(1)$ |
| 判断边是否存在 | $O(1)$ ⭐ |
| 求顶点度（无向图） | $O(n)$ |
| 求顶点度（有向图） | 出度 $O(n)$，入度 $O(n)$ |
| 遍历所有邻接点 | $O(n)$ |

**优点**：
- 判断边是否存在的时间复杂度为 **$O(1)$**，效率极高。
- 求顶点度的操作也较为直接。

**缺点**：
- 空间复杂度为 $O(n^2)$，当图**稀疏**（边数远小于 $n^2$）时，浪费大量存储空间。
- 遍历所有顶点的邻接点需要扫描整行/整列，效率较低。

> **适用场景**：适用于**稠密图**。

#### 2. 邻接表（链式表示法）

##### （1）存储结构定义

> 邻接表是图的一种**链式存储结构**，为图中每个顶点建立一个**单链表**，第 $i$ 个单链表中的结点表示依附于顶点 $v_i$ 的所有边。

```c
#define MAXV 100

typedef int InfoType;

// 边表（邻接表）结点
typedef struct ArcNode {
    int adjvex;                 // 该边所指向的顶点的位置
    InfoType info;              // 该边的相关信息（如权值）
    struct ArcNode *next;       // 指向下一条边的指针
} ArcNode;                      // 边表结点

// 顶点表（头结点）
typedef struct {
    int data;                   // 顶点信息
    ArcNode *first;             // 指向第一条依附该顶点的边（弧）的指针
} VNode;                        // 顶点类型

// 邻接表
typedef struct {
    VNode adjlist[MAXV];        // 邻接表（头结点数组）
    int n;                       // 图的当前顶点数
    int e;                       // 图的当前边数
} AdjGraph;                     // 图的邻接表类型
```

**结构说明**：
- **顶点表**（头结点数组 `adjlist[]`）：存储每个顶点的数据和指向第一个邻接点的指针。
- **边表**（`ArcNode`）：每条边用一个结点表示，包含指向的顶点编号、权值信息和指向下一条边的指针。

##### （2）无向图的邻接表

- 无向图的邻接表是**对称的**。
- 第 $i$ 个链表的结点个数 = 顶点 $v_i$ 的**度**。
- 一条边 $(v_i, v_j)$ 会在 $v_i$ 和 $v_j$ 的边表中**各出现一次**。

##### （3）有向图的邻接表（仅以出边建立）

- 通常只为每个顶点建立**出边链表**（即从该顶点出发的弧）。
- 第 $i$ 个链表的结点个数 = 顶点 $v_i$ 的**出度**。
- **求入度需要遍历整个邻接表**：扫描所有顶点的边表，统计指向该顶点的边数。

> **逆邻接表**：也可以只为每个顶点建立**入边链表**（即指向该顶点的弧）。
> - 第 $i$ 个链表的结点个数 = 顶点 $v_i$ 的**入度**。
> - 出度 = 邻接表链表长度；入度 = 逆邻接表链表长度。

##### （4）算法实现

```c
// 求无向图中顶点 v 的度 = 对应链表的长度
int GetDegree_AG(AdjGraph *G, int v) {
    int count = 0;
    ArcNode *p = G->adjlist[v].first;
    while (p != NULL) {
        count++;
        p = p->next;
    }
    return count;
}

// 求有向图中顶点 v 的出度 = 对应链表的长度
int GetOutDegree_AG(AdjGraph *G, int v) {
    int count = 0;
    ArcNode *p = G->adjlist[v].first;
    while (p != NULL) {
        count++;
        p = p->next;
    }
    return count;
}

// 求有向图中顶点 v 的入度 = 遍历全表，统计指向 v 的边数
int GetInDegree_AG(AdjGraph *G, int v) {
    int count = 0;
    for (int i = 0; i < G->n; i++) {
        ArcNode *p = G->adjlist[i].first;
        while (p != NULL) {
            if (p->adjvex == v) {
                count++;
            }
            p = p->next;
        }
    }
    return count;
}
```

##### （5）时间复杂度与空间分析

| 项目 | 复杂度 |
|------|--------|
| 空间复杂度 | $O(n + e)$（无向图）或 $O(n + 2e)$（含逆邻接表） |
| 添加顶点 | $O(1)$ |
| 添加边 | $O(1)$（头插法） |
| 判断边是否存在 | $O(\text{degree}(v))$ 最坏 $O(n)$ |
| 求顶点度（无向图） | $O(\text{degree})$ |
| 求顶点度（有向图） | 出度 $O(\text{degree})$，入度 $O(n+e)$ |
| 遍历所有邻接点 | $O(\text{degree})$ |

**优点**：
- 空间复杂度为 $O(n + e)$，适合**稀疏图**。
- 增加顶点和边的操作效率高。
- 便于统计顶点的度（无向图直接可得）。

**缺点**：
- 判断两个顶点之间是否存在边需要**遍历链表**，时间复杂度较高。
- 求有向图的入度需要遍历整个邻接表。
- 无向图的邻接表不唯一（取决于边的输入顺序和链表插入位置）。

> **适用场景**：适用于**稀疏图**。

#### 3. 十字链表（有向图的链式存储）

> 十字链表（Orthogonal List）是**有向图**的一种链式存储结构，是邻接表与逆邻接表的**结合**。

```c
// 边表结点
typedef struct ArcBox {
    int tailvex;                // 该弧的尾顶点位置
    int headvex;                // 该弧的头顶点位置
    struct ArcBox *hlink;       // 指向下一个入弧相同（同入边）的指针
    struct ArcBox *tlink;       // 指向下一个出弧相同（同出边）的指针
    InfoType info;              // 该弧的相关信息
} ArcBox;

// 顶点表结点
typedef struct VexNode {
    int data;
    ArcBox *firstin;            // 入边表头指针
    ArcBox *firstout;           // 出边表头指针
} VexNode;

// 十字链表
typedef struct {
    VexNode xlist[MAXV];        // 顶点表
    int n, e;                    // 顶点数和弧数
} OLGraph;
```

- 每个边结点的 `hlink` 指向**入弧**相同（即弧头相同的下一条弧）。
- 每个边结点的 `tlink` 指向**出弧**相同（即弧尾相同的下一条弧）。
- **入度** = 该顶点入边表的链表长度。
- **出度** = 该顶点出边表的链表长度。
- **总度** = 入度 + 出度。

**优点**：兼顾了邻接表和逆邻接表的功能，求入度和出度都很方便。

#### 4. 邻接多重表（无向图的链式存储）

> 邻接多重表（Adjacency Multilist）是**无向图**的一种链式存储结构，每条边只用**一个结点**表示。

- 每条边用一个结点表示，结点中同时指向两个顶点。
- 每个顶点有一个链表，链表中包含所有与该顶点相关联的边。
- 一条边 $(v_i, v_j)$ 的结点中，`ivex = i`，`jvex = j`，`ilink` 指向下一条与 $v_i$ 相关联的边，`jlink` 指向下一条与 $v_j$ 相关联的边。

**优点**：避免了一条边在存储中出现两次，适合对无向图的边进行操作。

#### 5. 边集数组

> 边集数组用**一维数组**存储图中所有边的信息。

```c
typedef struct {
    int u;                     // 边的起始顶点
    int v;                     // 边的终止顶点
    int w;                     // 边的权值
} Edge;

typedef struct {
    Edge edges[MAXE];          // 边数组
    int n, e;                   // 顶点数和边数
} EdgGraph;
```

- 适用于需要**依次扫描每条边**的运算（如 Kruskal 算法）。
- **缺点**：判断两条边是否关联同一顶点、求顶点的度等操作效率较低，需遍历整个边表。

#### 6. 各种存储结构对比

| 存储结构 | 空间复杂度 | 求顶点度 | 判断边是否存在 | 适合场景 |
|----------|-----------|---------|---------------|---------|
| 邻接矩阵 | $O(n^2)$ | 无向 $O(n)$，有向 $O(n)$ | $O(1)$ ⭐ | 稠密图 |
| 邻接表 | $O(n+e)$ | 无向 $O(degree)$，有向出度 $O(degree)$、入度 $O(n+e)$ | $O(degree)$ | 稀疏图 |
| 十字链表 | $O(n+e)$ | $O(\text{入度+出度})$ | $O(\text{degree})$ | 有向图 |
| 邻接多重表 | $O(n+e)$ | $O(\text{degree})$ | $O(\text{degree})$ | 无向图 |
| 边集数组 | $O(e)$ | $O(e)$ | $O(e)$ | 边相关算法 |

### 三、图的遍历（⭐🔥）

图的遍历是指从图中某一顶点出发，**系统地访问图中所有顶点**，使每个顶点仅被访问一次。遍历是图的基本运算，也是许多图算法的基础。

> **关键区别**：与树不同，图中可能存在**回路**，且一个顶点可能有多个邻接点，因此遍历时需要**记录已访问的顶点**，避免重复访问和陷入死循环。

设 `visited[1...n]` 为访问标志数组，初始值为 `false`。

---

#### 1. 深度优先搜索 DFS（Depth First Search）

##### （1）基本思想

> 深度优先搜索类似树的**先序遍历**（Preorder Traversal），采用**"一条路走到黑，碰壁再回头"**的策略。

**算法描述（递归）**：

```
DFS(G, v) {
    visited[v] = true;          // 标记 v 已被访问
    Visit(v);                   // 访问顶点 v

    for (w = FirstNeighbor(G, v); w >= 0; w = NextNeighbor(G, v, w)) {
        if (!visited[w]) {      // 若 w 未被访问
            DFS(G, w);          // 递归访问 w
        }
    }
}
```

**算法步骤**：
1. 访问起始顶点 $v$，并标记 $v$ 为已访问。
2. 从 $v$ 的**第一个未被访问的邻接点** $w$ 出发，递归进行 DFS。
3. 重复步骤 2，直到 $v$ 的所有邻接点都被访问过。
4. 若图中仍有未访问顶点，选取其中一个作为起始点继续 DFS，直到所有顶点均被访问。

##### （2）非递归实现（用栈）

```c
void DFS_NonRecursive(AdjGraph *G, int v) {
    SqStack S;                  // 辅助栈
    InitStack(&S);
    Push(&S, v);                // 起始顶点入栈
    visited[v] = true;          // 标记已访问

    while (!IsEmpty(S)) {
        int w = GetTop(S);      // 取栈顶元素
        Visit(w);               // 访问顶点 w

        int next = FirstNeighbor(G, w);
        if (next == -1 || visited[next]) {
            Pop(&S);            // 无未访问邻接点，回退
            continue;
        }

        for (int u = next; u != -1; u = NextNeighbor(G, w, u)) {
            if (!visited[u]) {
                Push(&S, u);    // 将第一个未访问邻接点入栈
                visited[u] = true;
                break;            // 跳出循环，继续处理新入栈的顶点
            }
        }
    }
}
```

> **DFS 递归与非递归等价**：递归实现中，系统隐式使用**调用栈**；非递归实现显式使用栈。两者生成的 DFS 序列**可能不同**（取决于邻接点的遍历顺序），但都符合 DFS 的定义。

##### （3）DFS 的时间复杂度

| 存储结构 | 时间复杂度 | 说明 |
|---------|-----------|------|
| 邻接表 | $O(n + e)$ | 每个顶点和每条边各访问一次 |
| 邻接矩阵 | $O(n^2)$ | 每个顶点需扫描一整行找邻接点 |

##### （4）DFS 的性质与用途

- **DFS 序列不唯一**：取决于起始顶点的选择和邻接点的遍历顺序。
- **DFS 生成树 / DFS 森林**：
  - 对于**连通图**，DFS 遍历过程中经过的边和顶点构成一棵**DFS 生成树**。
  - 对于**非连通图**，DFS 遍历过程中经过的边和顶点构成一棵**DFS 生成森林**。
- **DFS 可用于**：
  1. 判断图的**连通性**。
  2. 求图的**连通分量**个数。
  3. 检测图中是否存在**回路**（DFS 过程中若遇到已访问过的邻接点且不是父节点，则存在回路）。
  4. 求**简单路径**、**拓扑排序**的前置步骤等。

##### （5）DFS 算法完整实现

```c
// 邻接表实现 DFS
void DFS(AdjGraph *G, int v) {

    printf("%d ", v);           // 访问顶点

        if (!visited[p->adjvex]) {
            DFS(G, p->adjvex);
        }
        p = p->next;
    }
}

// 对全图进行 DFS（非连通图需调用多次）

        visited[i] = 0;         // 初始化访问标记
    }
    for (int i = 0; i < G->n; i++) {
        if (!visited[i]) {
            DFS(G, i);
        }
    }
}
```

#### 2. 广度优先搜索 BFS（Breadth First Search）

##### （1）基本思想

> 广度优先搜索类似树的**层序遍历**（Level-order Traversal），采用**"层层推进"**的策略。

**算法描述**：

```
BFS(G, v) {
    visited[v] = true;          // 标记 v 已被访问
    Visit(v);
    Enqueue(Q, v);              // v 入队

    while (!IsEmpty(Q)) {
        Dequeue(Q, v);          // 队头顶点出队

        for (w = FirstNeighbor(G, v); w >= 0; w = NextNeighbor(G, v, w)) {
            if (!visited[w]) {  // 若 w 未被访问
                visited[w] = true;
                Visit(w);       // 访问顶点 w
                Enqueue(Q, w);  // w 入队
            }
        }
    }
}
```

**算法步骤**：
1. 访问起始顶点 $v$，并标记 $v$ 为已访问。
2. 将 $v$ 的所有**未被访问过的邻接点**依次访问并**入队**。
3. 将 $v$ **出队**。
4. 从队头取顶点，重复步骤 2~3，直到队列空。
5. 若图中仍有未访问顶点，选取其中一个作为起始点继续 BFS，直到所有顶点均被访问。

##### （2）BFS 的时间复杂度

| 存储结构 | 时间复杂度 | 说明 |
|---------|-----------|------|
| 邻接表 | $O(n + e)$ | 每个顶点和每条边各访问一次 |
| 邻接矩阵 | $O(n^2)$ | 每个顶点需扫描一整行找邻接点 |

##### （3）BFS 的性质与用途

- **BFS 序列不唯一**：取决于起始顶点和邻接点的遍历顺序。
- **BFS 生成树 / BFS 森林**：
  - 对于**连通图**，BFS 遍历过程中经过的边和顶点构成一棵**BFS 生成树**。
  - 对于**非连通图**，BFS 遍历过程中经过的边和顶点构成一棵**BFS 生成森林**。
- **BFS 可用于**：
  1. 判断图的**连通性**。
  2. 求图的**连通分量**个数。
  3. 求**无权图的最短路径**（⭐🔥）。
  4. 求**最小生成树**的近似解等。

##### （4）BFS 算法完整实现

```c
// 邻接表实现 BFS
void BFS(AdjGraph *G, int v) {
    SqQueue Q;                  // 辅助队列
    InitQueue(&Q);

    printf("%d ", v);           // 访问顶点
    EnQueue(&Q, v);             // 入队

    while (!EmptyQueue(Q)) {
        DeQueue(&Q, v);         // 出队

        ArcNode *p = G->adjlist[v].first;
        while (p != NULL) {
            if (!visited[p->adjvex]) {
                visited[p->adjvex] = 1;
                printf("%d ", p->adjvex);
                EnQueue(&Q, p->adjvex);
            }
            p = p->next;
        }
    }
}

// 对全图进行 BFS（非连通图需调用多次）
void BFSTraverse(AdjGraph *G) {
    for (int i = 0; i < G->n; i++) {
        visited[i] = 0;         // 初始化访问标记
    }
    for (int i = 0; i < G->n; i++) {
        if (!visited[i]) {
            BFS(G, i);
        }
    }
}
```

#### 3. DFS 与 BFS 的比较

| 比较项 | DFS | BFS |
|--------|-----|-----|
| **使用的数据结构** | **栈**（递归隐式使用） | **队列** |
| **遍历特点** | 纵深搜索，一条路走到黑 | 层层推进，逐层扩展 |
| **遍历结果** | 不唯一（与邻接点顺序有关） | 不唯一（与邻接点顺序有关） |
| **时间复杂度（邻接表）** | $O(n + e)$ | $O(n + e)$ |
| **时间复杂度（邻接矩阵）** | $O(n^2)$ | $O(n^2)$ |
| **空间复杂度** | $O(n)$（栈） | $O(n)$（队列） |
| **生成树** | DFS 生成树 / 森林 | BFS 生成树 / 森林 |
| **典型应用** | 检测回路、拓扑排序、强连通分量等 | 最短路径（无权图）、连通分量等 |
| **是否保证最短路径** | ❌ 不保证 | ✅ 保证（无权图） |

> **记忆口诀**：
> - DFS：深搜像**爬树**，从上到下、从左到右，一路到底再回溯。
> - BFS：广搜像**水面涟漪**，从中心向外一圈一圈扩散。

### 四、图的最小生成树（⭐🔥）

> **生成树（Spanning Tree）**：对于一个有 $n$ 个顶点的**连通图**，其生成树是包含全部 $n$ 个顶点和 $n-1$ 条边的**极小连通子图**。
>
> **最小生成树（MST）**：在带权连通图中，所有生成树中**边的权值之和最小**的那一棵。
>
> **性质**：
> 1. 最小生成树**不唯一**（当存在权值相同的边时），但最小生成树的**权值之和唯一**。
> 2. 一棵有 $n$ 个顶点的生成树**有且仅有 $n-1$ 条边**。
> 3. 最小生成树一定是**连通的**且**无回路**。

---

#### 1. Prim 算法（普里姆算法）

##### （1）基本思想

> Prim 算法从**顶点**出发构建最小生成树。初始时令 $U = \{v_0\}$（$v_0$ 为任意选定的起始顶点），$TE = \emptyset$。反复在 $U$ 与 $V-U$ 之间选择一条**权值最小**的边 $(u, v)$（其中 $u \in U$，$v \in V-U$），将 $v$ 加入 $U$，边 $(u, v)$ 加入 $TE$，直到 $U = V$。

> **核心**："**加点法**"——每次选一条连接已选顶点集合与未选顶点集合的**最小权边**。

##### （2）算法步骤

```
Prim(G, v0) {
    U = {v0};                           // 已选顶点集合，初始为起始顶点
    TE = {};                            // 已选边集合，初始为空

    for (i = 1; i <= n-1; i++) {        // 执行 n-1 次迭代
        在 U 与 V-U 之间找权值最小的边 (u, v)；
        if (找到最小边) {
            将 v 加入 U；
            将边 (u, v) 加入 TE；
        }
    }
    return (U, TE);
}
```

##### （3）算法实现（邻接矩阵）

```c
// 使用邻接矩阵实现的 Prim 算法（适合稠密图）
void Prim(MGraph G, int v0) {
    lowcost[MAXV] = {G.edges[v0][j]};   // 初始化 lowcost 数组
    closest[MAXV] = {v0};               // 初始化 closest 数组
    visited[MAXV] = {0};
    visited[v0] = 1;

    for (int i = 1; i < G.n; i++) {     // 还需 n-1 次迭代
        min = INFINITY;
        for (int j = 0; j < G.n; j++) {
            if (!visited[j] && lowcost[j] < min) {
                min = lowcost[j];
                k = j;
            }
        }

        visited[k] = 1;                 // 将顶点 k 加入 U 集合
        printf("边 (%d, %d) 权值为 %d\n", closest[k], k, min);

        for (int j = 0; j < G.n; j++) { // 重新选择最小边
            if (!visited[j] && G.edges[k][j] < lowcost[j]) {
                lowcost[j] = G.edges[k][j];
                closest[j] = k;
            }
        }
    }
}
```

##### （4）时间复杂度分析

| 项目 | 复杂度 | 说明 |
|------|--------|------|
| 总时间复杂度 | $O(n^2)$ | 外层循环 $n-1$ 次，内层循环 $n$ 次 |
| 空间复杂度 | $O(n)$ | 使用 `lowcost` 和 `closest` 数组 |
| 适合场景 | **稠密图** | 与边数 $e$ 无关，只与顶点数 $n$ 有关 |

> **关键结论**：Prim 算法的时间复杂度只与**顶点数 $n$** 有关，与**边数 $e$** 无关，因此适合**稠密图**。

#### 2. Kruskal 算法（克鲁斯卡尔算法）

##### （1）基本思想

> Kruskal 算法从**边**出发构建最小生成树。初始时令 $U = V$（每个顶点自成一体），$TE = \emptyset$。将图中所有边按**权值从小到大**排序，依次检查每条边 $(u, v)$：若边 $(u, v)$ 连接的两个顶点属于**不同的连通分量**（即不构成回路），则将边 $(u, v)$ 加入 $TE$，合并两个连通分量；否则跳过。直到 $TE$ 中有 $n-1$ 条边为止。

> **核心**："**加边法**"——每次选一条**不构成回路**的**最小权边**。

##### （2）算法步骤

```
Kruskal(G) {
    将 G 的所有边按权值从小到大排序；
    U = V;                              // 每个顶点自成一体
    TE = {};                            // 已选边集合

    for (i = 1; i <= e; i++) {          // 遍历排序后的边
        取一条边 (u, v)；
        if (u 和 v 属于不同连通分量) {
            将边 (u, v) 加入 TE；
            合并 u 和 v 所在的连通分量；
        }
        if (TE 的边数 == n-1) break;    // 已选够 n-1 条边
    }
    return (U, TE);
}
```

##### （3）算法实现（邻接表 + 并查集）

```c
// 使用并查集实现的 Kruskal 算法（适合稀疏图）
struct Edge {
    int u, v, w;                        // 边的两个顶点和权值
};

int Find(int parent[], int x) {        // 并查集查找根节点
    while (parent[x] != x) {
        x = parent[x];
    }
    return x;
}

void Union(int parent[], int i, int j) { // 并查集合并
    int rootI = Find(parent, i);
    int rootJ = Find(parent, j);
    if (rootI != rootJ) {
        parent[rootI] = rootJ;
    }
}

void Kruskal(AdjGraph *G) {
    Edge edges[MAXE];
    int edgeCount = 0;

    // 从邻接表提取所有边
    for (int i = 0; i < G->n; i++) {
        ArcNode *p = G->adjlist[i].first;
        while (p != NULL) {
            if (p->adjvex > i) {        // 无向图只取一次
                edges[edgeCount].u = i;
                edges[edgeCount].v = p->adjvex;
                edges[edgeCount].w = p->info;
                edgeCount++;
            }
            p = p->next;
        }
    }

    // 按权值排序（如快速排序）
    Sort(edges, edgeCount);

    // 初始化并查集
    int parent[MAXV];
    for (int i = 0; i < G->n; i++) {
        parent[i] = i;
    }

    int count = 0;                      // 已选边数
    for (int i = 0; i < edgeCount && count < G->n - 1; i++) {
        int rootU = Find(parent, edges[i].u);
        int rootV = Find(parent, edges[i].v);
        if (rootU != rootV) {           // 不构成回路
            printf("边 (%d, %d) 权值为 %d\n", edges[i].u, edges[i].v, edges[i].w);
            Union(parent, rootU, rootV);
            count++;
        }
    }
}
```

##### （4）时间复杂度分析

| 项目 | 复杂度 | 说明 |
|------|--------|------|
| 总时间复杂度 | $O(e \log e)$ | 主要耗时在排序 |
| 并查集操作 | 近似 $O(e \cdot \alpha(n))$ | $\alpha$ 为阿克曼函数的反函数，近似为常数 |
| 空间复杂度 | $O(n + e)$ | 边表 + 并查集数组 |
| 适合场景 | **稀疏图** | 与边数 $e$ 直接相关，$e$ 越小效率越高 |

> **关键结论**：Kruskal 算法的时间复杂度与**边数 $e$** 直接相关（主要耗时在排序），因此适合**稀疏图**。

#### 3. Prim 与 Kruskal 的比较

| 比较项 | Prim 算法 | Kruskal 算法 |
|--------|-----------|-------------|
| **出发角度** | 从**顶点**出发（加点） | 从**边**出发（加边） |
| **核心操作** | 选择连接 $U$ 与 $V-U$ 的最小权边 | 选择不构成回路的最小权边 |
| **时间复杂度** | $O(n^2)$ | $O(e \log e)$ |
| **适合图类型** | **稠密图**（$e$ 较大时） | **稀疏图**（$e$ 较小时） |
| **实现复杂度** | 简单，用数组即可 | 需并查集/排序，稍复杂 |
| **依赖存储结构** | 邻接矩阵更合适 | 邻接表/边集数组更合适 |

> **记忆口诀**：
> - **Prim 稠密**：Prim 算法复杂度只与顶点数有关，稠密图边多，Prim 更优。
> - **Kruskal 稀疏**：Kruskal 算法复杂度与边数有关，稀疏图边少，Kruskal 更优。

### 五、图的拓扑排序（⭐🔥）

> **AOV 网（Activity On Vertex Network）**：用**顶点**表示活动、**有向边**表示活动间先后关系的**有向图**。在一个表示工程的有向图中，用顶点表示活动，用弧表示活动之间的优先关系。

> **特点**：AOV 网中**不能出现回路**（环），否则意味着某个活动以自己为先决条件，工程无法完成。

---

#### 1. 拓扑排序定义

> **拓扑排序**（Topological Sort）是对 AOV 网中所有顶点排成一个**线性序列**，使得图中**所有有向边**都指向序列中**靠后**的顶点。即：若存在从 $v_i$ 到 $v_j$ 的边，则 $v_i$ 在排序结果中一定**排在** $v_j$ **前面**。

- 拓扑排序结果**不一定唯一**（当多个顶点入度同时为 0 时）。
- 若 AOV 网中**存在环**，则**无法进行**拓扑排序。
- 若拓扑排序**成功**输出所有 $n$ 个顶点，则说明 AOV 网中**无环**。

---

#### 2. 拓扑排序算法步骤

```
拓扑排序(G) {
    计算所有顶点的入度；
    将所有入度为 0 的顶点入栈（或入队）；

    while (栈/队列不为空) {
        取出一个入度为 0 的顶点 v；
        将 v 加入排序序列；
        将 v 的所有邻接点 w 的入度减 1；
        若 w 的入度变为 0，将 w 入栈（或入队）；
    }

    if (排序序列中的顶点数 < G.n) {
        说明存在环，不能进行拓扑排序；
    } else {
        排序成功；
    }
}
```

##### （3）算法实现（邻接表）

```c
// 邻接表实现拓扑排序
bool TopologicalSort(AdjGraph *G) {
    int indegree[MAXV] = {0};
    // 1. 计算所有顶点的入度
    for (int i = 0; i < G->n; i++) {
        ArcNode *p = G->adjlist[i].first;
        while (p != NULL) {
            indegree[p->adjvex]++;
            p = p->next;
        }
    }

    // 2. 将入度为 0 的顶点入栈
    SqStack S;
    InitStack(&S);
    for (int i = 0; i < G->n; i++) {
        if (indegree[i] == 0) {
            Push(&S, i);
        }
    }

    int count = 0;                    // 已输出的顶点数
    int topoOrder[MAXV];              // 存储拓扑排序结果
    int top = 0;                      // topoOrder 的索引

    while (!IsEmpty(S)) {
        int v = Pop(&S);
        topoOrder[top++] = v;
        count++;

        // 3. 将 v 的所有邻接点的入度减 1
        ArcNode *p = G->adjlist[v].first;
        while (p != NULL) {
            int w = p->adjvex;
            indegree[w]--;
            if (indegree[w] == 0) {
                Push(&S, w);
            }
            p = p->next;
        }
    }

    // 4. 判断是否所有顶点都已输出
    if (count < G->n) {
        return false;                 // 存在环，无法拓扑排序
    }

    // 输出拓扑排序结果
    for (int i = 0; i < G->n; i++) {
        printf("%d ", topoOrder[i]);
    }
    return true;
}
```

##### （4）时间复杂度

| 项目 | 复杂度 | 说明 |
|------|--------|------|
| 计算入度 | $O(n + e)$ | 遍历所有边表 |
| 入度减一 | $O(n + e)$ | 每条边处理一次 |
| 总时间复杂度 | $O(n + e)$ | 与 BFS 同量级 |
| 空间复杂度 | $O(n)$ | `indegree` 数组 + 栈 |

---

#### 3. 拓扑排序的应用

1. **判断有向图是否存在环**：若拓扑排序无法输出所有顶点，则存在环。
2. **工程调度**：确定任务的执行顺序。
3. **课程先修关系**：确定课程的修读顺序。

### 六、关键路径（AOE 网）

> **AOE 网（Activity On Edge Network）**：用**边**表示活动、**顶点**表示事件的**带权有向图**。边的权值表示完成该活动所需的时间。

- **源点**：入度为 0 的顶点，表示工程的**开始**。
- **汇点**：出度为 0 的顶点，表示工程的**结束**。
- **活动**：边上的权值表示完成活动所需的时间。

---

#### 1. 相关概念

| 术语 | 符号 | 定义 |
|------|------|------|
| **事件 $v_k$ 的最早发生时间** | $ve(k)$ | 从源点到顶点 $v_k$ 的**最长路径**长度（即所有以 $v_k$ 为弧头的活动都完成后） |
| **事件 $v_k$ 的最迟发生时间** | $vl(k)$ | 在不推迟整个工程完工时间的前提下，事件 $v_k$ 必须发生的最迟时间 |
| **活动 $a_i$ 的最早开始时间** | $e(i)$ | 活动 $a_i$ 对应的弧的**弧尾**顶点的最早发生时间，即 $e(i) = ve(k)$ |
| **活动 $a_i$ 的最迟开始时间** | $l(i)$ | 活动 $a_i$ 的最迟开始时间 = 弧头顶点的最迟发生时间 - 活动持续时间，即 $l(i) = vl(j) - \text{weight}$ |
| **关键活动** | — | 满足 $e(i) = l(i)$ 的活动（即**没有余闲时间**的活动） |
| **关键路径** | — | 从源点到汇点的**最长路径**（即所有关键活动组成的路径） |

> **核心公式**：
> - $ve(k) = \max\{ve(j) + \text{weight}(\langle v_j, v_k \rangle)\}$（对每个以 $v_k$ 为弧头的活动）
> - $vl(k) = \min\{vl(j) - \text{weight}(\langle v_k, v_j \rangle)\}$（对每个以 $v_k$ 为弧尾的活动）
> - 若 $e(i) = l(i)$，则活动 $a_i$ 是**关键活动**。

---

#### 2. 关键路径求解步骤

```
关键路径求解(G) {
    1. 对 AOE 网进行拓扑排序；
    2. 初始化 ve(源点) = 0，其他 ve = 0（或 −∞）；
    3. 按拓扑序列顺序计算每个事件的 ve(k)：
       ve(k) = max{ve(j) + weight(<vj, vk>)}；
    4. 初始化 vl(汇点) = ve(汇点)，其他 vl = ve(汇点)；
    5. 按逆拓扑序列顺序计算每个事件的 vl(k)：
       vl(k) = min{vl(j) - weight(<vk, vj>)}；
    6. 计算每个活动的 e(i) 和 l(i)；
    7. 找出 e(i) = l(i) 的关键活动，
       这些关键活动组成的从源点到汇点的路径即为关键路径。
}
```

##### （3）时间复杂度

- 与拓扑排序相同，为 **$O(n + e)$**。

---

#### 3. 关键路径与拓扑排序的区别

| 比较项 | 拓扑排序（AOV 网） | 关键路径（AOE 网） |
|--------|-------------------|-------------------|
| **表示内容** | 顶点表示活动 | 边表示活动 |
| **关注点** | 活动间的先后关系 | 活动间的耗时 |
| **算法** | 拓扑排序 | 先拓扑排序，再求关键路径 |
| **时间复杂度** | $O(n + e)$ | $O(n + e)$ |

## ### ⚖️易混淆概念对比

### 1. 连通图 vs 强连通图

| 概念 | 适用范围 | 条件 |
|------|---------|------|
| **连通图** | 仅用于**无向图** | 任意两顶点间存在路径 |
| **强连通图** | 仅用于**有向图** | 任意两顶点间存在**双向**路径 |
| **连通分量** | 仅用于**无向图** | 极大连通子图 |
| **强连通分量** | 仅用于**有向图** | 极大强连通子图 |

### 2. 生成树 vs 连通图

- 生成树是**连通图的子图**，且是**树**（无环、连通、$n$ 个顶点 $n-1$ 条边）。
- **不是所有连通图都是生成树**——连通图可以有超过 $n-1$ 条边。

### 3. 回路 vs 环

- 在**无向图**中，"回路"和"环"通常视为同义。
- 在**有向图**中，"回路"指从某顶点出发又回到该顶点的路径；"环"通常也指回路。
- **简单回路**要求除首尾顶点外，其余顶点不重复。

### 4. DFS 生成树 vs BFS 生成树

- DFS 生成树的深度通常更深（一条路走到黑）。
- BFS 生成树的深度通常更浅（层层推进）。
- 同一图的 DFS 生成树和 BFS 生成树**一般不同**。

### 5. Prim 与 Kruskal 的选择

- 题目给出 $n$（顶点数）和 $e$（边数），判断选哪种：
  - $e$ 较大（接近 $n^2$）→ 选 **Prim**
  - $e$ 较小（稀疏图）→ 选 **Kruskal**

### 6. AOV 网 vs AOE 网

| 对比项 | AOV 网 | AOE 网 |
|--------|--------|--------|
| **元素含义** | 顶点 = 活动 | 边 = 活动 |
| **边/弧含义** | 表示活动间的先后关系 | 表示活动持续时间（权值） |
| **求解问题** | 活动执行顺序（拓扑排序） | 工程完成时间（关键路径） |
| **算法** | 拓扑排序 | 关键路径算法 |

## ### ⚠️考试高频坑点

### 坑点 1：邻接矩阵求有向图入度和出度

> ⚠️ **陷阱**：很多考生混淆有向图在邻接矩阵中入度和出度的计算方法。
> - **出度 = 第 $i$ 行的和**（以 $v_i$ 为弧尾的边数）。
> - **入度 = 第 $i$ 列的和**（以 $v_i$ 为弧头的边数）。
> - 总度 = 出度 + 入度 = 第 $i$ 行和 + 第 $i$ 列和。

### 坑点 2：邻接表求有向图入度

> ⚠️ **陷阱**：在邻接表中，求有向图某个顶点的**入度**需要**遍历整个邻接表**（所有顶点的边表），而非只遍历该顶点的边表。这是考研大题的高频考点。

### 坑点 3：生成树的边数

> ⚠️ **陷阱**：生成树是原图的**子图**，必须包含**所有顶点**。
> - $n$ 个顶点的图，其生成树恰好有 $n-1$ 条边。
> - 如果图中边数不足 $n-1$，则不可能有生成树（图不连通）。

### 坑点 4：无向完全图与有向完全图的边数

> ⚠️ **陷阱**：
> - 无向完全图：$\frac{n(n-1)}{2}$ 条边。
> - 有向完全图：$n(n-1)$ 条弧（每对顶点之间有两条方向相反的弧）。
> - 注意区分"完全图"和"完全二叉树"（后者边数 = $n-1$）。

### 坑点 5：连通分量与连通子图

> ⚠️ **陷阱**：
> - **连通分量**是**极大**连通子图（包含所有能连通的顶点）。
> - **连通子图**只要求子图内部连通，不一定是极大的。
> - 一个图的连通子图可以有无穷多个，但连通分量个数是固定的。

### 坑点 6：DFS/BFS 遍历序列不唯一

> ⚠️ **陷阱**：DFS 和 BFS 的遍历序列**都不是唯一的**——取决于起始顶点的选择和邻接点的遍历顺序。选择题中若给出多个可能的 DFS/BFS 序列，需要逐一验证。

### 坑点 7：最小生成树不唯一

> ⚠️ **陷阱**：
> - 最小生成树的**树本身可能不唯一**（存在权值相同的边时）。
> - 但最小生成树的**权值之和一定唯一**。
> - Kruskal 和 Prim 算法得到的最小生成树可能不同，但权值和相同。

### 坑点 8：拓扑排序与环

> ⚠️ **陷阱**：
> - 拓扑排序的**前提**是有向图**无环**（AOV 网）。
> - 若拓扑排序结束后输出的顶点数小于 $n$，说明图中**存在环**。
> - 拓扑排序结果**不唯一**——当有多个入度为 0 的顶点时，选择顺序不同导致结果不同。

### 坑点 9：存储结构选择

> ⚠️ **陷阱**：
> - 题目未明确给出存储结构时，需要根据运算特点选择。
> - 频繁判断边是否存在 → 邻接矩阵（$O(1)$）。
> - 频繁遍历邻接点（如遍历、DFS、BFS）→ 邻接表（$O(n+e)$）。
> - 求最短路径（Dijkstra）→ 邻接矩阵或邻接表均可，视稠密程度而定。

### 坑点 10：空间复杂度

> ⚠️ **陷阱**：
> - 邻接矩阵空间复杂度是 $O(n^2)$，与边数无关。
> - 邻接表空间复杂度是 $O(n+e)$，无向图每条边存储两次，有向图存储一次。
> - 若采用边集数组表示图，空间复杂度为 $O(e)$，但不适合遍历操作。
