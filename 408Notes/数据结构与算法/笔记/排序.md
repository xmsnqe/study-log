# 排序（Sorting）

---

## 一、排序的基本概念

### 📍知识定位

排序是数据结构中极为重要的操作之一，也是408计算机考研的**高频必考内容**。排序问题在各种实际应用场景中极为普遍，如数据库查询结果的有序排列、学生成绩排名、文件系统目录排序等。在考研中，排序既出现在**选择题**中考察概念与复杂度分析，也频繁以**大题（算法设计题）**的形式出现，要求手写完整排序算法（尤其是快速排序、堆排序、归并排序）。

排序算法的核心在于理解每种算法的思想本质、时间/空间复杂度特性以及稳定性，并能够在不同场景下合理选择算法。

---

### 📝核心概念与原理

#### 1. 排序的定义

**排序（Sorting）** 是计算机内排（internal sorting）中一个极其重要的操作，其定义为：**将一组记录（或元素）按照关键字（key）的递增序或递减序重新排列**的操作。

设待排序序列为 $\{R_1, R_2, \cdots, R_n\}$，每个记录 $R_i$ 有一个关键字 $K_i$。排序的结果是获得序列 $\{R'_1, R'_2, \cdots, R'_n\}$，使得：

$$K'_1 \leq K'_2 \leq \cdots \leq K'_n$$（升序排列，也称**非递减排列**）

或

$$K'_1 \geq K'_2 \geq \cdots \geq K'_n$$（降序排列，也称**非递增排列**）

> 【核心要点】排序的关键是依据**关键字（key）**进行比较和排列，关键字可以是一个字段（如学生的学号），也可以是多个字段的组合。

---

#### 2. 稳定排序 vs 不稳定排序

**⭐ 选择题高频考点**

- **稳定排序（Stable Sorting）**：若待排序序列中有两个记录的关键字相等（即 $K_i = K_j$，$i \neq j$），在排序后它们的相对位置保持不变，则称该排序算法是**稳定**的。

  直观理解：假设有两个关键字相同的元素 A 和 B，A 原本在 B 前面，排序后 A 仍然在 B 前面。

- **不稳定排序（Unstable Sorting）**：若排序后关键字相同的元素的相对位置可能改变，则称该排序算法是**不稳定**的。

> 【核心要点】稳定性只在关键字可能相等时才有意义。在实际应用中，如多级排序（先按部门排序，再按工资排序），稳定排序能保证前一级排序的结果不被破坏。

**稳定排序算法**：直接插入排序、冒泡排序、归并排序、基数排序

**不稳定排序算法**：选择排序、堆排序、希尔排序、快速排序

---

#### 3. 内排序 vs 外排序

- **内排序（Internal Sorting）**：在排序的整个过程中，待排序的所有记录**全部被加载到内存（内部存储）**中进行排序。本文所讨论的各种排序算法均为内排序。

- **外排序（External Sorting）**：当待排序记录的数量很大，以至于内存无法全部容纳时，需借助**外部存储**（如磁盘）进行的排序。外排序的基本思想通常是"排序-归并"策略，即先将文件分成若干适合内存处理的子文件，分别排好序后再合并（归并）。

> 【核心要点】408考研主要考查**内排序**算法。外排序在选择题中可能以概念形式出现，了解即可。

---

#### 4. 排序算法的性能评价

评价一个排序算法的优劣，主要考虑以下几个方面：

| 评价指标 | 说明 |
|---------|------|
| **时间复杂度** | 包括最好、最坏、平均时间复杂度。反映算法执行时间的增长趋势。 |
| **空间复杂度** | 算法执行过程中所需的额外存储空间。 |
| **稳定性** | 关键字相等的记录在排序后相对位置是否保持不变。 |
| **记录移动次数** | 元素在不同位置间的移动次数，影响实际执行效率。 |
| **算法复杂度** | 算法本身的实现复杂度，影响编码调试的难易程度。 |

> 【核心要点】考研中最核心的三个指标是：**时间复杂度、空间复杂度、稳定性**。其中时间复杂度是选择题最高频的考点。

**时间复杂度分析要点：**
- 排序算法的时间复杂度主要由**关键字比较次数**和**记录移动次数**决定。
- 最好时间复杂度：针对"最好情况"（如已经有序），反映算法在最佳场景下的性能。
- 最坏时间复杂度：针对"最坏情况"（如完全逆序），反映算法的底线性能。
- 平均时间复杂度：在所有可能输入情况下的期望时间复杂度。

## 二、插入排序（Insertion Sorting）⭐

插入排序的基本思想是：**每一趟将一个待排序的记录，按其关键字的大小插入到已经排好序的子序列中，直到全部记录插入完毕。**

---

### 2.1 直接插入排序

#### 2.1.1 基本思想

将待排序序列分为"已排序区间"和"待排序区间"。初始时，已排序区间只包含第一个元素。从第二个元素开始，依次将待排序区间的每个元素插入到已排序区间的适当位置。

具体步骤（以升序为例）：
1. 将第 1 个记录视为已排序区间。
2. 从第 $i = 2$ 个记录开始，将 $R_i$ 与已排序区间的记录从后往前依次比较。
3. 若 $K_i < K_j$（$j$ 为已排序区间中的记录），则将 $R_j$ 后移。
4. 重复步骤 3，直到找到插入位置，将 $R_i$ 插入。
5. 依次处理所有待排序记录。

#### 2.1.2 C语言实现

```c
/* 直接插入排序 */
void InsertSort(Sqlist &L) {
    // 对顺序表 L 作直接插入排序
    for (int i = 2; i <= L.length; ++i) {
        if (LT(L.r[i].key, L.r[i-1].key)) {  // 需将 L.r[i] 插入有序子表
            L.r[0] = L.r[i];  // 将 L.r[i] 存入监视哨
            for (int j = i - 1; LT(L.r[0].key, L.r[j].key); --j) {
                L.r[j+1] = L.r[j];  // 记录后移
            }
            L.r[j+1] = L.r[0];  // 插入到正确位置
        }
    }
}
```

**严蔚敏教材标准实现要点：**
- 使用 `r[0]` 作为**监视哨（Sentinel）**，避免在每次比较时都判断是否越界。
- `LT(x, y)` 表示 `x < y` 的宏定义，用于比较关键字大小。
- 外层循环从 $i = 2$ 开始（第 1 个元素已天然有序）。
- 内层循环从后往前扫描已排序区间。

#### 2.1.3 复杂度分析

| 指标 | 结果 | 说明 |
|-----|------|------|
| 最好时间复杂度 | $O(n)$ | 表已有序，每趟只需比较 1 次，无需移动 |
| 最坏时间复杂度 | $O(n^2)$ | 表逆序，第 $i$ 趟需比较 $i$ 次、移动 $i$ 次 |
| 平均时间复杂度 | $O(n^2)$ | 约需比较 $\frac{n^2}{4}$ 次，移动 $\frac{n^2}{4}$ 次 |
| 空间复杂度 | $O(1)$ | 只需一个辅助空间 `r[0]` 作为监视哨 |
| 稳定性 | 稳定 | 关键字相等的记录不会改变相对顺序 |

> 【核心要点 ⭐】直接插入排序的时间复杂度与**初始排序状态**密切相关。当表基本有序时，直接插入排序的效率接近 $O(n)$；当表逆序时，退化为 $O(n^2)$。

#### 2.1.4 适用场景

- 待排序记录**数量较少**（$n$ 较小）。
- 待排序记录**基本有序**（接近有序状态）。
- 对排序**稳定性**有要求。

---

### 2.2 折半插入排序

折半插入排序是对直接插入排序的改进：在确定插入位置时，使用**二分查找（折半查找）**代替顺序查找。

**基本思想：**
- 在已排序区间 $[1, i-1]$ 中使用折半查找确定 $R_i$ 的插入位置。
- 找到插入位置后，仍然需要移动记录。

**复杂度：**
- 关键字比较次数：减少为 $O(n\log_2 n)$（折半查找）。
- 记录移动次数：与直接插入排序相同，仍为 $O(n^2)$。
- 总体时间复杂度：$O(n^2)$（因为移动记录仍是主导因素）。
- 空间复杂度：$O(1)$。
- 稳定性：稳定。

> 【核心要点】折半插入排序虽然减少了比较次数，但**移动次数并未减少**，因此时间复杂度仍为 $O(n^2)$。仅在关键字比较耗时较大时才有实际意义。

---

### 2.3 希尔排序（Shell Sort）⭐🔥

#### 2.3.1 基本思想

希尔排序又称**缩小增量排序**，是对直接插入排序的改进。基本思想是：

1. 先将待排序序列分成若干**子序列**（子表），分别进行**直接插入排序**。
2. 当整个序列"基本有序"时，再对全体记录进行一次**直接插入排序**。

"基本有序"的含义：关键字较小的记录大致在前面，较大的记录大致在后面，而不是完全有序。

#### 2.3.2 算法实现

```c
/* 希尔排序 */
void ShellInsert(Sqlist &L, int dk) {
    // 对顺序表 L 作一趟希尔插入排序。dk 为增量
    for (int i = dk + 1; i <= L.length; ++i) {
        if (LT(L.r[i].key, L.r[i-dk].key)) {
            L.r[0] = L.r[i];  // 暂存
            for (int j = i - dk; j > 0 && LT(L.r[0].key, L.r[j].key); j -= dk) {
                L.r[j+dk] = L.r[j];  // 记录后移，增量为 dk
            }
            L.r[j+dk] = L.r[0];  // 插入
        }
    }
}

void ShellSort(Sqlist &L, int dt[], int t) {
    // 按增量序列 dt[0..t-1] 对顺序表 L 作希尔排序
    for (int k = 0; k < t; ++k) {
        ShellInsert(L, dt[k]);  // 一趟增量为 dt[k] 的插入排序
    }
}
```

#### 2.3.3 增量序列

增量序列的选取对希尔排序的性能有重要影响。

| 增量序列 | 定义 | 最坏时间复杂度 |
|---------|------|--------------|
| **希尔增量** | $d_1 = \lfloor n/2 \rfloor$，$d_k = \lfloor d_{k-1}/2 \rfloor$ | $O(n^2)$ |
| **Hibbard 增量** | $d_k = 2^k - 1$ | $O(n^{3/2})$ |
| **Sedgewick 增量** | $\{1, 5, 19, 41, 109, \cdots\}$ | $O(n^{7/4})$ |

> 【核心要点 ⭐】增量序列中各值**没有除 1 之外的公因子**。最后一个增量必须为 1，因此也称为**希尔排序**（Shell Sort 即取自 Shell 之名）。

**希尔增量的典型过程：**
假设 $n = 10$，则增量序列为：$5, 2, 1$。
- 第一趟：$\Delta = 5$，将序列分成 5 个子表，分别插入排序。
- 第二趟：$\Delta = 2$，将序列分成 2 个子表，分别插入排序。
- 第三趟：$\Delta = 1$，对整个序列作一次直接插入排序。

#### 2.3.4 复杂度分析

| 指标 | 结果 | 说明 |
|-----|------|------|
| 时间复杂度 | $O(n^{1.3}) \sim O(n^2)$ | 取决于增量序列的选取，希尔增量最坏为 $O(n^2)$ |
| 空间复杂度 | $O(1)$ | 只需一个辅助空间 |
| 稳定性 | **不稳定** ⭐ | 相同关键字的记录可能因跨增量而改变相对位置 |

> 【核心要点 ⭐】希尔排序的**时间复杂度与增量序列密切相关**，考研中常考"希尔排序时间复杂度不是 $O(n^2)$"这一结论（在选取合适的增量序列时）。同时，希尔排序是**不稳定**的。

#### 2.3.5 适用场景

- $n$ 较大，对稳定性无要求。
- 当增量序列选取合适时，性能优于直接插入排序。

## 三、交换排序（Exchange Sorting）⭐🔥

交换排序的基本思想是：**两两比较待排序记录的关键字，发现逆序时交换它们的位置**。

---

### 3.1 冒泡排序（Bubble Sort）

#### 3.1.1 基本思想

冒泡排序（又称**起泡排序**）的基本思想是：从前往后（或从后往前）两两比较相邻记录的关键字，若为逆序则交换，使得关键字较大的记录逐渐"漂浮"到序列的末尾（如同气泡上浮）。

每一趟确定一个**最大值**元素的位置。最多需要 $n-1$ 趟。

#### 3.1.2 C语言实现

```c
/* 冒泡排序（优化版本）*/
void BubbleSort(Sqlist &L) {
    // 对顺序表 L 作冒泡排序
    int n = L.length;
    for (int i = 1; i < n; ++i) {
        bool flag = false;  // 优化标志
        for (int j = 1; j <= n - i; ++j) {
            if (GT(L.r[j].key, L.r[j+1].key)) {  // 逆序则交换
                L.r[0] = L.r[j];
                L.r[j] = L.r[j+1];
                L.r[j+1] = L.r[0];
                flag = true;
            }
        }
        if (!flag) return;  // 本趟无交换，说明已有序，提前终止
    }
}
```

**优化要点：**
- 引入标志变量 `flag`。若某一趟遍历中**没有发生任何交换**，说明整个序列已经有序，可以**提前终止**排序。
- 若某趟排序中仅有最后几个元素无序，可以在下一趟减少比较范围。

#### 3.1.3 复杂度分析

| 指标 | 结果 | 说明 |
|-----|------|------|
| 最好时间复杂度 | $O(n)$ | 表已有序，只需一趟比较，无交换（优化后） |
| 最坏时间复杂度 | $O(n^2)$ | 表逆序，每趟都需比较和交换 |
| 平均时间复杂度 | $O(n^2)$ | 平均约需比较 $\frac{n^2}{4}$ 次 |
| 空间复杂度 | $O(1)$ | 只需一个辅助空间 |
| 稳定性 | 稳定 | 相同关键字不会改变相对位置 |

> 【核心要点 ⭐】优化后的冒泡排序在**最好情况**（已有序）下只需 $O(n)$ 时间复杂度，这是其重要特性，常在选择题中出现。

---

### 3.2 快速排序（Quick Sort）⭐🔥🔥

快速排序是目前**基于比较的内部排序方法中性能最好**的一种排序算法，也是408考研中的**最高频考点**（常以大题形式出现）。

#### 3.2.1 基本思想

快速排序采用**分治法（Divide and Conquer）**策略，由 Tony Hoare 于 1962 年提出。

基本思想：
1. 在待排序序列中选取一个记录作为**枢轴（pivot）**。
2. 通过**一趟快速排序**（Partition）将序列划分为两个子序列：
   - 左子序列：所有关键字**小于**枢轴的记录。
   - 右子序列：所有关键字**大于**枢轴的记录。
3. 枢轴记录处于其**最终位置**（即排序后的正确位置）。
4. 递归地对左右两个子序列分别进行快速排序。

#### 3.2.2 Partition 函数（⭐🔥🔥）

```c
/* 快速排序的划分函数 Partition */
int Partition(Sqlist &L, int low, int high) {
    // 对顺序表 L 中的子表 r[low..high] 进行划分
    L.r[0] = L.r[low];  // 用子表的第一个记录作枢轴记录
    int pivotkey = L.r[low].key;

    while (low < high) {
        // 从右向左搜索小于枢轴的记录
        while (low < high && L.r[high].key >= pivotkey) {
            --high;
        }
        L.r[low] = L.r[high];  // 将较小记录交换到前端

        // 从左向右搜索大于枢轴的记录
        while (low < high && L.r[low].key <= pivotkey) {
            ++low;
        }
        L.r[high] = L.r[low];  // 将较大记录交换到后端
    }

    L.r[low] = L.r[0];  // 枢轴记录最终定位
    return low;  // 返回枢轴记录的最终位置
}
```

**Partition 执行过程（"挖坑填数"法）：**
1. 以 $L.r[low]$ 为枢轴，其位置相当于一个"坑"。
2. 从 $high$ 开始向左扫描，找到第一个小于枢轴的记录，填入 $low$ 处的"坑"。
3. 从 $low$ 开始向右扫描，找到第一个大于枢轴的记录，填入 $high$ 处的"坑"。
4. 重复步骤 2 和 3，直到 $low = high$，将枢轴填入该位置。

#### 3.2.3 完整算法

```c
/* 快速排序主函数 */
void QSort(Sqlist &L, int low, int high) {
    // 对顺序表 L 中的子序列 L.r[low..high] 作快速排序
    if (low < high) {
        int pivotpos = Partition(L, low, high);  // 划分
        QSort(L, low, pivotpos - 1);              // 对左子序列递归排序
        QSort(L, pivotpos + 1, high);             // 对右子序列递归排序
    }
}

void QuickSort(Sqlist &L) {
    // 对顺序表 L 作快速排序
    QSort(L, 1, L.length);
}
```

#### 3.2.4 复杂度分析

| 指标 | 结果 | 说明 |
|-----|------|------|
| 最好时间复杂度 | $O(n\log_2 n)$ | 每次划分均匀（$n/2$） |
| 最坏时间复杂度 | $O(n^2)$ | 每次划分不均匀（一侧为空），如已排序序列 |
| 平均时间复杂度 | $O(n\log_2 n)$ ⭐ | 在随机情况下 |
| 空间复杂度 | $O(\log_2 n)$ ⭐ | 递归栈深度，最好 $\log_2 n$，最坏 $n-1$ |
| 稳定性 | **不稳定** ⭐ | 划分过程中可能改变相等记录的相对位置 |

**最好情况分析（$O(n\log_2 n)$）：**
- 每次 Partition 将序列均匀分成两个长度为 $n/2$ 的子序列。
- 递归树深度为 $\log_2 n$。
- 每层 Partition 总比较次数为 $n$。
- 总时间复杂度：$n \times \log_2 n = O(n\log_2 n)$。

**最坏情况分析（$O(n^2)$）：**
- 当序列**已经有序**（正序或逆序）且选取第一个（或最后一个）元素为枢轴时，每次划分只得到左子表（或右子表）为空，另一侧长度为 $n-1$。
- 递归树退化为单枝树，深度为 $n-1$。
- 每层比较次数递减：$(n-1) + (n-2) + \cdots + 1 = \frac{n(n-1)}{2}$。
- 总时间复杂度：$O(n^2)$。

> 【核心要点 ⭐🔥🔥】
> - 快速排序是**平均性能最好**的排序算法。
> - 空间复杂度 $O(\log_2 n)$ 是递归栈深度。
> - 快速排序是**不稳定**的。
> - 最坏情况发生在序列已有序且选取第一个元素为枢轴时。

#### 3.2.5 快速排序的优化方法

为尽量避免最坏情况，可采用以下优化措施：

| 优化方法 | 说明 |
|---------|------|
| **三数取中（Three-way Middle）** | 从 $low$、$high$ 和 $mid = (low+high)/2$ 三个位置选取关键字中值作为枢轴，避免选取极值为枢轴。 |
| **小序列优化** | 当子序列长度较小（通常 $n \leq 10$）时，不再递归调用快速排序，而是改用**直接插入排序**。 |
| **聚集相同元素** | 在一趟 Partition 中同时把所有等于枢轴的记录放到枢轴的两侧。 |

> 【核心要点】"三数取中"是最常用的优化手段。在考研中，可能会考到"三数取中法选取枢轴的具体步骤"。

#### 3.2.6 快速排序的执行过程示例

设待排序序列为：`[49, 38, 65, 97, 76, 13, 27, 49]`

以第一个元素 49 为枢轴进行一趟 Partition 后的结果：`[27, 38, 13, 49, 76, 97, 65, 49]`

- 枢轴 49 的最终位置为第 4 位。
- 左子表 `[27, 38, 13]` 全部小于 49。
- 右子表 `[76, 97, 65, 49]` 全部大于等于 49。

## 四、选择排序（Selection Sorting）⭐

选择排序的基本思想是：**每一趟从待排序的记录中选出关键字最小的记录，按顺序放在已排序子表的最后，直到全部记录排序完毕**。

---

### 4.1 简单选择排序

#### 4.1.1 基本思想

从 $i = 1$ 到 $n-1$，每趟在剩余的元素中选取关键字最小的元素，与第 $i$ 个位置的元素交换。

- 第 1 趟：从 $R_1 \sim R_n$ 中选出最小记录，与 $R_1$ 交换。
- 第 2 趟：从 $R_2 \sim R_n$ 中选出最小记录，与 $R_2$ 交换。
- ...
- 第 $i$ 趟：从 $R_i \sim R_n$ 中选出最小记录，与 $R_i$ 交换。
- ...
- 第 $n-1$ 趟：从 $R_{n-1} \sim R_n$ 中选出最小记录，与 $R_{n-1}$ 交换。

#### 4.1.2 C语言实现

```c
/* 简单选择排序 */
void SelectSort(Sqlist &L) {
    // 对顺序表 L 作简单选择排序
    for (int i = 1; i < L.length; ++i) {
        int min = i;  // 假设第 i 个位置是最小值
        for (int j = i + 1; j <= L.length; ++j) {
            if (LT(L.r[j].key, L.r[min].key)) {
                min = j;  // 记录最小值的位置
            }
        }
        if (min != i) {  // 若最小值不在第 i 个位置
            L.r[0] = L.r[i];
            L.r[i] = L.r[min];
            L.r[min] = L.r[0];  // 交换
        }
    }
}
```

#### 4.1.3 复杂度分析

| 指标 | 结果 | 说明 |
|-----|------|------|
| 最好时间复杂度 | $O(n^2)$ | 即使已有序，仍需全部比较 |
| 最坏时间复杂度 | $O(n^2)$ | 完全逆序 |
| 平均时间复杂度 | $O(n^2)$ ⭐ | 与初始状态无关 |
| 空间复杂度 | $O(1)$ | 只需一个辅助空间 |
| 稳定性 | **不稳定** ⭐ | 交换操作可能改变等值记录的相对位置 |

**⭐ 核心特性：**
1. **时间复杂度与初始状态无关**：无论序列初始是否有序，简单选择排序的比较次数始终是 $\frac{n(n-1)}{2}$，即 $O(n^2)$。
2. **记录移动次数最少**：最多移动 $3(n-1)$ 次（每次交换最多 3 次移动），是所有 $O(n^2)$ 排序中移动次数最少的。
3. **不稳定**：例如序列 `[5a, 5b, 1]`，第 1 趟将 1 与 5a 交换得到 `[1, 5b, 5a]`，5a 和 5b 的相对位置改变了。

> 【核心要点 ⭐】简单选择排序的**比较次数与序列初始状态无关**，始终为 $\frac{n(n-1)}{2}$ 次。这是它与直接插入排序的重要区别。

### 4.2 堆排序（Heap Sort）⭐🔥

堆排序结合了**完全二叉树**（堆）的结构特性和直接插入排序的思想，是考研中的高频大题。

#### 4.2.1 堆的定义 ⭐

**堆（Heap）** 是一棵**完全二叉树**，且满足以下性质之一：

- **大顶堆（Max Heap）**：根结点的值 $\geq$ 左右子树中所有结点的值。即对于所有非叶子结点 $i$，有 $K_i \geq K_{2i}$ 且 $K_i \geq K_{2i+1}$。
- **小顶堆（Min Heap）**：根结点的值 $\leq$ 左右子树中所有结点的值。即对于所有非叶子结点 $i$，有 $K_i \leq K_{2i}$ 且 $K_i \leq K_{2i+1}$。

> 【核心要点 ⭐】排序时，大顶堆对应**升序**排列，小顶堆对应**降序**排列。

堆的性质：
- 堆中每个结点的值都**大于等于（或小于等于）其左右子结点**的值。
- 堆的**根结点**一定是堆中所有结点的最大值（或最小值）。
- 堆可以用**一维数组**（顺序存储）表示，即堆是"逻辑上的完全二叉树，存储在线性表中"。

**数组下标关系（根结点从 1 开始编号）：**
- 父结点：$i$
- 左孩子：$2i$
- 右孩子：$2i + 1$
- 最后一个非叶子结点：$\lfloor n/2 \rfloor$

#### 4.2.2 堆的调整（筛选 Sift Down / Heapify）⭐

**堆调整（Sift Down）** 是将一个以结点 $s$ 为根的子树调整为堆的过程。

```c
/* 堆调整（筛选）算法 */
void HeapAdjust(Sqlist &L, int s, int m) {
    // 已知 L.r[s..m] 中记录的关键字除 L.r[s].key 外均满足堆的定义
    // 本函数调整 L.r[s] 的关键字，使 L.r[s..m] 成为一个大顶堆
    L.r[0] = L.r[s];  // 暂存
    int rc = L.r[s].key;
    int j;

    for (j = 2 * s; j <= m; j *= 2) {  // 沿关键字较大的孩子结点向下筛选
        if (j < m && LT(L.r[j].key, L.r[j+1].key)) {
            ++j;  // j 为关键字中较大的记录的下标
        }
        if (rc >= L.r[j].key) break;  // rc 应插入在位置 s 上
        L.r[s] = L.r[j];
        s = j;
    }
    L.r[s] = L.r[0];  // 插入
}
```

**筛选过程说明：**
1. 暂存结点 $s$ 的值（即 `r[0]` 监视哨）。
2. 从 $s$ 的左孩子 $2s$ 开始，找出**关键字较大**的孩子结点。
3. 若孩子结点的关键字大于 $s$ 结点的关键字，则将孩子结点上移，继续向下调整。
4. 否则，将暂存的值插入到当前位置。

#### 4.2.3 建堆过程

将无序序列构建成一个堆。从**最后一个非叶子结点**开始，自底向上逐一遍历所有非叶子结点，对每个结点调用 `HeapAdjust`。

```c
/* 建堆 */
void CreatHeap(Sqlist &L) {
    // 对顺序表 L 进行建堆
    for (int i = L.length / 2; i > 0; --i) {
        HeapAdjust(L, i, L.length);
    }
}
```

**建堆的起始位置：**
- 最后一个非叶子结点的下标为 $\lfloor n/2 \rfloor$。
- 从 $\lfloor n/2 \rfloor$ 到 1 依次对每个结点进行筛选。

#### 4.2.4 堆排序完整算法 ⭐🔥

```c
/* 堆排序 */
void HeapSort(Sqlist &L) {
    // 对顺序表 L 进行堆排序
    CreatHeap(L);  // 初始建堆

    for (int i = L.length; i > 1; --i) {
        // 将堆顶元素（最大值）与堆底元素交换
        L.r[0] = L.r[1];
        L.r[1] = L.r[i];
        L.r[i] = L.r[0];

        // 调整剩余元素为堆，此时堆的大小为 i-1
        HeapAdjust(L, 1, i - 1);
    }
}
```

**堆排序的执行过程：**
1. **建堆**：将无序序列建成大顶堆。
2. **交换**：将堆顶元素（最大值）与堆的最后一个元素交换，此时最大值就位。
3. **调整**：将剩余的 $i-1$ 个元素重新调整为堆。
4. **重复**：重复步骤 2 和 3，直到堆中只剩一个元素。

#### 4.2.5 复杂度分析

| 指标 | 结果 | 说明 |
|-----|------|------|
| 最好时间复杂度 | $O(n\log_2 n)$ | 建堆 + 每次调整 |
| 最坏时间复杂度 | $O(n\log_2 n)$ | 始终不变 |
| 平均时间复杂度 | $O(n\log_2 n)$ ⭐ | 始终为 $O(n\log_2 n)$ |
| 空间复杂度 | $O(1)$ | 原地排序，无需额外空间 |
| 稳定性 | **不稳定** ⭐ | 交换操作可能改变等值记录的相对位置 |

**⭐ 核心特性：**
1. 堆排序的时间复杂度在**最好、最坏、平均情况下均为 $O(n\log_2 n)$**，性能稳定。
2. 堆排序是**原地排序**（空间 $O(1)$）。
3. 堆排序是**不稳定**的。
4. 不适用于初始基本有序的序列。

> 【核心要点 ⭐🔥】堆排序最突出的优点是**最坏情况下仍为 $O(n\log_2 n)$**，优于快排。且空间复杂度为 $O(1)$，是原地排序。

#### 4.2.6 堆排序 vs 快速排序

| 比较项 | 堆排序 | 快速排序 |
|-------|--------|---------|
| 平均时间复杂度 | $O(n\log_2 n)$ | $O(n\log_2 n)$ |
| 最坏时间复杂度 | $O(n\log_2 n)$ | $O(n^2)$ |
| 空间复杂度 | $O(1)$ | $O(\log_2 n)$ |
| 稳定性 | 不稳定 | 不稳定 |
| 比较次数 | 较多（与初始状态无关） | 较少（与初始状态有关） |
| 移动次数 | 较少 | 较多 |
| 适用场景 | 数据量大、对稳定性无要求、要求最坏情况保证 | 一般场合，平均性能最优 |

> 【核心要点】在数据量相同的情况下，**快速排序通常比堆排序快**（因为快速排序的比较和移动次数相对较少，且常数因子小）。但当对最坏情况有要求时，堆排序更优。

## 五、归并排序（Merge Sort）⭐🔥

归并排序是**稳定**的 $O(n\log_2 n)$ 排序算法之一，采用分治法策略。

---

### 5.1 基本思想

**归并（Merge）** 是将两个或两个以上的**有序表**组合成一个新的有序表的过程。

**归并排序的基本思想：**
1. 将待排序序列从中间分成两个子序列。
2. 对两个子序列分别递归地进行归并排序。
3. 将两个已排序的子序列**合并**为一个有序序列。

---

### 5.2 算法实现（递归）⭐

```c
/* 将有序的 sr[i..m] 和 sr[m+1..n] 归并为有序的 tr[i..n] */
void Merge(int sr[], int tr[], int i, int m, int n) {
    // sr 为输入，tr 为输出
    int j, k;
    for (j = m + 1, k = i; i <= m && j <= n; ++k) {
        if (LE(sr[i].key, sr[j].key)) {  // LE 表示 <=
            tr[k] = sr[i++];  // 将较小的元素复制到 tr
        } else {
            tr[k] = sr[j++];
        }
    }
    // 将剩余部分复制到 tr
    while (i <= m) {
        tr[k++] = sr[i++];
    }
    while (j <= n) {
        tr[k++] = sr[j++];
    }
}

/* 递归实现归并排序 */
void MSort(int sr[], int tr1[], int s, int t) {
    if (s == t) {
        tr1[s] = sr[s];  // 子序列只有一个元素
    } else {
        int m = (s + t) / 2;  // 划分
        MSort(sr, tr2, s, m);  // 递归排序左半部分
        MSort(sr, tr2, m+1, t);  // 递归排序右半部分
        Merge(tr2, tr1, s, m, t);  // 合并
    }
}

/* 归并排序主函数 */
void MergeSort(Sqlist &L) {
    MSort(L.r, L.r, 1, L.length);
}
```

> 【核心要点】归并排序需要**额外的 $O(n)$ 空间**来存放合并结果。严蔚敏教材中归并排序使用的是两个辅助数组交替使用，以优化空间。

---

### 5.3 复杂度分析

| 指标 | 结果 | 说明 |
|-----|------|------|
| 最好时间复杂度 | $O(n\log_2 n)$ | 所有情况 |
| 最坏时间复杂度 | $O(n\log_2 n)$ | 所有情况 |
| 平均时间复杂度 | $O(n\log_2 n)$ ⭐ | 始终为 $O(n\log_2 n)$ |
| 空间复杂度 | $O(n)$ | 需要 $O(n)$ 的辅助空间 |
| 稳定性 | **稳定** | 合并时相等元素的顺序不变 |

**⭐ 核心特性：**
1. 归并排序的时间复杂度在**所有情况下均为 $O(n\log_2 n)$**。
2. 空间复杂度为 $O(n)$，需要额外的辅助空间。
3. 归并排序是**稳定的**。
4. 是**唯一**稳定的 $O(n\log_2 n)$ 排序算法（与归并有关）。

> 【核心要点 ⭐】归并排序是**唯一稳定的 $O(n\log_2 n)$ 排序算法**，这是它最核心的特征。

---

### 5.4 一趟归并分析

**一趟归并**是指：对序列中长度为 $k$ 的子序列进行两两归并。

- 初始状态：每个子序列长度为 1。
- 第 1 趟归并后：子序列长度为 2。
- 第 2 趟归并后：子序列长度为 4。
- ...
- 第 $k$ 趟归并后：子序列长度为 $2^k$。

**一趟归并的比较次数为 $O(n)$**。共需进行 $\log_2 n$ 趟归并。

---

### 5.5 归并排序的非递归实现

归并排序可以使用非递归（迭代）方式实现，避免递归调用栈：

```c
/* 非递归归并排序 */
void MergeSortNonRec(Sqlist &L, int n) {
    int k = 1;
    while (k < n) {
        MergePass(L.r, L.r1, n, k);  // 一趟归并
        k *= 2;  // 子序列长度加倍
    }
}

/* 一趟归并 */
void MergePass(int sr[], int tr[], int n, int k) {
    int i = 1;
    while (i <= n - 2*k + 1) {
        Merge(sr, tr, i, i+k-1, i+2*k-1);  // 两两归并
        i += 2 * k;
    }
    // 处理剩余元素
    if (i < n - k + 1) {
        Merge(sr, tr, i, i+k-1, n);
    } else {
        for (int j = i; j <= n; ++j) {
            tr[j] = sr[j];
        }
    }
}
```

## 六、基数排序（Radix Sort）⭐了解

基数排序是一种**非比较型**的排序算法，它不通过关键字比较来确定元素的顺序，而是通过**多关键字的分配与收集**完成排序。

---

### 6.1 基本思想

基数排序基于"多关键字排序"的思想：
- 每个关键字由多个"位"组成（如十进制数字的个位、十位、百位等）。
- 从最低位（LSD）或最高位（MSD）开始，逐位进行排序。

#### 6.1.1 LSD（Least Significant Digit）——最低位优先

从最低位（如个位）开始，依次对每一位进行排序，直到最高位。

```
示例：待排序序列 [53, 3, 542, 748, 14, 214, 154, 63, 646]

第 1 趟（按个位）:  542, 646, 14, 214, 154, 53, 3, 63, 748
第 2 趟（按十位）:  542, 646, 748, 14, 214, 154, 53, 3, 63
第 3 趟（按百位）:  3, 14, 53, 63, 154, 214, 542, 646, 748
```

#### 6.1.2 MSD（Most Significant Digit）——最高位优先

从最高位开始，依次对每一位进行排序。MSD 递归处理。

> 【核心要点】408 考研中主要考查 **LSD 基数排序**，MSD 了解即可。

---

### 6.2 算法实现（LSD）

```c
/* LSD 基数排序 */
void RadixSort(RecType r[], int n) {
    int maxd = getMaxDigits(r, n);  // 求最大关键字位数
    int f, e, k;

    for (k = 1; k <= maxd; ++k) {
        // 初始化 n 个箱
        for (int i = 0; i < 10; ++i) {
            first[i] = 0;
            last[i] = -1;
        }

        // 分配：按第 k 位的值分配到不同箱子
        for (int i = 1; i <= n; ++i) {
            kth = getDigit(r[i].key, k);  // 取第 k 位
            if (first[kth] == 0) {
                first[kth] = i;
            } else {
                r[last[kth]].next = i;
            }
            last[kth] = i;
        }

        // 收集：将所有箱子中的记录依次连回
        f = 0;
        for (int i = 0; i < 10; ++i) {
            if (first[i] != 0) {
                if (f == 0) {
                    f = first[i];
                } else {
                    r[last[e]].next = first[i];
                }
                e = last[i];
            }
        }
        r[0].next = f;  // r[0] 为头结点
        // 将链表中记录依次取出
        // ...
    }
}
```

---

### 6.3 复杂度分析

| 指标 | 结果 | 说明 |
|-----|------|------|
| 时间复杂度 | $O(d(n+r))$ | $d$ 为关键字位数（基数），$r$ 为基数（如 $r=10$） |
| 空间复杂度 | $O(n+r)$ | $n$ 为记录数，$r$ 为基数 |
| 稳定性 | **稳定** | 基于分配与收集的稳定操作 |

**参数说明：**
- $d$：关键字的位数（如三位数，$d = 3$）。
- $r$：基数（如十进制，$r = 10$）。
- 总共进行 $d$ 趟分配和收集，每趟的时间复杂度为 $O(n+r)$。
- 总时间复杂度：$O(d \times (n + r))$。

> 【核心要点】基数排序**不进行比较**，因此不受 $O(n\log_2 n)$ 的比较排序下界的限制。当 $d$ 较小且 $r$ 不太大时，基数排序效率很高。但基数排序仅适用于**整型**或可分解为多关键字的场景。

---

## 七、各种排序算法的综合比较 ⭐🔥

### 7.1 排序算法综合对比表

| 排序方法 | 最好时间复杂度 | 最坏时间复杂度 | 平均时间复杂度 | 空间复杂度 | 稳定性 | 关键字比较次数 | 记录移动次数 | 适用场景 |
|---------|--------------|--------------|--------------|-----------|-------|--------------|------------|---------|
| 直接插入排序 | $O(n)$ | $O(n^2)$ | $O(n^2)$ | $O(1)$ | 稳定 | 约 $\frac{n^2}{4}$ | 约 $\frac{n^2}{4}$ | $n$ 较小、基本有序 |
| 折半插入排序 | $O(n\log_2 n)$ | $O(n^2)$ | $O(n^2)$ | $O(1)$ | 稳定 | $O(n\log_2 n)$ | 约 $\frac{n^2}{4}$ | 比较耗时时 |
| 希尔排序 | $O(n\log_2 n)$ | 依赖增量 | 依赖增量 | $O(1)$ | **不稳定** | 较少 | 较少 | $n$ 较大、无稳定性要求 |
| 冒泡排序 | $O(n)$ | $O(n^2)$ | $O(n^2)$ | $O(1)$ | 稳定 | 约 $\frac{n^2}{4}$ | 约 $\frac{n^2}{4}$ | $n$ 较小、基本有序 |
| 快速排序 | $O(n\log_2 n)$ | $O(n^2)$ | $O(n\log_2 n)$ | $O(\log_2 n)$ | **不稳定** | 约 $n\log_2 n$ | 约 $n\log_2 n$ | 一般场合（平均最优） |
| 简单选择排序 | $O(n^2)$ | $O(n^2)$ | $O(n^2)$ | $O(1)$ | **不稳定** | $\frac{n(n-1)}{2}$ | 最多 $3(n-1)$ | 记录移动次数要最少时 |
| 堆排序 | $O(n\log_2 n)$ | $O(n\log_2 n)$ | $O(n\log_2 n)$ | $O(1)$ | **不稳定** | 约 $n\log_2 n$ | 约 $n\log_2 n$ | $n$ 较大、要求最坏保证 |
| 归并排序 | $O(n\log_2 n)$ | $O(n\log_2 n)$ | $O(n\log_2 n)$ | $O(n)$ | 稳定 | 约 $n\log_2 n$ | $n\log_2 n$ | 对稳定性有要求、外排序 |
| 基数排序 | $O(d(n+r))$ | $O(d(n+r))$ | $O(d(n+r))$ | $O(n+r)$ | 稳定 | 0（不比较） | $O(d(n+r))$ | 关键字位数小、范围可控 |

### 7.2 高频考点总结 ⭐🔥🔥

#### 最快平均时间复杂度（$O(n\log_2 n)$）
- **快速排序**：平均性能最好，常数因子最小。
- **堆排序**：最坏情况仍为 $O(n\log_2 n)$，性能稳定。
- **归并排序**：唯一稳定的 $O(n\log_2 n)$ 排序。

#### 最慢平均时间复杂度（$O(n^2)$）
- **直接插入排序**、**冒泡排序**、**简单选择排序**、**希尔排序**（最坏）。

#### 关键结论（⭐ 选择题高频）

1. **唯一稳定的 $O(n\log_2 n)$ 排序**：**归并排序**。
2. **唯一稳定的 $O(n^2)$ 排序**：**直接插入排序** 和 **冒泡排序**（折半插入也稳定，但时间复杂度仍为 $O(n^2)$）。
3. **原地排序**（空间 $O(1)$）：直接插入排序、冒泡排序、简单选择排序、堆排序、希尔排序、快速排序。
4. **非原地排序**：归并排序 $O(n)$、基数排序 $O(n+r)$。
5. **时间复杂度与初始状态无关**：简单选择排序、堆排序、归并排序、基数排序。
6. **记录移动次数最少**：简单选择排序（最多 $3(n-1)$ 次）。
7. **最坏时间复杂度 $O(n^2)$**：快速排序（已有序序列且取首元素为枢轴）。
8. **最坏时间复杂度 $O(n\log_2 n)$**：堆排序、归并排序、基数排序。
9. **最好时间复杂度 $O(n)$**：直接插入排序（已有序）、冒泡排序（已有序且优化）。

### 7.3 算法选择建议

在实际应用中，排序算法的选择策略如下：

| 场景 | 推荐算法 |
|-----|---------|
| 数据量小（$n < 50$） | 直接插入排序、冒泡排序 |
| 数据基本有序 | 直接插入排序、冒泡排序 |
| 数据量大、无稳定性要求 | 快速排序（首选）、堆排序 |
| 要求最坏情况保证 | 堆排序、归并排序 |
| 要求稳定性 | 归并排序（唯一稳定的 $O(n\log_2 n)$） |
| 数据量大、对稳定性无要求且需最坏 $O(n\log_2 n)$ | 堆排序 |
| 关键字为整数、位数少 | 基数排序 |
| 外部排序（数据量极大） | 归并排序（多路归并） |

> 【核心要点】实际应用中常采用**混合策略**：当子序列长度小于某个阈值时采用直接插入排序，否则采用快速排序。这是快速排序优化中常见的做法。

### ⚖️易混淆概念对比

#### 对比一：快速排序 vs 堆排序

| 比较项 | 快速排序 | 堆排序 |
|-------|---------|--------|
| 平均性能 | 更快（常数因子小） | 稍慢 |
| 最坏性能 | $O(n^2)$ | $O(n\log_2 n)$ |
| 空间复杂度 | $O(\log_2 n)$ | $O(1)$ |
| 稳定性 | 不稳定 | 不稳定 |
| 比较次数 | 较少 | 较多（与初始状态无关） |
| 实际运行速度 | 通常更快 | 通常稍慢 |
| 适用场合 | 一般场合首选 | 对最坏情况有要求的场合 |

#### 对比二：快速排序 vs 归并排序

| 比较项 | 快速排序 | 归并排序 |
|-------|---------|---------|
| 平均性能 | 更快 | 稍慢 |
| 最坏性能 | $O(n^2)$ | $O(n\log_2 n)$ |
| 空间复杂度 | $O(\log_2 n)$ | $O(n)$ |
| 稳定性 | 不稳定 | 稳定 |
| 排序方式 | 原地分区 | 需要辅助数组 |
| 适用场合 | 内存受限、无需稳定性 | 要求稳定性、外排序 |

#### 对比三：直接插入排序 vs 冒泡排序

| 比较项 | 直接插入排序 | 冒泡排序 |
|-------|------------|---------|
| 核心操作 | 插入到已排序区间 | 两两比较交换 |
| 最好情况 | $O(n)$（已有序） | $O(n)$（已有序，优化后） |
| 平均性能 | 略优（移动次数少） | 略差（交换频繁） |
| 稳定性 | 稳定 | 稳定 |
| 实现复杂度 | 简单 | 简单 |

> 【核心要点】直接插入排序在性能上通常略优于冒泡排序，因为插入排序通过"后移"而非"逐次交换"来完成操作，减少了交换次数。

#### 对比四：希尔排序 vs 直接插入排序

| 比较项 | 希尔排序 | 直接插入排序 |
|-------|---------|------------|
| 思想 | 缩小增量、分组插入 | 逐个插入 |
| 时间复杂度 | 优于 $O(n^2)$（合适增量） | $O(n^2)$ |
| 稳定性 | 不稳定 | 稳定 |
| 适用场景 | $n$ 较大 | $n$ 较小或基本有序 |

### ⚠️考试高频坑点

1. **快速排序的最坏情况**：已排序序列且选第一个元素为枢轴时，时间复杂度退化为 $O(n^2)$。常见错误答案：认为快排始终为 $O(n\log_2 n)$。

2. **堆排序的稳定性**：堆排序是**不稳定**的。常见错误：认为建堆后只交换堆顶和堆底，所以稳定。（实际上筛选过程中相等元素可能改变相对位置。）

3. **简单选择排序的时间复杂度与初始状态无关**：无论序列是否有序，比较次数始终是 $\frac{n(n-1)}{2}$。

4. **折半插入排序的时间复杂度仍为 $O(n^2)$**：虽然比较次数减少为 $O(n\log_2 n)$，但移动次数仍为 $O(n^2)$，总体仍为 $O(n^2)$。

5. **希尔排序的不稳定性**：希尔排序在多次增量插入过程中，相同关键字的记录可能改变相对位置。

6. **归并排序的空间复杂度为 $O(n)$**：归并排序需要辅助数组存储合并结果，这是它唯一比快速排序和堆排序差的地方。

7. **快速排序的空间复杂度为 $O(\log_2 n)$ 而非 $O(1)$**：快速排序需要递归栈空间，不是真正的原地排序。

8. **冒泡排序的优化**：未优化的冒泡排序在最好情况下仍为 $O(n^2)$（仍需遍历所有趟），只有加入"提前终止"标志后才是 $O(n)$。

9. **基数排序不进行比较**：基数排序通过"分配与收集"完成排序，关键字比较次数为 0，因此不受比较排序 $O(n\log_2 n)$ 下界的限制。

10. **"原地排序"的定义**：空间复杂度为 $O(1)$ 的排序才是原地排序。快速排序不是原地排序（需要 $O(\log_2 n)$ 栈空间）。
