## 📝核心概念与原理

### 一、基本概念与术语

#### 1. 数据（Data）

**数据**是描述客观事物的数值、字符以及能输入到计算机中并被计算机程序处理的**所有符号的集合**。它是计算机程序处理的对象的全体。

- **数据元素**（Data Element）：是数据的基本单位，在计算机程序中通常作为一个整体进行考虑和处理。一个数据元素可由若干个**数据项**（Data Item）组成。
- **数据项**：是数据的不可分割的最小单位。例如，一个学生记录（数据元素）可由学号、姓名、成绩等数据项组成。

> **示例**：在一元多项式 $P_n(x) = p_0 + p_1x + p_2x^2 + \cdots + p_nx^n$ 中，每一项 $p_i x^i$ 可看作一个数据元素，而系数 $p_i$ 和指数 $i$ 则是数据项。

#### 2. 数据结构（Data Structure）

**数据结构**是相互之间存在**一种或多种特定关系**的数据元素的集合。通常包括三个方面的内容：

| 层面 | 含义 | 举例 |
|------|------|------|
| **逻辑结构** | 数据元素之间的逻辑关系，与数据的存储无关 | 线性结构（线性表）、树形结构（树）、图状结构（图） |
| **存储结构**（物理结构） | 数据的逻辑结构在计算机存储器中的实现（表示） | 顺序存储、链式存储 |
| **数据运算** | 施加在数据上的操作集合 | 检索、插入、删除、修改、遍历、排序 |

> **严蔚敏教材定义要点**：数据结构是一门研究非数值计算的程序设计问题中计算机的操作对象以及它们之间的关系和操作等的学科。

#### 3. 抽象数据类型（ADT）

**抽象数据类型**（Abstract Data Type, ADT）是指一个数学模型以及定义在该模型上的一组操作。其核心特征是"抽象"——仅描述数据类型相关的特性（数据的逻辑结构、操作的定义），而**不关心具体实现**（存储方式和操作的具体算法）。

ADT 的三元组定义形式为：

$$ADT = (D, S, P)$$

- $D$：数据对象的有限集合
- $S$：$D$上关系的有限集合
- $P$：对$D$的基本操作集合

以**抽象数据类型线性表**为例：

```
ADT 线性表 (List) {
    数据对象：D = {a_i | a_i ∈ Element, i = 1,2,...,n, n ≥ 0}
    数据关系：R1 = {<a_{i-1}, a_i> | a_{i-1}, a_i ∈ D, i = 2,3,...,n}
    基本操作：
        InitList(&L)     // 初始化
        ListInsert(&L, i, e)  // 插入
        ListDelete(&L, i, &e) // 删除
        ...
}
```

### 二、数据的逻辑结构 ⭐选择题高频考点

数据的逻辑结构是指数据元素之间**逻辑关系**的总和。它独立于计算机，是面向问题的。根据数据元素之间关系的特征，逻辑结构可分为以下四类：

#### 1. 集合结构

数据元素之间仅有"同属于一个集合"的关系，除此之外**无其他逻辑关系**。

```
示例：{A, B, C, D, E}
关系：所有元素平等地属于同一集合，无先后之分
```

#### 2. 线性结构

数据元素之间呈**一对一**的线性关系，即除第一个和最后一个外，每个元素有且仅有一个直接前驱和一个直接后继。

```
示例：{A, B, C, D, E}
关系：A→B→C→D→E
其中：A无前驱，E无后继；B、C、D各有唯一前驱和后继
```

典型逻辑结构：[[数据结构与算法/笔记/线性表]]、[[数据结构与算法/笔记/栈和队列]]

> **线性结构的特点**（判断要点）：
> - 存在唯一的**首元素**，它无前驱
> - 存在唯一的**尾元素**，它无后继
> - 其余元素均有且仅有一个**前驱**和一个**后继**

#### 3. 树形结构

数据元素之间呈**一对多**的层次关系，即每个元素（除根节点外）有且仅有一个直接前驱（父节点），但可以有多个直接后继（子节点）。

```
示例：树结构
          A
         /|\
        B C D
       /|
      E F
关系：A是根，B、C、D是A的孩子；E、F是B的孩子
```

典型逻辑结构：[[数据结构与算法/笔记/树与二叉树]]

#### 4. 图状结构（或称网状结构）

数据元素之间呈**多对多**的关系，即任一元素的前驱和后继个数均不固定。

```
示例：图结构
    A ↔ B ↔ C
    ↑ ↘  ↗  ↑
    D ↔ E
关系：任意两个节点之间都可能存在关联
```

典型逻辑结构：[[数据结构与算法/笔记/图]]

#### 逻辑结构对比总结

| 逻辑结构 | 关系特征 | 元素关系 | 首/尾元素 | 典型代表 |
|----------|----------|----------|-----------|----------|
| 集合 | 无关系 | 同属集合 | 无 | 集合 |
| 线性结构 | 一对一 | 唯首唯尾，其余一对一 | 有唯一首、唯一尾 | 线性表、栈、队列 |
| 树形结构 | 一对多 | 除根外各一个前驱，可有多个后继 | 有唯一根，多个叶 | 树、二叉树 |
| 图状结构 | 多对多 | 任意关系 | 无 | 图、有向图、网 |

> **考试要点**：选择题中常给出一个具体实例，要求判断其逻辑结构类型。判断的关键是看数据元素之间关系的"一对一/一对多/多对多"特征。

### 三、数据的存储结构 🔥大题考点

数据的存储结构（物理结构）是数据的逻辑结构在计算机中的**实现/表示**。同一种逻辑结构可以有不同的存储表示。

#### 1. 顺序存储（Sequential Storage）

**定义**：把逻辑上相邻的数据元素存储在物理位置上**相邻**的存储单元中，数据元素之间的逻辑关系由存储位置的邻接关系来体现。

```
逻辑结构：A → B → C → D → E

顺序存储：
内存：| A | B | C | D | E |
      ^          ^
     地址i    地址i+1

元素a_i的地址 = LOC(a_1) + (i-1) × L   （L为每个元素所占存储单元数）
```

**特点**：
- 优点：存储密度高（存储密度 = 结点数据所占存储 / 结点总存储 = 1）；支持随机访问（通过下标直接定位）
- 缺点：插入、删除需要移动大量元素；需要预先分配连续存储空间

**典型实现**：数组（Array）

#### 2. 链式存储（Chained Storage）

**定义**：逻辑上相邻的数据元素在物理位置上**不必相邻**，通过指针来反映数据元素之间的逻辑关系。

```
逻辑结构：A → B → C → D → E

链式存储：
内存：| A |→| B |→| C |→| D |→| E |→ NULL
      | 指针|  | 指针|  | 指针|  | 指针|
```

每个结点通常由两部分组成：
- **数据域**：存储数据元素本身
- **指针域**：存储直接后继的存储地址

**特点**：
- 优点：插入、删除灵活（只需修改指针）；动态分配存储空间，无需预先分配
- 缺点：存储密度低（需额外空间存储指针）；不支持随机访问，只能顺序访问

**典型实现**：链表（Linked List）——直接后继地址存储在**前一结点**的指针域中。

> **对比记忆**：顺序存储用"数组"实现，链式存储用"链表"实现。同一逻辑结构（如线性表）可以用不同存储结构来实现。

#### 3. 索引存储（Indexed Storage）

在存储数据元素的同时，还建立**附加的索引表**。索引表中的每项称为**索引项**，索引项的一般形式为：`(关键字，地址)`。

```
数据区：    | A(关键字10) | B(关键字20) | C(关键字30) |
索引区：   |  10 → 地址1 |  20 → 地址2 |  30 → 地址3 |
```

**特点**：
- 优点：检索速度快
- 缺点：增加了额外的存储空间；插入、删除时需要维护索引表

**典型应用**：数据库中的索引结构

#### 4. 散列存储（Hash Storage / 哈希存储）

根据数据元素的**关键字**直接计算出该元素的存储地址，即 `H(key)`。

```
关键字 key → 哈希函数 H(key) → 存储地址
```

**特点**：
- 优点：检索速度极快（平均 $O(1)$）
- 缺点：可能产生冲突（不同关键字映射到同一地址），需要冲突处理策略；不适合范围查找

**典型应用**：哈希表（Hash Table）

#### 存储结构对比总结

| 存储结构 | 特点 | 优点 | 缺点 | 存储密度 |
|----------|------|------|------|----------|
| 顺序存储 | 逻辑相邻→物理相邻 | 随机访问，存储密度高 | 插删需移动，需连续空间 | 高 |
| 链式存储 | 逻辑关系→指针指示 | 插删灵活，动态分配 | 不可随机访问，需额外空间 | 低 |
| 索引存储 | 附加索引表 | 检索速度快 | 需额外空间，维护复杂 | 中 |
| 散列存储 | 关键字→直接地址 | 检索速度最快 | 有冲突，不可范围查找 | 中 |

> **考试要点**：选择题常考"同一逻辑结构可对应多种存储结构"这一概念，以及各存储结构的优缺点对比。

### 四、数据的运算

数据运算是指施加在数据上的操作集合，主要包括以下六种：

| 运算 | 描述 | 说明 |
|------|------|------|
| **检索/查找** | 根据给定值找出满足条件的数据元素 | 静态运算，不改变数据 |
| **插入** | 将新数据元素插入到指定位置 | 动态运算，数据元素个数+1 |
| **删除** | 将指定位置的数据元素从集合中移除 | 动态运算，数据元素个数-1 |
| **修改** | 修改指定位置上数据元素的值 | 动态运算，元素个数不变 |
| **遍历** | 按某种次序访问数据结构中每个元素，且每个元素仅被访问一次 | 可视为一种特殊的检索 |
| **排序** | 将数据元素按关键字的某种次序重新排列 | 动态运算 |

> **重要关系**：一种数据逻辑结构上定义的运算与它的存储结构密切相关。例如，对于线性表的"插入"运算，在顺序存储下需要移动元素（$O(n)$），在链式存储下只需修改指针（$O(1)$，但找到位置仍需遍历）。

### 五、算法及其特性 ⭐选择题高频考点

#### 1. 算法的定义

**算法**（Algorithm）是**解决特定问题**的有限步骤的描述，或者说是一组**有穷的**指令集合，每条指令对应一个或多个操作。

#### 2. 算法的5个特性 ⭐

| 特性 | 含义 | 说明 |
|------|------|------|
| **有穷性**（Finiteness） | 算法必须在执行**有限步**后结束，且每一步都在**有限时间**内完成 | 无限循环不是算法 |
| **确定性**（Definiteness） | 算法的**每条指令**必须有**确切的含义**，不能有二义性 | 相同的输入必须得到相同的输出 |
| **可行性**（Effectiveness） | 算法中的所有操作都可以通过**已经实现**的基本操作**有限次**执行完成 | 算法必须是可执行的 |
| **输入**（Input） | 算法有**零个或多个**输入 | 零输入也是合法的 |
| **输出**（Output） | 算法有**一个或多个**输出 | 输出的结果与输入之间存在确定关系 |

> **经典考题**：以下哪些是算法的特性？常见干扰项包括"高效性""存储量低"等——这些是"好算法"的**评价标准**，而非算法的**基本特性**。

#### 3. 好算法的评价标准

| 标准 | 说明 |
|------|------|
| **正确性** | 算法应能正确解决问题 |
| **可读性** | 算法应易于理解、交流 |
| **健壮性** | 当输入非法数据时，能做出合理响应而非崩溃 |
| **高效率** | 包括时间效率高（时间复杂度低）和存储空间效率高（空间复杂度低） |

### 六、算法分析 ⭐⭐ 全卷最高频考点

算法分析的核心任务：在算法实现之前，**定性**和**定量**地分析算法的效率，即估算算法所需的**时间**资源和**空间**资源。

#### 1. 时间复杂度

**时间复杂度**（Time Complexity）：定性描述算法**运行时间**随问题规模 $n$ 增长的**变化趋势**。它不是算法执行的绝对时间，而是执行过程中**基本操作重复执行的次数**（与机器速度、编程语言无关）。

**求取方法（四步法）**：

> **Step 1**：找出算法中的**基本操作**（通常是最深层循环内的语句）
> **Step 2**：估算基本操作的**执行次数** $T(n)$（关于问题规模 $n$ 的函数）
> **Step 3**：求 $T(n)$ 的**数量级**（即最高阶），使用大O记号表示
> **Step 4**：写出时间复杂度的大O表示

**常见求取技巧**：

| 场景 | 方法 | 示例 |
|------|------|------|
| 无循环/顺序结构 | 直接统计执行次数 | $T(n) = 3n + 2 \Rightarrow O(n)$ |
| 单层循环 | 循环次数 × 循环体内执行次数 | `for(i=0;i<n;i++) x++;` → $O(n)$ |
| 多层循环 | 各层循环次数**相乘** | `for(i=0;i<n;i++) for(j=0;j<m;j++) x++;` → $O(nm)$ |
| 嵌套循环（内层与n相关） | 累加求和 | `for(i=0;i<n;i++) for(j=i;j<n;j++) x++;` → $\sum_{i=0}^{n-1}(n-i) = n^2/2 \Rightarrow O(n^2)$ |
| 分支结构（if/else） | 取**最坏情况** | `if(a>b) for(...) else for(...)` → 取执行次数多的分支 |
| 递归算法 | 建立递归方程后求解 | 见下文递归分析法 |

**大O记号的数学定义**：

若存在正常数 $c$ 和 $n_0$，使得当 $n \geq n_0$ 时，$f(n) \leq c \cdot g(n)$ 恒成立，则记为 $f(n) = O(g(n))$，称 $g(n)$ 是 $f(n)$ 的**上界**。

直观理解：$O(g(n))$ 表示 $f(n)$ 的增长速度**不超过** $g(n)$。

#### 2. 常见时间复杂度排序 ⭐

从小到大排列（从低到高，性能由优到劣）：

$$O(1) \lt O(\log_2 n) \lt O(n) \lt O(n \log_2 n) \lt O(n^2) \lt O(n^3) \lt O(2^n) \lt O(n!) \lt O(n^n)$$

| 复杂度 | 名称 | 典型算法 |
|--------|------|----------|
| $O(1)$ | 常数阶 | 直接访问数组元素 |
| $O(\log_2 n)$ | 对数阶 | 二分查找、辗转相除法 |
| $O(n)$ | 线性阶 | 遍历数组、单重循环 |
| $O(n \log_2 n)$ | 线性对数阶 | 快速排序（平均）、归并排序、堆排序 |
| $O(n^2)$ | 平方阶 | 冒泡排序、插入排序、选择排序 |
| $O(n^3)$ | 立方阶 | 朴素矩阵乘法（三重循环） |
| $O(2^n)$ | 指数阶 | 求解子集的枚举算法 |
| $O(n!)$ | 阶乘阶 | 旅行商问题的暴力解法 |

> **核心结论（必须牢记）**：
> - 随着问题规模 $n$ 增大，低阶项和常数系数**可以忽略不计**
> - 例如：$T(n) = 3n^2 + 17n + 5$ 的时间复杂度为 $O(n^2)$
> - 判断原则：**取最高阶项作为数量级**

> **重要推论**：
> - 若算法外层循环执行 $m$ 次，内层循环执行 $n$ 次，则总次数为 $mn$ 次，时间复杂度为 $O(mn)$。当 $m$ 与 $n$ 无关时，可视 $m$ 为常数。
> - 对数阶 $O(\log_2 n)$ 通常出现在将问题规模**每次减半**的算法中。例如二分查找每轮将范围缩小为原来的一半，故执行次数为 $\log_2 n$。

#### 3. 时间复杂度求取示例

**示例1——顺序结构：**
```c
x = 1;                          // 执行1次
while(x < n) {
    x = x * 2;                   // 执行? 次
}
```
`x` 每次乘以 2，执行 $k$ 次后 $2^k \geq n$，即 $k \geq \log_2 n$，所以 $T(n) = O(\log_2 n)$。

**示例2——循环结构：**
```c
s = 0;                           // 执行1次
for(i = 0; i < n; i++)           // 执行n次
    for(j = 0; j < n; j++)       // 内层执行 n×n 次
        s++;                      // 执行 n² 次
```
$T(n) = n^2 + n + 1 \Rightarrow O(n^2)$

**示例3——分支结构（取最坏情况）：**
```c
if(a > b) {
    for(i = 0; i < n; i++) x++;  // n次
} else {
    for(i = 0; i < n; i++)
        for(j = 0; j < n; j++) x++; // n² 次
}
```
最坏情况为 else 分支：$T(n) = O(n^2)$

**示例4——递归算法（二分查找）：**
```c
int BinSearch(int A[], int low, int high, int key) {
    if(low > high) return -1;    // 基本情况
    int mid = low + (high - low) / 2;  // 执行1次
    if(A[mid] == key) return mid;        // 执行1次
    else if(A[mid] > key) return BinSearch(A, low, mid-1, key);
    else return BinSearch(A, mid+1, high, key);
}
```
递归方程：$T(n) = T(n/2) + O(1)$，由主定理得 $T(n) = O(\log_2 n)$。

#### 4. 空间复杂度

**空间复杂度**（Space Complexity）：算法运行所需**存储空间**随问题规模 $n$ 增长的**变化趋势**，记为 $S(n) = O(g(n))$。

空间复杂度考虑的因素：
- **输入数据占用的空间**（通常不计入，因为它是问题本身所需的）
- **算法本身占用的空间**（指令常数、常量常数）
- **辅助空间**（算法执行过程中临时分配的存储空间）——这是主要考量

**常见空间复杂度**：

| 空间复杂度 | 场景 | 说明 |
|------------|------|------|
| $O(1)$ | 原地算法 | 仅使用常数个辅助变量 |
| $O(n)$ | 线性表、数组复制 | 需要额外 $O(n)$ 的空间 |
| $O(n^2)$ | 二维数组 | 需要 $O(n^2)$ 的空间 |
| $O(\log_2 n)$ | 递归深度 | 递归栈的深度 |
| $O(n)$ | 递归深度为n | 最坏情况下的递归调用栈 |

> **注意**：递归算法的空间复杂度主要看**递归调用栈的最大深度**。例如归并排序递归深度为 $\log_2 n$，每层需要 $O(n)$ 的辅助空间，总空间复杂度为 $O(n)$。

#### 5. 渐近复杂度记号 ⭐

以下五个记号用于描述函数的**渐近行为**，是算法分析的核心工具：

| 记号 | 名称 | 数学定义 | 直观含义 |
|------|------|----------|----------|
| $O$ | 大O记号（上界） | $f(n) = O(g(n))$ 当且仅当存在正常数 $c, n_0$ 使得 $\forall n \geq n_0, 0 \leq f(n) \leq c \cdot g(n)$ | $f(n)$ 的增长速度**不超过** $g(n)$ |
| $\Omega$ | 大Ω记号（下界） | $f(n) = \Omega(g(n))$ 当且仅当存在正常数 $c, n_0$ 使得 $\forall n \geq n_0, 0 \leq c \cdot g(n) \leq f(n)$ | $f(n)$ 的增长速度**不低于** $g(n)$ |
| $\Theta$ | 大Θ记号（紧界） | $f(n) = \Theta(g(n))$ 当且仅当 $f(n) = O(g(n))$ 且 $f(n) = \Omega(g(n))$ | $f(n)$ 的增长速度**与** $g(n)$ **同阶** |
| $o$ | 小o记号（非紧上界） | $f(n) = o(g(n))$ 当且仅当对任意正常数 $c > 0$，存在 $n_0$ 使得 $\forall n \geq n_0, 0 \leq f(n) < c \cdot g(n)$ | $f(n)$ 的增长速度**严格低于** $g(n)$ |
| $\omega$ | 小ω记号（非紧下界） | $f(n) = \omega(g(n))$ 当且仅当对任意正常数 $c > 0$，存在 $n_0$ 使得 $\forall n \geq n_0, 0 \leq c \cdot g(n) < f(n)$ | $f(n)$ 的增长速度**严格高于** $g(n)$ |

**关系总结**：

```
           f(n) = o(g(n))    ⊂    f(n) = O(g(n))
                                    |
           f(n) = ω(g(n))    ⊂    f(n) = Ω(g(n))
                                    |
           f(n) = Θ(g(n))  =  f(n) = O(g(n)) ∩ f(n) = Ω(g(n))
```

> **直观理解口诀**：
> - 大O = "不超过"（≤）
> - 大Ω = "不低于"（≥）
> - 大Θ = "等于"（=，同阶）
> - 小o = "严格低于"（<）
> - 小ω = "严格高于"（>）

**常见关系示例**：

| 关系 | 示例 | 说明 |
|------|------|------|
| $3n + 5 = O(n)$ | $3n+5 \leq 4n$，取 $c=4, n_0=5$ | 成立 |
| $3n + 5 = \Omega(n)$ | $3n+5 \geq 3n$，取 $c=3, n_0=0$ | 成立 |
| $3n + 5 = \Theta(n)$ | 同时满足上、下界 | 成立，$3n+5$ 与 $n$ 同阶 |
| $3n + 5 = o(n^2)$ | $3n+5$ 的增长速度严格低于 $n^2$ | 成立 |
| $n^2 = \omega(n)$ | $n^2$ 的增长速度严格高于 $n$ | 成立 |
| $3n + 5 = O(n^2)$ | $3n+5 \leq 3n^2$，取 $c=3, n_0=2$ | 成立，但**不是紧确界** |

### 六、算法效率与数据结构的联系

数据结构与算法是**相辅相成**的两个概念：

1. **数据结构是算法的基础**——合适的数据结构可以使算法更加高效
2. **算法是数据结构的灵魂**——算法的有效性依赖于数据结构的有效组织
3. **存储结构影响运算效率**——同一逻辑结构在不同存储方式下，各运算的时间复杂度可能不同

> **关键认知**：在408考试中，数据结构的选择直接影响算法的时间复杂度和空间复杂度。例如，在线性查找中，使用顺序存储（数组）可以直接按位置访问，而链式存储（链表）需要逐个遍历；但在频繁插入删除的场景下，链式存储的优势则凸显。

## ⚖️易混淆概念对比

### 对比一：逻辑结构 vs 存储结构

| 对比项 | 逻辑结构 | 存储结构 |
|--------|----------|----------|
| **关注点** | 数据元素之间的**关系** | 数据在计算机中的**存储方式** |
| **独立性** | 独立于计算机，面向问题 | 依赖于计算机，面向实现 |
| **分类** | 集合、线性、树形、图状 | 顺序、链式、索引、散列 |
| **关系** | 一种逻辑结构可以有多种存储结构 | 一种存储结构可以实现多种逻辑结构 |

**经典例题**：
> Q：线性表的逻辑结构属于什么类型？
> A：**线性结构**（一对一关系）。注意：逻辑结构不分"顺序"或"链式"，那是存储结构的概念。

**经典例题**：
> Q：在顺序存储方式下，线性表中相邻的两个元素在物理位置上也一定相邻吗？
> A：**一定相邻**。顺序存储的本质就是逻辑相邻 → 物理相邻。

### 对比二：大O vs 小o

| 记号 | 含义 | 关系 | 示例 |
|------|------|------|------|
| $O(g(n))$ | 上界（可相等） | 包含 Θ 和 o | $2n + 3 = O(n)$ |
| $o(g(n))$ | 严格上界（不可相等） | 真子集 | $2n + 3 = o(n^2)$ |

关键区分：
- 若 $\lim_{n \to \infty} \frac{f(n)}{g(n)} = c$（$c$ 为常数且 $c \neq 0$），则 $f(n) = \Theta(g(n))$，此时 $f(n) = O(g(n))$ 但 $f(n) \neq o(g(n))$
- 若 $\lim_{n \to \infty} \frac{f(n)}{g(n)} = 0$，则 $f(n) = o(g(n))$

### 对比三：数据元素 vs 数据项

| 对比项 | 数据元素 | 数据项 |
|--------|----------|--------|
| **地位** | 数据的基本单位 | 数据的不可分割最小单位 |
| **处理** | 在程序中作为一个整体处理 | 构成数据元素的最小成分 |
| **举例** | 一个学生的完整记录 | 学生的学号、姓名、年龄 |

### 对比四：ADT vs 具体实现

| 对比项 | ADT | 具体实现 |
|--------|-----|----------|
| **关注** | "做什么" | "怎么做" |
| **内容** | 数据模型 + 操作定义 | 存储结构 + 具体算法 |
| **抽象程度** | 高（与实现无关） | 低（与实现相关） |
| **示例** | ADT 线性表：有插入、删除等操作 | 用数组实现线性表 vs 用链表实现线性表 |

## ⚠️考试高频坑点

### 坑点1：混淆"算法特性"与"好算法的评价标准"

- **算法的5个特性**（必须满足）：有穷性、确定性、可行性、输入、输出
- **好算法的评价标准**（追求的目标）：正确性、可读性、健壮性、高效率
- **常见错误选项**："高效性"是算法特性的说法是**错误的**——高效性是评价标准，不是必要特性

### 坑点2：混淆"逻辑结构"的分类与"存储结构"的分类

- 逻辑结构分：集合、线性、树形、图状
- 存储结构分：顺序、链式、索引、散列
- **绝对不可混淆**：不能说"线性表的存储结构是线性的"——逻辑结构才是线性的

### 坑点3：时间复杂度求取的常见错误

| 错误 | 正解 |
|------|------|
| 忽略循环嵌套，直接把循环次数相加 | 嵌套循环应相乘：$O(n) \times O(m) = O(nm)$ |
| 保留常数系数 | $O(2n) = O(n)$，常数系数应省略 |
| 保留低阶项 | $O(n^2 + 100n + 500) = O(n^2)$，低阶应省略 |
| 取最好情况的时间复杂度 | 算法的时间复杂度默认取**最坏情况** |
| 误以为 $O(1)$ 表示只执行一条语句 | $O(1)$ 表示执行时间与 $n$ 无关，可能执行多条语句 |

### 坑点4：对数阶的理解

- $O(\log_2 n)$ 出现在**每次将规模减半**的场景中（如二分查找）
- 如果每次规模减 3，则复杂度为 $O(\log_3 n)$，但根据换底公式 $\log_3 n = \frac{\log_2 n}{\log_2 3}$，常数系数可省略，故仍然是 $O(\log_2 n)$
- **无论底数是多少，对数阶统一记为 $O(\log n)$**

### 坑点5：空间复杂度与辅助空间

- 算法的空间复杂度**主要考虑辅助空间**（临时分配的空间）
- 输入数据所占空间通常**不计入**空间复杂度
- 递归算法的空间复杂度看递归调用栈的深度

### 坑点6：渐近记号的正确使用

- $f(n) = O(g(n))$ 读作"f 是 g 的渐近上界"，**不是**"f 等于 g 的某个函数"
- 正确的数学表述是 $f(n) \in O(g(n))$（f 属于 O(g(n)) 这个集合），但考研中习惯用等号表示
- $O(1)$ 不一定表示"执行1次"，而是表示"与问题规模无关"

1. **数据结构 = 逻辑结构 + 存储结构 + 数据运算**，三个层面缺一不可
