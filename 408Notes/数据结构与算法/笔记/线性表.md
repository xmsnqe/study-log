# 线性表（Linear List）

## 一、线性表的定义和基本操作

### 📍知识定位

线性表是数据结构中最基础、最核心的数据结构之一，是后续学习栈、队列、串、数组等线性结构的基础。在408计算机考研中，线性表是必考内容，选择题和大题均有涉及，尤其是顺序表和单链表的插入、删除操作的时间复杂度分析为高频考点。

---

### 📝核心概念与原理

#### 1. 线性表的定义

**线性表（Linear List）** 是最简单且最常用的一种数据结构。**一个线性表是 n 个数据元素的有限序列**，记为：

$$L = (a_1, a_2, \cdots, a_i, a_{i+1}, \cdots, a_n)$$

其中：
- $n$ 为线性表的**长度**，当 $n = 0$ 时，称为**空表**。
- $a_i$ 为第 $i$ 个**元素**，称为**数据元素**。
- $a_1$ 为**第一个元素**（直接开始元素），$a_n$ 为**最后一个元素**（直接后继元素）。
- 称 $a_i$ 是 $a_{i-1}$ 的**直接后继**，$a_{i-1}$ 是 $a_i$ 的**直接前驱**（当 $i > 1$ 时）。

> 【核心要点】线性表的本质特征：**有序性**。数据元素之间呈**一对一**的线性关系，即除第一个和最后一个元素外，每个元素有且仅有一个直接前驱和一个直接后继。

**⭐ 选择题高频考点**：线性表与数组的区别
- 线性表是一种**逻辑结构**，描述数据元素之间的逻辑关系（一对一的线性关系）。
- 数组是一种**存储结构/数据类型**，是一组具有相同类型的变量集合。
- 线性表可以是顺序存储（如顺序表），也可以是链式存储（如链表）。

---

#### 2. 线性表的基本操作

线性表的主要操作如下（对齐严蔚敏教材定义）：

```
// 线性表的基本操作
InitList(&L)       // 操作结果：构造一个空的线性表 L
DestroyList(&L)    // 初始条件：线性表 L 已存在。操作结果：销毁线性表 L
ClearList(&L)      // 初始条件：线性表 L 已存在。操作结果：将 L 重置为空表
ListEmpty(L)       // 初始条件：线性表 L 已存在。操作结果：若 L 为空表，返回 true，否则返回 false
ListLength(L)      // 初始条件：线性表 L 已存在。操作结果：返回 L 中数据元素个数
GetElem(L, i, &e)  // 初始条件：线性表 L 已存在，1 ≤ i ≤ ListLength(L)。
                   // 操作结果：用 e 返回 L 中第 i 个数据元素的值
LocateElem(L, e)   // 初始条件：线性表 L 已存在，e 与数据元素有相同的定义。
                   // 操作结果：返回 L 中第 1 个与 e 满足关系的数据元素的位序。
                   // 若这样的数据元素不存在，则返回 0。
PriorElem(L, cur_e, &pre_e)  // 初始条件：线性表 L 已存在。
                             // 操作结果：若 cur_e 是 L 的数据元素，且不是第一个，
                             // 则用 pre_e 返回其前驱，否则操作失败
NextElem(L, cur_e, &next_e)  // 初始条件：线性表 L 已存在。
                             // 操作结果：若 cur_e 是 L 的数据元素，且不是最后一个，
                             // 则用 next_e 返回其后继，否则操作失败
ListInsert(&L, i, e) // 初始条件：线性表 L 已存在，1 ≤ i ≤ ListLength(L)+1。
                     // 操作结果：在 L 中第 i 个位置之前插入新的数据元素 e，
                     // L 的长度加 1
ListDelete(&L, i, &e) // 初始条件：线性表 L 已存在，1 ≤ i ≤ ListLength(L)。
                      // 操作结果：删除 L 的第 i 个数据元素，并用 e 返回其值，
                      // L 的长度减 1
TraverseList(L)      // 初始条件：线性表 L 已存在。
                     // 操作结果：对 L 进行遍历，依次对 L 的每个数据元素执行 visit()
```

> 📌 **注意**：严蔚敏教材中采用**引用参数**（`&L`、`&e`）来修改参数值，C++ 中用引用语义实现；若用纯 C 语言实现，则需用**指针参数**（`SqList *L`、`ElemType *e`）。

## 二、线性表的顺序表示和实现

### 1. 顺序表的定义

**顺序表**是用一组**地址连续的存储单元**依次存储线性表的数据元素。逻辑上相邻的元素，物理位置上也相邻。

顺序表有两种实现方式：
1. **静态分配**：用数组存储数据元素，容量固定。
2. **动态分配**：用**动态数组**（堆内存）存储数据元素，容量可动态扩容。严蔚敏教材采用动态分配方式。

---

### 2. 顺序表的存储结构定义

```c
#define INIT_SIZE 100      // 线性表初始分配量
#define INCREMENT 10       // 存储空间分配增量

typedef struct {
    ElemType *elem;     // 存储空间基址（指向动态分配的数组）
    int length;         // 当前长度（已占用的元素个数）
    int listsize;       // 当前分配的存储容量（以 sizeof(ElemType) 为单位）
} SqList;
```

> 📌 **三个关键字段说明**：
> - `elem`：指向存储空间的指针（基址）。顺序表的本质就是**一个动态数组**，通过基址可以实现随机访问。
> - `length`：当前实际存储的元素个数，即线性表的当前长度。
> - `listsize`：当前已分配的存储容量，当 `length >= listsize` 时需要重新分配存储空间。

**初始化顺序表（InitList）的 C 实现**：

```c
Status InitList_Sq(SqList &L) {
    // 构造一个空的线性表 L
    L.elem = (ElemType *)malloc(INIT_SIZE * sizeof(ElemType));
    if (!L.elem) exit(OVERFLOW);      // 存储分配失败
    L.length = 0;                      // 空表长度为 0
    L.listsize = INIT_SIZE;            // 初始存储容量
    return OK;
}
```

---

### 3. 顺序表的基本运算实现

#### 3.1 按值查找 `LocateElem_Sq` ⭐

```c
int LocateElem_Sq(SqList L, ElemType e) {
    // 在顺序表 L 中查找与给定值 e 相等的元素
    // 若查找成功，返回该元素在表中的位序（从 1 开始）
    // 若查找失败，返回 0
    for (i = 0; i < L.length; i++) {
        if (compare(L.elem[i], e)) {  // compare 为比较函数
            return i + 1;             // 返回位序（从 1 开始）
        }
    }
    return 0;  // 查找失败
}
```

**时间复杂度分析** ⭐：
- **最好情况**：目标元素在第一个位置，`O(1)`
- **最坏情况**：目标元素在最后一个位置或不存在，`O(n)`，`n = L.length`
- **平均情况**：假设每个元素被查找的概率相等（均为 1/n），则：

$$ASL = \sum_{i=1}^{n} \frac{i}{n} = \frac{n+1}{2}$$

故平均时间复杂度为 **`O(n)`**。

---

#### 3.2 插入操作 `ListInsert_Sq` ⭐🔥

```c
Status ListInsert_Sq(SqList &L, int i, ElemType e) {
    // 在顺序表 L 的第 i 个位置之前插入新的数据元素 e
    // i 的合法范围为 1 ≤ i ≤ L.length + 1

    if (i < 1 || i > L.length + 1)  // 判断 i 的范围是否合法
        return ERROR;

    if (L.length >= L.listsize) {   // 当前存储空间已满，需要扩容
        ElemType *newbase = (ElemType *)realloc(L.elem,
                    (L.listsize + INCREMENT) * sizeof(ElemType));
        if (!newbase) exit(OVERFLOW);
        L.elem = newbase;
        L.listsize += INCREMENT;    // 增加存储容量
    }

    // 插入位置及之后的元素后移（注意从后往前移动）
    ElemType *q = &(L.elem[i - 1]);     // q 指向插入位置
    for (p = &(L.elem[L.length - 1]); p >= q; --p) {
        *(p + 1) = *p;                   // 元素后移
    }
    *q = e;                               // 插入 e
    ++L.length;                           // 表长增 1
    return OK;
}
```

**时间复杂度分析** ⭐🔥：

插入操作的核心代价是**元素后移**。假设在位置 $i$ 插入（$1 \leq i \leq n+1$），则需从位置 $n$ 到 $i$ 共 $n - i + 1$ 个元素后移。

设 $p_i$ 为在第 $i$ 个位置插入元素的概率，通常假设 $p_i = \frac{1}{n+1}$（等概率）。

平均移动元素个数：

$$ASL_{insert} = \sum_{i=1}^{n+1} p_i \cdot (n - i + 1) = \frac{1}{n+1} \sum_{i=1}^{n+1} (n - i + 1) = \frac{1}{n+1} \cdot \frac{n(n+1)}{2} = \frac{n}{2}$$

| 情况 | 移动元素个数 | 时间复杂度 |
|------|-------------|-----------|
| **最好情况** | 插入在表尾（$i = n+1$），无需移动 | `O(1)` |
| **最坏情况** | 插入在表头（$i = 1$），全部元素后移 | `O(n)` |
| **平均情况** | 移动约 $n/2$ 个元素 | `O(n)` |

> 🔥 **考试大题核心考点**：必须熟练掌握插入操作的元素移动规律——**从后往前移动**，即先移动最后一个元素，再移动倒数第二个，……，最后移动插入位置处的元素。如果顺序错了（从前往后移），会导致数据覆盖。

**⭐ 选择题高频坑点**：
- 插入位置 $i$ 的合法范围是 `1 ≤ i ≤ n+1`，不是 `0 ≤ i ≤ n`。（严蔚敏教材使用**从 1 开始的位序**）
- 若题目给出的是数组下标（从 0 开始），需注意转换。

---

#### 3.3 删除操作 `ListDelete_Sq` ⭐🔥

```c
Status ListDelete_Sq(SqList &L, int i, ElemType &e) {
    // 在顺序表 L 中删除第 i 个数据元素，并用 e 返回其值
    // i 的合法范围为 1 ≤ i ≤ L.length

    if (i < 1 || i > L.length)
        return ERROR;

    e = L.elem[i - 1];              // 被删除元素的值赋给 e

    // 删除位置之后的元素前移
    ElemType *q = L.elem + L.length - 1;  // q 指向表尾元素
    for (++p; p <= q; ++p) {
        *(p - 1) = *p;                 // 元素前移
    }
    --L.length;                        // 表长减 1
    return OK;
}
```

**时间复杂度分析** ⭐🔥：

删除操作的核心代价是**元素前移**。假设删除第 $i$ 个元素（$1 \leq i \leq n$），则需从位置 $i+1$ 到 $n$ 共 $n - i$ 个元素前移。

设 $p_i$ 为删除第 $i$ 个元素的概率，通常假设 $p_i = \frac{1}{n}$（等概率）。

平均移动元素个数：

$$ASL_{delete} = \sum_{i=1}^{n} p_i \cdot (n - i) = \frac{1}{n} \sum_{i=1}^{n} (n - i) = \frac{1}{n} \cdot \frac{n(n-1)}{2} = \frac{n-1}{2}$$

| 情况 | 移动元素个数 | 时间复杂度 |
|------|-------------|-----------|
| **最好情况** | 删除表尾元素（$i = n$），无需移动 | `O(1)` |
| **最坏情况** | 删除表头元素（$i = 1$），全部元素前移 | `O(n)` |
| **平均情况** | 移动约 $(n-1)/2$ 个元素 | `O(n)` |

> 🔥 **与插入操作对比记忆**：
> - 插入：移动 $n/2$ 个元素，位置范围 `1 ≤ i ≤ n+1`
> - 删除：移动 $(n-1)/2$ 个元素，位置范围 `1 ≤ i ≤ n`
> - 删除不需要扩容判断，插入需要判断是否需要扩容

---

#### 3.4 顺序表的特点总结 ⭐

| 特性 | 说明 |
|------|------|
| **存储方式** | 地址连续的存储单元（物理连续 → 逻辑连续） |
| **随机存取** | ✅ 可以通过下标直接访问任意元素，`GetElem` 时间复杂度为 `O(1)` |
| **插删效率** | ❌ 需要移动大量元素，平均时间复杂度为 `O(n)` |
| **存储密度** | `存储密度 = 1`（结点全部是数据本身，无额外空间开销） |
| **空间分配** | 静态分配（固定数组）或动态分配（堆内存，可扩容） |
| **预分配问题** | 过小 → 频繁扩容开销大；过大 → 内存浪费 |

**⭐ 选择题高频结论**：

> 1. 顺序表的**优点**：随机存取（`O(1)` 访问）、存储密度高（`= 1`）、无需额外指针空间。
> 2. 顺序表的**缺点**：插入/删除需要移动元素（`O(n)`）、需要预先分配空间、扩容有开销。
> 3. 顺序表适用于：**频繁查找、很少插入删除**的场景。

## 三、线性表的链式表示和实现

### 1. 链表的定义

**链表**是用一组**任意的存储单元**存储线性表的数据元素（存储单元可以是连续的，也可以是不连续的）。为了表示每个数据元素与其直接后继元素之间的逻辑关系，每个元素除了存储自身信息外，还需存储一个指示其直接后继的指针（或**链域**）。

> 📌 **核心思想**：链表通过指针链接实现逻辑上的"连续"，物理上可以不连续。

---

### 2. 单链表

#### 2.1 单链表的存储结构

```c
typedef struct LNode {
    ElemType data;            // 数据域
    struct LNode *next;       // 指针域，指向后继结点
} LNode, *LinkList;
```

> 📌 **两种声明方式的含义**：
> - `LNode *`：指向单链表结点的指针
> - `LinkList`：等价于 `struct LNode *`，表示**单链表的头指针**
>
> 在严蔚敏教材中，用 `LinkList` 声明头指针，用 `LNode *` 声明指向结点的指针，二者等价但语义略有区别。

**带头结点的单链表**（严蔚敏教材默认采用）：

```
              头指针 L
                ↓
         ┌───────────────┐
         │ data │ next ──┼──→ ┌──────────┐       ┌──────────┐
         │  伪      │      │   │ a₁    next │────→│ a₂    next │────→ ...
         └──────────┘       │   └──────────┘       └──────────┘
                            │        ↓                             ↓
                            │   ┌──────────┐               ┌──────────┐
                            └──→│ aₙ    next │─────────────→│ NULL   │
                                └──────────┘               └──────────┘
```

- **头结点**（附加）：数据域通常为空或不存有效数据，其指针域指向第一个结点。引入头结点的目的是使**空表和非空表的处理统一**，也使**第一个结点的插入和删除与其他结点统一**。
- **头指针**（必须）：指向头结点的指针变量。头指针是链表的**唯一**标识。

> 📌 **头指针 vs 头结点** ⭐
> | 概念 | 是否必须 | 说明 |
> |------|---------|------|
> | 头指针 | ✅ 必须 | 指向第一个结点（或头结点）的指针，是链表的唯一标识 |
> | 头结点 | ❌ 可选 | 第一个结点之前的结点，数据域可不存数据，目的是简化操作 |

---

#### 2.2 单链表的创建

##### （1）头插法（Head Insertion）⭐

```c
Status CreateList_H(LinkList &L, int n) {
    // 逆位序输入 n 个元素的值，建立带头结点的单链表 L

    L = (LinkList)malloc(sizeof(LNode));     // 头结点
    L->next = NULL;                           // 头结点的指针域置空

    for (i = 0; i < n; ++i) {
        p = (LNode *)malloc(sizeof(LNode));   // 创建新结点
        scanf("%d", &p->data);                // 输入元素值
        p->next = L->next;                    // 新结点指向原第一个结点
        L->next = p;                          // 头结点指向新结点
    }
    return OK;
}
```

**特点**：
- 新结点始终插入在**头结点之后**（第一个位置）。
- 输入顺序与链表结点**逆序**排列。
- 时间复杂度：`O(n)`

##### （2）尾插法（Tail Insertion）⭐

```c
Status CreateList_R(LinkList &L, int n) {
    // 正位序输入 n 个元素的值，建立带头结点的单链表 L

    L = (LinkList)malloc(sizeof(LNode));     // 头结点
    r = L;                                    // r 为尾指针，始终指向当前链表的最后一个结点

    for (i = 0; i < n; ++i) {
        p = (LNode *)malloc(sizeof(LNode));   // 创建新结点
        scanf("%d", &p->data);                // 输入元素值
        p->next = NULL;                       // 新结点的指针域置空
        r->next = p;                          // 尾结点的 next 指向新结点
        r = p;                                // r 指向新的尾结点
    }
    return OK;
}
```

**特点**：
- 新结点始终插入在**链表尾部**。
- 输入顺序与链表结点**顺序**排列。
- 时间复杂度：`O(n)`
- 必须维护一个**尾指针 `r`**

> 🔥 **考试考点**：头插法建立的链表与输入顺序**相反**，尾插法建立的链表与输入顺序**相同**。这是选择题和大题中常见的区分点。

---

#### 2.3 单链表的基本运算实现

##### （1）按序号查找 `GetElem_L`

```c
Status GetElem_L(LinkList L, int i, ElemType &e) {
    // 在带头结点的单链表 L 中根据位序 i 获取数据元素的值
    // i 的合法范围为 1 ≤ i ≤ 表长

    p = L->next;        // p 指向第一个结点
    j = 1;              // j 为计数器

    while (p && j < i) {   // 顺链域向后扫描，直到 p 指向第 i 个结点或 j == i 或 p 为空
        p = p->next;
        ++j;
    }

    if (!p || j > i)       // 第 i 个元素不存在
        return ERROR;

    e = p->data;           // 取第 i 个元素
    return OK;
}
```

**时间复杂度分析**：
- 需要从头指针出发，沿 `next` 指针逐结点扫描。
- 最坏情况：扫描到第 $n$ 个结点，时间复杂度为 **`O(n)`**。

---

##### （2）按值查找 `LocateElem_L`

```c
LNode *LocateElem_L(LinkList L, ElemType e) {
    // 在带头结点的单链表 L 中查找值为 e 的元素
    p = L->next;

    while (p && !compare(p->data, e)) {
        p = p->next;
    }

    return p;  // 成功返回指向该结点的指针，失败返回 NULL
}
```

**时间复杂度分析**：
- 最好情况：第一个结点就匹配，`O(1)`
- 最坏情况：最后一个结点才匹配或不存在，`O(n)`
- 平均时间复杂度：**`O(n)`**

---

##### （3）插入操作 `ListInsert_L` ⭐🔥

```c
Status ListInsert_L(LinkList &L, int i, ElemType e) {
    // 在带头结点的单链表 L 中第 i 个位置之前插入元素 e
    // 分两步：① 找到第 i-1 个结点；② 插入新结点

    p = L;
    j = 0;

    while (p && j < i - 1) {       // 寻找第 i-1 个结点
        p = p->next;
        ++j;
    }

    if (!p || j > i - 1)            // i 值不合法（i < 1 或 i > 表长+1）
        return ERROR;

    s = (LNode *)malloc(sizeof(LNode));  // 创建新结点 s
    s->data = e;
    s->next = p->next;                   // 新结点指向原第 i 个结点
    p->next = s;                         // 第 i-1 个结点指向新结点
    return OK;
}
```

> 🔥 **核心步骤（两步）**：
> 1. **找前驱**：找到第 $i-1$ 个结点 `p`（`O(n)` 复杂度）
> 2. **实际插入**：`s->next = p->next; p->next = s;`（`O(1)` 复杂度）
>
> ⚠️ **插入的顺序不能颠倒**！必须先让新结点的 `next` 指向原后继，再让前驱指向新结点。如果先执行 `p->next = s`，就会丢失原后继结点的引用。

**时间复杂度分析** ⭐🔥：
- 查找前驱结点：`O(n)`
- 实际插入操作：`O(1)`
- 整体时间复杂度：**`O(n)`**（由查找步骤决定）

---

##### （4）删除操作 `ListDelete_L` ⭐🔥

```c
Status ListDelete_L(LinkList &L, int i, ElemType &e) {
    // 在带头结点的单链表 L 中删除第 i 个元素，并用 e 返回其值

    p = L;
    j = 0;

    while (p->next && j < i - 1) {     // 寻找第 i-1 个结点，并检查其后继是否存在
        p = p->next;
        ++j;
    }

    if (!(p->next) || j > i - 1)        // 第 i 个元素不存在
        return ERROR;

    q = p->next;                         // q 指向待删除的第 i 个结点
    e = q->data;
    p->next = q->next;                   // 将 q 的后继结点改为 q 的后继的后继
    free(q);                             // 释放结点 q
    return OK;
}
```

> 🔥 **核心步骤（两步）**：
> 1. **找前驱**：找到第 $i-1$ 个结点 `p`（`O(n)` 复杂度）
> 2. **实际删除**：`p->next = q->next; free(q);`（`O(1)` 复杂度）
>
> ⚠️ **必须先保存 q 再修改链**！即必须先 `e = q->data` 和记录 `q`，再执行 `p->next = q->next`，最后 `free(q)`。如果先修改了 `p->next`，就无法正确访问 `q` 来释放内存。

**时间复杂度分析** ⭐🔥：
- 查找前驱结点：`O(n)`
- 实际删除操作：`O(1)`
- 整体时间复杂度：**`O(n)`**（由查找步骤决定）

#### 2.4 单链表的遍历

```c
Status TraverseList_L(LinkList L) {
    // 遍历单链表，对每个数据元素调用 visit() 函数
    p = L->next;
    while (p) {
        visit(p->data);
        p = p->next;
    }
    return OK;
}
```

### 3. 循环链表（Circular Linked List）

#### 3.1 定义

**循环链表**是另一种形式的链式存储结构。其特点是将单链表中**终端结点的指针从 NULL 改为指向头结点**（或第一个结点），使得整个链表形成一个**环**。从表中任一结点出发均可找到表中其他结点。

```
              ┌──────────────────────┐
              │                      ▼
         ┌──────────┐       ┌──────────┐
         │ head │ next ─────→│ a₁    next │────→ ...
         └──────────┘       └──────────┘
              ▲                  │
              └──────────────────┘
              （尾结点指向头结点/第一个结点）
```

**判别条件**：链表中是否存在某个结点的 `next` 指向头结点（或首结点），即 `q->next == L` 或 `q->next == head`。

> 📌 **循环单链表 vs 带头结点的单链表**：
> - 判断**空表**：循环单链表中 `L->next == L`（尾结点指向自己）；带头结点单链表中 `L->next == NULL`。
> - 判断**是否遍历完**：循环单链表看 `p->next == L`；普通链表看 `p->next == NULL`。
> - **优势**：从任一结点出发可以访问到表中所有结点，某些操作可以简化（如从尾结点找首结点仅需 `O(1)`）。

---

### 4. 双向链表（Doubly Linked List）

#### 4.1 定义和存储结构

**双向链表**是在单链表的每个结点中再设置一个指向其**前驱结点**的指针域。

```c
typedef struct DLNode {
    ElemType data;                    // 数据域
    struct DLNode *prior;             // 前驱指针域
    struct DLNode *next;              // 后继指针域
} DLNode, *DuLinkList;
```

```
  头指针 L
    ↓
 ┌─────────────────────────────────────┐
 │ prior │ data │ next               │
 └───────┴──────┴────────────────────┘
    ↓       ↓         ↓          ↓
   NULL   │         │          │  NULL
         ┌──────────┴──────────┴───┐
         │ prior │ data │ next    │
         └───────┴──────┴─────────┘
           ↓         ↓           ↓
         NULL     │          │  NULL
                  ↓           ↓
                ...         ...
                  ↓
             ┌─────────────────┐
             │ prior │ data │ next │
             └───────┴──────┴──────┘
                  ↓      ↓       ↓
                NULL    │     NULL
                        ↑
                   （头结点的 prior 指向尾结点）
```

**双向链表的两个重要特性**：
1. **对称性**：`p->prior->next == p` 且 `p->next->prior == p`
2. 头结点的 `prior` 指向**最后一个结点**，尾结点的 `next` 指向 `NULL`（非循环双向链表）；循环双向链表中，头结点的 `prior` 指向尾结点，尾结点的 `next` 指向头结点。

---

#### 4.2 双向链表的插入操作 ⭐🔥

在双向链表结点 `p` 之后插入新结点 `s`：

```c
// 在 p 结点之后插入 s 结点（4步操作）
s->prior = p;                          // ① 新结点的前驱指向 p
s->next = p->next;                     // ② 新结点的后继指向 p 的后继
p->next->prior = s;                    // ③ p 的后继结点的前驱改为 s
p->next = s;                           // ④ p 的后继指向 s
```

> 🔥 **插入操作的 4 步必须按此顺序执行**（核心记忆：**先连后断**）：
> 1. 先建立新结点 `s` 与原链表的连接（`s->prior = p`、`s->next = p->next`）
> 2. 再修改原链表的连接关系（`p->next->prior = s`、`p->next = s`）
>
> ⚠️ **常见错误**：如果先执行 `p->next = s`，就会丢失原 `p->next` 的值，导致无法找到 `p` 的后继结点，更无法修改其后继的 `prior` 指针。

---

#### 4.3 双向链表的删除操作 ⭐🔥

删除双向链表中结点 `p` 的后继结点 `q`：

```c
// 删除 p 的后继结点 q（4步操作）
p->next = q->next;                     // ① p 的后继改为 q 的后继
q->next->prior = p;                    // ② q 的后继结点的前驱改为 p
free(q);                               // ③ 释放结点 q
```

> 🔥 **删除操作的核心**：
> 1. 将 `p` 的后继指向 `q` 的后继（绕过 `q`）
> 2. 修改 `q` 后继结点的 `prior` 指向 `p`（保持双向一致性）
> 3. 释放 `q`

在**循环双向链表**中，删除结点 `q` 还需注意将表长的更新，循环双向链表的插入和删除均保持环形结构不断裂。

---

#### 4.4 双向链表的特点

| 特性 | 说明 |
|------|------|
| **前驱查找** | ✅ 可以从任一结点直接访问前驱，`O(1)` |
| **后继查找** | ✅ 可以从任一结点直接访问后继，`O(1)` |
| **插入/删除** | ✅ 若已知指向该结点的指针，插入/删除均为 `O(1)` |
| **空间开销** | ❌ 每个结点多一个 `prior` 指针，空间密度较低 |
| **操作复杂度** | 插入需修改 4 个指针（前后各两个），删除需修改 2 个指针 |

> 📌 **关键结论**：双向链表的插入/删除操作在**已知指向该结点的指针**时，指针修改是 `O(1)` 的，但**查找该结点**仍需 `O(n)`。这与单链表的插入/删除时间复杂度分析一致。

---

### 5. 静态链表（Static Linked List）

#### 5.1 定义

**静态链表**借助**数组**来描述链表，数组中的每个结点包含：
- `data`：数据域
- `cur`：游标（cursor），指示后继元素在数组中的下标

```c
#define MAXSIZE 1000

typedef struct {
    ElemType data;
    int cur;     // 游标：后继元素在数组中的下标
} Component, StaticList[MAXSIZE];
```

**特点**：
- 数组的第一个和最后一个元素可用作**备用链表**，存储空闲结点的下标。
- 首元素 `cur` 指向第一个空闲结点（备用链表头），末元素 `cur` 指向第一个有数据的结点（静态链表的头指针）。

#### 5.2 静态链表的特点

| 特性 | 说明 |
|------|------|
| **优点** | 不需要指针，适用于不支持指针的语言；插入/删除无需移动元素 |
| **缺点** | 长度固定、不便查找、需要额外游标空间 |
| **适用场景** | 主要在不支持指针的语言中使用，或特定场景下避免动态分配 |

> 📌 **游标（cur）的作用**：类似于单链表中的 `next` 指针，只是 `cur` 存储的是**数组下标**而非内存地址。

## 四、顺序表和链表的对比 ⭐

| 比较维度 | 顺序表（SeqList） | 链表（Linked List） |
|---------|-------------------|---------------------|
| **存储方式** | 地址连续的存储单元（物理连续） | 地址任意的存储单元（物理可不连续） |
| **存储密度** | `存储密度 = 1`（无指针开销） | `存储密度 < 1`（每个结点有指针域） |
| **存取方式** | **随机存取**：`GetElem(i)` 为 `O(1)` | **顺序存取**：`GetElem(i)` 为 `O(n)` |
| **插入效率** | 平均移动 $n/2$ 个元素，`O(n)` | 找到位置后插入为 `O(1)`，但查找需 `O(n)` |
| **删除效率** | 平均移动 $(n-1)/2$ 个元素，`O(n)` | 找到位置后删除为 `O(1)`，但查找需 `O(n)` |
| **空间分配** | 静态分配（固定大小）或动态分配（可扩容） | 动态分配（按需分配，灵活） |
| **预分配问题** | 过小→频繁扩容；过大→内存浪费 | 无预分配问题，但可能产生内存碎片 |
| **空间利用率** | 可能浪费（预分配过大） | 灵活但有过头结点/指针的额外开销 |
| **适用场景** | 元素个数稳定、频繁查找、很少插入删除 | 元素个数变化大、频繁插入删除、需灵活管理 |

---

### ⚖️易混淆概念对比

#### 4.1 头指针、头结点、首结点

| 概念 | 定义 | 是否必须 | 说明 |
|------|------|---------|------|
| **头指针** | 指向链表中第一个结点（或头结点）的指针 | ✅ 必须 | 是链表的唯一标识，无论链表是否为空，头指针都不为空 |
| **头结点** | 数据域不存有效数据的附加结点（放在首结点之前） | ❌ 可选 | 目的是使空表和非空表统一处理，使首结点插入删除与其他结点统一 |
| **首结点** | 链表中存放第一个有效数据元素的结点 | 随头结点存在与否变化 | 有头结点时，首结点是 `L->next` 指向的结点 |

> 【考试考法】选择题常考：设有头结点的单链表，判断其是否为空的条件是 `L->next == NULL`，而非 `L == NULL`。

---

#### 4.2 顺序表的动态分配与静态分配

| 特性 | 静态分配 | 动态分配 |
|------|---------|---------|
| **实现方式** | 定长数组 `ElemType data[MAX_SIZE]` | 指针+malloc `ElemType *elem` |
| **容量固定** | ✅ 是 | ❌ 否（可通过 realloc 扩容） |
| **扩容** | 不支持（需新建更大的数组并拷贝） | 支持（realloc 重新分配更大空间） |
| **内存管理** | 编译器管理（栈/静态区） | 程序员管理（堆内存，需 free） |
| **教材采用** | 严蔚敏教材**动态分配** | — |

---

#### 4.3 单链表、循环链表、双向链表

| 特性 | 单链表 | 循环链表 | 双向链表 |
|------|-------|---------|---------|
| **指针域数量** | 1（next） | 1（next） | 2（prior, next） |
| **终端结点指向** | NULL | 头结点/首结点 | NULL（或非循环） |
| **从任一结点出发能否访问所有结点** | ❌ 不能 | ✅ 能 | ✅ 能（非循环则从首结点开始） |
| **插入/删除** | 需找前驱 | 需找前驱 | 需找前驱（已知结点则 O(1)） |
| **存储空间** | 较小 | 较小 | 较大（多 prior） |

### ⚠️考试高频坑点

#### 【坑点 1】位序 vs 下标 ⭐

> 【教材原文】严蔚敏教材中，线性表的位序**从 1 开始**，即第一个元素的位序为 1。
>
> 【考试考法】
> - 插入位置 `i` 的合法范围：**`1 ≤ i ≤ n+1`**（含两端）
> - 删除位置 `i` 的合法范围：**`1 ≤ i ≤ n`**（含两端）
> - 若题目用数组下标（从 0 开始），需要转换：数组下标 `k` → 位序 `k+1`
>
> 这是选择题中最常设的陷阱之一！

---

#### 【坑点 2】插入操作的元素移动方向 ⭐

> 【教材原文】插入操作中，从后往前移动元素，即从最后一个元素开始，依次后移。
>
> 【考试考法】选择题常给出从前往后移动的错误选项，要求判断对错。
>
> 关键记忆：**插入从后往前移，删除从前往后移**。
> - 插入：避免新插入的元素被后续元素覆盖
> - 删除：避免待删除元素覆盖未处理的元素

---

#### 【坑点 3】空表判断条件 ⭐

> 【教材原文】
> - 顺序表为空：`L.length == 0`
> - 带头结点单链表为空：`L->next == NULL`
> - 不带头结点单链表为空：`L == NULL`
> - 循环单链表为空：`L->next == L`
>
> 【考试考法】选择题给出不同链表的空表判断条件，要求选出正确的。

---

#### 【坑点 4】头指针 vs 头结点混淆 ⭐

> 【教材原文】严蔚敏教材中，`LinkList L` 是头指针，`LNode *p` 是结点指针，两者在类型上等价的，但 `LinkList` 强调其为链表标识。
>
> 【考试考法】
> - 函数参数用 `LinkList &L` 表示引用传参（修改头指针本身）
> - 函数参数用 `LNode *p` 表示结点访问（修改结点数据）
> - 不带头结点的链表，删除第一个结点时头指针需要修改

---

#### 【坑点 5】时间复杂度的准确描述 ⭐

> 【教材原文】
> - 顺序表查找：`O(n)`
> - 顺序表插入/删除：平均 `O(n)`
> - 单链表查找（按位）：`O(n)`
> - 单链表查找（按值）：`O(n)`
> - 单链表插入/删除（已知位置）：`O(1)`
> - 单链表插入/删除（需先查找）：`O(n)`
>
> 【考试考法】选择题常问"某操作的总时间复杂度"，需要区分"纯操作"和"包含查找的完整操作"。
>
> **关键区分**：
> - 单链表的 `ListInsert` 和 `ListDelete` 操作，如果不指明"已找到位置"，则需要先查找，总时间复杂度为 `O(n)`。
> - 如果题目说"在已知指向该结点的指针的情况下"，则插入/删除的时间复杂度为 `O(1)`。

---

#### 【坑点 6】顺序表的扩容开销 ⭐

> 【教材原文】当顺序表满时，需要重新分配更大的存储空间，将原数据复制到新空间。
>
> 【考试考法】如果顺序表连续扩容，每次扩容时元素移动的次数为 $n + (n+k) + \cdots$，总体均摊复杂度仍为 `O(1)` 的均摊分析。
