# CPU数据通路与控制器

## 📍知识定位

### 在408体系中的位置

CPU数据通路（Datapath）与控制器（Control Unit）是计算机组成原理中**最核心、最复杂**的知识点之一。它描述了CPU内部各功能部件（ALU、寄存器、PC、IR、CU等）之间的数据流动路径，以及控制器如何产生控制信号来协调数据通路的操作。这是理解计算机"如何执行指令"的关键模块，是408考试中**大题最高频的考点之一**（控制信号分析、数据通路分析、指令执行流程）。

### 学习前置条件

- **指令系统**：了解指令格式（操作码、地址码）、指令类型（数据传送、算术运算、逻辑运算、控制转移）
- **数据表示**：理解二进制的补码表示、移位操作
- **运算器**：理解ALU的结构与功能、寄存器的作用

### 学完之后支撑的知识点

- **指令流水线**：数据通路是流水线的基础，流水线是对数据通路的时间分割
- **CPU性能评估**：CPI、时钟频率与数据通路延迟的关系
- **计算机组成概述**：理解CPU的整体组织

## 📝核心概念与原理

### 一、CPU的基本组成 ⭐

#### 1. CPU的功能与结构

```
                    ┌──────────────────────────────────┐
                    │              CPU                  │
                    │                                  │
  ┌──────────┐     │  ┌──────────┐    ┌──────────┐   │
  │ 寄存器组  │─────┼─→│  运算器   │←──→│ 控制器   │   │
  │ (Registers)│   │  │  (ALU)    │    │  (CU)    │   │
  └──────────┘     │  └──────────┘    └──────────┘   │
                    │                                  │
  ┌──────────┐     │  ┌──────────┐    ┌──────────┐   │
  │  程序计数 │─────┼─→│  指令寄存器 │←──→│  时序    │   │
  │  器(PC)   │     │  │  (IR)     │    │  和控制  │   │
  └──────────┘     │  └──────────┘    └──────────┘   │
                    │                                  │
  ┌──────────┐     │  ┌──────────┐    ┌──────────┐   │
  │  指令译码 │◄────┼─→│  数据通路  │←──→│  状态    │   │
  │  器       │     │  │ (Datapath)│    │  寄存器  │   │
  └──────────┘     │  └──────────┘    └──────────┘   │
                    │                                  │
                    └──────────────────────────────────┘

  与外部交互：
  - 地址总线 → 存储器/IO
  - 数据总线 ← → 存储器/IO
  - 控制总线 → R/W、中断请求等
```

**CPU的核心功能部件**：

| 部件 | 功能 | 说明 |
|------|------|------|
| **运算器（ALU）** | 执行算术和逻辑运算 | 加、减、与、或、非、移位等 |
| **寄存器组（Registers）** | 暂存数据和地址 | 通用寄存器、特殊用途寄存器 |
| **程序计数器（PC）** | 存放下一条指令地址 | 自动递增，跳转时更新 |
| **指令寄存器（IR）** | 存放当前执行指令 | 操作码→译码→产生控制信号 |
| **指令译码器（ID/Decoder）** | 将操作码译码为控制信号 | 硬连线译码或微程序译码 |
| **控制器（CU）** | 产生所有控制信号 | 硬连线控制器或微程序控制器 |
| **状态寄存器（PSW/Flags）** | 存放运算状态 | 进位CF、零标志ZF、溢出OF等 |
| **数据通路（Datapath）** | 连接各部件的数据通道 | 寄存器间数据流动的路径 |

#### 2. 关键寄存器详解

```
通用寄存器（R0~Rn）：
  - 用于暂存操作数和中间结果
  - 可用作栈指针、变址寄存器等

特殊用途寄存器：
  PC（Program Counter，程序计数器）：
    - 存放下一条要执行的指令地址
    - 顺序执行时：PC ← PC + 指令长度
    - 转移指令时：PC ← 目标地址

  IR（Instruction Register，指令寄存器）：
    - 存放当前正在执行的指令
    - 操作码字段 → 译码器 → 产生控制信号
    - 地址码字段 → 形成有效地址

  MAR（Memory Address Register，存储器地址寄存器）：
    - 存放要访问的存储器地址
    - 连接到地址总线

  MDR（Memory Data Register，存储器数据寄存器）：
    - 存放从存储器读出的数据或要写入存储器的数据
    - 连接到数据总线

  PC（程序计数器）和 IR（指令寄存器）是最核心的两个寄存器。
```

> ⭐ **选择题考点**：
> - PC用于存放下一条指令地址
> - IR用于存放当前指令
> - MAR和MDR是CPU与主存之间的缓冲寄存器
> - MAR可读出（送地址总线），MDR可读写

### 二、数据通路（Datapath）⭐🔥

数据通路是指数据在各功能部件之间的传输路径。理解数据通路是掌握指令执行过程的基础。

#### 1. 单周期数据通路（Single-Cycle Datapath）⭐🔥

这是408考试中最重要的数据通路模型，以MIPS架构为例。

```
                    ┌────────────────────────────────────────────┐
                    │              单周期数据通路                  │
                    │                                            │
                    │       取指阶段（IF）                         │
                    │       PC ──→ I-Memory（取指令）              │
                    │       PC + 4 ──→ ALU（计算PC+4）             │
                    │       IR[31-26] ──→ 控制单元                 │
                    │                                            │
                    │       译码阶段（ID）                        │
                    │       Read Register → Read Data1, Read Data2  │
                    │       Sign Extend（符号扩展立即数）           │
                    │                                            │
                    │       执行阶段（EX）                        │
                    │       ALU运算：ALU(src1, src2, ALU-control) │
                    │       条件判断：Branch Equal                 │
                    │                                            │
                    │       访存阶段（MEM）                       │
                    │       Load/Store：访问 Data Memory           │
                    │       地址 = Read Data1 + 符号扩展立即数      │
                    │                                            │
                    │       写回阶段（WB）                        │
                    │       Write Register ← 结果（ALU/MEM输出）   │
                    └────────────────────────────────────────────┘
```

**数据通路的关键数据流**：

```
取指（IF）：
  1. PC → I-Memory地址输入 → 读取指令
  2. PC → ALU → PC+4（下一条顺序指令地址）
  3. 指令 → IR → 操作码→控制单元

译码（ID）：
  4. 读寄存器 → 读数据1（Rs）
  5. 读寄存器 → 读数据2（Rt/立即数）
  6. 立即数 → 符号扩展

执行（EX）：
  7. ALU(src1, src2) → 运算结果
  8. 地址 = Read Data1 + 扩展立即数（Load/Store）
  9. 条件判断：Zero=1 且 Branch=1 → 跳转

访存（MEM）：
  10. Load：Data Memory[地址] → 读数据
  11. Store：写数据 → Data Memory[地址]

写回（WB）：
  12. 写寄存器 ← ALU结果 / 内存读数据 / PC+4
```

> 🔥 **大题必考**：给定指令格式和数据通路图，分析某条指令（如 `ADD R1, R2, R3`、`LW R1, 0(R2)`、`BEQ R1, R2, Label`）在数据通路中的执行流程，标注每一步的数据流动。

#### 2. 多周期数据通路（Multi-Cycle Datapath）⭐

单周期数据通路中，时钟周期必须等于最慢指令的执行时间（如Load指令），导致其他指令也被迫等待。多周期数据通路将指令执行分为多个阶段，每个阶段在一个时钟周期内完成。

```
多周期数据通路的阶段划分：

  阶段1：取指（IF）— 所有指令都执行
  阶段2：译码/读寄存器（ID）— 所有指令都执行
  阶段3：执行/有效地址计算（EX）— 大多数指令执行
  阶段4：访存（MEM）— Load/Store指令执行
  阶段5：写回（WB）— 大多数指令执行

  关键区别：
  - 单周期：所有阶段在1个时钟周期内完成
  - 多周期：各阶段分布在多个时钟周期
  - 单周期时钟频率高（周期短但受最慢指令限制）
  - 多周期时钟频率可以更高（每个阶段时间较短）
```

> ⭐ **选择题考点**：
> - 单周期数据通路：时钟周期 = 最慢指令的执行时间
> - 多周期数据通路：时钟周期 = 最慢阶段的执行时间
> - 多周期数据通路可以使用单周期的硬件复用（如ALU在多个阶段复用）
> - 多周期需要更多控制信号（每个阶段不同）

### 三、控制单元（Control Unit）⭐🔥

控制单元是CPU的"大脑"，负责产生和执行指令所需的所有控制信号。

#### 1. 控制信号的产生方式

```
控制信号的来源有两种主要方式：

┌─────────────────────────────────────────────────────────┐
│                    控制单元设计方式                        │
│                                                         │
│  ┌──────────────────┐    ┌──────────────────┐          │
│  │  硬连线控制器      │    │  微程序控制器      │          │
│  │  (Hardwired)      │    │  (Microprogrammed)│          │
│  │                  │    │                  │          │
│  │  操作码 → 逻辑门  │    │  操作码 → 微程序  │          │
│  │  组合逻辑产生     │    │  控制存储器产生    │          │
│  │  控制信号         │    │  微指令 → 控制信号 │          │
│  │                  │    │                  │          │
│  │  优点：速度快      │    │  优点：灵活、易修改 │          │
│  │  缺点：设计复杂    │    │  缺点：速度较慢    │          │
│  └──────────────────┘    └──────────────────┘          │
└─────────────────────────────────────────────────────────┘
```

#### 2. 硬连线控制器（Hardwired Control）⭐

**原理**：

> 硬连线控制器使用组合逻辑电路（与门、或门、译码器等）直接将操作码译码为控制信号。控制信号由操作码和各条件标志通过组合逻辑直接产生。

```
硬连线控制器的结构：

  操作码 ──→ 主译码器 → 产生主要控制信号
                │
  条件标志 ──→ 条件逻辑 → 产生分支判断信号
                │
  指令类型 ──→ 功能译码 → 产生ALU控制信号
                │
  ┌─────────────────────────────────────────┐
  │  最终控制信号 = f(操作码, 条件, 时序)     │
  │           由组合逻辑电路实现               │
  └─────────────────────────────────────────┘
```

**硬连线控制器的设计步骤**：

```
步骤1：确定指令格式和控制信号
  - 分析每条指令需要的控制信号
  - 如：RegWrite（写寄存器）、MemRead（读内存）、
    MemWrite（写内存）、ALUSrc（ALU第二个操作数选择）、
    RegDst（写寄存器目标选择）等

步骤2：绘制控制信号真值表
  列出一条条指令 → 对应的控制信号值（0/1）

步骤3：用组合逻辑实现
  将真值表转化为逻辑表达式（卡诺图化简）
  用逻辑门实现

步骤4：时序控制
  在相应的时钟沿产生控制信号
```

**关键控制信号（MIPS为例）**：

| 控制信号 | 说明 | 0含义 | 1含义 |
|---------|------|-------|-------|
| RegDst | 写寄存器目标选择 | Rt | Rd |
| ALUSrc | ALU第二操作数来源 | 寄存器 | 立即数 |
| MemRead | 读内存 | 不读 | 读 |
| MemWrite | 写内存 | 不写 | 写 |
| MemtoReg | 写回数据选择 | ALU结果 | 内存数据 |
| RegWrite | 写寄存器 | 不写 | 写 |
| Branch | 分支判断 | 不分支 | 分支（需Zero配合） |
| ALUOp | ALU操作类型 | 00=ADD, 01=SUB, 10=AND, 11=OR |

> 控制信号真值表（示例）：
>
> | 指令 | RegDst | ALUSrc | MemRead | MemWrite | MemtoReg | RegWrite | Branch | ALUOp |
> |------|--------|--------|---------|----------|----------|----------|--------|-------|
> | R-type | 1 | 0 | 0 | 0 | 0 | 1 | 0 | 10 |
> | LW | 0 | 1 | 1 | 0 | 1 | 1 | 0 | 00 |
> | SW | X | 1 | 0 | 1 | X | 0 | 0 | 00 |
> | BEQ | X | 0 | 0 | 0 | X | 0 | 1 | 01 |
> | ADD | 1 | 0 | 0 | 0 | 0 | 1 | 0 | 10 |
> | SUB | 1 | 0 | 0 | 0 | 0 | 1 | 0 | 11 |

> 🔥 **大题必考**：给定指令格式和数据通路，写出指令执行时各控制信号的值。这是408考试的经典大题题型。

#### 3. 微程序控制器（Microprogrammed Control）⭐🔥

**原理**：

> 微程序控制器将每条机器指令分解为一系列微指令（Microinstruction），每条微指令包含一组控制信号。微指令存储在控制存储器（Control Store）中，通过微地址寻址执行。

```
微程序控制器的结构：

  ┌──────────┐    ┌───────────────────┐
  │  操作码   │───→│  微地址形成逻辑    │
  │  (OP)     │    │  (Micro-PC)       │
  └──────────┘    └────────┬──────────┘
                           │
                           ▼
                    ┌───────────────────┐
                    │   控制存储器       │
                    │  (Control Store)   │
                    │                   │
                    │  微地址 → 微指令   │
                    │  （包含控制信号）    │
                    └────────┬──────────┘
                             │
                             ▼
                    ┌───────────────────┐
                    │   微指令寄存器      │
                    │  (μIR)             │
                    │                   │
                    │  微指令 → 控制信号  │
                    └───────────────────┘

  微指令格式：
  ┌────────────────────────────────────┐
  │  控制字段 │  下址字段 │  条件字段  │
  │ (控制信号) │ (微地址) │ (跳转条件) │
  └────────────────────────────────────┘
```

**微指令的详细结构**：

```
微指令格式（定长微指令 vs 变长微指令）：

定长微指令：
  ┌──────────────────────────────────────────┐
  │  操作控制字段 (7~10bit) │ 下址控制字段 (6bit) │
  │  (直接/编码控制信号)      │  (微地址/跳转条件)  │
  └──────────────────────────────────────────┘

  操作控制字段：
  - 直接控制（水平型）：每个bit对应一个控制信号
  - 编码控制（垂直型）：多位编码选择一组控制信号

  下址控制字段：
  - 提供下一条微指令的微地址
  - 可以通过微地址形成逻辑计算（如微地址+偏移）
```

**微程序控制器的执行流程**：

```
机器指令执行过程：

  1. 取指微程序（所有指令共用）：
     μROM[000] → 取指令（PC→MAR→Memory→MDR→IR）
     μROM[001] → PC+4→PC
     μROM[002] → 根据IR的操作码形成下一条微指令地址

  2. 译码微程序：
     根据IR的操作码 → 查询微程序入口地址

  3. 执行微程序（每条机器指令对应一个微程序）：
     按微地址顺序执行微指令 → 产生控制信号 → 完成操作
     遇到条件跳转 → 判断条件 → 决定下一微地址

  4. 写回微程序：
     将结果写回寄存器

  一个典型的微程序流程：
  ┌─────────┐   ┌──────────┐   ┌──────────┐   ┌──────────┐
  │  取指    │→ │  译码    │→ │  执行    │→ │  写回    │
  │ 微程序   │   │ 微程序   │   │ 微程序   │   │ 微程序   │
  └─────────┘   └──────────┘   └──────────┘   └──────────┘
      │              │              │              │
      ▼              ▼              ▼              ▼
   控制信号         控制信号       控制信号       控制信号
```

**微地址的形成**：

```
微地址的来源（多种方式组合）：

方法1：由操作码直接形成（取指微程序的入口）
  微地址 = 操作码的某些位

方法2：由微程序计数器递增
  微地址 = 当前微地址 + 1（顺序执行）

方法3：由条件跳转决定
  微地址 = 当前微地址 + 偏移（条件满足时）
  微地址 = 当前微地址 + 1（条件不满足时）

方法4：由操作码和目标微地址拼接
  微地址 = 操作码高位 + 下址字段
```

> 例：某微程序控制器，控制存储器的容量为 256×32位。
> 微地址位数 = log₂(256) = 8位。
> 每条微指令 32位，其中操作控制字段26位，下址字段6位。

> ⭐ **选择题高频考点**：
> - 微程序控制器中，微指令存储在控制存储器中
> - 微地址由微程序计数器（μPC）指向
> - 水平型微指令并行度高（控制信号多），垂直型微指令编码密度高
> - 微程序控制器执行速度慢于硬连线控制器

#### 4. 硬连线 vs 微程序对比 ⭐

| 对比项 | 硬连线控制器 | 微程序控制器 |
|--------|-----------|-----------|
| 控制信号来源 | 组合逻辑电路 | 控制存储器中的微指令 |
| 速度 | 快（信号直接产生） | 慢（需读控制存储器） |
| 灵活性 | 差（修改需改电路） | 好（修改微程序即可） |
| 设计复杂度 | 复杂（大规模组合逻辑） | 简单（微程序编写） |
| 芯片面积 | 大 | 小 |
| 适用场景 | RISC处理器、高性能CPU | CISC处理器、早期CPU |
| 指令执行速度 | 每条指令1~多周期 | 每条指令多微周期 |

> 现代高性能CPU（如Intel x86、ARM）主要采用硬连线控制器（结合少量微码辅助），以追求更快的执行速度。

### 四、指令执行过程 ⭐🔥

#### 1. 指令周期与CPU周期

```
指令周期的层次结构：

  指令周期（Instruction Cycle）= 取指 + 执行 + （间址 + 中断）

  ┌──────────────────────────────────────────────────┐
  │              指令周期                              │
  │                                                  │
  │  ┌────────┐ ┌────────┐ ┌────────┐ ┌────────┐   │
  │  │ 取指    │ │ 间址    │ │ 执行    │ │ 中断    │   │
  │  │ 周期    │ │ 周期    │ │ 周期    │ │ 周期    │   │
  │  └────────┘ └────────┘ └────────┘ └────────┘   │
  │       │                              │          │
  │       ▼                              ▼          │
  │   CPU周期                          CPU周期      │
  │   （机器周期）                     （机器周期）    │
  │                                                  │
  └──────────────────────────────────────────────────┘

  各周期说明：
  - 取指周期：从内存取出指令，放入IR
  - 间址周期：取操作数的地址（间接寻址时）
  - 执行周期：执行指令（运算、转移、I/O等）
  - 中断周期：响应中断，保护现场、跳转处理程序
```

> 取指周期是所有指令都必须经历的。执行周期根据指令类型不同而异。间址周期仅在间接寻址时出现。中断周期仅在发生中断时出现。

#### 2. 典型指令的执行流程 ⭐🔥

**以3条典型指令为例**：

```
指令1：ADD R1, R2, R3  （R-type，寄存器操作）
  取指阶段（IF）：
    1. PC → MAR → 取指令 → MDR → IR
    2. PC ← PC + 4

  执行阶段（EX）：
    3. 译码IR：操作码为ADD，寄存器为R2、R3、R1
    4. R2的内容 → ALU输入A，R3的内容 → ALU输入B
    5. ALU执行加法 → 结果
    6. 结果 → R1（写寄存器）

  控制信号：RegDst=1, ALUSrc=0, MemRead=0, MemWrite=0,
            MemtoReg=0, RegWrite=1, Branch=0

指令2：LW R1, 0(R2)  （Load，存储器读操作）
  取指阶段（IF）：
    1. PC → MAR → 取指令 → MDR → IR
    2. PC ← PC + 4

  译码阶段（ID）：
    3. 译码IR：操作码为LW，基址寄存器为R2，偏移量为0
    4. R2的内容 → ALU输入A，符号扩展的0 → ALU输入B

  执行阶段（EX）：
    5. ALU计算有效地址 = R2的内容 + 0

  访存阶段（MEM）：
    6. 有效地址 → MAR → 读内存 → MDR
    7. MDR内容 → 暂存

  写回阶段（WB）：
    8. 内存读出的数据 → R1

  控制信号：RegDst=0, ALUSrc=1, MemRead=1, MemWrite=0,
            MemtoReg=1, RegWrite=1, Branch=0

指令3：BEQ R1, R2, Offset  （Branch，条件转移）
  取指阶段（IF）：
    1. PC → MAR → 取指令 → MDR → IR
    2. PC ← PC + 4

  译码阶段（ID）：
    3. 译码IR：操作码为BEQ，寄存器为R1、R2
    4. R1的内容、R2的内容 → 比较

  执行阶段（EX）：
    5. 比较R1和R2，若相等 → Zero标志=1
    6. 若Zero=1 → PC ← PC + (Offset × 4)
       若Zero=0 → PC不变（PC+4已确定）

  控制信号：RegDst=X, ALUSrc=0, MemRead=0, MemWrite=0,
            MemtoReg=X, RegWrite=0, Branch=1
```

> 1. 给定指令格式和数据通路，分析指令执行过程中的数据流动
> 2. 写出指令执行过程中各控制信号的值
> 3. 画出指令执行的时间图（数据通路在时序中的变化）
> 4. 分析某条指令在单周期和多周期数据通路中的执行差异

### 五、控制信号与数据通路的关系 ⭐

#### 1. 数据通路中的关键通路

```
数据通路中可能的数据流动路径：

路径1：寄存器 → ALU → 寄存器（R-type指令）
路径2：寄存器 → ALU → 存储器地址（Load/Store）
路径3：存储器 → 寄存器（Load指令）
路径4：寄存器 → 存储器（Store指令）
路径5：PC → PC+4（顺序执行）
路径6：PC → 目标地址（转移指令）
路径7：ALU → 条件标志 → 控制单元（分支判断）
```

#### 2. 关键路径分析（CPI与时钟频率）

```
关键路径决定时钟周期的下限：

单周期数据通路：
  时钟周期 ≥ max(取指时间, 译码时间, 执行时间, 访存时间, 写回时间)
  
  最慢路径通常是：
  取指 → 译码 → ALU运算 → 写回
  
  如果 ALU运算 + 写回时间最长，则时钟周期受此路径限制

多周期数据通路：
  时钟周期 ≥ max(取指时间, 译码时间, 执行时间, 访存时间, 写回时间)
  
  每个阶段的延迟更短，因此时钟频率可以更高
  
  但需要多个时钟周期完成一条指令

性能比较：
  单周期：CPI=1，但时钟频率低
  多周期：CPI>1，但时钟频率高
  
  实际性能 = 时钟频率 / CPI
```

> ⭐ **选择题考点**：
> - 关键路径决定了时钟周期的最小值
> - 单周期数据通路中，时钟周期由最慢的指令决定
> - 多周期数据通路中，时钟周期由最慢的阶段决定
> - 流水线通过重叠执行提高吞吐率

### 六、CPU中的状态寄存器 ⭐

#### 1. 程序状态字（PSW/Flags）

```
状态寄存器（Flags / PSW）的常见标志位：

┌────────────────────────────────────────────┐
│ CF(进位)│ ZF(零) │ SF(符号) │ OF(溢出) │ ...│
└────────────────────────────────────────────┘

CF（Carry Flag）：无符号数运算产生进位/借位时为1
ZF（Zero Flag）：运算结果为0时为1
SF（Sign Flag）：运算结果为负数时为1（最高位=1）
OF（Overflow Flag）：有符号数运算产生溢出时为1
PF（Parity Flag）：结果低8位中1的个数为偶数时为1
```

**标志位的含义与产生条件**：

| 标志位 | 全称 | 含义 | 产生条件 |
|--------|------|------|---------|
| CF | Carry Flag | 进位标志 | 无符号数溢出（进位或借位） |
| ZF | Zero Flag | 零标志 | 运算结果等于0 |
| SF | Sign Flag | 符号标志 | 运算结果最高位为1（负数） |
| OF | Overflow Flag | 溢出标志 | 有符号数运算溢出 |
| PF | Parity Flag | 奇偶标志 | 结果低8位中1的个数为偶数 |

> 例：有符号数运算中，溢出（OF）的判别：
> - 正 + 正 = 负 → 溢出（OF=1）
> - 负 + 负 = 正 → 溢出（OF=1）
> - 正 + 负 或 负 + 正 → 不会溢出

> ⭐ **选择题考点**：
> - CF用于无符号数，OF用于有符号数
> - ZF=1表示结果为0
> - 减法运算的CF借位时也为1

## ⚖️易混淆概念对比

### 硬连线控制器 vs 微程序控制器

| 对比项 | 硬连线控制器 | 微程序控制器 |
|--------|-----------|-----------|
| 控制信号产生方式 | 组合逻辑电路 | 控制存储器中的微指令 |
| 执行速度 | 快（1~3ns延迟） | 慢（需读控制存储器，5~10ns） |
| 灵活性 | 差（修改需改硬件） | 好（修改微程序即可） |
| 设计复杂度 | 高（大规模组合逻辑设计） | 低（微程序编写） |
| 芯片面积 | 大 | 小 |
| 指令复杂度 | 适合简单指令（RISC） | 适合复杂指令（CISC） |
| 现代应用 | 高性能CPU（Intel/ARM） | 嵌入式、FPGA |

### 单周期数据通路 vs 多周期数据通路

| 对比项 | 单周期数据通路 | 多周期数据通路 |
|--------|-----------|-----------|
| 时钟周期 | 最长路径决定（较慢） | 最慢阶段决定（可更快） |
| CPI | 1 | >1（不同指令不同） |
| 硬件复用 | 每个功能部件只用一次 | 功能部件可跨周期复用 |
| 控制信号数量 | 每条指令一套 | 每个阶段一套（更多） |
| 数据冒险 | 无 | 存在（需解决） |
| 实现难度 | 简单 | 复杂（需状态机） |

### 水平型微指令 vs 垂直型微指令

| 对比项 | 水平型微指令 | 垂直型微指令 |
|--------|-----------|-----------|
| 控制信号数量 | 多（每位对应一个信号） | 少（编码选择） |
| 并行度 | 高（多信号同时有效） | 低（编码限制） |
| 微指令长度 | 长 | 短 |
| 微程序长度 | 短（每条机器指令少微周期） | 长（每条机器指令多微周期） |
| 存储空间 | 大 | 小 |
| 类比 | 类似机器指令的"并行版" | 类似机器指令的"编码版" |

## ⚠️考试高频坑点

### 坑点1：PC和IR的区别

> 【坑点】PC存放的是**下一条**指令地址，IR存放的是**当前**指令。
> 取指阶段完成后，PC已更新为下一条指令地址，IR中是当前指令。
> 在分析数据通路时，要分清PC和IR的不同角色。

### 坑点2：控制信号与指令执行的关系

> 【坑点】每条指令对应的控制信号组合不同。
> R-type指令：RegWrite=1, MemRead=0, MemWrite=0
> Load指令：RegWrite=1, MemRead=1, MemWrite=0, MemtoReg=1
> Store指令：RegWrite=0, MemRead=0, MemWrite=1
>
> 注意：Store指令不需要RegWrite=1（不写寄存器）。

### 坑点3：硬连线控制器与微程序控制器的速度比较

> 【坑点】硬连线控制器更快，因为控制信号通过组合逻辑直接产生，无需从控制存储器中读取微指令。
> 但微程序控制器更灵活，适合指令集复杂的CISC处理器。

### 坑点4：单周期与多周期的CPI比较

> 【坑点】单周期数据通路的CPI=1，但时钟周期长（由最慢指令决定）。
> 多周期数据通路的CPI>1，但时钟周期短（由最慢阶段决定）。
> 实际性能需要综合时钟频率和CPI来比较：性能 = 时钟频率 / CPI。

### 坑点5：ALU的运算结果与标志位

> 【坑点】ALU运算后，不仅产生结果，还产生标志位。
> 标志位用于条件分支判断（如BEQ、BNE指令）。
> 在数据通路中，Zero标志是从ALU输出的比较结果产生的。
