# 输入输出系统

## 📍知识定位

### 在408体系中的位置

输入输出系统（I/O 系统）是计算机组成原理的最后一个核心模块。它研究计算机**主机与外部设备之间**的数据传输机制，包括 I/O 接口结构、I/O 编址方式、I/O 数据传输控制方式、I/O 接口标准等。I/O 系统是连接计算机与外部世界的"桥梁"。

- **知识层级**：在掌握总线技术和 CPU 基本结构之后，理解系统如何与外部设备通信。
- **前置知识**：
  - [[总线]]：I/O 设备通过总线与 CPU 和内存连接
  - [[CPU结构]]：理解 CPU 如何响应和响应 I/O 请求
  - [[指令流水线]]：I/O 操作可能影响流水线（中断/异常）
- **后续延伸**：
  - [[内存管理]]：内存与 I/O 设备的共享（如 DMA 直接访问内存）
  - [[中断与异常处理]]：I/O 中断是 I/O 系统的重要组成部分
- **跨科目联动**：操作系统的 [[IO管理]] 完全建立在本模块的硬件基础之上，操作系统 I/O 子系统的实现（如缓冲管理、设备分配、I/O 处理程序）都基于这些硬件机制。

## 📝核心概念与原理

### 一、I/O 系统的基本概念

#### 1.1 I/O 系统的组成 ⭐

I/O 系统由以下部分组成：

| 组成部分 | 说明 |
|---------|------|
| **外部设备** | 输入设备（键盘、鼠标、扫描仪等）和输出设备（显示器、打印机等）及外存储器（硬盘、U盘等） |
| **I/O 接口（I/O 控制器）** | 连接外部设备和总线的硬件电路，负责设备控制和数据缓冲 |
| **I/O 指令** | CPU 执行的 I/O 操作命令（IN、OUT 等） |
| **I/O 端口** | I/O 接口中的寄存器，分为数据端口、状态端口、控制端口 |
| **I/O 软件** | 设备驱动程序、中断处理程序、设备独立驱动程序等 |

> 核心理解：**I/O 接口是 I/O 系统中最重要的硬件部件**。它充当外部设备和总线之间的"翻译官"——将外部设备的并行/串行、快/慢、模拟/数字信号转换为总线可处理的格式。

#### 1.2 I/O 端口的分类 ⭐

I/O 接口中一般包含三类端口：

| 端口类型 | 方向 | 功能 |
|---------|------|------|
| **数据端口** | 双向 | 存放实际传输的数据 |
| **状态端口** | 只读（CPU读） | 存放设备的状态信息（忙/闲、就绪等） |
| **控制端口** | 只写（CPU写） | 存放 CPU 发来的控制命令 |

> 示例：硬盘控制器的端口：
> - 数据端口：存放待读/写的扇区数据
> - 状态端口：0=就绪，1=忙
> - 控制端口：写 0x05 表示读扇区，写 0x03 表示写扇区

#### 1.3 端口编址方式 ⭐

CPU 访问 I/O 端口的编址方式分为两种：

**（1）统一编址（内存映射 I/O，Memory-Mapped I/O）**

- I/O 端口**占用主存地址空间**的一部分
- CPU 用访存指令（如 LOAD、STORE）访问 I/O 端口
- 不区分内存和 I/O，指令集简单

**（2）独立编址（I/O 映射 I/O，Isolated I/O）**

- I/O 端口有**独立的地址空间**
- CPU 使用专门的 I/O 指令（如 x86 的 IN、OUT）访问
- 需要额外的控制线（如 x86 的 I/O/M# 线）

| 比较项 | 统一编址 | 独立编址 |
|-------|---------|---------|
| **地址空间** | 与内存共享 | 独立地址空间 |
| **访存指令** | 通用 LOAD/STORE | 专用 IN/OUT |
| **指令系统** | 简单（无需专门 I/O 指令） | 需要专门 I/O 指令 |
| **优点** | 编程灵活，可利用全部访存指令 | 地址空间分离，编程直观 |
| **代表架构** | ARM、MIPS | x86（两者都用，但独立编址更常见于I/O） |

> ⭐ 考试要点：统一编址下，I/O 端口地址与内存地址共享同一地址空间，CPU 无法仅从地址判断是访问内存还是 I/O，需要依赖指令类型或地址范围约定。

### 二、I/O 数据传输控制方式 ⭐🔥（核心考点）

这是 408 考研**最重要的内容之一**，涉及五种数据传输控制方式，需要深度比较理解。

#### 2.1 程序控制方式（Programmed I/O） ⭐

**（1）无条件传送**

- CPU 执行 I/O 指令时，**不检查**外设状态，直接传输数据
- 适用于**简单、高速、始终就绪**的设备（如 ADC 的数据锁存器、LED 显示器的数据寄存器）

```assembly
    MOV DX, 60h      ; 端口地址
    IN  AL, DX       ; 无条件读取数据
```

**（2）条件传送（查询方式）**

- CPU 执行 I/O 指令前，**先查询**外设状态
- 只有设备就绪（Ready）时才传输数据
- 设备未就绪时，CPU 循环查询（忙等）

```assembly
check_ready:
    MOV DX, 60h
    IN  AL, DX          ; 读状态端口
    TEST AL, 1          ; 检查就绪位
    JZ  check_ready     ; 未就绪则继续等待
    MOV DX, 62h
    IN  AL, DX          ; 就绪后读数据
```

> 问题：**CPU 利用率低**，在设备准备数据期间，CPU 处于"忙等"状态，无法做其他工作。

#### 2.2 中断驱动方式（Interrupt-driven I/O） ⭐🔥

**核心思想**：外设准备好数据后，**主动发中断请求**通知 CPU，CPU 响应中断后执行中断服务程序（ISR）完成数据传输。

**工作流程**：

```
1. CPU 发出 I/O 写命令
2. 外设开始准备数据（CPU 去做其他事情）
3. 外设数据就绪 → 发中断请求（IRQ）
4. CPU 完成当前指令 → 保存断点 → 响应中断
5. 执行中断服务程序（ISR）→ 读取/写入数据
6. 中断返回 → CPU 继续执行原程序
```

**中断请求的四种响应方式**：

| 方式 | 说明 |
|------|------|
| **同步中断** | 由程序执行引起的（异常、陷阱），必须响应 |
| **异步中断** | 由外部事件引起的（I/O 中断、Timer），可屏蔽/不可屏蔽 |
| **可屏蔽中断** | 可通过中断屏蔽位控制是否响应 |
| **不可屏蔽中断** | 必须响应（如电源故障） |

**中断响应条件**：
1. 外设发出中断请求
2. CPU 未正在处理同级或更高级中断
3. 中断屏蔽触发器为 0（中断允许）
4. CPU 当前指令已执行完毕

> 🔥 408 大题重点：对比程序查询方式和中断方式——程序查询方式 CPU 浪费在忙等上，而中断方式 CPU 可以在设备准备期间做其他工作，但中断处理本身也有开销（保存/恢复上下文）。

#### 2.3 DMA 方式（Direct Memory Access） ⭐🔥🔥

**核心思想**：数据在**外设和内存之间直接传输**，不经过 CPU。CPU 只负责初始化 DMA 传输（设置起始地址、传输字节数等），传输完成后外设通过中断通知 CPU 结果。

**DMA 控制器的功能模块**：

| 模块 | 功能 |
|------|------|
| **地址寄存器** | 存放当前传输的内存地址 |
| **计数器/长度寄存器** | 存放待传输的数据个数 |
| **控制寄存器** | 存放命令字（读/写、起始地址、传输长度） |
| **状态寄存器** | 存放传输状态（传输完成、缓冲区满/空） |
| **DMA 控制器** | 接收外设的 DMA 请求，向 CPU 申请总线使用权 |

**DMA 传输过程** 🔥：

```
阶段1：DMA 预处理（由软件完成）
  ① CPU 设置 DMA 控制器的起始地址
  ② CPU 设置传输字节数
  ③ CPU 设置传输方向（读/写）
  ④ CPU 启动 DMA 控制器

阶段2：DMA 数据传输（由硬件自动完成）
  ① 外设向 DMA 控制器发出 DMA 请求（DRQ）
  ② DMA 控制器向 CPU 发出总线请求（HOLD）
  ③ CPU 当前指令结束后响应（HLDA，总线应答）
  ④ CPU 释放总线（地址线、数据线、控制线）
  ⑤ DMA 控制器获得总线控制权（HOLD ACK）
  ⑥ DMA 控制器直接控制外设与内存之间的数据传输
  ⑦ 每传输一个字节，地址寄存器自增，计数器自减

阶段3：DMA 后处理
  ① 传输完成 → DMA 控制器发中断请求通知 CPU
  ② CPU 中断响应，执行中断服务程序
  ③ CPU 清除计数器（为下次传输做准备）
```

**DMA 与中断的本质区别** 🔥：

| 对比项 | DMA 方式 | 中断方式 |
|-------|---------|---------|
| **传输单位** | 一个**数据块**（多个字节） | 一个**字节/字** |
| **传输过程** | 外设 ↔ 内存（不经过 CPU） | 外设 ↔ CPU 寄存器 ↔ 内存 |
| **总线控制权** | DMA 控制器获得**总线控制权** | CPU 始终拥有总线控制权 |
| **传输时机** | 外设准备好后发 DMA 请求 | 外设准备好后发中断请求 |
| **CPU 参与** | 仅在初始化/后处理时参与 | 每次传输都需 CPU 参与（保存/恢复现场） |
| **适用场景** | 大批量数据传输（磁盘、网卡） | 少量数据传输（键盘、鼠标） |

> ⭐ 关键理解：**DMA 是"硬件"级别的传输**，由 DMA 控制器直接控制总线；中断是"软件"级别的传输，需要 CPU 执行指令来完成。

**DMA 传送的三种方式** 🔥：

| 方式 | 说明 | 适用场景 |
|------|------|---------|
| **停止传送（Daisy-chained）** | CPU 放弃总线，DMA 独占总线直到传输完成 | 传输量大、实时性要求高的场景 |
| **周期挪用（Cycle Stealing）** | DMA 每次传输一个字节/字就挪用 1 个总线周期，然后归还总线 | 最常用的方式 |
| **DMA 与 CPU 交替传输** | DMA 和 CPU 轮流使用总线（如一个周期 DMA，一个周期 CPU） | 对实时性要求不高的场景 |

#### 2.4 通道方式（Channel I/O） ⭐

**核心思想**：通道是一种**专门用于管理 I/O 操作的处理器**（I/O 协处理器）。CPU 只需发出通道程序（起始地址），通道就自动执行通道程序完成 I/O 操作。

> 通道 = DMA 的升级版，通道有自己的指令（通道命令字）和程序（通道程序），功能更强。

**通道类型**：

| 类型 | 说明 | 特点 |
|------|------|------|
| **I/O 通道** | 专门用于管理 I/O 操作的处理器 | 可执行通道程序，批量处理 |
| **DMA 控制器** | 简单的数据搬运控制器 | 只能完成固定操作（读/写），无指令系统 |

**通道的通道程序**：

```
通道程序由通道命令字（CCW）组成：
  CCW 1: 读取磁盘块 → 内存地址 A，长度 512
  CCW 2: 处理数据 → 内存地址 B，长度 256
  CCW 3: 写回磁盘块 → 内存地址 A，长度 512
```

通道依次执行这些命令，CPU 只需初始化并等待中断。

#### 2.5 I/O 处理程序（Device Driver） ⭐

操作系统层面对 I/O 管理的软件实现：

```
用户程序调用 read()
  → 系统调用处理（进入内核态）
  → I/O 管理模块
    → 设备驱动程序（针对具体设备）
      → I/O 控制器（通过总线发送命令）
        → 外设硬件
```

### 三、五种 I/O 控制方式综合对比 ⭐🔥🔥（考试大题核心）

| 方式 | CPU 参与度 | 传输单位 | 是否占用总线 | 适用场景 | 实时性 | 数据传输效率 |
|------|-----------|---------|-------------|---------|--------|-------------|
| 无条件传送 | 最高（每次传输） | 字节/字 | 否 | 简单、高速外设（LED） | 差 | 低 |
| 程序查询 | 高（忙等） | 字节/字 | 否 | 简单外设（早期打印机） | 差 | 低 |
| 中断驱动 | 中（仅传输瞬间） | 字节/字 | 否 | 中等数据量（键盘、鼠标） | 中 | 中 |
| DMA | 低（仅初始化/后处理） | 数据块 | 是（周期挪用） | 大批量数据（磁盘、网卡） | 高 | 高 |
| 通道 | 最低（仅启动通道程序） | 大批量数据块 | 是 | 大型机/服务器多设备 | 高 | 最高 |

> 🔥 408 考研必考：五种方式的比较，特别是 DMA 与中断的本质区别（是否占用总线、传输单位大小）。

### 四、I/O 软件层次 ⭐

I/O 软件通常分为四层：

```
┌─────────────────────────────┐
│   用户 I/O 软件              │  ← 用户程序中的 I/O 库（如 printf）
├─────────────────────────────┤
│   设备独立性软件              │  ← 操作系统提供的通用接口（如 open、read）
├─────────────────────────────┤
│   设备驱动程序                │  ← 针对具体设备的驱动代码
├─────────────────────────────┤
│   中断处理程序                │  ← 硬件中断的服务例程
└─────────────────────────────┘
```

**各层功能**：

| 层次 | 功能 | 示例 |
|------|------|------|
| 用户 I/O 软件 | 提供用户友好的接口 | `fread()`、`printf()` |
| 设备独立性软件 | 设备无关的统一接口，实现缓冲管理、设备分配 | `read()`、`write()` 系统调用 |
| 设备驱动程序 | 将通用 I/O 请求转换为设备-specific 命令 | 硬盘驱动、显卡驱动 |
| 中断处理程序 | 响应外设中断，完成数据读取 | ISR（Interrupt Service Routine） |

### 五、I/O 可靠性与性能 ⭐

#### 5.1 I/O 性能指标

| 指标 | 定义 | 示例 |
|------|------|------|
| **数据传输率** | 单位时间传输的数据量 | 硬盘：150 MB/s |
| **响应时间** | 从发出请求到数据就绪的时间 | 键盘：几乎即时 |
| **吞吐量** | 单位时间内完成的 I/O 操作数 | 磁盘：IOPS（每秒 I/O 次数） |
| **CPU 开销** | I/O 操作占用的 CPU 时间比例 | 中断方式 > DMA 方式 |

#### 5.2 缓冲区（Buffer）

**作用**：缓解 CPU 与外设速度不匹配的问题。

| 缓冲类型 | 说明 |
|---------|------|
| **单缓冲** | 一块缓冲区，传输完再申请下一块 |
| **双缓冲** | 两块缓冲区交替使用，提高吞吐量 |
| **缓冲池** | 多个缓冲区，供多个设备共享 |

### 六、常见 I/O 标准与接口 ⭐

| 标准 | 全称 | 特点 | 应用场景 |
|------|------|------|---------|
| **UART** | Universal Asynchronous/synchronous Receiver/Transmitter | 通用异步收发器，串行通信 | 早期串口 |
| **USB** | Universal Serial Bus | 通用串行总线，热插拔，高速 | 外设连接 |
| **SATA** | Serial ATA | 串行 ATA 接口 | 硬盘/SSD 连接 |
| **SCSI** | Small Computer System Interface | 小型计算机系统接口 | 服务器存储 |
| **FireWire** | IEEE 1394 | 高速串行总线 | 视频设备 |

#### USB 特性 ⭐：

| 特性 | 说明 |
|------|------|
| **热插拔** | 支持带电插拔 |
| **即插即用** | 自动识别设备并加载驱动 |
| **总线供电** | 通过 USB 线提供电源（5V） |
| **传输速率** | USB 2.0: 480 Mbps; USB 3.0: 5 Gbps; USB 3.2: 20 Gbps |
| **级联能力** | 最多 127 个设备（通过集线器扩展） |

## ⚖️易混淆概念对比

| 对比项 | DMA 方式 | 中断驱动方式 |
|--------|---------|-------------|
| **数据搬运主体** | DMA 控制器 | CPU |
| **传输单位** | 数据块（多个字节/字） | 字节/字 |
| **是否占用总线** | ✅ 占用（周期挪用） | ❌ 不占用（CPU 始终控制总线） |
| **CPU 干预频率** | 低（仅初始化和完成后中断） | 高（每次传输都中断一次） |
| **适用数据量** | 大批量 | 小批量 |
| **本质区别** | 硬件自动搬运 | 软件（中断服务程序）搬运 |

| 对比项 | DMA 控制器 | 通道 |
|--------|-----------|------|
| **智能程度** | 简单，只能做固定操作 | 有指令系统（通道命令字） |
| **可编程性** | 低（只能设置参数） | 高（可执行通道程序） |
| **功能** | 数据块搬运 | 复杂的 I/O 序列操作 |
| **复杂度** | 低 | 高 |
| **应用场景** | PC、服务器 | 大型机、高性能服务器 |

| 对比项 | 同步传输 | 异步传输 |
|--------|---------|---------|
| **时钟** | 发送方和接收方时钟同步 | 无统一时钟 |
| **效率** | 高（无需额外同步字符） | 较低（需要起始位/停止位） |
| **可靠性** | 较好（需时钟同步） | 较好（每字节有起始/停止位） |
| **适用** | 高速通信（磁盘、DMA） | 低速通信（串口、键盘） |

| 对比项 | 并行传输 | 串行传输 |
|--------|---------|---------|
| **传输方式** | 多位同时传输 | 一位一位传输 |
| **速度** | 快（并行） | 较慢（串行，但高速串行已超越并行） |
| **抗干扰** | 差（串扰、 skew 问题） | 好（差分信号） |
| **线数** | 多（8/16/32 条数据线） | 少（2 条差分线） |
| **代表** | 并行口（老打印机）、PCI（旧） | USB、SATA、PCIe、SAS |

## ⚠️考试高频坑点

### 坑点 1：DMA 与中断的本质区别

> DMA 传输过程中，CPU 做什么？

【❌ 错误理解】DMA 传输时 CPU 执行中断服务程序搬运数据

【✅ 正确理解】**DMA 传输时 CPU 完全不参与数据搬运**！CPU 只负责初始化 DMA 控制器，数据传输完全由 DMA 控制器通过总线直接完成。传输完成后外设才通过中断通知 CPU。这是 DMA 与中断方式最本质的区别：**是否占用总线**。

### 坑点 2：传输单位的差异

【❌ 错误理解】中断方式和 DMA 方式的传输单位一样

【✅ 正确理解】中断方式传输**一个字节/字**就中断一次；DMA 方式传输**一个数据块**（多个字节/字）才中断一次。这就是为什么 DMA 适合大批量数据传输。

### 坑点 3：无条件传送的适用条件

【❌ 错误理解】无条件传送适合所有外设

【✅ 正确理解】无条件传送只适合**始终就绪且速度匹配**的设备（如 LED 显示器的数据寄存器）。如果外设未准备好而 CPU 强制读/写，会读到错误数据或覆盖未处理的数据。

### 坑点 4：周期挪用 vs 停止传送

【❌ 错误理解】周期挪用方式中 DMA 一直占用总线

【✅ 正确理解】**周期挪用**是每次传输一个字节就挪用 1 个总线周期，然后归还总线给 CPU。**停止传送**方式是 DMA 传输期间独占总线，CPU 完全无法访问内存。

### 坑点 5：通道的本质

【❌ 错误理解】通道和 DMA 是一样的

【✅ 正确理解】通道是 DMA 的升级——DMA 只能做简单的数据搬运（读/写），而通道有自己的指令系统（通道命令字）和程序，可以执行**复杂的 I/O 操作序列**。通道 = I/O 协处理器。

### 坑点 6：统一编址 vs 独立编址

【❌ 错误理解】统一编址下 I/O 端口地址和内存地址是不同的

【✅ 正确理解】**统一编址（内存映射 I/O）**下，I/O 端口和内存共享同一地址空间，CPU 用同样的 LOAD/STORE 指令访问。而**独立编址**下，I/O 有独立的地址空间，需要使用专门的 IN/OUT 指令。

## 🔗知识链路总结

### 向上依赖（前置知识）

- [[总线]]：I/O 设备通过总线与 CPU 和内存连接；DMA 传输直接占用总线
- [[CPU结构]]：理解 CPU 如何响应中断、如何初始化 DMA
- [[指令流水线]]：I/O 中断发生时，流水线需要冲刷（flush）并保存状态
- [[指令系统]]：I/O 指令（如 x86 的 IN/OUT）是程序控制方式的基础

### 向下支撑（后续延伸）

- [[内存管理]]：DMA 直接访问内存；Cache 与 I/O 的一致性需要同步
- [[中断与异常处理]]：I/O 中断是中断系统的重要组成部分
- [[文件系统]]：文件的读写最终通过 I/O 系统实现

### 跨科目打通

- [[IO管理]]（操作系统）：操作系统的 I/O 子系统完全建立在本模块的硬件基础之上
  - I/O 软件层次（驱动层、缓冲层）对应本模块的 I/O 软件层次
  - 设备分配与回收对应本模块的 I/O 控制方式选择
  - 缓冲管理对应本模块的缓冲区概念
- [[进程上下文管理]]（操作系统）：I/O 中断发生时，需要保存进程上下文（与流水线状态保存相关）
- [[进程调度]]（操作系统）：I/O 阻塞调度——进程发起 I/O 请求后进入阻塞状态，CPU 调度其他进程
