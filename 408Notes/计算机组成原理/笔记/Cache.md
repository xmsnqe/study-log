# Cache

## 📍知识定位

### 在408体系中的位置

Cache（高速缓冲存储器）是计算机组成原理中**极高频考点**，位于存储器层次结构核心位置。它解决了CPU与主存之间速度不匹配的根本问题。Cache的设计与性能评估贯穿408计算机组成原理的选择题和大题，与指令系统、CPU数据通路、存储层次结构紧密关联。

### 学习前置条件

- **存储器层次结构**：理解存储层次模型、局部性原理
- **数据表示**：理解地址的位级表示、字节序
- **指令系统**：了解指令格式中的地址字段（用于理解Cache地址字段划分）

### 学完之后支撑的知识点

- **CPU数据通路**：Cache是CPU访问数据的重要中间层
- **主存储器**：Cache与主存的协同工作
- **性能评估**：Amdahl定律中的Cache加速比

## 📝核心概念与原理

### 一、Cache的基本工作原理 ⭐

#### 1. 为什么需要Cache

现代CPU的执行速度（GHz级别）远高于主存的访问速度（几十纳秒）。如果CPU每次取指令或数据都要等待主存访问，将造成巨大的性能浪费。

```
CPU → [寄存器] → [Cache] → [主存] → [外存]
      最快     次快（缓存近期数据）  较慢     最慢
```

**核心原理**：利用程序执行的**局部性原理**（时间局部性与空间局部性），将近期频繁访问的数据复制到Cache中，使得CPU大部分时间访问的是Cache而非主存。

> ⭐ 局部性原理是Cache存在的理论基础，详见 [[计算机组成原理/存储器层次结构]]。

#### 2. Cache的基本结构

```
┌─────────────────────────────────────────────┐
│                 Cache                         │
│  ┌──────┬──────────┬────────┬────────┐      │
│  │ Tag  │ 有效位   │  数据  │  替换信息 │     │
│  │ 标记  │ (Valid) │ (Data) │ (LRU等) │      │
│  └──────┴──────────┴────────┴────────┘      │
│  ┌──────┬──────────┬────────┬────────┐      │
│  │ Tag  │ 有效位   │  数据  │  替换信息 │     │
│  │ 标记  │ (Valid) │ (Data) │ (LRU等) │      │
│  └──────┴──────────┴────────┴────────┘      │
│  ┌──────┬──────────┬────────┬────────┐      │
│  │ Tag  │ 有效位   │  数据  │  替换信息 │     │
│  │ 标记  │ (Valid) │ (Data) │ (LRU等) │      │
│  └──────┴──────────┴────────┴────────┘      │
│                    ...                        │
└─────────────────────────────────────────────┘
```

**Cache行（Cache Line / Cache Block / 块）**：

每个Cache行包含：
- **Tag（标记）**：主存块号的高位部分，用于判断命中与否
- **Valid（有效位）**：1表示该Cache行包含有效数据，0表示无效
- **Data（数据）**：存储的实际数据（块大小，如64字节）
- **替换信息**：用于LRU等替换算法的额外信息

> ⭐ **选择题考点**：
> - Cache行的大小 = 块大小（Block Size）
> - Cache行中Tag + 有效位 + 数据 + 替换信息 = 一行的大小
> - 有效位是必需的：用于判断Cache行中是否有有效数据

#### 3. Cache的读写过程 ⭐🔥

**读Cache的过程**：

```
1. 根据CPU给出的主存地址，分解为：Tag | Index（组号/行号）| Block Offset（块内偏移）
2. 用Index定位到对应的Cache行（或组）
3. 比较该Cache行的Tag与地址中的Tag
4. 如果Tag匹配且有效位=1 → 命中（Hit）→ 根据Block Offset从数据中取出所需字节
5. 如果Tag不匹配或有效位=0 → 未命中（Miss）→ 从主存中读取对应块装入Cache，再返回数据
```

**写Cache的过程**：取决于写策略（见下文）。

> 地址分解的公式（以直接映射为例）：
> - 块内偏移位数 = log₂(块大小)
> - 组号（Index）位数 = log₂(Cache行数)
> - Tag位数 = 主存地址位数 - 组号位数 - 块内偏移位数

> 🔥 **大题必考**：Cache地址字段划分。给定Cache参数（总容量、块大小、相联方式），计算Tag/Index/Block Offset的位数并画图说明地址结构。

### 二、Cache的映射方式 ⭐🔥

映射方式决定了主存块可以存放在Cache的哪些位置。这是408考试中最核心的大题考点。

#### 1. 直接映射（Direct Mapping）⭐

**规则**：

> 主存中的每个块只能映射到Cache中的**唯一固定位置**。

```
主存块号 → mod Cache行数 → 对应的Cache行号

地址结构：
┌──────────┬──────────┬──────────────┐
│   Tag    │  组号(i)  │   块偏移(b)   │
│  (n-k-w) │  (k-bit)  │   (w-bit)    │
└──────────┴──────────┴──────────────┘

其中：
- w = log₂(块大小)，块偏移位数
- k = log₂(Cache行数)，组号位数
- n = 主存地址总位数
- n-k-w = Tag位数
```

**映射公式**：

```
主存块号 j 映射到 Cache 行号 i：
i = j mod m

其中 m 为 Cache 总行数。
```

> 例：Cache有64行，主存块号为127，则127 mod 64 = 63 → 映射到第63行。

**特点**：

| 优点 | 缺点 |
|------|------|
| 硬件简单，只需比较一行 | 冲突频繁（多个主存块映射到同一行） |
| 命中判断速度快（单行比较） | 命中率较低 |
| 成本低 | 可能出现"颠簸"（Thrashing）：两个频繁访问的主存块竞争同一Cache行 |

> ⭐ **选择题考点**：直接映射中，如果两个主存块映射到同一Cache行，它们不能同时存在于Cache中，必有一个被淘汰（冲突未命中）。

#### 2. 全相联映射（Fully Associative Mapping）⭐

**规则**：

> 主存中的**任意块**可以装入Cache中的**任意位置**。

```
地址结构：
┌──────────┬──────────────┐
│   Tag    │   块偏移(b)   │
│ (n-w-bit)│   (w-bit)    │
└──────────┴──────────────┘
```

**特点**：

| 优点 | 缺点 |
|------|------|
| 灵活性最高，无映射冲突 | 硬件复杂，需同时比较所有行的Tag |
| 命中率最高 | 替换算法复杂（LRU等） |
| 没有"颠簸"问题 | 成本高，功耗大 |

> 例：Cache有64行，块大小64字节，主存地址32位。
> - 块偏移位数 = log₂(64) = 6位
> - Tag位数 = 32 - 6 = 26位
> - 每个Cache行都要比较26位的Tag

> ⭐ **选择题考点**：全相联映射的Tag位数 = 主存地址位数 - 块偏移位数。因为没有组号字段。

#### 3. 组相联映射（Set-Associative Mapping）⭐🔥

**规则**：

> Cache分为若干组，每组包含r行（r路）。主存块可以映射到指定组的任意一行。

```
地址结构：
┌──────────┬──────────┬──────────────┐
│   Tag    │  组号(s)  │   块偏移(b)   │
│ (n-s-w)  │  (s-bit)  │   (w-bit)    │
└──────────┴──────────┴──────────────┘

其中：
- w = log₂(块大小)，块偏移位数
- s = log₂(每组行数)，组号位数
- n-s-w = Tag位数

"r路组相联"：每组有r行
组数 = Cache总行数 / r
组号位数 = log₂(组数) = log₂(总行数/r)
```

> 例：Cache总容量64KB，块大小64字节，4路组相联。
> - 总行数 = 64KB / 64B = 1024行
> - 组数 = 1024 / 4 = 256组
> - 组号位数 = log₂(256) = 8位
> - 块偏移位数 = log₂(64) = 6位
> - Tag位数 = 32 - 8 - 6 = 18位

**特点**：

| 对比项 | 直接映射 | 全相联映射 | 2路组相联 | 4路组相联 | 8路组相联 |
|--------|---------|-----------|----------|----------|----------|
| 灵活性 | 低 | 高 | 中高 | 中 | 中低 |
| 命中率 | 最低 | 最高 | 较高 | 中等 | 中等 |
| 硬件复杂度 | 最低 | 最高 | 低 | 中等 | 较高 |
| 比较器数量 | 1 | N行 | r行 | r行 | r行 |
| 实际应用 | 少 | 小Cache | 常见 | 常见 | 中等 |

> 408考试中，**组相联映射**是最常考的，通常设定为2路、4路或8路。

> 🔥 **大题必考**：
> 1. 给定Cache参数，画出地址结构并标明各字段位数
> 2. 给定主存地址，判断其在Cache中的位置
> 3. 计算不同映射方式的命中率差异

### 三、Cache的替换算法 ⭐

当Cache满且需要装入新块时，需要选择替换哪个块。

#### 1. 直接映射的替换

> 直接映射中每个主存块只能放在唯一一行，**无需选择**——新块直接覆盖旧块（强制替换）。

#### 2. 全相联/组相联的替换算法

**LRU（Least Recently Used，最近最久未使用）⭐**：

> 替换最近最长时间未被访问的块。

```
4路组相联，每组的LRU计数器：
行0：5秒前访问
行1：2秒前访问
行2：8秒前访问 ← 被替换（最久未用）
行3：1秒前访问
```

> 4路组相联需要 4×(4-1)/2 = 6个计数器位来记录LRU顺序。

**FIFO（First In First Out，先进先出）**：

> 替换最早装入Cache的块。

> 注意：FIFO不考虑访问频率，可能替换频繁访问的块，通常性能不如LRU。

**LFU（Least Frequently Used，最不经常使用）**：

> 替换访问频率最低的块。

**RANDOM（随机替换）**：

> 随机选择一个块替换。简单但性能不可控。

> ⭐ **选择题高频考点**：
> - LRU是实际最广泛使用的替换算法
> - LRU用"最近访问时间"判断，LFU用"访问总次数"判断
> - 直接映射不需要替换算法
> - LRU的硬件开销比FIFO大

### 四、Cache的写策略 ⭐🔥

Cache的写操作有四种经典策略，核心问题是：**当CPU写Cache时，主存是否同步更新？**

#### 1. 写直达法（Write-Through）⭐

> 写操作同时写入Cache和主存。

```
CPU写Cache → 同步写主存
```

| 优点 | 缺点 |
|------|------|
| Cache与主存数据始终一致 | 写命中时写主存，耗时较长 |
| 实现简单 | 每次写都访问主存，总线带宽占用大 |
| 读Miss时直接从主存取数据 | 写性能较低 |

#### 2. 写回法（Write-Back）⭐🔥

> 写操作只写Cache，将该行标记为"Dirty（脏）"。只有当该行被替换出Cache时，才写回主存。

```
CPU写Cache → 标记为Dirty
被替换时 → 写回主存
```

| 优点 | 缺点 |
|------|------|
| 写命中只写Cache，速度快 | Cache与主存可能不一致 |
| 减少主存写操作，降低总线负载 | 需要Dirty位（额外1bit/行） |
| 适合写频繁的场景 | 实现复杂 |
| 命中率更高 | 替换时可能产生写流量 |

| 对比项 | 写直达法 | 写回法 |
|--------|---------|--------|
| 写命中时间 | 长（写Cache+主存） | 短（只写Cache） |
| 写Miss时间 | 短（直接写主存） | 长（先读入Cache再写） |
| 是否需要Dirty位 | 不需要 | 需要（1bit/行） |
| 数据一致性 | 始终一致 | 替换时保持一致 |
| 总线负载 | 大（每次写都写主存） | 小（只写Miss或替换时） |
| 适用场景 | 写少读多 | 写频繁 |

> 🔥 **大题考点**：
> 1. 写回法需要一个Dirty位（写污位），直接映射不需要，组相联/全相联都需要
> 2. 写直达法不需要Dirty位
> 3. 现代处理器（如x86）多采用写回法

### 五、Cache的性能评估 ⭐🔥

#### 1. 命中率与平均访问时间 ⭐🔥

**命中率（Hit Rate, h）**：

```
命中率 = 命中次数 / 总访问次数

miss率 = 1 - h
```

**平均访问时间（Average Access Time, ta）**：

```
ta = h × tc + (1-h) × tm

其中：
- tc：Cache访问时间（命中时间）
- tm：Miss后的平均访问时间（包含从主存取数据并装入Cache的时间）

如果区分命中时间tc和Miss惩罚：
ta = h × tc + (1-h) × (tc + 主存访问时间)
   = tc + (1-h) × 主存访问时间

如果采用"同时访问"（Parallel Access）：
ta = h × tc + (1-h) × (tc + tm)
   = tc + (1-h) × tm
```

> 例：Cache访问时间10ns，主存访问时间100ns，命中率95%。
> ta = 0.95 × 10 + 0.05 × (10 + 100) = 9.5 + 5.5 = 15ns
> 或者：ta = 10 + 0.05 × 100 = 15ns

> 🔥 **大题必考**：命中率、Cache访问时间、主存访问时间的综合计算。可能结合Amdahl定律。

#### 2. Miss率与Miss分类 ⭐

**Miss的三种类型**：

| 类型 | 说明 | 能否减少 |
|------|------|---------|
| **强制Miss（Compulsory Miss）** | 第一次访问某个块，块不在Cache中 | 只能通过预热（Warm-up）减少 |
| **容量Miss（Capacity Miss）** | Cache容量不够，之前驻留的块被替换 | 增大Cache容量可以减少 |
| **冲突Miss（Conflict Miss）** | 直接映射/组相联中，多个块竞争同一位置 | 增加路数/改为全相联可以减少 |

> ⭐ **选择题考点**：
> - 直接映射/组相联可能有三种Miss
> - 全相联映射不会有冲突Miss（最多有强制Miss和容量Miss）
> - 增大块大小可以减少强制Miss（空间局部性），但可能增大容量Miss（Cache行数减少）

#### 3. Amdahl定律中的Cache加速比

```
Cache加速比 = 有Cache时的平均执行时间 / 无Cache时的执行时间

如果CPU原有周期时间为T，Cache命中率为h：
加速比 = 1 / (h × 1 + (1-h) × 主存访问倍率)
```

> 例：h=0.95，主存访问时间是Cache的10倍。
> 平均周期 = 0.95 × 1 + 0.05 × 10 = 0.95 + 0.5 = 1.45倍
> 加速比 = 1 / 1.45 ≈ 0.69（实际是性能降低，因为引入了Cache延迟）
> 但如果不考虑Cache命中延迟（命中时不增加延迟），则性能提升明显。

### 六、Cache的一致性维护 ⭐

#### 1. 写直达法的同步保证

> 写直达法在写Cache的同时写主存，Cache和主存数据始终一致，无需额外维护。

#### 2. 写回法的Dirty位 ⭐

> 写回法中，每个Cache行需要一个Dirty（写污）位。Dirty=1表示该Cache行已被修改且未写回主存，Dirty=0表示与主存一致。

```
Cache行结构（写回法）：
┌──────────┬──────────┬──────────┬────────┬──────────┐
│   Tag    │  Valid   │  Dirty   │  数据  │  替换信息 │
│  标记     │  有效位   │  写污位   │  Data  │  (LRU等) │
└──────────┴──────────┴──────────┴────────┴──────────┘
```

#### 3. 多核Cache一致性（CSAPP补充视角）

> 在多核处理器中，每个核心有自己的L1 Cache。当核心A修改了共享数据，其他核心的Cache中该数据副本是过期的。这需要通过**缓存一致性协议**（如MESI协议）来解决。

> 408考试可能涉及MESI协议的四种状态：
> - **Modified（已修改）**：Cache独占，数据已被修改，与主存不一致
> - **Exclusive（独占）**：Cache独占，数据与主存一致
> - **Shared（共享）**：多个Cache共有，数据与主存一致
> - **Invalid（无效）**：数据无效

## ⚖️易混淆概念对比

### 三种映射方式综合对比

| 对比项 | 直接映射 | 全相联映射 | 组相联映射 |
|--------|---------|-----------|-----------|
| 主存块可放位置 | 唯一固定行 | 任意行 | 指定组内任意行 |
| 地址字段 | Tag + Index + Offset | Tag + Offset | Tag + Index + Offset |
| 比较器数量 | 1 | N（全部） | r（每路） |
| 命中率 | 最低 | 最高 | 中等偏高 |
| 冲突Miss | 有（严重） | 无 | 有（较轻） |
| 硬件成本 | 最低 | 最高 | 中等 |
| 替换算法 | 无（强制替换） | LRU/FIFO等 | LRU/FIFO等 |
| 实际应用 | 较少 | 小Cache | 主流（2路~8路） |

### 写直达法与写回法综合对比

| 对比项 | 写直达法 | 写回法 |
|--------|---------|--------|
| 写命中行为 | 写Cache + 写主存 | 写Cache + 设Dirty位 |
| 写Miss行为 | 写主存 | 从主存读入Cache，再写Cache |
| Dirty位 | 不需要 | 需要 |
| 写性能 | 较低 | 较高 |
| 读Miss性能 | 较好（主存数据始终最新） | 需检查Dirty位（可能写回） |
| 总线带宽消耗 | 大 | 小 |
| 实现复杂度 | 简单 | 复杂 |
| 现代CPU | 少见 | 主流（L1/L2 Cache） |

### 命中时间 vs Miss惩罚

| 对比项 | 命中时间（Hit Time） | Miss惩罚（Miss Penalty） |
|--------|-------------------|-----------------------|
| 定义 | Cache命中时的访问时间 | Cache未命中时额外增加的时间 |
| 组成 | Cache访问时间 | 主存访问时间 + 替换开销 + 写回开销（写回法） |
| 影响因素 | Cache结构、映射方式 | Miss率、主存速度、块大小 |
| 优化方向 | 降低Cache访问时间 | 降低Miss率（提高命中率） |

## ⚠️考试高频坑点

### 坑点1：Cache地址字段划分

> 【考试考法】给定Cache总容量、块大小、相联度，求Tag/Index/Offset位数。
>
> 关键步骤：
> 1. 块偏移 = log₂(块大小)
> 2. 组数 = Cache总容量 / (块大小 × 相联度)
> 3. 组号位数 = log₂(组数)
> 4. Tag位数 = 地址位数 - 组号位数 - 块偏移位数
>
> 例：64KB Cache，64B块，4路组相联，32位地址。
> 块偏移 = log₂(64) = 6
> 总行数 = 64KB/64B = 1024行
> 组数 = 1024/4 = 256组 → 组号 = 8位
> Tag = 32 - 8 - 6 = 18位

### 坑点2：Cache容量 vs Cache行数

> 【坑点】Cache容量 ≠ Cache行数。
> Cache行数 = Cache总容量 / 块大小。
> 例：64KB Cache，块大小64B → 1024行，不是64K行。

### 坑点3：写回法的Dirty位开销 ⭐

> 【考试考法】一个4路组相联Cache，64行，块大小32字节，写回法。问每行需要的额外控制位（不包括数据）？
> Tag + Valid + Dirty + LRU信息
> 每行：Valid位1bit，Dirty位1bit，4路LRU需要6bit（4×3/2）

### 坑点4：平均访问时间的公式选择

> 【坑点】如果题目说"命中时只访问Cache"，则 ta = h × tc + (1-h) × (tc + tm)
> 如果题目说"同时访问Cache和主存"，则 ta = h × tc + (1-h) × tm
> 注意区分题目描述的模型。408考试通常采用"命中时只访问Cache"模型。

### 坑点5：块大小与命中率的关系

> 【考试考法】增大块大小对命中率的影响：
> - 降低强制Miss（空间局部性，一次装入更多相邻数据）
> - 但可能增加容量Miss（Cache行数减少，相同容量下每行更大）
> - 可能增加冲突Miss（组数减少，冲突概率增加）
>
> 因此块大小的选择需要权衡，并非越大越好。
