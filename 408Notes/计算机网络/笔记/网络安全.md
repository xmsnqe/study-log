> 📌 网络安全是408考研的**重要模块**，对称加密、非对称加密、数字签名、HTTPS等是必考内容。密码学基础是理解网络安全的前提。

## 📝核心概念与原理

### 一、网络安全基本概念

#### 1.1 安全服务（Security Services）

```
网络安全的五大服务（OSI安全框架）：
┌─────────────────────────────────────────────────┐
│  1. 认证（Authentication）     │  确认身份真实    │
│  2. 访问控制（Access Control）  │  限制资源使用    │
│  3. 数据机密性（Confidentiality）│  防止窃听       │
│  4. 数据完整性（Integrity）     │  防止篡改       │
│  5. 不可否认性（Non-repudiation）│  防止抵赖       │
└─────────────────────────────────────────────────┘
```

#### 1.2 安全攻击分类

| 攻击类型 | 说明 | 示例 |
|---------|------|------|
| **截获（Interception）** | 未授权实体获得数据（机密性破坏） | 网络嗅探、抓包 |
| **中断（Interruption）** | 系统资源被破坏或变得不可用（可用性破坏） | 拒绝服务攻击（DoS） |
| **篡改（Modification）** | 未授权实体修改数据（完整性破坏） | Man-in-the-Middle |
| **伪造（Fabrication）** | 未授权实体插入假数据到系统（真实性破坏） | 伪造IP包、DNS欺骗 |

### 二、密码学基础 🔥

#### 2.1 对称加密（Symmetric-Key Cryptography）⭐

**原理**：加密和解密使用**同一把密钥**

```
对称加密过程：
  发送方                    接收方
   │                        │
   │  明文 + 密钥K → 密文     │
   │────────────────────────→│
   │                        │  密文 - 密钥K → 明文
   │                        │
```

**主流对称加密算法**：

| 算法 | 密钥长度 | 块大小 | 说明 |
|------|---------|--------|------|
| **DES** | 56位 | 64位 | 已不安全，已被破解 |
| **3DES** | 168位（3×56） | 64位 | DES的增强版，速度较慢 |
| **AES** | 128/192/256位 | 128位 | 当前标准算法，高效安全 |

> **⭐选择题高频考点**：
> - DES密钥有效长度为56位（64位中8位为校验位）
> - AES是DES的替代算法，由NIST标准选定
> - 对称加密的**核心问题**：密钥分发（双方必须安全共享密钥）

---

#### 2.2 非对称加密（Public-Key Cryptography）🔥

**原理**：加密和解密使用**不同的密钥**——公钥和私钥

```
非对称加密过程（加密场景）：
  发送方                    接收方
   │                        │
   │  公钥（K_pub）           │  私钥（K_priv）
   │                        │  （私钥保密）
   │  明文 + K_pub → 密文     │
   │────────────────────────→│
   │                        │  密文 - K_priv → 明文
   │                        │

非对称加密过程（签名场景）：
  发送方                    接收方
   │                        │
   │  私钥（K_priv）签名      │  公钥（K_pub）验签
   │  明文 + K_priv → 签名    │
   │────────────────────────→│
   │                        │  签名验证 + K_pub → 明文
   │                        │
```

> **📌关键理解**：
> - **公钥加密、私钥解密**：用于加密通信（保密性）
> - **私钥签名、公钥验签**：用于身份认证（不可否认性）

**主流非对称加密算法**：

| 算法 | 原理 | 应用 |
|------|------|------|
| **RSA** | 大整数分解的困难性 | 最广泛使用的非对称加密 |
| **Diffie-Hellman** | 离散对数的困难性 | 密钥交换 |
| **ECC** | 椭圆曲线离散对数 | 移动设备，密钥短、安全性高 |

> **🔥大题考点**：
> - RSA安全性基于大整数分解的困难性
> - RSA中：n = p × q（两个大素数），φ(n) = (p-1)(q-1)
> - e为公钥指数（与φ(n)互质），d为私钥指数（e×d ≡ 1 mod φ(n)）

---

#### 2.3 单向哈希函数（Hash Function）🌟

**原理**：将任意长度的输入映射为**固定长度**的输出（哈希值/消息摘要）

```
哈希函数特性：
  输入 → Hash(x) → 输出

  核心特性：
  ├── 单向性（Pre-image resistance）：无法从哈希值反推输入
  ├── 抗碰撞性（Collision resistance）：很难找到两个不同输入产生相同哈希值
  ├── 固定输出长度：如SHA-256始终输出256位
  └── 雪崩效应：输入微小变化导致输出完全不同
```

**主流哈希算法**：

| 算法 | 输出长度 | 说明 |
|------|---------|------|
| **MD5** | 128位 | 已不安全，已发现碰撞 |
| **SHA-1** | 160位 | 已不安全，已发现碰撞 |
| **SHA-256** | 256位 | 当前安全标准 |
| **SHA-3** | 可变（224/256/512等） | 最新标准，基于海绵结构 |

---

#### 2.4 消息认证码（MAC）🌟

```
消息认证码（MAC）：
  发送方：HMAC(密钥K, 消息M) → 认证码
  接收方：HMAC(密钥K, 消息M) == 认证码？ → 验证消息完整性+身份认证

  与哈希的区别：
  ├── 哈希函数：无密钥，只提供完整性
  ├── MAC：需要共享密钥，提供完整性和认证
  └── HMAC：MAC的具体实现方式（Hash-based MAC）
```

---

#### 2.5 对称加密 vs 非对称加密 对比 🔥

| 对比项 | 对称加密 | 非对称加密 |
|-------|---------|-----------|
| **密钥数量** | 1个（共享密钥） | 2个（公钥+私钥） |
| **速度** | 快（硬件实现效率高） | 慢（数学运算复杂） |
| **密钥管理** | 困难（n个用户需要n(n-1)/2个密钥） | 简单（每个用户只需保管私钥） |
| **主要用途** | 大量数据加密 | 密钥交换、数字签名 |
| **代表算法** | AES、DES、3DES | RSA、DH、ECC |
| **安全性基础** | 密钥保密 | 数学难题（大数分解/离散对数） |

> **📌关键理解**：实际应用中，对称加密和非对称加密**结合使用**——非对称加密用于密钥交换，对称加密用于数据加密（如HTTPS）。

### 三、数字签名 🔥

#### 3.1 数字签名原理

```
数字签名过程：
  发送方（Alice）：
  1. 对消息M计算哈希：h = Hash(M)
  2. 用私钥签名：s = Encrypt_priv(K_priv, h)
  3. 发送 (M, s)

  接收方（Bob）：
  4. 用Alice的公钥验签：h' = Decrypt_pub(K_pub, s)
  5. 计算消息哈希：h'' = Hash(M)
  6. 比较：h' == h'' ? → 验证成功

  提供保障：
  ├── 认证（Authentication）：只有Alice的私钥能产生该签名
  ├── 完整性（Integrity）：消息被篡改则哈希值不匹配
  └── 不可否认（Non-repudiation）：Alice不能否认自己签过名
```

> **🔥大题考点**：
> - 数字签名使用的是**私钥签名、公钥验签**
> - 签名的是**消息的哈希值**而不是消息本身（提高效率）
> - 数字签名 ≠ 加密（签名提供认证和不可否认性，加密提供机密性）

---

#### 3.2 数字证书（Digital Certificate）🌟

```
数字证书：解决公钥真实性问题

问题：如果Bob收到Alice的公钥，如何确认真的是Alice的公钥？
解决：使用CA（Certificate Authority，证书颁发机构）

证书结构：
  ┌─────────────────────────────────┐
  │  证书内容：                      │
  │  ├── 持有者身份（Subject）       │
  │  ├── 持有者公钥（Public Key）    │
  │  ├── 有效期（Validity）          │
  │  ├── 颁发机构（Issuer = CA）     │
  │  └── CA的数字签名（Signature）   │
  └─────────────────────────────────┘

验证过程：
  用户 → 收到证书 → 用CA的公钥验证证书签名 → 确认证书有效 → 使用证书中的公钥
```

> **⭐选择题高频考点**：
> - CA（Certificate Authority）是受信任的第三方
> - 数字证书将公钥与实体身份绑定
> - X.509是国际标准证书格式

### 四、密钥分配与管理 🌟

#### 4.1 密钥分配中心（KDC）⭐

```
Kerberos 密钥分配流程（KDC模型）：

  客户端（A）  认证服务器（AS）  票据授权服务器（TGS）  服务端（B）
      │              │                 │               │
      │────登录请求──→│                 │               │
      │←──密钥K_AS+票据─│               │               │
      │              │                 │               │
      │──票据+认证器──→│────转发票据──→│               │
      │              │                 │──票据给B──→   │
      │              │                 │←──会话密钥───│
      │              │                 │──响应认证器──→│
      │              │                 │←──加密响应───│
      │              │                 │               │
      │  完成身份认证                        │           │
```

#### 4.2 Diffie-Hellman 密钥交换 🔥

```
Diffie-Hellman 密钥交换过程：
  参数公开：大素数p，原根g

  发送方A          发送方B
    │                │
    │  选随机数 a    │  选随机数 b
    │  计算 A = g^a mod p │  计算 B = g^b mod p
    │                │
    │─── A = g^a mod p ──→│
    │                │
    │                │─── B = g^b mod p ──→│（实际上双向传输）
    │←── B = g^b mod p ──│
    │                │
    │  计算密钥：s = B^a mod p │
    │  s = (g^b)^a mod p = g^(ab) mod p │
    │                │  计算密钥：s = A^b mod p
    │                │  s = (g^a)^b mod p = g^(ab) mod p
    │                │  s = g^(ab) mod p
    │                │
    │  双方得到相同密钥s │  双方得到相同密钥s

  安全性基于离散对数问题的困难性：
  已知g、p、A = g^a mod p，很难求出a
```

> **🔥大题考点**：
> - DH密钥交换不提供认证（需要配合数字签名防止中间人攻击）
> - 双方计算出的共享密钥相同：g^(ab) mod p = g^(ba) mod p

### 五、认证协议 🌟

#### 5.1 三次握手认证

```
A认证B的三次握手：
  A              B
  │              │
  │  n1（随机数）│  （A发送随机数挑战）
  │─────────────→│
  │              │
  │  E_Kb(n1, n2)│  （B用A的公钥解密n1验证，生成随机数n2并用私钥加密）
  │←─────────────│
  │              │
  │  E_Ka(n2)    │  （A用B的公钥解密n2验证）
  │─────────────→│
  │              │
  │  认证成功     │  认证成功
```

#### 5.2 一次性口令（One-Time Password）

```
S/KEY 一次性口令方案：
  用户设定口令P，服务器存储H^n(P)

  登录时（逆序使用）：
  第n次登录：用户发送 H^(n-1)(P)，服务器验证 H(H^(n-1)(P)) == H^n(P)
  第n-1次登录：用户发送 H^(n-2)(P)，服务器验证 H(H^(n-2)(P)) == H^(n-1)(P)
  ...

  优点：即使口令被窃听，下一次登录的口令也是不同的
```

### 六、网络层安全：IPsec 🔥

**IPsec（Internet Protocol Security）**：在网络层提供的安全协议套件

```
IPsec 两大协议：

  1. 认证首部（AH, Authentication Header）：
     ├── 提供数据源认证、数据完整性、抗重放
     └── 不提供加密（不保密）

  2. 封装安全载荷（ESP, Encapsulating Security Payload）：
     ├── 提供加密（机密性）
     ├── 提供数据源认证、完整性、抗重放
     └── 使用最广泛

IPsec 工作模式：

  传输模式（Transport Mode）：
  ┌────────┐ ┌───────────────────┐ ┌────────┐
  │ IP头   │ │  ESP/AH头 + 数据   │ │ 上层头  │
  └────────┘ └───────────────────┘ └────────┘
  （保护传输层+数据）

  隧道模式（Tunnel Mode）：
  ┌────────┐ ┌──────────────────────┐ ┌───────┐
  │ 新IP头 │ │  ESP/AH头 + 原IP包   │ │ 原数据 │
  └────────┘ └──────────────────────┘ └───────┘
  （保护整个IP包，常用于VPN）
```

> **🔥大题考点**：
> - IPsec工作在网络层，对传输层及以上透明
> - ESP提供加密和认证，AH只提供认证不提供加密
> - 隧道模式常用于VPN，传输模式用于端到端通信

### 七、传输层安全：TLS/SSL 🔥

**TLS（Transport Layer Security）**：传输层安全协议，是SSL的继任者

```
TLS 握手过程（简化版）：

  客户端                        服务器
    │                              │
    │  ClientHello                │  （客户端支持的密码套件、随机数）
    │─────────────────────────────→│
    │                              │
    │  ServerHello                │  （选择的密码套件、服务器随机数）
    │  Certificate                │  （服务器证书，含公钥）
    │  ServerHelloDone            │
    │←─────────────────────────────│
    │                              │
    │  ClientKeyExchange          │  （生成预主密钥，用服务器公钥加密）
    │  ChangeCipherSpec           │
    │─────────────────────────────→│
    │                              │
    │  Finished                   │  （加密的握手完成消息）
    │─────────────────────────────→│
    │                              │
    │  ChangeCipherSpec           │
    │  Finished                   │  （加密的握手完成消息）
    │←─────────────────────────────│
    │                              │
    │  应用数据传输（对称加密）       │
    │                              │
```

> **🔥大题考点**：
> - TLS握手使用非对称加密交换**预主密钥**（pre-master secret）
> - 握手完成后，双方协商出**会话密钥**（对称密钥）用于数据传输
> - TLS提供：加密、认证（服务器身份）、完整性

### 八、应用层安全：电子邮件安全 🌟

| 方案 | 说明 | 标准 |
|------|------|------|
| **PGP（Pretty Good Privacy）** | 应用层安全方案，用户管理信任 | OpenPGP |
| **S/MIME** | 基于PKI的数字签名和加密 | ITU标准 |
| **DKIM** | 域名密钥识别邮件 | 用于反垃圾邮件 |

```
PGP 工作流程：
  发送方：
  1. 压缩消息M
  2. 计算哈希：h = Hash(M)
  3. 用私钥签名：s = Encrypt_priv(h)
  4. 用会话密钥K加密：E_K(M || s)
  5. 用接收方公钥加密会话密钥：E_Kpub(K)
  6. 发送：(E_Kpub(K), E_K(M || s))

  接收方：
  1. 用私钥解密会话密钥：K = Decrypt_priv(E_Kpub(K))
  2. 用会话密钥解密消息：(M || s) = Decrypt_K(encrypted)
  3. 计算哈希：h' = Hash(M)
  4. 用发送方公钥验签：h = Decrypt_pub(s)
  5. 比较：h' == h → 认证+完整性
```

### 九、网络攻击与防御 🔥

#### 9.1 常见网络攻击

| 攻击类型 | 说明 | 防御措施 |
|---------|------|---------|
| **DoS/DDoS** | 拒绝服务/分布式拒绝服务 | 流量过滤、速率限制 |
| **中间人攻击（MitM）** | 窃听并修改通信 | 使用TLS/SSL |
| **DNS欺骗** | 伪造DNS响应 | DNSSEC |
| **IP欺骗** | 伪造源IP地址 | 输入验证、ACL |
| **缓冲区溢出** | 向缓冲区写入超出容量的数据 | 栈保护、ASLR |
| **重放攻击** | 截获并重复发送合法报文 | 时间戳、序号、Nonce |
| **社会工程** | 利用人的心理弱点 | 安全意识培训 |

#### 9.2 入侵检测系统（IDS）🌟

```
IDS 工作原理：
  网络流量 → 检测引擎 → 报警/阻断

  检测方法：
  ├── 误用检测（Misuse Detection）：
  │     基于已知攻击特征（签名）匹配
  │     优点：误报率低
  │     缺点：无法检测未知攻击
  │
  └── 滥用检测（Anomaly Detection）：
        基于正常行为基线，偏离基线即报警
        优点：可检测未知攻击
        缺点：误报率高
```

### 十、防火墙（Firewall）🌟

```
防火墙架构：

  Internet ──→ 防火墙 ──→ 内部网络
              │
              ├── 数据包过滤防火墙（网络层/传输层）
              │     基于IP地址、端口、协议过滤
              ├── 状态检测防火墙（网络层/传输层）
              │     维护连接状态表
              └── 应用层防火墙（应用层）
                    深度包检测（DPI）

  典型防火墙规则：
  ┌──────────────────────────────────────┐
  │  规则号 │ 源IP    │ 目的IP   │ 端口 │ 动作  │
  ├──────────────────────────────────────┤
  │   1    │ 任何     │ 192.168.1.0/24 │ 80  │ 允许  │
  │   2    │ 任何     │ 192.168.1.0/24 │ 443 │ 允许  │
  │   3    │ 任何     │ 任何       │ 任何 │ 拒绝  │
  └──────────────────────────────────────┘
  （按规则号从上到下匹配，找到第一条即停止）
```

## ⚖️易混淆概念对比

### 对称加密 vs 非对称加密

| 对比项 | 对称加密 | 非对称加密 |
|-------|---------|-----------|
| **密钥数量** | 共享密钥（1个） | 公钥+私钥（2个） |
| **速度** | 快 | 慢（约慢1000倍） |
| **用途** | 大量数据加密 | 密钥交换、数字签名 |
| **安全性基础** | 密钥保密 | 数学难题 |
| **密钥管理** | 困难 | 简单 |
| **代表算法** | AES、DES | RSA、DH、ECC |
| **关联文档** | [[07-网络安全]] | [[07-网络安全]] |

### 数字签名 vs 数字加密

| 对比项 | 数字签名 | 数字加密 |
|-------|---------|---------|
| **目的** | 认证、不可否认性 | 机密性 |
| **签名/加密方** | 发送方用私钥 | 发送方用接收方公钥 |
| **验证/解密方** | 接收方用发送方公钥 | 接收方用私钥 |
| **保护内容** | 消息哈希值 | 消息内容 |
| **关联文档** | [[07-网络安全]] | [[07-网络安全]] |

### AH vs ESP（IPsec）

| 对比项 | AH（认证首部） | ESP（封装安全载荷） |
|-------|---------------|-------------------|
| **机密性** | ❌ 不提供 | ✅ 提供（加密） |
| **完整性** | ✅ 提供 | ✅ 提供 |
| **认证** | ✅ 提供 | ✅ 提供 |
| **抗重放** | ✅ 提供 | ✅ 提供 |
| **覆盖范围** | 覆盖IP头+数据 | 仅覆盖数据（传输模式） |
| **使用频率** | 较少 | 最常用 |
| **关联文档** | [[07-网络安全]] | [[07-网络安全]] |

### 误用检测 vs 滥用检测（IDS）

| 对比项 | 误用检测（Misuse） | 滥用检测（Anomaly） |
|-------|------------------|-------------------|
| **原理** | 匹配已知攻击特征 | 检测偏离正常行为 |
| **优点** | 误报率低 | 可检测未知攻击 |
| **缺点** | 无法检测未知攻击 | 误报率高 |
| **更新** | 需更新特征库 | 需重新训练基线 |
| **关联文档** | [[07-网络安全]] | [[07-网络安全]] |

## ⚠️考试高频坑点

### 坑点1：数字签名的加解密方向

> 【考试考法】"数字签名用哪个密钥？"
> 
> ⚠️ 常见错误：用公钥签名
> 
> ✅ 正确：签名用**私钥**（只有签名者持有），验签用**公钥**（任何人可验证）

### 坑点2：DES的有效密钥长度

> 【考试考法】"DES密钥长度是多少？"
> 
> ⚠️ 常见错误：答64位（有效密钥只有56位）
> 
> ✅ 正确：DES密钥**有效长度为56位**（64位含8位校验位）

### 坑点3：DH密钥交换不提供认证

> 【考试考法】"Diffie-Hellman密钥交换能防止中间人攻击吗？"
> 
> ⚠️ 常见错误：认为DH是安全的
> 
> ✅ 正确：DH**不提供认证**，可被中间人攻击（MitM）。需配合数字签名使用

### 坑点4：TLS握手后的加密方式

> 【考试考法】"TLS握手完成后使用什么加密？"
> 
> ⚠️ 常见错误：继续用非对称加密
> 
> ✅ 正确：握手完成后使用**对称加密**（会话密钥），因为对称加密速度快

### 坑点5：IPsec的两种模式

> 【考试考法】"IPsec隧道模式和传输模式的区别？"
> 
> ⚠️ 常见错误：混淆两种模式的覆盖范围
> 
> ✅ 正确：传输模式仅保护传输层数据；隧道模式保护整个IP包（含原IP头）

### 坑点6：数字证书的作用

> 【考试考法】"数字证书解决什么问题？"
> 
> ⚠️ 常见错误：答"提供加密"
> 
> ✅ 正确：数字证书解决**公钥真实性**问题——将公钥与实体身份绑定
