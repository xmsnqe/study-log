# 计算机网络概述

**学习前置条件：**

> ⭐ **选择题高频考点：** 五层模型各层功能、分组交换与电路交换对比、时延类型及计算、协议三要素。

## 📝核心概念与原理

### 一、计算机网络的定义与组成

**定义：** 计算机网络是"一些由软件和硬件组成的设备"的集合，这些设备"通过通信链路和交换机/路由器互联"，目的是"共享资源"和"信息交换"。

**两个核心组成：**

1. **边缘部分（Edge）**
   用户直接使用的设备及其上的应用程序，分为两类：
   - **客户（Client）→ 服务器（Server）** 架构：C/S 模式
   - **对等（Peer）→ 对等（Peer）** 架构：P2P 模式

2. **核心部分（Core）**
   由大量互联的路由器和通信链路组成，核心功能是将边缘部分连接起来，提供"分组交付"服务。核心部分的关键组件：
   - **通信链路（Link）**：传输介质，如双绞线、光纤、微波等，以"带宽"衡量传输能力
   - **路由器（Router）**：在转发数据分组时进行"存储-转发"（Store-and-Forward）

> ⭐ 边缘部分与核心部分的关系：边缘部分提供应用程序，核心部分提供通信服务。可以理解为"服务提供者"与"服务使用者"的关系。

### 二、交换技术

#### 2.1 电路交换（Circuit Switching）

**原理：** 通信前需在通信双方之间建立一条**专用的物理通路**，通信期间该通路被独占，通信结束后释放。

**三个阶段：**
1. **建立连接**：通过信令网络在发送方与接收方之间建立一条专用通路
2. **通信**：数据沿已建立的通路传输，时延很小
3. **释放连接**：通信结束后拆除通路

**特点：**
- 通信期间资源（带宽）被**独占**，无论是否传输数据
- 资源利用率低，但传输时延小、无排队
- 通信双方带宽**固定分配**，无法动态共享

> ⭐ 电路交换的经典例子：传统电话网络。拨打号码→建立电路→通话→挂断释放。

#### 2.2 分组交换（Packet Switching）

**原理：** 将报文切分成若干个**较短的分组（Packet）**，每个分组独立选择路径，在中间节点进行**存储-转发**。

**工作过程：**
1. 发送方将报文**分片**成多个分组，每个分组包含头部（目的地址等）和数据部分
2. 每个分组在网络中**独立路由**，可能走不同路径
3. 中间节点（路由器）接收整个分组后，检查头部信息，再转发到下一跳
4. 接收方按顺序重组分组为原始报文

**特点：**
- 资源**共享**，链路带宽被多个通信"时分复用"
- 灵活、高效，适合突发性数据
- 可能产生**排队时延**和**丢包**
- 需要**分组编号**以保证正确重组

> ⭐ 分组交换是互联网的核心交换方式，也是408考试重点。分组交换的"存储-转发"机制意味着路由器必须收到**完整的分组**后才能开始转发，这是理解传输时延的关键。

#### 2.3 电路交换 vs 分组交换对比

| 对比维度 | 电路交换 | 分组交换 |
|---------|---------|---------|
| 资源分配 | 专用资源，固定带宽 | 共享资源，动态分配 |
| 传输时延 | 建立连接时有呼叫时延，之后很小 | 无呼叫建立，但每跳有存储-转发时延 |
| 利用率 | 低（空闲时资源仍被占用） | 高（充分利用带宽） |
| 可靠性 | 专用通路，故障时通信中断 | 多路径可选，容错性好 |
| 适用场景 | 实时性要求高的连续数据（如语音） | 突发性数据、文件传输 |
| 是否408高频考点 | ⭐ 理解概念即可 | ⭐ 重点对比分析 |

> ⭐ **经典考题：** "为什么互联网采用分组交换而非电路交换？" 答案要点：① 互联网流量具有突发性，分组交换共享带宽利用率高；② 分组交换容错性好，单点故障不影响其他通信；③ 分组交换支持异构网络互联。

### 三、时延、丢失与吞吐量

#### 3.1 网络时延（Delay/Latency）

网络中一个比特从链路一端传到另一端所需的时间，分为四种：

1. **发送时延（传输时延，Transmission Delay）**

   公式：$$T_{trans} = \frac{L}{R}$$
   
   其中 L = 分组长度（bit），R = 信道带宽（bps）
   
   **物理含义：** 主机将分组"推"到链路上所需的时间。就像给一个管道灌水，灌满整个分组需要的时间。
   
   > ⭐ **高频易错：** 发送时延只在有发送能力的节点（如主机、路由器）处产生，传播时延在链路上产生。

2. **传播时延（Propagation Delay）**

   公式：$$T_{prop} = \frac{d}{v}$$
   
   其中 d = 链路长度（m），v = 电磁波在信道中的传播速度（m/s，光纤中约 2×10⁸ m/s）
   
   **物理含义：** 一个比特在链路上"跑完"整个距离所需的时间。就像光从A点传播到B点的时间。

3. **处理时延（Processing Delay）**

   路由器检查分组首部、决定转发端口、进行差错检测等所需的时间。通常很小（微秒级）。

4. **排队时延（Queuing Delay）**

   分组在路由器的输出队列中等待传输的时间。取决于**当前网络拥塞程度**，具有不确定性。

> ⭐ **重点公式：** 总时延 = 发送时延 + 传播时延 + 处理时延 + 排队时延。在408计算题中，通常处理时延可忽略，排队时延视情况计算或忽略。

**多跳时延计算示例：**

一个分组从源主机经 n 个路由器到达目的主机，经过 n+1 条链路：

$$T_{total} = (n+1) \times T_{prop} + (n+1) \times T_{trans} + n \times T_{proc} + T_{queue}$$

> ⭐ 注意：每个路由器都要进行一次存储-转发，所以发送时延和传播时延各要乘以 (n+1)，而处理时延只有 n 个路由器参与。

#### 3.2 分组丢失（Loss）

当路由器输出队列已满时，到达的分组将被**丢弃**。分组丢失的可能原因：
- 缓冲区不足
- 链路故障
- 路由器过载

丢失后由上层协议（如TCP）负责**重传**，这是"端到端"原则的体现。

#### 3.3 吞吐量（Throughput）

- **带宽（Bandwidth）：** 链路的最高数据传输速率（理论上限）
- **实际吞吐量（Throughput）：** 单位时间内实际成功传输的数据量

$$Throughput = \min(R_c, R_s, \frac{R}{n})$$

其中：
- $R_c$ = 通信源的发送速率
- $R_s$ = 通信目的地的接收速率
- $R$ = 核心网络路径中各链路的带宽
- $n$ = 路径上的链路数

> 🔥 瓶颈链路（Bottleneck Link）决定了最大吞吐量。408常考找出瓶颈链路的题目。

### 四、协议与分层模型

#### 4.1 网络协议三要素

1. **语法（Syntax）**：数据与控制信息的结构或格式（如IP首部各字段的长度、顺序）
2. **语义（Semantics）**：需要发出何种控制信息，完成何种动作（如某标志位表示确认还是请求）
3. **同步（Timing/Synchronization）**：事件实现顺序和速度匹配（如超时重传的时间设定）

> ⭐ 三要素缺一不可。一个协议如果只有语法没有语义，接收方知道"这是什么格式"但不知道"这是什么意思"。

#### 4.2 OSI 参考模型（七层）

ISO（国际标准化组织）提出的开放系统互连参考模型，从下到上：

| 层号 | 名称 | 主要功能 | 典型协议/设备 |
|------|------|---------|--------------|
| 7 | 应用层（Application） | 为应用程序提供网络服务 | HTTP, FTP, DNS |
| 6 | 表示层（Presentation） | 数据格式转换、加密/解密、压缩/解压 | SSL/TLS |
| 5 | 会话层（Session） | 建立、管理、终止会话 | NetBIOS |
| 4 | 传输层（Transport） | 端到端可靠传输、流量控制、差错控制 | TCP, UDP |
| 3 | 网络层（Network） | 路由选择、分组转发、拥塞控制 | IP, ICMP, OSPF |
| 2 | 数据链路层（Data Link） | 相邻节点间帧传输、差错控制 | Ethernet, PPP |
| 1 | 物理层（Physical） | 比特流的透明传输 | 双绞线、光纤、RS-232 |

#### 4.3 TCP/IP 参考模型（四层/五层）

实际互联网采用的协议簇，自顶向下：

| TCP/IP四层模型 | 五层原理模型 | 主要功能 |
|---------------|-------------|---------|
| 应用层 | 应用层 | 各种应用协议 |
| 传输层 | 传输层 | TCP、UDP |
| 网络层（网际层） | 网络层 | IP协议 |
| 网络接口层 | 数据链路层 + 物理层 | 以太网等 |

> ⭐ **关键理解：** 五层原理模型是教学模型，综合了OSI和TCP/IP的优点。OSI模型理论严谨但实现复杂，实际并未广泛采用；TCP/IP是先有实现后有标准的典范。408考试中主要采用**五层原理模型**。

#### 4.4 分层思想的核心优势

1. **各层之间相互独立**：某一层不必知道其他层是如何实现的
2. **灵活性**：每一层可以使用最适合的技术实现
3. **结构上可分割**：各层之间是独立的，某一层的更改不会影响其他层
4. **易于实现和维护**：模块化降低复杂度
5. **促进标准化**：每层功能明确，接口定义清晰

#### 4.5 服务、接口与协议

这三者是分层模型中极易混淆的概念：

| 概念 | 定义 | 范围 |
|------|------|------|
| **服务（Service）** | 下层为相邻上层提供的功能 | **垂直方向**：层与层之间 |
| **接口（Interface）** | 上层使用下层服务的入口（如系统调用） | **层间边界** |
| **协议（Protocol）** | 对等实体之间通信的规则 | **水平方向**：对等层之间 |

> ⭐ **经典记忆：** "下层为上层提供服务"是垂直的；"对等层之间通过协议通信"是水平的。接口是垂直方向上层与层之间的"分界线"。

#### 4.6 封装与解封装

- **封装（Encapsulation）：** 发送方从应用层向下逐层添加头部（有时还有尾部），每添加一层就变成该层的"数据"
- **解封装（Decapsulation）：** 接收方从网络层向上逐层去掉头部，还原原始数据

**封装过程（发送端）：**

```
应用层数据 → + 传输层头部 → 段（Segment）/数据报 → + 网络层头部 → 分组（Packet）
→ + 链路层头部+尾部 → 帧（Frame）→ 比特流
```

> 🔥 封装是408选择题高频考点。注意各层的PDU（协议数据单元）名称：段/数据报、分组/包、帧。

### 五、计算机网络安全概述

计算机网络的安全威胁包括：
- **被动攻击：** 窃听（Eavesdropping），如嗅探
- **主动攻击：** 篡改（Tampering）、重放（Replay）、否认（Denial）
- **常见攻击类型：** DNS劫持、ARP欺骗、DDoS、中间人攻击

> 📘 网络安全是后续章节的延伸，详见 [[网络安全]]。

### 六、计算机网络的历史发展（了解）

1. **第一代：面向终端的计算机网络（1950s-1960s）**
   - 以主机为中心，多个终端通过通信线路连接到主机
   - 终端无处理能力，完全依赖主机

2. **第二代：计算机-计算机网络（1960s-1970s）**
   - 多台计算机互联，如 ARPANET（1969年）
   - 分组交换思想诞生

3. **第三代：标准化计算机网络（1980s-1990s）**
   - OSI模型提出
   - TCP/IP协议簇广泛应用
   - Internet雏形形成

4. **第四代：信息高速公路（1990s-至今）**
   - 宽带化、高速化、智能化
   - 移动互联网、云计算、物联网

> ⭐ 历史发展部分以选择题为主，重点记忆 ARPANET 是 Internet 的雏形，1969年诞生。

## ⚖️易混淆概念对比

| 易混淆概念 | 辨析要点 | 关联文档 |
|-----------|---------|---------|
| 发送时延 vs 传播时延 | 发送时延是"推数据入链路"的时间，取决于分组长度和带宽；传播时延是"比特跑完距离"的时间，取决于链路长度和传播速度 | [[物理层]] |
| 电路交换 vs 分组交换 | 电路交换独占资源、无排队；分组交换共享资源、有排队风险 | [[网络层]] |
| OSI七层 vs TCP/IP四层 | OSI理论严谨但未普及；TCP/IP先实现后有标准，互联网实际采用 | [[传输层]] |
| 协议 vs 服务 vs 接口 | 协议是水平的（对等实体间）；服务是垂直的（下层给上层）；接口是分层的边界 | [[数据链路层]] |
| 带宽 vs 吞吐量 | 带宽是理论上限；吞吐量是实际速率，受多种因素限制 | [[传输层]] |
| 编码 vs 调制 | 编码：数字→数字信号；调制：数字→模拟信号 | [[物理层]] |

## ⚠️考试高频坑点

| 坑点 | 易错理解 | 正确理解 | 来源 |
|------|---------|---------|------|
| 时延计算漏乘 | 多跳时延只算一条链路的时延 | 要乘以链路数（n+1），每个路由器都要存储-转发 | 教材原文+考试考法 |
| 发送时延 vs 传播时延主次 | 带宽越大时延越小（混淆概念） | 带宽只影响发送时延（L/R），不影响传播时延（d/v） | 考试考法 |
| 分组交换的"存储-转发" | 路由器收到一个比特就转发 | 必须收到完整分组才开始转发，这是分组交换时延的根源 | 教材原文 |
| 吞吐量公式 | 吞吐量=带宽 | 吞吐量=min(源速率, 目的速率, 路径中各链路带宽/n) | 教材原文 |
| 协议三要素 | 认为还有"规则" | 只有语法、语义、同步三要素 | 教材原文 |
| OSI七层各层功能 | 记混各层名称和功能 | 应用层面向用户、传输层端到端、网络层路由选择、链路层相邻节点 | 教材原文 |
| 分层独立性 | 分层完全独立、互不影响 | 层间独立但通过接口交互，某层实现改变不影响其他层 | 考试考法 |
