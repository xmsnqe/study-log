# 数据链路层

## 📍知识定位

**在408体系中的位置：** 数据链路层是五层模型的第二层，负责将物理层的原始比特流转化为相邻节点之间的"无差错数据帧"传输。它是408计算机网络模块中**最重要的章节**，知识点最多、计算量最大、大题最常出现。

**学习前置条件：** 理解 [[物理层]] 的比特流传输和 [[计算机网络概述]] 中的分层思想。

**后续支撑：** 为 [[网络层]] 提供相邻节点间的数据传输服务；链路层将原始比特流组装为帧，网络层在此基础上进行跨网络的分组转发。

**跨教材视角：**
- 📘 **自顶向下方法（Kurose & Ross）**：以"从不可靠的物理链路构建可靠通信"为主线，重点讲解信道划分协议和CSMA/CD。
- 📗 **谢希仁《计算机网络》**：对以太网、PPP协议、链路层设备着墨更多。
- 📙 **CSAPP**：从网卡实现角度理解链路层。

> ⭐ **选择题高频考点：** 成帧方法、CRC校验码计算、CSMA/CD原理、以太网帧格式、MAC地址。
> 🔥 **大题考点：** CRC校验码计算（必考）、滑窗协议计算（滑动窗口大小与效率）、CSMA/CD争用期计算。

## 📝核心概念与原理

### 一、数据链路层的基本功能

数据链路层位于物理层之上、网络层之下，负责将"不可靠的物理线路"变为"相邻节点间的可靠数据传输"。

#### 1.1 三个基本问题

数据链路层需解决以下三个核心问题：

1. **封装成帧（Framing）**
   在数据前后添加首部（SOP）和尾部（EOP），标记帧的起止。
   - 典型标志：`01111110`（HDLC、以太网的帧定界符）
   - 功能：让接收方知道从哪开始、到哪结束

2. **透明传输（Transparent Transmission）**
   保证数据部分无论出现什么比特组合都能正确传输，不被误认为控制信息。
   - 方法：**字节填充（字节 stuffing）** 和 **零比特填充**
   - 核心：通过转义字符或零比特插入，避免数据与标志符混淆

3. **差错控制（Error Control）**
   检测并纠正传输过程中产生的比特差错。
   - 主要方法：**CRC循环冗余校验**（检错）、**海明码**（纠错）
   - 目的：确保帧在传输中没有错误

#### 1.2 数据链路层的其他功能

| 功能 | 说明 |
|------|------|
| 流量控制 | 控制发送方的发送速率，防止接收方缓冲区溢出 |
| 链路管理 | 建立、维护、释放链路连接 |
| 寻址 | 用MAC地址标识网络中的每台主机 |

> ⭐ 三个基本问题（封装成帧、透明传输、差错控制）是408选择题的固定考法，需逐字记忆。

### 二、成帧方法

#### 2.1 字符计数法

在帧首部用一个字段（1字节）表示帧内字符的个数。

- **缺点：** 若字符计数字段出错，整个帧同步丢失
- **应用：** 极少使用

#### 2.2 字符填充法（字节填充）

使用特殊字符 **SOH（Start of Header，0x02）** 和 **STX（Start of Text，0x03）** 标记帧头尾。若数据中恰好出现SOH或STX，则在前面插入转义字符 **ESC（0x11）**。

- 接收方看到ESC就去掉它
- **缺点：** 占用额外的转义字符

#### 2.3 零比特填充法 ⭐ 必考

**适用协议：** HDLC、PPP等

**原理：**
- 帧的首部和尾部使用标志字段 `01111110`
- 发送方扫描数据流，遇到5个连续的`1`就立即插入一个`0`
- 接收方扫描接收到的比特流，遇到5个连续的`1`就删除紧随其后的`0`

**示例：**
- 数据中出现 `01111110` → 发送方变成 `011111010`（第6个1前插入0）
- 接收方看到 `011111010` → 还原为 `01111110`

> 🔥 **408大题必考！** 要求考生对给定数据进行零比特填充。注意：
> 1. 标志字段固定为 `01111110`
> 2. 只在数据中出现5个连续1时才插入0
> 3. 接收端严格反向操作

**编码过程（伪代码）：**

```
发送端：
计数器 = 0
for 每个比特:
    if 比特 == 1:
        计数器++
        发送该比特
        if 计数器 == 5:
            发送 0          // 插入零比特
            计数器 = 0
    else:
        计数器 = 0
        发送该比特

接收端：
计数器 = 0
for 每个比特:
    if 比特 == 1:
        计数器++
        输出该比特
        if 计数器 == 5:
            丢弃下一个比特  // 删除填充的0
            计数器 = 0
    else:
        计数器 = 0
        输出该比特
```

#### 2.4 成帧方法对比

| 方法 | 特点 | 优点 | 缺点 | 典型应用 |
|------|------|------|------|---------|
| 字符计数 | 首部指定字符数 | 实现简单 | 计数出错则同步丢失 | 极少用 |
| 字符填充 | 转义字符 | 灵活 | 转义字符可能出现在数据中 | 早期协议 |
| 零比特填充 | 5个1后插入0 | 只涉及比特操作 | 需要扫描和插入 | HDLC、PPP |

### 三、差错控制

#### 3.1 差错类型

- **单比特差错：** 只有1个比特出错
- **突发差错：** 连续多个比特出错（更常见于实际网络）

#### 3.2 检错与纠错

| 类型 | 原理 | 开销 | 适用场景 |
|------|------|------|---------|
| 检错 | 检测出错误后丢弃帧，由上层重传 | 较小 | 误码率低的环境（如以太网） |
| 纠错 | 不仅能检测还能自动纠正错误 | 较大 | 误码率高的环境（如卫星通信） |

408主要考查两种检错/纠错码：**CRC** 和 **海明码**。

#### 3.3 CRC 循环冗余校验 ⭐ 大题必考

**核心思想：** 在数据后面添加一个校验码（FCS），使得整个帧（数据+FCS）能被某个预设的 **生成多项式 G(x)** 整除。

**计算步骤：**

1. **确定生成多项式 G(x)**
   常见：CRC-16、CRC-32等。考试中给出多项式如 $G(x) = x^4 + x + 1$

2. **将G(x)转为二进制**
   $G(x) = x^4 + x + 1$ → 系数为 $1 \cdot x^4 + 0 \cdot x^3 + 0 \cdot x^2 + 1 \cdot x^1 + 1 \cdot x^0$ → 二进制：`10011`
   - 生成多项式的位数 = 最高次幂 + 1
   - 若最高次幂为 r，则校验码为 r 位

3. **在数据后面补 r 个0**
   数据 $M$，后面补 r 个0（r = G(x) 的最高次幂）

4. **用补0后的数据除以生成多项式（模2除法）**
   模2除法 = 异或运算（无进位、无借位的除法）

5. **余数即为FCS（校验码）**
   余数位数必须为 r 位（不够则在前面补0）

6. **将FCS附加到原始数据后面发送**

**模2除法（异或除法）计算规则：**
- 除数的每一位与余数的每一位做**异或（XOR）**运算
- 异或规则：相同为0，不同为1
- 每次异或后，从结果的最高位开始去掉前导0
- 直到余数的位数 = 除数位数 - 1

> 🔥 **408必考计算题！** 要求用CRC计算校验码。记住口诀："补r个0 → 模2除 → 取余数 → 加到末尾"。

**CRC示例：**

数据：`10110011`，生成多项式：$G(x) = x^4 + x^2 + 1$ → `10101`（5位，r=4）

步骤1：数据后补4个0 → `101100110000`

步骤2：模2除法计算：
```
  101100110000
⊕ 10101       (对齐)
  ------
    000110110000 → 去掉前导0 → 00110110000
  ⊕ 10101
  ------
    000000110000 → 去掉前导0 → 00000110000
  ⊕ 10101
  ------
    00000100100 → 去掉前导0 → 0000100100
  ⊕ 10101
  ------
    0000001110 → 去掉前导0 → 000001110
  ⊕ 10101
  ------
    000001011 → 余数为 1011（4位）
```

步骤3：FCS = `1011`

步骤4：实际发送帧 = 原始数据 + FCS = `101100111011`

> ⭐ 校验过程：接收方将接收到的帧除以生成多项式，若能整除（余数为0），则认为传输正确。

**CRC的检错能力：**
- 能检测出所有**单比特差错**
- 能检测出所有**双比特差错**（只要G(x)有至少3项）
- 能检测出所有**奇数位差错**（只要G(x)含有因子(x+1)）
- 能检测出所有**长度 ≤ r 的突发差错**
- 能检测出 **99.6% 的长度 > r 的突发差错**

> ⭐ 选择题常考："CRC不能检测出所有错误"——这是正确的！

#### 3.4 海明码（Hamming Code）⭐ 重点

海明码是**既能检错又能纠错**的编码。

**核心思想：** 在数据中插入多个校验位，使每个数据位的错误都能被唯一定位。

**计算步骤：**

1. **确定校验位的位数 r**
   关系式：$$2^r \geq m + r + 1$$
   其中 m = 数据位位数

2. **确定校验位的位置**
   校验位 P 放在 $2^{k-1}$ 的位置（k=1,2,3,...）
   即第 1、2、4、8、16...位是校验位

3. **每个校验位校验一组数据位**
   - P1（第1位）校验：1, 3, 5, 7, 9, 11...
   - P2（第2位）校验：2, 3, 6, 7, 10, 11...
   - P4（第4位）校验：4, 5, 6, 7, 12, 13, 14, 15...
   - P8（第8位）校验：8-15, 24-31...

   **规律：** Pi 校验所有二进制位号第 i 位为 1 的位（从最低位开始数）

4. **每个校验位取对应位置所有数据的异或（模2和）**

5. **接收端用同样的校验位重新计算，得到纠错字（Syndrome）**
   纠错字的二进制值即为出错位的位置

> ⭐ 海明码在408中是选择题+小题，通常给出数据让你计算校验位。记住公式 $2^r \geq m + r + 1$ 即可。

**海明码示例：**

数据：`1011`（m=4位），求校验位数 r

$$2^r \geq 4 + r + 1 = r + 5$$

- r=3: $2^3=8 \geq 8$ ✓ 满足

校验位 P1, P2, P4 放在位置 1, 2, 4：

位置编号（从1开始）：
```
位置:  1   2   3   4   5   6   7
内容:  P1  P2  d1  P4  d2  d3  d4
      (10)(11)      (011)
```

即：
- 位置3 = d1 = 1
- 位置5 = d2 = 0
- 位置6 = d3 = 1
- 位置7 = d4 = 1

计算校验位（异或）：
- P1 = d1 ⊕ d2 ⊕ d3 ⊕ d4 = 1 ⊕ 0 ⊕ 1 ⊕ 1 = 1
- P2 = d1 ⊕ d2 ⊕ d4 = 1 ⊕ 0 ⊕ 1 = 0
- P4 = d1 ⊕ d3 ⊕ d4 = 1 ⊕ 1 ⊕ 1 = 1

海明码：`1011001`

### 四、流量控制与可靠传输

#### 4.1 流量控制的必要性

如果发送方发送速度过快，接收方的缓冲区可能被溢出。流量控制的目的：**发送方速率 ≤ 接收方能处理的速率**。

#### 4.2 停止-等待协议（Stop-and-Wait）

**原理：** 发送方每发送**一个帧**就等待接收方的确认（ACK），收到ACK后才能发送下一帧。

**工作流程：**
1. 发送方发送帧（包含序号0或1）
2. 发送方等待 ACK
3. 收到 ACK → 发送下一帧
4. 超时未收到 ACK → 重传该帧

**特点：**
- 发送窗口 = 1，接收窗口 = 1
- 效率低：信道利用率 = 帧传输时间 / (帧传输时间 + 往返时延)
- 简单可靠

**信道利用率公式：**

$$U = \frac{T_{frame}}{T_{frame} + 2 \times T_{prop}}$$

其中 $T_{frame}$ 是帧的发送时间（L/R），$T_{prop}$ 是传播时延。

> ⭐ 当传播时延远大于帧发送时间时，利用率极低。这就是为什么需要滑动窗口。

#### 4.3 后退N帧协议（GBN, Go-Back-N）⭐ 重点

**原理：** 发送方可以连续发送多个帧（发送窗口内），接收方按序接收。

**核心机制：**
- **发送窗口大小 N：** 允许发送 N 个未确认的帧
- **序号位数 n：** 序号范围为 0 到 2^n - 1
- **序号复用条件：** 发送窗口 N ≤ 2^n - 1（防止序号模糊）

**工作过程：**
1. 发送方连续发送窗口内的所有帧
2. 接收方按序接收，接收窗口 = 1
3. 收到正确帧 → 发送累计确认（ACK n 表示已收到 n 之前的所有帧）
4. 发送方收到 ACK n → 发送窗口前进 n 位
5. 超时未收到 ACK → **重传所有已发送但未确认的帧**（"后退N帧"）

> 🔥 GBN的"后退N"是关键词——发送方超时后必须重传从第一个未被确认的帧开始的**所有**帧。

**GBN的约束条件：**
$$W_{send} \leq 2^n - 1$$
其中 W_send 是发送窗口大小，n 是序号位数。

> ⭐ 为什么是 2^n - 1？如果 W_send = 2^n，当接收方收到序号 0~2^n-1 的所有帧并发送 ACK 0 后，发送窗口全部前进，如果 ACK 0 丢失，发送方重传 0，接收方已经期望收到 0 了，无法区分是新的还是重传的。

#### 4.4 选择重传协议（SR, Selective Repeat）⭐ 重点

**原理：** 发送方可以连续发送多个帧，接收方可以按任意顺序接收并单独确认每个帧。

**核心机制：**
- **发送窗口大小 W_send：** 允许发送 W_send 个未确认的帧
- **接收窗口大小 W_recv：** 可以接收 W_recv 个乱序帧并缓存
- **序号位数 n：** 序号范围为 0 到 2^n - 1

**工作过程：**
1. 发送方连续发送窗口内的所有帧
2. 接收方接收到乱序帧也接受（在接收窗口内），单独确认每个帧
3. 发送方收到某个帧的 ACK → 只重传该帧（而非全部）
4. 接收方将已收到的帧按序交付给网络层

**SR的约束条件：**
$$W_{send} + W_{recv} \leq 2^n$$

特别地，当 $W_{send} = W_{recv}$ 时：
$$W_{send} \leq 2^{n-1}$$

> ⭐ 对比 GBN 和 SR：
> - GBN：发送窗口可以大，接收窗口=1，超时重传N个帧
> - SR：发送窗口和接收窗口都可大，超时只重传一个帧
> - GBN 实现简单但效率低；SR 实现复杂但效率高

**GBN vs SR 对比：**

| 对比项 | GBN | SR |
|--------|-----|----|
| 发送窗口 | ≤ 2^n - 1 | ≤ 2^{n-1} |
| 接收窗口 | 1 | ≤ 2^{n-1} |
| 确认方式 | 累计确认 | 逐个确认 |
| 超时重传 | 从第一个未确认开始全部重传 | 只重传超时的那个帧 |
| 实现复杂度 | 简单 | 复杂（需缓存乱序帧） |
| 效率 | 较低 | 较高 |
| 408考法 | 计算题常见 | 选择题+计算题 |

### 五、介质访问控制（MAC）

#### 5.1 多路访问信道的问题

当多个节点共享同一信道时，如何协调各节点的发送以避免冲突？这就是介质访问控制（MAC）协议要解决的问题。

#### 5.2 信道划分协议

##### （1）频分复用（FDMA）

- 每个用户获得固定的频率带宽
- 优点：无冲突
- 缺点：用户少时浪费带宽

##### （2）时分复用（TDMA）

- 每个用户获得固定的时间时隙
- 优点：无冲突，精确同步
- 缺点：时隙浪费，同步开销大

##### （3）码分复用（CDMA）

- 每个用户获得独特的码片序列
- 优点：同时同频，灵活度高
- 缺点：实现复杂

#### 5.3 随机访问协议（含退避）⭐ 重点

##### （1）ALOHA 协议

**纯ALOHA：**
- 任何节点随时可以发送
- 若冲突则等待随机时间后重传

**时隙ALOHA：**
- 将时间划分为离散时隙
- 节点只能在时隙开始时发送
- 冲突窗口减半 → 吞吐量翻倍

> ⭐ ALOHA是随机访问协议的鼻祖，了解其思想即可。408主要考CSMA系列。

##### （2）CSMA（载波监听多点接入/碰撞检测）⭐ 大题核心

**基本思想：** "先听后发，边听边发，冲突停发，随机重发"

**工作原理：**
1. 发送前先监听信道
2. 若信道空闲 → 立即发送
3. 若信道繁忙 → 等待一段时间后再次监听
4. 发送过程中继续监听（碰撞检测）
5. 若检测到冲突 → 立即停止发送，等待随机时间后重试

**3种坚持算法：**

| 算法 | 信道空闲 | 信道繁忙 | 碰撞后 |
|------|---------|---------|--------|
| 1-坚持（1-persistent） | 立即发送 | 继续监听，信道一旦空闲就立即发送 | 等待争用期后重试 |
| 0-坚持（0-persistent） | 立即发送 | 等待随机时间后再次监听 | 等待随机时间后重试 |
| p-坚持（p-persistent） | 以概率p发送，以(1-p)延迟 | 等下一时隙再判断 | 等待争用期后重试 |

- **1-坚持：** 最容易产生冲突（多个节点同时检测到空闲就同时发送）
- **0-坚持：** 最节省信道但延迟最大
- **p-坚持：** 折中方案

**争用期（Contention Period）：**

- 又称"碰撞窗口"，等于 2τ（τ 是单程传播时延）
- 如果 2τ 内没有检测到碰撞，则此次发送成功
- 以太网中争用期 = 512 bit = 64 帧（以10Mbps计，51.2μs）

> 🔥 **408必考：** 以太网的最短帧长和争用期的关系。最短帧长 = 2τ × 数据速率 = 512 bit = 64 字节。如果帧短于512 bit，可能在帧发送完之前都没有检测到碰撞，发送方会误认为发送成功。

##### （3）CSMA/CD（带碰撞检测的CSMA）⭐ 大题核心

**CSMA/CD 的核心增强：** 在发送过程中检测碰撞。

**工作流程：**
1. 检测信道：如果信道空闲 → 发送；如果繁忙 → 等待
2. 发送帧，同时检测碰撞
3. 如果检测到碰撞 → 立即停止发送，发送32比特（或48比特）的强化冲突信号
4. 等待随机时间（截断二进制指数退避算法）后重传

**截断二进制指数退避算法：**

1. 确定基本退避时间 = 2τ（争用期）
2. 取 k = min(重传次数, 10)
3. 从 {0, 1, 2, ..., 2^k - 1} 中随机取一个整数 r
4. 重传等待时间 = r × 2τ
5. 重传次数达到 16 次 → 丢弃帧，向上层报告

> 🔥 **408必考算法！** 记住关键点：
> 1. 重传次数 ≤ 10 时，k = 重传次数
> 2. 重传次数 > 10 时，k 固定为 10（不再增加）
> 3. 从 0 ~ 2^k-1 中随机选 r
> 4. 等待 r × 2τ

> ⭐ 为什么叫"截断"？因为 k 最大为 10（2^10=1024），即使重传了16次也不会让窗口无限增大。

**以太网关键参数（选择题高频）：**

| 参数 | 值 | 说明 |
|------|-----|------|
| 最小帧长 | 64 字节 | 512 bit / 10 Mbps = 51.2μs = 2τ |
| 最大帧长 | 1518 字节 | 64~1518 字节 |
| 争用期 | 51.2 μs | 在10Mbps以太网中 |
| 最短帧长 | 64 字节 | 与争用期配合 |

##### （4）CSMA/CA（带碰撞避免的CSMA）

**CSMA/CD vs CSMA/CA 对比：**

| 对比项 | CSMA/CD | CSMA/CA |
|--------|---------|---------|
| 应用场景 | 有线局域网（以太网） | 无线局域网（WiFi） |
| 碰撞检测 | 可以检测（有线） | 无法检测（无线） |
| 处理方式 | 碰撞后退避重传 | 碰撞前避免（RTS/CTS） |
| 核心思想 | 边发边听，碰撞后停 | 先申请，得到许可再发 |
| 408考法 | 大题（计算） | 选择题（对比） |

> ⭐ 无线环境中，站点无法在发送时检测碰撞（因为发送功率远大于接收信号），所以用CSMA/CA（碰撞避免）而非CSMA/CD。

#### 5.4 取回访问协议

##### （1）轮询

主站依次询问每个从站是否有数据要发送。优点无冲突；缺点是主站负担重。

##### （2）令牌传递（Token Passing）

一个特殊的控制帧"令牌"在网络中传递，持有令牌的站点才能发送数据。
- **应用：** 令牌环网（IEEE 802.5）、FDDI
- **408了解即可**

### 六、局域网与以太网

#### 6.1 以太网（Ethernet）概述

以太网是最广泛使用的局域网技术，基于 IEEE 802.3 标准。

**发展历程：**
- 1970s：Xerox/Digital/Intel 开发的原始以太网（2.94 Mbps）
- 1980s：标准以太网（10 Mbps）
- 1990s：快速以太网（100 Mbps，IEEE 802.3u）
- 2000s：千兆以太网（1 Gbps，IEEE 802.3z）
- 2010s：万兆以太网（10 Gbps，IEEE 802.3ae）
- 2020s：40G/100G/400G

#### 6.2 以太网帧格式 ⭐ 必考

IEEE 802.3 标准帧格式（最常见）：

```
| 前导码(7B) | 帧起始定界符(1B) | 目的MAC(6B) | 源MAC(6B) | 长度/类型(2B) | 数据(46-1500B) | FCS(4B) |
```

| 字段 | 长度 | 说明 |
|------|------|------|
| 前导码 | 7 字节 | 56个交替的0和1，用于时钟同步 |
| 帧起始定界符 | 1 字节 | `10101011`，标志帧开始 |
| 目的地址 | 6 字节 | MAC地址（单播、组播、广播） |
| 源地址 | 6 字节 | 发送方的MAC地址 |
| 长度/类型 | 2 字节 | 数据字段长度（≤1500）或协议类型 |
| 数据 | 46-1500 字节 | 网络层数据包 |
| FCS | 4 字节 | CRC-32 校验 |

> ⭐ **408必考：** 注意几个数字：
> 1. 数据字段最小46字节（最短帧64字节 = 14+64+4，14字节首部+512bit最小帧+4字节FCS）
> 2. 数据字段最大1500字节（最大帧MTU）
> 3. 目的MAC为 `FF:FF:FF:FF:FF:FF` 时是广播

#### 6.3 MAC 地址

- MAC地址（物理地址）：48位（6字节），通常以十六进制表示
- 格式：`XX:XX:XX:XX:XX:XX` 或 `XX-XX-XX-XX-XX-XX`
- 前3字节 = 组织唯一标识符（OUI），由IEEE分配
- 后3字节 = 厂家分配
- **广播地址：** `FF:FF:FF:FF:FF:FF`

> ⭐ MAC地址是链路层的"地址"，IP地址是网络层的"地址"。

#### 6.4 以太网交换机

以太网交换机是数据链路层设备，具有以下特点：

| 特性 | 说明 |
|------|------|
| 工作方式 | 存储转发 / 直通转发 |
| 每个端口 | 独立冲突域（无冲突） |
| 地址学习 | 自动学习MAC地址表 |
| 转发方式 | 基于MAC地址转发帧 |
| 与集线器区别 | 集线器所有端口在同一冲突域；交换机每个端口独立 |

**地址学习过程：**

1. 收到帧 → 检查源MAC → 学习并记录端口
2. 检查目的MAC → 查表：已知 → 转发到对应端口；未知 → 泛洪
3. 表中项有老化时间（通常300秒）

> ⭐ 交换机是408选择题常考内容。记住"冲突域"和"广播域"：交换机隔离冲突域但不隔离广播域。

### 七、链路层设备

| 设备 | 工作层 | 功能 | 冲突域 | 广播域 |
|------|--------|------|--------|--------|
| 中继器 | 物理层 | 信号放大 | 不隔离 | 不隔离 |
| 集线器 | 物理层 | 多端口中继器 | 不隔离 | 不隔离 |
| 网桥 | 链路层 | 连接两个局域网 | 隔离 | 不隔离 |
| 以太网交换机 | 链路层 | 多端口网桥 | 隔离 | 不隔离 |
| 路由器 | 网络层 | 连接不同网络 | 隔离 | 隔离 |

> ⭐ 隔离冲突域的设备：网桥、交换机、路由器。隔离广播域的设备：路由器（只有路由器隔离广播域）。

## ⚠️考试高频坑点

| 坑点 | 易错理解 | 正确理解 | 来源 |
|------|---------|---------|------|
| CRC校验 | 认为CRC能检测所有错误 | CRC有局限性，不能检测所有错误 | 教材原文 |
| 最短帧长 | 用误码率推导最短帧长 | 最短帧长 = 2τ × 数据率 = 512bit，由争用期决定 | 考试考法 |
| GBN窗口大小 | 认为GBN发送窗口可以是任意值 | 必须满足 W_send ≤ 2^n - 1 | 教材原文 |
| SR窗口大小 | 认为SR和GBN窗口约束相同 | SR: W_send + W_recv ≤ 2^n | 教材原文 |
| CSMA/CD冲突处理 | 认为检测到冲突就立即重传 | 需执行截断二进制指数退避，随机等待 | 教材原文 |
| 交换机与集线器 | 认为交换机隔离广播域 | 交换机只隔离冲突域，不隔离广播域 | 教材原文 |
| 帧填充 | 认为填充会改变帧中的0 | 零比特填充只在5个连续1后插入0 | 考试考法 |
